## 2. 用法

```bash
xiaojianghu/tools_common/codex-router.sh [-m 模型] [-r] [-w all|docs|game] [-l 日志名] "任务说明" [-- 其他codex参数]
```

- `-r`：只读（调研、统计、审读）。
- `-w`：可写范围。`docs` 只能写 `xiaojianghu`，`game` 只能写 `xiaojianghu-legacy-prologue`，`all`（默认）两边都能写。按 R-工作区-01 选最小的那个。
- 任务说明为 `-` 时从标准输入读，长说明写成文件后 `< file` 传入。
- 必须在本机终端（沙箱外）运行，受限沙箱里连不上网。
- 已知无害输出：`Reading additional input from stdin...`。

## 3. 什么分派、什么不分派

**适合分派**：
- 只读调研与统计（某场次用到哪些素材、哪些台词超长、哪些标记没人读）；
- 明确文件范围的小改动；
- 独立的检查脚本或工具脚本、补写测试；
- 素材批处理脚本（不含出图本身）。

**不分派**：
- 剧情台词的起草和改写（走 story-writing 的三道关）；
- 设定、人物、定稿事实；
- 要用户审美判断的美术、界面、特效定稿（R-特效-01～02）；
- 改已批准的 ink 剧本或运行 `--approve`；
- 改规则（R-文档-02）；
- 涉及密钥、提交、发布的操作（R-git-01、R-发布-01）。

### 3.1 什么时候该调用（2026-10-25 用户：“开发过程中多点使用 302 的 claude5.5 模型去进行子任务，完善好什么时候该调用的场景”）

主会话每次要派子任务时先过这张表，能走路由器的一律走路由器；只有落在第 3 节“不分派”里的，才用会话内子代理或主会话自己做。

| 场景 | 例子 | 模型 | 权限 |
| --- | --- | --- | --- |
| 跟着已定设计改测试断言 | 剧本改写后台词断言过时；时间线改了，verify 脚本要跟上 | sonnet | `-w game` |
| 文档同步、名词替换 | 货币单位统一、已删物品换现行物品、链接与状态行同步、拍板记录照原话誊写 | sonnet | `-w docs` |
| 数据登记与生成 | 采用的素材三处登记（json、md、js）；装备数据改源头后重新生成 | sonnet | `-w game`／`-w docs` |
| 检查与统计脚本 | 透明洞扫描、台词超长统计、未读标记统计、素材引用清点 | sonnet 或 haiku | `-r` 或 `-w` 到工具目录 |
| 只读调研 | 某场次用到哪些素材；某个旧设定在哪些文档出现过 | haiku | `-r` |
| 机械性代码改动 | 版本号批量更新；按清单改常量；已设计好的数据表填表 | sonnet | 最小工作区 |
| 已有设计、文件范围明确的开发小块 | 已定稿界面的某个组件、已定规则的数据驱动表 | opus | 最小工作区 |

不走路由器的（照第 3 节）：剧情台词起草与改写、设定与定稿事实、要用户审美判断的美术界面定稿、已批准剧本与 `--approve`、规则、密钥、提交与发布。另外两类先用会话内子代理：要在 8792 截图验证的开发（路由器沙箱起不了浏览器，2026-10-25 实测）和生图（要用 `imggen.py` 与密钥）。

已知限制：路由器子任务在沙箱里起不了 Playwright／Chromium，凡是要截图、导出渲染图的，交回后由主会话补跑；子任务自报“完成”时主会话照第 5 节自己核对（2026-10-23 货币统一、旧物替换两次都有漏改，由主会话补上）。

## 4. 任务说明怎么写

写清楚四件事：
- 允许改哪些文件、不许碰哪些；
- 完成标准，包括要跑哪条检查；
- 汇报格式；
- 按 R-子任务-01 从登记表挑出的相关规则。

并行的子任务先分好文件归属，同一个文件同时只有一个人写。

## 5. 验收

子任务说“做完了”不算证据。主会话自己核对改动的文件，重跑相关检查后才算通过：
- 运行代码：`node tools_scene/qihe/verify_*.cjs`；
- 剧本：`node tools_story/build_ink.cjs`；
- 文档：`python3 tools_docs/check_docs.py`。

改动照常登记进改动清单（R-文档-03），由主会话登记。
