# 战斗特效规范（js/vfx.js）

目标：所有招式特效**同一像素语言**、**强度与招式等级严格挂钩**。低等级招式在机制上不可能比高等级招式更炫。

## 1. 像素语言

- 特效画在 **1/3 分辨率离屏层（320×180）**：1 个特效像素 = 画面 3×3，与角色精灵（47 像素高 ×3）同尺度，最近邻放大，不允许半透明柔边的矢量图形。
- 辉光：把像素层缩到 1/12 分辨率模糊后叠加（`lighter`），得到块状光晕。**不在像素层之外另画平滑渐变光**（压暗 `dim` 与闪白 `flash` 除外）。
- 纯光源层（v2）：与像素层同分辨率的第二张离屏层，只以「块状半透明光（×0.75，`lighter`）+ 辉光」出现，不遮挡角色。用于蓄势光柱、蓄力红光等需要「罩住身体」的光，接口 `API.PG(x,y,w,h,col,a)`。
- v2 舞台偏暗：各调色板第 4/5 阶（暗、余烬）整体提亮一档，粒子尾段不再直接"消失在黑里"；辉光强度 .9→.78；新增 `冰`（破势/回盾）、`金`（蓄势）两条调色板。
- 颜色：每种兵刃/内劲一条 5 阶调色板 `VFX.PAL`（白 → 亮 → 主色 → 暗 → 余烬），粒子按寿命沿调色板走完。新增类型先加调色板，**不要在招式里写死新颜色**。
- 叠加混合：发光元素一律 `lighter`；尘土等实体元素用 `source-over`。

## 2. 等级与预算（硬上限，代码截断）

| 等级 | 适用 | 时长 | 粒子 | 震屏 | 闪白 | 压暗 | 顿帧 | 允许的元素 |
|---|---|---|---|---|---|---|---|---|
| **T0 普攻** | 普攻、敌人基础招 | ≤380ms | ≤14 | ≤3 | 0 | 0 | ≤30ms | 单个命中图形（环/刀光/刺点）+ 火花 |
| **T1 入门** | 内力 1–7 | ≤650ms | ≤28 | ≤5 | ≤.12 | 0 | ≤50ms | + 施法前摇（弹道/鞭影/脚下法阵）、地面裂纹、少量上升光点 |
| **T2 进阶** | 内力 8–12 | ≤950ms | ≤56 | ≤8 | ≤.22 | ≤.25 | ≤70ms | + 压暗背景、全屏横扫/天降元素（落雷、叶刃群）、多层图形 |
| **T3 绝学** | 内力 ≥13；头目招式；破势 | ≤1400ms | ≤110 | ≤12 | ≤.4 | ≤.5 | ≤110ms | + 巨型刀光/光柱、碎片爆散、强闪白 |

- **同档内按内力线性分配**：预算系数 `s = .62 + .3 × (mp−档下限)/(档上限−档下限)`，内力越高越接近上限。
- **蓄势**：每点 ×1.08，但 `s ≤ 1`，永远不能突破本档上限。
- 头目招式（`FXDEF.boss`）可比内力档位高 **1 档**（鬼头斩 mp10 → T3）。
- 所有接口都走预算：`emit()` 超额的粒子直接丢弃；`shake/doFlash/doDim/hitStop` 取 `min(请求值, 档上限)`；实例时长截断到档上限。

### 2.1 战斗时钟与顿帧（v2）

- `window.BT`（vfx.js 定义）：`BT.now()` 为扣除顿帧后的毫秒，`BT.stop(ms)` 从此刻冻结 ms（重叠取最远结束点），`BT.frozen()`。
- 顿帧 `hitStop` 改为 `BT.stop(min(ms, 档上限))`：冻结期间**特效时钟、粒子步进、单位动作帧、冲刺/后跳位移、受击闪白、死亡碎散**全部停住；`wait()` 的真实节奏不冻结（出手编排用 `VFX.btWait(ms)` 按战斗时钟等待，会被顿帧顺延）。
- 粒子改为按 BT 时间以 60Hz 定步长推进（每帧最多 3 步），与帧率无关。
- **破势时停**是系统演出，不属招式预算：`doBreak` 额外 `BT.stop(250)`（招式顿帧上限仍按表）。

## 3. 单调性约束（自检）

`VFX.audit()` 在加载后自动运行，违规在控制台 `console.warn('[VFX 等级自检]')`：

1. `tier ≤ tierCap(mp)`（头目 +1）。
2. **同类比较**（伤害类 `dmg` / 辅助类 `sup` 分开）：内力更高的招式 tier 不得更低。
3. `BSK` 中每个招式都必须在 `FXDEF` 登记。

新增招式流程：`SKILLS` 定内力 → `FXDEF` 登记 tier/cls → `SK[key]` 写 `cast/hit`（可省略，省略则按兵刃类型走 T0 通用命中）→ 刷新页面看控制台自检无警告。

## 5. 战斗动作与出手编排（js/bfx.js，v2）

### 5.1 动作驱动的 `drawUnit`

- 读 `window.BART[u.art]`（格式见 battle-v2.md §2.1）：按状态播动作，缺动作回退 `dash→idle`、`atk2→atk`、`brk→hurt`、`dead→hurt`、`win→idle`（`hurt/cast/atk→idle`）；精灵表未加载时自动 `loadOpt`，加载前按缺条目处理。
- 状态优先级：倒下 `dead`（保持末帧）＞ 进行中的动作（`atk/atk2/hurt/cast/dash/win`，`dash/win` 为保持型）＞ 破势 `brk`（循环）＞ 头目蓄力 `cast`（保持）＞ 待机 `idle`（每个单位相位错开）。
- 缺条目的角色：原静态帧 `c_{art}_{r|l}_0` + 呼吸，并以**程序化姿态**补动作（冲刺前倾、出招后缩→前顶、受击后仰、运功微浮 + 淡金、破势灰化倾斜、我方倒下后仰压暗）。表内缺某动作时同样补程序化姿态。
- 全员动作表已由 `js/bart.js`（`BART`）提供（主角 `b_hero` 18 帧、苏芷 `b_suzhi` 16 帧、大黄与 7 种敌人各 14 帧），规格见 [battle-sprite-spec.md](battle-sprite-spec.md)。`s_hero_battle` 仅作 `BART.hero` 缺失时的回退，已不再生成。
- 尺寸一律 `unitH(u)`（A 负责）。影子为 3px 阶梯的像素椭圆，跳起时缩小变淡。
- 着色在一张复用的小离屏画布上按源分辨率完成（闪白=剪影、灰化=`saturation` 混合、压暗=`source-atop`），不逐帧新建画布：受击闪白（0–70ms 全白，120–190ms 70%）、治疗淡绿、回盾冰蓝、蓄力红脉动、蓄势淡金。
- 同一帧 `drawUnit` 只执行一次，按「站位 y + 位移 y」重新排序全部单位，冲到目标跟前的出手者画在目标之前。

### 5.2 出手编排

| 场景 | 时序 |
|---|---|
| 普攻 / 近身武学（伏虎拳、摔碑手、莲花落、嗅探）/ 敌人出手 | `CAM.focus`（双方中点，1.08）→ **冲刺**到目标前方（dash 帧 + 3 个递减透明残影，170–280ms，ease-out）→ `atk` 出招，等到命中帧再结算 → 连击段 `atk2` → `CAM.reset` → **后跳回位**（300ms，30px 抛物线） |
| 远程/群体武学（金针、牧羊鞭法、柳叶剑法、刮风脚、鬼头斩前摇） | 前踏 36px + `atk` → 施法前摇（`VFX.cast` 返回的毫秒，按 BT 等待）→ 命中 → 退回原位；群体时镜头 1.04 |
| 治疗 / 增益 / 道具 | 前踏半步（28px）+ `cast` 运功帧 + 脚下法阵 → 生效 → 退回 |
| 闪避 | 目标向后跳闪（340ms，34px + 12px 抬起） |
| 受击 | 所有单位播 `hurt` + 12px 击退 + 闪白 |

- 敌人被打倒：先红白交替闪 260ms，再按原精灵颜色**自上而下**分块碎散（约 44 行像素块，每块在 0–560ms 内依高度释放，释放瞬间闪白，随后带余烬色上飘、`lighter` 叠加），全部散尽后不再绘制。取像素失败时回退为淡出。
- 我方倒下：闪白 160ms → `dead` 帧（无则受击帧/程序化后仰）灰化压暗。
- 胜利 `BFX.victoryPose()`：镜头推向我方存活者（1.12），逐个错开 90ms：有 `win` 动作播 `win`，否则运功帧 + 两次小跳；总约 900ms。
