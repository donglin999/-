# 队伍页背景：分层与整张生成对比试样

状态：等用户选　日期：2026-11-09

用户 11-09：“背景的内容设计必须要结合人物卡，以及配合角色动作立绘等，实在不行就直接连角色同步生成，不用切割。”试两种做法，各两张：殷红缨、裴知古。

## 共同点

- 场景从人物卡来：
  - 裴知古：归云谷溪东半亩书屋前的溪边石径，左边一块她在拓的旧碑（她目光朝左），右后方书屋檐下晾拓片，午后光从左上来。
  - 殷红缨：归云谷谷口，她扛剑站在入谷石阶前像守门（人物卡：常年在外、最怕家散、护短），身后台阶通向谷里的屋檐炊烟，左老松、右界石，上午光从左上来，对比强。
- 光向按立绘本身的受光方向定；画面中间人物身后简淡。
- 背景只许用菜单底图的 20 色（同第四版背景板）。

## A 分层（`*-A.txt`）

1. `place.py` 按队伍页的实际摆法把立绘放到画布上（`refs/*-placed.png`）。
2. 让模型“人物一个像素都不动，只把周围空白画成场景”，地平线、脚下投影按人物来。
3. `finish.py`：背景按底图色板压饱和度 → 原立绘原样叠回 → 裁成立绘区比例 1200x1072。

人物就是定稿那张，和对话、头像一致；背景配色能单独管住。

## B 整张（`*-B.txt`）

参考图给立绘，让模型把人物和场景画成一整张。融合最自然，但人物是重画的：裴知古两张里一张丢了耳侧木笔、人物整体变小、脸略有出入；而且人物和背景分不开，没法只压背景的颜色。

## 游戏里怎么看

试样放在 `game/assets/ui/jianghu-v4/portraits/bgtest/tr*/`，用 `--menu=party-peizhigu#art^trA1` 这类参数截图（注意 `#art` 要写在 `^` 前面）。总对比图 `_cmp_ingame.jpg`。

## 量化

`finish.py` 输出背景色相在底图范围内的比例与饱和度（底图饱和度 10，上限 17）：

| 试样 | 色相在范围内 | 饱和度 |
| --- | --- | --- |
| 裴知古 A1／A2（压色后，只量背景） | 99.9%／99.8% | 11.9／11.6 |
| 裴知古 B1／B2（整张，含人物） | 99.8%／99.8% | 19.2／19.6 |
| 殷红缨 A1／A2（压色后，只量背景） | 99.1%／99.1% | 11.5／11.0 |
| 殷红缨 B1／B2（整张，含人物） | 93.9%／94.2%（不到 95%，红发带、酒葫芦和背景混在一起分不开） | 14.9／14.7 |

殷红缨用的是 11-09 重画的新立绘候选 new1（见 [yin-portrait-new-v1](../yin-portrait-new-v1/README.md)）；`obsolete-fix3/` 是先用局部修腿版做的、被用户叫停的那一批。

## 我的看法

A 和 B 在游戏里看，融合程度差不多（光向、脚下投影、地平线都对得上），差别在人物：A 是定稿立绘原样，B 每张都在重画人物，脸和细节会漂。所以推荐 A 作为以后的标准做法：背景按人物卡定场景、按立绘定光向和视平线，带着立绘出图，再把原立绘叠回。
