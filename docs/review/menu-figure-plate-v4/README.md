# 队伍页背景板 · 第四版（只用菜单底图的颜色）

状态：等验收　日期：2026-11-08

## 为什么有第四版

第三版按量化规格拉开了差异，但靠的是换色相（青、蓝、紫、橙各一张）。用户说：“背景不需要更多的颜色，还是以背景的色点作为组成色，不然就太乱了。”所以第四版定了一条硬规矩：**颜色只许用菜单底图里有的那一族**，差异只靠明暗、对比、雾与留白、光线方向和构图来拉开。

## 颜色从哪来

- `ref-page-bg.png`：菜单底图 `game/assets/ui/jianghu-v4/background.webp` 的拷贝。
- `palette.json`／`palette.png`：从底图聚类取的 20 色。色相 34～43°，明度 25～98%；底图里有颜色的像素（饱和度 >10%）色相全在 15～60° 之间，也就是纸白、暖灰、赭黄、墨褐。

## 怎么出图

1. `spec.json`：每人一条量化规格——地点、明暗调子（目标明度）、对比、雾与留白、时辰与光线、地平线高度、主景位置和宽度、近景。通用要求：画面中间 30% 留给人物，平地约占四分之一高，四边淡出 12%。
2. `prompts/*.txt`：提示词里写死色板十六进制值，参考图只给底图，明令不许出现底图没有的颜色。`run.sh` 并发 4、`--background opaque`，原图在 `raw/`。
3. `tone.py`：只调深浅不动色相，把每张的明度均值和对比拉到目标值，饱和度压到底图同一明度上出现过的最大值以内，结果在 `toned/`。
4. `measure.py`：量化检查（见下）。通过后缩到 768×768，存成 webp（质量 90）装进 `game/assets/ui/jianghu-v4/figplate/`。

`lock.py` 和 `try_lock_v3/` 是先试过的“事后锁色”做法：把第三版硬改成底图色，结果发黄发粉、像旧照片，弃用，留作记录。

## 量化检查（measure.py）

- **配色合规**：有色像素中色相在 13～62° 的要 ≥ 95%，饱和度均值不超过底图的 1.5 倍＋2。
- **两两差异**：两张至少满足一条——明度差 ≥ 8、对比差 ≥ 5、留白差 ≥ 0.12、左右重心差 ≥ 0.10、上下明暗差之差 ≥ 10。
- 结果见 `measure_final.md`：八张全部在底图色内，28 对全部拉得开。

## 新角色怎么加

在 `spec.json` 加一条规格（明暗调子和雾要和已有的错开），按 `prompts/` 的格式写提示词，跑 `run.sh` → `tone.py`（加目标值）→ `measure.py`，退出码 0 才能装。
