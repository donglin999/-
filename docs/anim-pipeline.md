# 帧动画管线：程序白模 → 参考生图 → 自动校验组表

## 0. 原则：原型优先，程序给骨架，生图给皮肤

单纯让生图模型画连续动作：姿势不可控、帧间形象漂移、只能反复抽卡，成本高且效果差。
单纯程序变形（行错位、手臂贴片）：动作可控但形象呆板、细节糊。

本管线把两者分工：

| 环节 | 负责 | 产出 |
|---|---|---|
| 动作（姿势、时序、位置） | **程序**：2D 骨骼 + 关键帧 + 正向运动学 | 每帧的**白模**（灰色人偶剪影）与关节坐标 |
| 外观（服装、脸、材质、画风） | **生图模型**：参考「白模 + 角色定妆图」生成 | 每帧的角色图 |
| 对齐、像素化、质检 | **程序** | 精灵表 + BART 条目 |

动作的确定性全部来自程序：白模怎么动，角色就怎么动；要改局部动作（比如出剑的手腕角度）只改一个关节的关键帧、只重生成受影响的帧。

## 2. 骨骼与白模

- **人形骨骼**：骨盆（根）→ 脊柱 → 颈 → 头；左右肩 → 上臂 → 前臂 → 手；左右髋 → 大腿 → 小腿 → 脚；可挂**武器骨**（剑/刀/针/杖，挂在手上，有长度与握持角）。四足（狼/犬）、蛇（样条链）、禽（鸡）各自一套简化骨骼。
- **比例**：按角色的目标美术像素高与头身比实例化（我方约 64 像素、6 头身；敌人按档位），保证白模剪影就是最终精灵的比例。
  人形 `Body(H, heads, weapon, build, bulk, robe, cape)`：`bulk` 四肢躯干粗细倍数（山贼 1.18、头目 1.4、丐帮长老 0.94），`robe` 长袍下摆（老僧 0.7 = 小腿 70% 处），`cape` 背后披风（头目，深灰 `#646464`）。
  武器骨 `kind`：`sword` 剑、`needle` 针、`saber` 厚背刀（刀背直、刃口外鼓的多边形）、`ghost` 鬼头大刀（更宽 + 环首）、`staff` 竹棒（握中段 grip≈0.42）。
- **白模渲染规则**（给生图模型读得懂、给程序校验得了）：
  - 侧身，我方朝左、敌方朝右；地面线固定在同一高度，脚底贴地。
  - 近侧肢体浅灰 `#d8d8d8`、躯干中灰 `#b0b0b0`、远侧肢体深灰 `#808080`，关节处小圆；武器纯色（如剑 `#4aa3ff`），便于生成后定位武器尖。
  - 头部画出朝向（鼻尖小三角），避免生成时脸朝错方向。
  - 同时导出关节坐标 JSON，后续配准与质检用。

### 2.2 非人形骨骼（`rig_beast.py`，工作流 I）

`fk()` 返回 `shapes`（胶囊 / 多边形 / 圆 / 眼点，分 F 远侧 / T 躯干 / N 近侧三层）而不是人形的 `segs`；`mannequin.draw/silhouette` 按 `fr['kind']` 自动转交，所以配准、质检、组表代码对所有骨骼通用。角度约定同人形：0 = 朝前，90 = 向下。

| 骨骼 | 结构 | 姿势参数 | 质检关节 |
|---|---|---|---|
| 四足 Quad（狼 s=1.0、犬 s=0.8） | 髋→肩躯干（胸/腹/臀三圆凸包）、颈、头（颅圆 + 吻部楔形 + 可张下颌 + 耳三角）、3 节尾（`tail='curl'` 上卷画在身后）、前腿 3 节、后腿 4 节（大腿-小腿-跖-掌） | `dx dy pitch neck head jaw tail[3] fN/fF[3] hN/hF[3] air` | head nose pawFN pawHN pawFF pawHF tail |
| 禽 Bird（斗鸡） | 椭圆身体、2 节颈、头（圆 + 喙 + 可张下喙 + 5 齿鸡冠 + 肉垂）、3 根镰刀尾羽（逐节弯曲的胶囊链）、近/远翅（泪滴多边形，可扬起张开）、腿（羽毛大腿 + 细跗跖 + 前趾/后趾/距） | `pitch neck[2] head beak wingN/wingF[角,张开] tail lN/lF[髋,膝] air` | head beak toeN toeF tail |
| 蛇 Snake | 控制点 Catmull-Rom 样条，按弧长给粗细（尾尖 0.18 → 中段 1 → 颈 0.7）；`coil()` 生成侧视盘圈（下半圈近侧、上半圈远侧画深灰，看得出层叠）；头为椭圆 / 张口时上下颚两片 | `pts=[[x,y,z]…] head jaw` | head snout tail |

动作集各自定义（`poses.py`：`QUAD_ACTIONS / BIRD_ACTIONS / SNAKE_ACTIONS`），每种 8 个生图姿势、2 张 2×2 网格：
四足 `stand run crouch leap bite hurt low dead`（atk = 蓄 crouch → 扑 leap → 咬 bite → 收 stand，hit 在咬）；
禽 `stand run rear peck kick hurt low dead`（atk 扬翅后仰 → 啄，atk2 扑腾飞踢）；
蛇 `coil slither rear strike wrap hurt low dead`（atk 后缩 → 扑咬，atk2 缠绕：前段身体在空中绕成一圈）。
派生帧新增 `('air', 姿势, dy)`：整体上提（冲刺腾空帧不再单独生图）。

## 3. 生图：参考白模 + 定妆图

- **定妆图**（每个角色一次）：先生成/选定一张该角色**标准侧身站姿**的高清图（服装配色对齐对话立绘），作为全部帧的外观参考；必要时加正面立绘作补充参考。
- **按动作条带生成**（推荐）：把一个动作的 3–6 帧白模横排成一张条带图，与定妆图一起输入，一次生成整条——同一次生成内帧间风格一致性最好；也支持单帧生成（局部修帧用）。
- 提示词要点：严格按白模的姿势与位置作画、保持定妆图的服装发型配色、侧身、纯白背景、不要额外人物/文字、每格一个角色且位于白模同一位置。
- 接口（实测）：FlatRouter `gpt-image-2.5-flare`、quality=medium，**只用异步接口** `/images/edits/async`、`/images/generations/async`（202 → 轮询 `poll_url` → 带浏览器 UA 下载 `image_url`）。多图 `image[]` 忠实度差，默认**单张拼图**（左定妆图、右 ≤4 格白模）。账号级并发约 3 个任务（与其他工作流共享），`call()` 遇 "Concurrency limit exceeded"/429 退避 20–60s 重交、不计失败次数。
- 定妆图：`generations/async` 纯文字生成，品红底，人形 1024×1536、动物 1536×1024；非人形提示词用"realistic animal anatomy"，并在 WPN 说明里告诉模型白模各部件是什么（耳三角、吻部、尾羽、鸡冠、盘圈深浅）。

## 4. 配准、像素化、质检

1. **配准**：生成图去背后得到剪影，与该帧白模剪影做平移（必要时微缩放）搜索使 IoU 最大；用白模的脚底/骨盆锚点把所有帧对齐到同一基线——**帧间抖动由程序保证为零**。
2. **像素化**：全角色共用一套调色板（从定妆图提取）；按目标美术像素高降采样（面积平均后再限色），1px 深色描边；**整数 3× 输出**。
3. **质检**（`qa.py`）：剪影 IoU ≥ 阈值（如 0.8）、手/脚/武器尖与白模关节误差 ≤ 阈值（如 2 美术像素）、调色板距离；不达标的帧自动重生成（有上限），仍失败则标记给人工。
4. **组表**：输出 `assets/b_{char}.webp` 与 `js/bart.js` 条目（`hit` 帧取自动作定义中标记的命中关键帧）。

合计 34 个请求、全部一次成功（0 次失败重试，0 次并发退避），模型耗时合计约 30 分钟（单请求 38–63s，3 并发墙钟约 13 分钟）。
经验：
- 模型画出的敌人/动物普遍比白模**小 10–35%**：配准缩放上限从 1.36 放宽到 1.62（`CHARS[c]['sc_max']`），否则会卡在上限、配准偏。
- 腾空帧（leap/kick）模型常画成贴地：质检与组表都先贴地再按姿势 `air` 上提（`extract()` 统一给 `lift`），否则 IoU 会被误判。
- 关节距离阈值按身高缩放（`H/64`，头目 ×1.6）；头目披风随动作外飘，`spill` 放宽到 0.30（`qa_th`）。
- 模型对"扬翅/后仰"一类躯干大幅动作（rear、kick）遵从度低于四肢动作，但剪影仍能配准；对人形的持械方向、四足的步态、蛇的盘圈与缠绕遵从度很高。

## 5. 迭代方式

- 改动作：改 `poses.py` 的关键帧 → 重渲白模 → 只重生成变化的帧 → 重组表。
- 改外观：换定妆图 → 全部帧重生成（白模不变，动作完全一致）。
- 新角色：选骨骼类型 + 比例 + 定妆图，动作库直接复用。
- 敌人一条龙（仓库根目录）：
  ```bash
  python3 tools_fx/rig/mannequin.py wolf                          # 白模总览 review/battle_v4/I/rig_wolf.png
  python3 tools_fx/rig/batch.py model wolf dog                    # 定妆图（已有则跳过）
  python3 tools_fx/rig/batch.py grid wolf:atk,base dog:atk,base   # 动作网格（≤3 并发）
  python3 tools_fx/rig/qa.py wolf                                 # 质检选帧（--regen N 自动重生成）
  python3 tools_fx/rig/assemble.py wolf --pipe all                # 组表 assets/b_wolf.webp + raw_battle/I/sheets.json + pipe_wolf.png
  python3 tools_fx/bart_sync.py && python3 tools_fx/rig/compare.py
  ```

### 6.1 骨骼：3D 摆姿势、按方向投影

- 坐标（美术像素）：X = 角色自身左侧，Y 向上（地面 0），Z = 角色前方；骨盆地面投影为原点。步态只在 3D 里定义一次，4 个方向都是它的投影，所以**正/背面也有左右腿交替与手臂前后摆**。
- 投影：`d` x=+X、深度=+Z；`u` x=−X、深度=−Z；`r` x=+Z、深度=−X；`l` x=−Z、深度=+X；屏幕 y = −Y + 0.5·深度（3/4 俯视：靠近镜头的地面点更低 → 正面行走时前脚低、后脚高）。
- 比例（约 2.5 头身）：头半径 8.6（头顶 ≈41）、肩高 22.6、腰带 14.2、髋高 12.6、大腿 6.1、小腿 5.9、脚为半径 1.25 的胶囊。主角袍摆在膝（hem 6）、背剑、高马尾；苏芷裙摆到踝上（hem 3，裙摆下缘随两踝张开，靠镜头一侧的脚画在裙摆之上，否则裙子把步态全遮住）、发髻。
- 白模：浅灰=近镜头、深灰=远离（按深度连续着色），每个图元带深灰描边（重叠的同色肢体分得开）；头部深灰=头发、浅灰=脸（两点眼 + 鼻三角标朝向），马尾/发髻/发带红点、剑鞘、腰带线帮助模型定位。
- 膝盖用两骨 IK（膝朝前）从脚的轨迹解出。

### 6.2 动作与帧数

| 动作 | 帧 | 设计 |
|---|---|---|
| walk | 12 | 单腿支撑相 β=0.56（每半周期 0.06 双支撑）；支撑脚贴地匀速后移（A=±4.1），脚跟着地时脚尖上翘 12°、蹬地时脚跟抬起 30°；摆动脚走样条轨迹（抬高 2.3）；骨盆起伏 接触 −0.4 → 下沉 −1.0 → 过渡 0 → 腾起 +0.7；侧向重心摆 ±0.35；肩与骨盆反向扭转 ±6°；手臂与对侧腿同相摆 ±24°（滞后 0.35 rad、前摆时屈肘加大）|
| run | 10 | 支撑相 β=0.36（每半周期 0.14 腾空，双脚离地）；支撑中段压低 −1.2、腾空最高 +1.5；前倾 10°、头 −4°；后踢腿（脚跟抬到 3.6）→ 高抬膝前送；屈肘 78° 大摆臂 ±50° |
| idle | 6 | 站姿派生，不让模型重画（避免细节闪烁）：腰带以上上提 1px（呼吸）、衣摆两行横移 1px；逐帧 ms `[420,180,380,200,260,200]`（约 1.6s 一周） |

帧数取舍：一个步态周期 = 两步。walk 12 帧 = 每步 6 帧，正好放下 接触/下沉/过渡/腾起 四个关键相位外加两个中间帧，在常速（见 6.4，约 17fps）下每帧间隔 ~60ms，腿不会"跳格"；再多帧在 47px 高的精灵上相邻帧只差 0–1 像素，收益很小而生图成本线性增加。run 周期更短、有腾空相，10 帧（每步 5 帧：着地/压低/蹬离/腾空/前摆）在约 21fps 下同样顺滑；12 帧与 10 帧同为 3 张拼图，但 10 帧的每帧差异更明显、不易出现"看着像停住"的重复帧。

### 6.3 生成、配准与质检

1. **定妆图**（每角色 1 次）：拼图左栏 = 立绘 `assets/p_{c}.webp`（只借服装/发型/配色），右侧 2×2 = 4 个站姿白模（左上正面、右上朝左、左下朝右、右下背面）→ Q 版 4 方向转面图 `raw_anim/explore/<c>/model_0.png`。
2. **条带**：每个 动作×方向 按帧序切成 ≤4 格（walk 4+4+4、run 4+3+3），拼图左栏 = 定妆图中**同方向**那一格（与白模同比例、同地面高度），右侧 2×2 白模 → 一次生成。接口 `tools_common/flatimg.py`（异步 edits、gpt-image-2.5-flare、medium、1536×1024、≤3 并发）。l/r **分别生成**（背剑在右肩、药囊在左胯，镜像会左右颠倒）。
3. **去背**：模型多数直接返回透明底 + 低 alpha 光晕 → 用 alpha≥128；否则品红色键。
4. **配准**：剪影 IoU 最大化（缩放 0.8–1.35 + 平移，半像素网格）——用于质检；组表时缩放改为**逐帧按身高归一**：目标身高 = 站姿 41 美术像素 + 白模该帧相对站姿的高度差（`height_sc`），限制在条带中位数 ±8% 内。只用 IoU 缩放时各条带大小差 5–7%，每 4 帧头顶跳 2–3px。
5. **锚点**：y = 生成帧最低像素贴到白模最低点（脚底锚点，腾空帧自动离地）；x = IoU 配准后再按"头部水平重心相对白模的偏差"在同一 动作×方向 内取中位数对齐。帧间位置完全由白模决定。
6. **像素化**：共用调色板（定妆图右侧 4 格：中位切分 26 色 + 高饱和像素另取 6 色，保住剑鞘青/发带红/玉簪绿；gamma .82、饱和 ×1.1 对齐 NPC 明亮版）；高清前景按目标网格**精确相位**取格内平均色 → 最近调色板色（众数法 `EXPLORE_DOWN=mode` 实测会把模型的描边/阴影扩成黑斑）；去孤立像素、去孤立杂色、1px 深色外描边；×3 输出。
7. **质检**（`explore.py qa`）：cover ≥.62、spill ≤.16、**腿脚区 IoU ≥.5**（地面上 8 行，检查步态相位画没画对）、头/手/脚关节到生成剪影距离（头 ≤2、近侧 ≤3.5、远侧 ≤6）、分段平均色与定妆图同方向的差 ≤48；不合格条带 `--regen N` 自动重生成；**整条带选同一张生成图**（不合格帧最少、总分最高），不跨候选拼帧。

### 6.4 步幅与播放速度（实测 2026-09-28）

`drawChar` 按走过的距离推进帧：每帧前进 `stride × 身高`（世界像素）。

| | stride | 常速 | 播放帧率 | 步态周期/秒 |
|---|---|---|---|---|
| walk | .13 | 200 px/s（SPEED .2） | ≈16.7 fps（实测） | 1.4（2.8 步/秒） |
| run | .17 | ~330 px/s（×1.7） | ≈21 fps（实测） | 2.1（4.2 步/秒） |

**滑步的物理限制**：Q 版腿长只有身高的约 30%，侧视支撑脚每帧后移 walk 1.2、run 2.0 美术像素（一周期骨盆前进 walk 14.6、run 20 美术像素 ≈ 0.31h / 0.43h）。要做到侧视完全不滑步，walk stride 需 ≈.026（常速下 ≈84fps）。在当前移动速度（每秒约 2.2 个身高，相当于真人小跑）下不可能兼顾"不滑步"与"10–14fps"，这里按**步频自然**取值：walk 2.8 步/秒、run 4.2 步/秒，侧视支撑脚仍有约 4× 的相对滑动（正/背面基本看不出）。若要进一步减轻，只能降低探索移动速度（如 SPEED .2→.12，walk stride 同时降到 .09），这属于 scene.js 的玩法参数，未改。

**步幅**（`STRIDE_C.dog`；大黄身高 = 92×0.6 = 55.2 世界像素）：
