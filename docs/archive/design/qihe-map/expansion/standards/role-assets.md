## 1. 新角色先回答这些问题

可加入成年女角色先查第五版逐人选择（来源：`female-visual-v5.md`）：默认沿双图身材基准；叶蘅恢复初版，唐照雪沿最新指定原图。沈雁回、乔行舟整图重置，以整体美感为第一要素；姿态、衣装轮廓、背景及构图均重新生成，职业由衣装、工具、动作表达。身份原图、身材参考与画风参考的用途须分开记录，最新指定版本优先。普通NPC与不可加入人物继续依职业、年龄制作。

| 必填字段 | 允许值与判断依据 |
| --- | --- |
| `species` | human／具体动物种类；宠物不能归入人类同伴 |
| `role_type` | 下表七种之一；不允许只写「NPC」 |
| `joinability` | player／recruitable／pet／none；依据实际设计，不由名字、配音或精细立绘猜测 |
| `availability` | current／future；是否在当前交付章节可加入或出场 |
| `combat` | true／false；含可切磋、临时援助、敌对战斗，不仅看是否长期在队 |
| `combat_side` | none／ally／enemy／both；临时援助用我方战斗标准，可切磋或转阵营按实际两侧需求列包 |
| `exploration_presence` | on_map／none；只有画外对白、只出现在立绘／CG 的阶段不派地图人物 |
| `exploration_motion` | fixed／walk／walk_run；依据地图实际移动需求 |
| `story_importance` | core／recurring／ordinary；按下方明确条件判定，不因在重大事件里有一句台词就升为重要人物 |
| `services` | 无或具体服务，如商铺、授课；服务不自动升级角色类型 |
| `current_stage`／`planned_stages` | 当前服装、能力与经历；未来阶段另列，不能混进当前出图 |
| `chapter_scope` | 已进入制作范围的场景 ID；仅有远期设定不构成本次生成需求 |

一张角色卡对应一个当前阶段。同一人物换装另建阶段卡，保留 character_id；该阶段只要有一处地图出场就写 on_map。主角、可加入人类与宠物进入探索时使用 walk 或 walk_run；fixed 只供固定 NPC 等实际不移动对象使用。

**招募前阶段**：已确认未来可加入的人物仍写 companion，同时记录 `recruitment_availability=future`、`controls_available=false` 和 `package_scope=appearance_before_recruitment`。本章只作为固定 NPC 出场时，可先交付重要人物的外观／三情绪／固定站立；临时援助依然交付完整我方战斗映射。六张完整对白状态、菜单和四向步行放入完整同伴阶段清单，开放入队前必须补齐。当前出场包通过不等于完整同伴包通过。陆衡、岑霜的具体派单见开篇角色卡（来源：`opening-character-assets.json`）。

## 2. 分类顺序：有多种职责时怎么判

1. 玩家固定主角 → `player`。
2. 动物明确可成为独立宠物 → `pet`；仅敌对动物按 `enemy`，不会变成人类队友。
3. 人类明确可加入队伍 → `companion`，即使首次以商贩、敌人、客人出现也按可加入角色准备。暂未开放招募仍保留这个类型，交付时间写 future。
4. 不可加入，且满足任一条件 → `important_npc`：主要去向／阵营邀约者；长期导师或关系对象；已规划跨章的独立人物线；玩家需单独处理的具名对立人物。只是执行职务、传话、在火灾里救人或有一句语音，不满足这一项。
5. 只承担交战职责 → `enemy`；重要反派则仍为 important_npc，另加 combat=true。
6. 普通商店／授课／兑换等服务 → `service_npc`。
7. 普通任务人物、证人、路人 → `ordinary_npc`。

周砚为 important_npc；陆衡现有开篇素材仍按重要角色与临时参战盘点，但全作已确认可招募，应以 companion 规划未来所需包，不能沿用旧“无正式招募设计”的判断。叶蘅是 companion；苏芷若按当前后续可入队设计生产，也用 companion。周婶、陈伯、药商、店家等用 ordinary_npc；有名字不改变分类。

## 3. 按类型展开必需包

**必需包是交付标准，不是要求立即把未来人物全量生成。** availability=future 或未进入 chapter_scope 时，记录需求并留在计划；current 必需项缺失要列为缺口，不能静默降为普通 NPC。

| 类型 | 身份基准／头像 | 菜单立绘 | 对话立绘与表情 | 独立剧情静态姿态 | 探索 | 战斗 |
| --- | --- | --- | --- | --- | --- | --- |
| player | 定妆原稿 + 同源头像 | 当前阶段 1 张带背景全身图 | 基础 neutral + smile、worry、firm、surprise、hurt 五种 | 按实际场景列出；基础图与 CG 已能表达时为 0，不凑数量 | 四向站立、步行；专用跑步单列为提升项，新增功能另审 | 当前可参战阶段必需专用角色表与实际技能映射 |
| companion | 定妆原稿 + 同源头像 | 当前阶段 1 张带背景全身图 | 6 张透明完整对白状态（含常态，表情与动作合一），详见合同（来源：`companion-performance.md`） | 六状态之外的事件特殊姿态按缺口另列 | 四向站立、步行；专用跑步单列为提升项，新增功能另审 | 当前可参战阶段必需专用角色表；不能以探索小人代替完成 |
| important_npc | 身份基准 + 头像 | 不可入队时不要求角色菜单全身图 | 基础 + firm、worry 两种；更复杂情绪按实际场景补 | 明确代表行为，已有立绘或事件 CG 足够则不另画姿态 | 固定站立；移动才补相应移动包 | combat=true 时必需对应战斗包 |
| service_npc | 职业外观卡；头像可由站立图裁出 | 不要求 | 小头像／场景图 + 对话，不要求大立绘与表情集 | **0** | 所需朝向站立图；移动才补通用步行 | combat=true 时补战斗包，不增加专属剧情动作 |
| ordinary_npc | 简短身份外观卡；头像可由站立图裁出 | 不要求 | 小头像／场景图 + 对话，不要求大立绘与表情集 | **0** | 所需朝向站立图；已有同职业候选可复用 | 实际参与战斗才补包；普通送药、交物不需要 |
| enemy | 体型、服装、武器与种类基准 | 不要求 | 没有对白时不要求；有对白用头像 | **0** | 只在战斗出现则不要求地图包 | 必需敌方战斗包，按人形／动物与招式确定 |
| pet | 物种与个体外观基准 + 宠物图标 | 当前阶段宠物肖像 1 张，不画成人类队友造型 | 无人类对话表情集 | 无人类剧情姿态包 | 该物种四向跟随与移动包 | 自主进攻、护主、受击等，按宠物规范（来源：`pets.md`）展开 |

表中探索项以 `exploration_presence=on_map` 为前提。画外角色和只在立绘／CG 中出现的阶段写 none，不生成地图包；实际开放探索时再补齐。现代工位若只用背景与对白，就不派现代装四向移动图。战斗项由 combat 与 combat_side 决定；临时我方援助也要有胜利等我方映射。

普通 NPC 任务 CG 每项 **0 或 1 张**，根据该任务是否需要一次画面确定；不随角色类型给每个人默认发一张 CG。重要 CG 按事件列出多人构图，不计为各出场者的独立动作包。

头像用于角色列、队伍、战斗等显示位置，可以从同阶段定妆／立绘裁出；这是明确派生项，无须额外生成陌生脸。语音按语音规范（来源：`voice-management.md`）另列；有配音不会增加动作等级。

## 4. 素材键与基数

可加入人类角色每个已开放阶段静态包：**身份基准、1张带背景菜单图、6张完整对白状态立绘、同源头像**。常态已含在六张里，动作与表情整体协调，不另做纯脸图或组合矩阵。每人专属手势、视线、道具、情绪和用途见逐人目录（来源：`companion-performance/index.md`），机器数据见新包（来源：`companion-performance.json`）。

动作与表情都有实际可调用资源才计完成。旧表情键允许显式映射，如angry→firm；同一neutral不得冒充多种情绪。已有图只有通过当前身份、阶段、姿态和裁框复验才计入新包，不能用菜单图、CG或战斗精灵充数。额外事件姿态仍按场景缺口列0…N，CG另计。

2026-10-04以前叶蘅等已验收的基础包和当前运行状态保留。新增完整状态包单列未完成项，不能沿用旧“基础已齐”声称新包通过，也不因新配额否认旧验收事实。未来人物先完成明确需求与提示词，实际制作状态独立登记；当前没有招募或素材的功能继续按实际交付边界记录。

## 5. 阶段变化与招募变化

- 新服装、武器或能力方向改变 → 新阶段；重新核对菜单、对白、姿态、探索、战斗的覆盖情况，脸与体型仍锁定。
- 仅出现短暂情绪 → 补必要表情，不重生全部素材。
- 普通 NPC 后来决定可加入 → 分类改为 companion，先列完整可加入包，不能只加一个入队按钮。
- 可加入人物尚未参战或某套换装尚未开放 → 列出需要的战斗／阶段包并标未交付；不得在该阶段允许相关功能却声称资源完整。
- 战斗、姿态和菜单图只能使用实际拥有的道具。初入村的萧白没有剑，即使襄阳旧图已有剑也只能复用脸部参照。

## 6. 角色设计输出与判定

每个新角色交付：**分类字段、当前阶段身份卡、必需素材逐项清单、现有可复用项、待生成项、质量档案与实际验收状态**。模板字段在规则 JSON（来源：`character-asset-rules.json`）的 `card_template`，本次完整盘点见叶蘅实例卡（来源：`character-card-ye.json`）。

JSON 是规划与 AI 读取格式，本轮尚未接入自动派单程序。质量不靠模型名称保证：每项必须遵守[质量规格](character-asset-quality.md)，生成候选逐项验收后才进入采用、接入和实机验收。必需项只要未满足，就显示具体缺口，不标「角色素材已齐」。
