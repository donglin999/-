## 1. 四个方向不是四张不同人物

| 项目 | 必须满足 |
| --- | --- |
| 视角与方向 | 同一三分之四俯视视角，方向键与朝向一致；行顺序为 d 下／l 左／r 右／u 上，不调错行 |
| 身份与阶段 | 发型、服色、体型、年龄、医具／装备一致；背面也能凭发束、衣领、背带辨认同一人；不开篇加未来佩剑或门派服 |
| 道具左右 | 左胯药囊、右肩剑鞘等按角色身体的实际侧固定。有不对称道具不能直接镜像另一侧充数；只有确认左右对称的造型可采用镜像 |
| 尺度 | 用同地面、同机位、同类姿态的可见身体比较，普通成人相对主角目标 0.97–1.03；有明确高矮设定可 0.93–1.08。透明外框、发簪与行李不代替身体量尺 |
| 像素与色彩 | 与已采用探索角色的颗粒、描边、光向和色阶一致；同角色共用色板，帧间衣色不闪。不是把淡彩大立绘缩成小图冒充像素角色 |
| 画布与锚点 | 同一动作表各方向的单元尺寸、帧数和脚点有明确元数据；不逐帧自动紧裁导致人物移位。不同走／跑表可有不同单元，但切换后实际身体尺度和地面锚点一致 |

当前常规单元高 141 源像素（47 美术像素 ×3）是已有管线基准，单元宽按角色轮廓确定。不得仅为统一矩形宽度拉胖／压瘦人物。

### 分辨率与图集尺寸

| 层次 | 当前标准 | 检查方式 |
| --- | --- | --- |
| 生图原稿／动作拼图 | 现有探索管线请求目标 1536×1024；左侧 384 像素参考栏，右侧 2×2 姿势区，每格约 576×512；每次最多 4 个姿势 | 保存模型实际返回尺寸，低尺寸输出不能先放大再冒充原生高清；逐格检查脸、医具、手与鞋是否能辨，不把四向几十帧挤到同一张生图里 |
| 逻辑美术网格 | 常规单元高 47 美术像素；宽按角色与动作轮廓确定。同一表各帧统一单元 | 47 是含透明余量的单元高度，不是保证人物身体占满 47 像素；按可见身体另验比例、完整性与脚点 |
| 运行单帧 | 逻辑网格整数 ×3 打包，常规高 141 文件像素；单元宽为 3 的整数倍 | 新像素表使用最近邻整数倍率、透明 PNG 或 lossless WebP；不使用平滑放大制造模糊边。宽高必须与 ART 元数据一致 |
| 四向图集 | 固定四行 d/l/r/u，总高 141×4=564；总宽=单帧宽×列数 | 逐格切分无误、无格线、无夹带参考栏、无头脚／道具裁切；不得将整张原稿直接当运行表 |
| 游戏显示 | 当前普通成人可见身体基准约 92 世界像素，屏幕大小随实际镜头／缩放变化 | 在 1280×720、1920×1080 视口实看。文件高 141 不等于游戏里人物必须高 141 屏幕像素；不能混用世界像素、文件像素与截图像素 |

2026-10-01 读取的现有例子：

| 角色／表 | 单帧文件尺寸 | 列×行 | 整张运行图 |
| --- | --- | --- | --- |
| 叶蘅站立／行走合表 | 75×141（逻辑 25×47） | 4×4 | **300×564** |
| 萧白站立／行走合表 | 90×141 | 4×4 | 360×564 |
| 萧白专用行走 | 78×141 | 12×4 | 936×564 |

这些是当前像素密度下的交付规格，不要求所有角色统一为 75 像素宽或统一列数。更大文件只有在实际逻辑细节与共同像素密度提升时才算提高画质；简单放大不增加角色细节，也不能替代步态／身份／实机验收。更改逻辑网格时同步更新角色表、元数据与场景同框检查，不能只放大一名角色。

## 2. 完整循环和动作质量

| 项目 | 通过条件／退回现象 |
| --- | --- |
| 完整步态 | 四方向都有左脚、过渡、右脚、过渡的完整两步循环；正面／背面同样能辨认交替。只有衣摆晃、身体整体上下平移、重复同一静止帧，不算行走 |
| 承重接地 | 步行至少有一只承重脚落在地面投影，鞋与小腿连续；不能双脚长期浮在影圈上、出现脱离人体的贴片鞋，或用底部杂点骗脚点 |
| 长袍／长裙 | 衣摆可遮住部分腿，但应能看出支撑与换脚；下摆不穿地，袋子和肩带跟随身体、不凭空换边或闪失 |
| 循环首尾 | 连续重复时不突然换脸、换衣、改身高，首尾不反向抽动；摆腿、手臂和重心连续 |
| 起伏与转向 | 允许正常走路起伏，不能整个人持续蹦跳；扣除正常步态后检查剩余漂移。停下回站姿、四向切换不突然横跳、脚点瞬移或比例改变 |
| 播放与速度 | 按实际移动距离推进帧、停下停止行走；不原地踏步、移动却僵站、追随加速时腿频与移动严重失配。记录实际 stride 和循环方式，不把旧文档 fps 当成当前固定参数 |
| 裁切与透明边 | 头发、承重鞋、摆臂和必要道具不被单元裁掉；深浅背景均无明显白圈、品红底和游离杂块 |

步行与奔跑分开判：真实跑步有短暂腾空相，阴影仍留在地面，落地相必须恢复正确承托。叶蘅当前用步行表加速跟随，仍按快速步行检查，不能以「跑步允许腾空」解释连续悬空。

当前 Q 版移动存在步幅与速度取舍，侧向轻微滑步不能只靠提高帧数解决；明显滑行、没有换脚或步频失配须处理。是否接受小幅滑步，应保存正常速度录像及理由，不写「保证完全零滑步」。

## 3. 帧数与复用

- 叶蘅当前四列合表：第 0 列站立，第 1／2／3 列为左脚／过渡／右脚；运行按 `1→2→3→2` 循环。已有合格表可直接复用，不把四列误写成四张不同运动帧。
- 主角／苏芷专用行走表为每方向 12 帧，是当前丰富步态的参考方案；新角色先确定循环与实际用途，再选帧数，不强制将全部既有四列表重做成 12 帧。
- 帧多不代表质量高：重复姿态、四向身份变化或鞋腿错误，即使有 12 帧仍退回。
- 独立跑步按角色卡 `needs_dedicated_run` 决定，不因四向行走验收而自动增派跑步或待机表。

## 4. 怎么检验

1. **文件与映射**：核对四方向齐备、尺寸／列数与 ART 一致、播放序列无越界、站姿与行走键可用；画出四向逐帧联系图，检查左右道具与关键部位裁切。
2. **自动姿势 QA（有对应白模时）**：`explore.py qa` 检查 cover≥0.62、spill≤0.16、腿脚区 IoU≥0.5；头到剪影≤2、近侧≤3.5、远侧≤6 美术像素，分段颜色差≤48。结果及角色例外保留，不能只凭存在 qa.json 判通过。
3. **实际四向移动**：在 1280×720、1920×1080 游戏视口各检查四方向完整循环，连续播放至少两轮，覆盖站立→行走→停止、左右及上下转向；同时检查同伴跟随、加速及走／跑切换（实际支持时）。
4. **接地检查**：看真实鞋、小腿与影圈的关系，不只量最低 alpha；站立脚点与阴影地面锚点在同机位检查，既有目标偏差不超过 3 屏幕像素。步行抬脚不视为错位，查看承重脚而非所有脚必须同时落地。
5. **记录结果**：保存角色／阶段、素材版本、方向和帧覆盖、视口／缩放、场景、截图／短录像、失败事实或通过范围。单帧静图、无页面报错、四向文件存在都不能单独证明完整行走通过。

已有接地单元测试（来源：`../../tests/character-grounding.test.cjs`）覆盖绘制锚点与底部残片处理，使用的是测试图形；它不能证明真人物每帧的鞋腿、朝向和步态正确。既有实际移动抽验见视觉验收（来源：`visual-acceptance.md`），其通过范围不自动扩充到所有人物、地形或新章节。

自动 QA 目前只覆盖相应白模管线，既有普通四列表需按上述联系图和实机流程检查；本页没有新增统一自动阻断器，也没有启动角色素材重生成。
