## 1. 当前状态与失败原因

画板同时描述物件和 `wallRuns` 时，删除墙段再删除对应要求，可以让两份同源数据一起“通过”。容器 `visualRect` 一样，也不能证明素材实际可见大小一样；透明留白和源图裁切会改变最终房屋尺寸。仅核查连通性不能证明院墙闭合，仅看缩小全景不能证明门柱、立面和成人比例正确。

本轮先在用户指出问题的村落实行独立基线。其余地图需要逐图建立、审核自己的基线，不能沿用村落的通过结论。当前工具已经支持每图的 `design-intent-{key}.json` 和对应 `design-intent-{key}-approval.json`；未覆盖输出 `not-covered`，阻止 `productionReady`。有文件也不代表已接受，当前哈希、证据和审核身份都必须有效。

此前第一章整体视觉接受结论撤回，旧文件保留作比较。旧分区通过、旧走行记录不证明本次独立基线已通过。村落建筑位置、尺寸、源图或院墙结构变化后，依赖旧几何的争执、火灾及救援关键帧标记为**过期／待重建**；未重建时明确列为交付缺口，不能当作修后截图。此次不要求为了建立基线立即再生成火场，但不能把旧图计入新验收。

## 2. 在生成前冻结独立设计基线

生产画板负责实现，独立设计基线负责说明应当实现什么。构建器可以读取、比较基线，不能自动从当前画板生成并批准基线。初次整理可参考画板，但必须先对照设计图逐栋、逐墙、逐门检查，然后由另一位评审者确认并冻结；不能只复制 JSON 就算独立设计。

每张图先提交以下设计包：

- 带世界尺寸、成人尺、道路宽度和高度连接的参数草图。
- 功能关系图：房屋用途、可入内状态、所属院落、剧情交互、入口与实际目的地；私人房间分别标明主人和权限。
- 建筑清单：模型类别、源图、位置、预期可见尺寸、实体占地、脚底基线；同模型同尺度组及允许差异的理由。
- 院落边界图：完整围墙路径、墙与房体连接、主门、明确生活通口及其内外路线。开放集市等区域标明开放性质，不强行套封闭院落。
- 素材同尺样板和设计预览，以及源图、设计图、基线文件的内容哈希。

现有独立检查比较 `worldSize`、结构对象集合及每个对象的 `asset`、`visualRect`、`footprintRect`、`baseline`、实际 `visibleSize`、`visibleRect`、`sourceSha256`，同时比较 `wallRuns`、`wallOpenings`、`wallConnections` 和 `scaleGroups`。`boundarySegments` 声明连续边界，`buildings` 声明全部建筑的门源矩形、功能和尺寸理由。审批文件保存基线哈希、评审人和证据文件哈希；基线或证据被改写，原审批失效。

新增素材分两步冻结：生成前先冻结功能、位置、门净高、同类尺度与边界要求；样板生成并接受后，再绑定真实源图哈希与门洞标注。不能因新图不合格而降低第一步的尺寸或补墙要求。

合理改方案需要提交新版设计及理由，重新独立评审。禁止因成图漏墙而删设计要求，或把不合理断口事后统一改名为“生活通口”。当前文件哈希机制用来识别变化，不是防止有权限的人伪造审批；评审分工与证据阅读仍必须执行。

## 3. 成人、房屋与实际可见像素

成人基准为 **92 世界像素**，脚底半宽14。所有对比使用同一世界尺度、镜头、地面基线和采样设置。实际截图像素受视口与缩放影响，需要记录比例；不能把画面上92屏幕像素直接当成92世界像素。

每个物件按真实构建路径裁切、等比例拟合后，对 alpha≥128 的像素测量可见边界。目标容器只是放置范围；验收应查看最终可见宽高、位置与源图哈希，保留原始源图尺寸和实际采样倍率。建筑的投影、装饰与透明边缘不能充当墙脚或门尺寸。

建筑样板还必须由人标注这些语义点：门框左右边与门槛、门顶、墙脚、檐口、每层立面界线。以成人身高为分母记录门宽、门高、檐口到墙脚的立面高度和各层比例。二维投影测量不是建筑真实厘米数，不用统一屋顶总高代替门与层高检查。各建筑类别的允许区间来自接受的同尺样板；没有样板和范围就写“待定”，不能临时编出阈值宣称合格。

同来源房屋不能因摆放空间不足就单独缩小。客栈可以按功能增加宽度或层数，但门、同层立面和成人关系仍应满足该类别样板。确有大小区别须在设计阶段声明不同类别或结构，不能拿“房子各不相同”豁免任意缩放。

当前门净高硬门槛为 **100世界像素＝成人92＋头顶余量8**。`doorSourceRect` 必须由独立评审者直接查看源图确认，标注实际可通行的门洞净高，不能把门框、檐口或墙面算入。检查器按“源矩形高度×最终可见高度÷源可见高度”投影到世界尺度，再验证≥100；同时要求全部建筑纳入 `buildings`，且有 `role` 和 `sizeReason`。该公式依赖等比例构建与正确标注，程序不会自行判断标注是不是门洞；门宽、层高及其它比例仍执行同尺人工评审。

门净宽另按现有通道原则冻结：单人住宅／服务门至少 **56世界像素**，公共主要入口至少 **84世界像素**。净宽只量两侧门框之间的实际通口，不计柱、墙、门扇与交互提示范围。门扇关闭时仍须核对打开后的可用宽度。生成前登记用途及宽度；实施后独立标注源图内口并按统一缩放投影。脚底28像素能通过、或远处触发传送，都不能代替成人肩部和侧余量验收。当前通用自动检查尚只覆盖已标注净高，净宽证据必须单独记录，不得写成通用检查器已经自动识别。

### 必交预览

1. **全部建筑并列成人尺图**：每栋房屋旁放同一个既有成人占位，脚点对齐当地地面，统一倍率，不把各栋分别缩放以填满格子。标明对象ID、用途、源尺寸、最终可见尺寸及样板版本。
2. **原生分区图**：查看门柱、檐口、墙脚、砖纹、房墙衔接及家具与成人关系。
3. **实机站位与走行图**：在每个门和建筑侧边走近，确认视觉脚点、实体边界、遮挡和进入权限一致。

并列图方便发现尺度差异，不能代替地图上的空间关系。当前 `map_preflight.py` 自动检查 alpha边界、连续边界、冻结数据和已标注门洞的投影净高；**不会识别门框、层高、房屋用途或美术颗粒**。语义点标注与其它比例范围仍需人工建立、审核；尚未自动化的项目不得写成已由程序验证。

## 4. 院落拓扑与入口可读性

每个封闭院落必须形成完整边界，只保留基线中列出的主门和有明确生活功能的通口。每个开口记录唯一ID、位置、净宽、用途、内外接近点、目的地，以及应该看见的门框／门柱、门槛或明确地面过渡。门口须让成人与同伴通过，并能从内外两侧理解这是一条通路。

墙与房体、侧墙与前墙、端帽与中段分别是连接对象。端柱完整不等于院落闭合；两段之间有缝、路穿进私宅、房后漏口、墙末端裁到砖块中间都应拒收。设计为开放终端时须说明它为何终止及如何收口。故意破损墙口需要剧情理由和可见破损表现，不能用它解释生成遗漏。

独立基线比较能拒绝未经批准的边界修改，但不会判断门柱看起来像不像门柱。视觉评审逐个读门、读墙角，再进行正反方向和斜向走行；墙补齐后重新验证通行、遮挡及交互净空。

连续边界不是只检查几个接头探针。检查器沿冻结的 `boundarySegments` 每1世界像素采样，读取经过实际裁切／拟合的最终RGBA物件；每个采样点在基线声明的半径内，必须在指定墙段中找到alpha≥128的可见结构。所有 `wall_h`／`wall_v` 对象必须纳入连续边界，否则拒收。额外 `boundaryProbes` 可补重要接头，不能代替连续扫描。扫描只验证已定义的边界线和采样范围，不等于整张墙面逐像素完整性判断；线的位置、半径和指定物件仍须独立审核，防止误把旁边屋顶等可见像素算成墙。

## 5. 对检测器的恶意负例

先让冻结参考正例通过，再故意构造以下错误并确认拒收；负例改动不能同时修改审批基线来迎合结果。

| 负例 | 必须拒收的理由 |
| --- | --- |
| 同时删除墙对象和画板 `wallRuns` 中的要求 | 独立结构清单与边界设计仍要求该墙，不能靠同源数据一起删掉通过 |
| 生成后登记新的院口，试图解释缺口 | 开口与冻结设计不一致，必须重新设计和独立审核 |
| 同源房屋缩小，包括容器不变但实际 alpha变小 | 实际可见尺寸／同尺度组不符；即使连同容器和占地一起改，也与冻结结构不符 |
| 替换同名源图，保持文件名或尺寸相同 | 源内容哈希改变，原尺寸、语义点和视觉评审不能继续继承 |
| 重写独立基线以删掉要求 | 当前基线哈希与旧审批不符 |
| 修改审批引用的设计图或样板 | 证据哈希不符，必须重新读图评审 |
| 移除审批 | 缺少有效独立审核，不能放行 |
| 外边界不变，但墙接头的最终alpha有缺口 | 指定接头缺少可见结构，不能由可见包围盒通过来豁免 |
| 墙中段在接头之外出现透明断口 | 每1像素的连续边界扫描应拦截，不能只检少量接头 |
| 房屋容器已批准，但标注门洞投影净高不足100 | 门洞仍无法满足成人净高要求，整栋矩形合格不能代替门检查 |

当前 测试（来源：`../../tests/map-preflight.test.py`） 共11项：1项参考正例和10项拒收负例，不能称为11项坏例。这证明这些变更能够被当前检查器拦住，不能推断所有视觉缺陷都能被自动识别。门不可辨认、源图颗粒变化、同模型合理差异等仍需对应视觉证据。

## 6. 阶段放行与大小图覆盖

| 阶段 | 放行条件 | 未达到时 |
| --- | --- | --- |
| 设计 | 功能、参数、成人比例样板、边界与入口经独立评审并冻结 | 待定／待审；不进入整批素材生产 |
| 单件 | 原稿与实际 alpha测量齐全，同尺图和语义点人工接受 | 失败或待审；不通过任意缩放补位置 |
| 拼装 | 独立 preflight通过；全部分区、接缝、入口及尺度视检接受 | 失败／未覆盖；不标生产完成 |
| 实机 | 全部功能与路线、遮挡、高差和状态变化验证；受影响CG更新 | 待验／失败／过期；明确剩余缺口 |

分级尺寸和局部分区规则沿用[地图分级与分区验收](map-size-review.md)，不另设一套相互冲突的阈值：

- 小图也要覆盖每栋建筑、每条边界、每个门与交互，不能以一张缩略图代替。
- 中图在整体拓扑和建筑并列尺图之外，检查全部核心区、重叠范围及相邻接缝；跨区墙和房屋不能只由一侧负责。
- 大图另看街坊关系与跨区任务路线，仍覆盖全部局部区和接缝；不抽样替代全图覆盖。当前没有实际大图采用稿，不能声称大图已实机通过。

`pass` 是某项已验证，`fail` 是已发现错误，`not-covered` 是缺少独立检查覆盖；人工待审和输入变更后的过期状态也阻止接受。不能把未知转换成通过。`productionReady` 需独立preflight、源素材、几何、结构、全部分区／接缝和运行关卡共同满足；它不是用户批准或线上发布状态。

## 7. 评审记录与可证明的边界

每次评审保存基线版本／哈希、审批和证据哈希、画板与源图摘要、原稿尺寸、实际 alpha测量、构建采样参数、全部建筑尺图、分区／接缝索引、门连接清单、实机输入记录、评审身份、失败坐标和未验证项。生成者自查后，独立验收者读取真实文件和图像，再给限定范围的结论；不能转述生成者的“已经修好”。

自动检查可比较冻结坐标、源身份、可见边界、同尺度组，并验证已定义的碰撞与路径条件。人工判断负责语义标注、建筑功能、门与收口可读性、画风颗粒和空间是否合理。两类证据相互补充，任何一类都不承诺零bug。交付报告分别列出通过、失败、未覆盖和过期项目，尤其不能用旧CG、旧接受记录或一张全景掩盖当前设计问题。
