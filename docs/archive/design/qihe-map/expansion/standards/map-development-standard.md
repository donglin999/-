状态：历史　最后核对：2026-10-19（2026-10-19 归档，只供追溯）

<!-- map-standard: current -->

版本：MAP-2026-10-04.1。适用于新建、扩展、重做的探索地图和室内；人物、战斗、UI 图标仍执行各自专项规范。本文定义制作要求，不表示已有地图全部达标。流程与硬参数以本文为准；章节文档定义剧情和地点用途；版本记录只说明当时实现。冲突时先更新设计与本规范，再制作，禁止从历史参数挑选方便的版本。

## 1. 开发入口与历史隔离

- 开发地图先读本文，再读[生活空间设计](village-layout-research.md)、[空间合同](scene-spatial-contract.md)、[前置验收](map-preflight.md)、[分区验收](map-size-review.md)。
- 文档状态清单（来源：`map-document-status.json`）标出当前规范、实现说明和被替代页面。旧页面保留原路径的跳转说明；旧正文在 `archive/map-process-20261004/`，不得作为新生产输入。
- 当前参考采用栖河村 functional-v2 的视角、材质与清晰度方向；用户认可生图质量，仍不等于接缝、尺度、遮挡和全图玩法全部通过。
- 更新必须同时修改本文版本、状态清单、相关设计和资产清单。参数修改影响的旧验收失效；保留历史失败图，不覆盖成成功记录。

## 2. 硬参数：世界、碰撞与验收

单位默认是**世界像素**，屏幕像素、原图像素和逻辑坐标必须显式写单位。不得把二维投影尺寸当作现实厘米数。

| 参数 | 标准 | 说明 |
| --- | --- | --- |
| 成人量尺 | 身体可见高 92，脚底半宽 14（宽 28） | 当前占位主角及预览 NPC 为92；正式人物差异执行角色规范，不能随地图缩放人物 |
| 脚点检测 | 中心、x±14、y+3、y−5 | 新场景显式 footX=14；旧引擎默认7仅是兼容值 |
| mask 密度 | 每位2世界像素 | 宽高按世界尺寸/2取整；记录实际比率，禁止旧8像素精度回退 |
| preciseNav | true；导航网格8；路径扫描步长≤2 | 预览场景路径另检查四向1世界像素余量，避免擦尖角；不得扩大整个障碍冒充修复 |
| 普通通道、住宅门净宽 | ≥56 | 两侧实体之间的真实可用宽度，含转角最窄处 |
| 主路、公共主要入口净宽 | ≥84 | 有队友、人群或装卸的区域须进一步预留绕行空间 |
| 建筑门洞投影净高 | ≥100（92+8） | 人工标注真实门洞，不能算门框或檐口；现有原型仍须逐门量测 |
| 工程格坐标 | TS=40，仅接入旧API使用 | 世界坐标除40一次；不得把格坐标拿去画板标注 |
| 当前镜头 | ZOOM=5/6 | 固定引擎现值；实际屏幕倍率还受画布/CSS/DPR影响，截图记录三者 |
| 检查视口 | 1280×720、1920×1080 | 仅电脑；同时保存原生1:1环境局部图 |
| 局部验收核心区 | ≤640×480；四周重叠96 | 并集覆盖全图，不能只检查主路 |
| 大图街坊区 | ≤1280×960 | 仍需核心区与独立接缝图 |
| 接缝验收范围 | 共享边界两侧各96 | 完整对象另需全轮廓图，不能被裁图截断 |

56/84/100是新生产硬门槛，旧稿尺寸不足写整改，不通过增加远距离传送范围豁免。特殊窄缝须重新定义用途、适用角色和专用规则并审阅，不能作为普通门路放行。

### 地图分级（四项必须同时满足）

| 等级 | 面积上限 | 最长边上限 | 物件上限 | 锚点上限 |
| --- | --- | --- | --- | --- |
| 小 | 1,250,000 | 1440 | 24 | 16 |
| 中 | 5,000,000 | 3072 | 80 | 48 |
| 大 | 超过中档任一项 | — | — | — |

面积按世界宽×高；物件包含地面实体、建筑、墙段、家具，不能只数碰撞对象。桥、台阶、高差的小图至少按中图验收；复杂状态可以升级。当前栖河村3072×2048，仅面积即属大图；不是过去1920×1200中图的验收结论。

## 3. 美术与像素合同

- 相机：既有栖河村高三分之四近正交俯视；常规朝南房屋与现有参考一致。不人为指定未经量测的相机角度数值；以固定参考图和屋顶/立面语义点校准，不让各块使用不同透视。
- 光源：左上柔光；灰蓝瓦、灰米墙、土褐地、灰绿植被沿用同批参考。禁止单块过曝、过饱和或单件锐化/量化导致画风变化。
- 参考集必须绑定文件和SHA256：整图用于布局；合格近景用于颗粒、材质；同尺建筑/家具与成人对照用于比例。人物暂用既有占位，生成环境不混入人物。
- 新正式环境目标原生有效密度≥1源像素/世界像素。逐块分别计算 `实际源尺寸 ÷ 对应世界范围`，X/Y都记录；有效主体之外的黑边和透明留白不算细节。输出画布放大不算原生密度达标。
- 全图同批固定目标密度；各块密度差不得超过目标的±5%。生成结果超出时重新裁切/生成或统一一次采样；不能单块任意拉伸。几何X/Y倍率不一致须先对齐并记录裁切，不直接扭曲建筑。
- 同尺比较区量描边、瓦片/砖块等代表性纹理；相同材质相对样板尺度比须在0.9–1.1。此为新制作量尺门槛，必须实际量测；文件大、肉眼“清楚”不能自动判通过。
- 环境采用最近邻采样，交付PNG或lossless WebP；透明物件保留真实alpha。不统一要求源图固定1536或4K，工具返回尺寸必须读取文件验证。请求4K但返回1536只能记1536。
- 同类建筑保持同一尺度；不同宽度/层数必须事先有用途与类别说明。家具表逐件冻结可见宽/高、实体深度、承重点、与成人/门的比例区间；**未填数值不得生成**。餐桌需成组椅凳和就座/服务空间，工作桌需对应工作用途；箱桶、柴料、植被均须解释所在位置。
- 不强制村落整齐网格：道路顺地形和生活关系转折，院落大小由功能决定；自然植被按河岸、林缘、遮阴或庭院种植成组。开放公共区不为填空制造围院。

## 4. 七步生产流程与提交物

| 阶段 | 必交材料 | 放行条件 |
| --- | --- | --- |
| A 功能设计 | 地点/主人/权限/剧情/资源/时间季节；功能关系图；道路与边界用途 | 每栋房屋、门路和装饰组有用途，入口有实际目的地 |
| B 参数草图与灰盒 | 世界尺寸、道路净宽、建筑/家具量尺表、墙体及合法开口、碰撞与遮挡、出生和返回点 | 占位成人自然实走主路、转角、门口；独立审阅冻结设计 |
| C 完整预览 | 按同一草图和参考集生成可读预览；全部建筑同尺对照 | 先审摆放、入口、墙体完整性和比例，再开始正式分区；不接受漏墙后删要求 |
| D 分区生产 | 区域逻辑范围、精确裁切参考、完整对象归属、目标密度、提示词与实际输出记录 | 每块保持已批准几何与风格；跨区物件有唯一提供者 |
| E 拼接与标定 | 分区合成、所有接缝、更新的实体/前景/交互、源与输出哈希 | 没有重复物件、缺口、双影、色阶断层；图和数据一致 |
| F 实机验收 | 全部分区/接缝截图、真实走行/进出/任务/存档记录、逐图判断 | 技术和视觉分别通过；未看图写未验；必需项未验或失败不得正式放行 |
| G 交付与归档 | 当前入口、版本清单、已测范围、剩余问题、旧版备份 | 明确原型/正式/线上状态；本地验收不能称已上线 |

灰盒在预览前验证空间，预览再确认美术构图；不能等拼完美术才首次设计碰撞。阶段B冻结用途和几何；阶段C/D接受样板后绑定实际源图哈希，两次都要有证据。

## 5. 分区拼接的具体约束

1. 在画板先划完整对象归属，生成区沿功能区域组织，拼接线尽量落在空地。生成分块大小和验收640×480核心区是不同概念。
2. 以精确裁切图作为局部参考；不让模型仅凭“大图右上角”重新构图。重叠区共用已确认像素/图层。完整房屋、门、桥、树冠由一个区域提供，不在两个图中分别重画后混合。
3. 墙体、屋檐、树干等结构不做透明渐变；地面仅在一致几何且无实体的区域允许过渡。色差或额外物件先修共同区域，不能靠模糊遮罩掩盖。
4. 局部修绘明确消费多边形；参考图中未要求的改变不得进入成品。检查裁切边界和对象全轮廓，再复查相邻区及接缝。
5. 底图烘焙模式可作为可玩原型；正式若需要树冠/屋顶淡化、季节变化或动态拆墙，必须补干净底层和独立前景。已经烘焙在底图的物件仅重画前景不能真正消除遮挡。

## 6. 空间、入口和高差

- 对象必须有唯一ID、用途、所属功能区、可见范围、实体脚底多边形、前景轮廓、当地排序线、交互接近点及状态条件。无实体的地色、低草和阴影可走；树冠不等于树根碰撞。
- 围墙记录连续路径、起止接头/端柱和合法开口；无用途就不建墙。长纵墙按当地脚底分段排序；缺口必须在冻结设计中声明，生成漏墙不能事后改名为通口。
- 房门进入独立室内；院门仅连室外通路；地图出口必须绑定已存在的目的地与回程。未实现下一地图时不画强烈的出口门楼、道路延伸或闪光。
- 提示在场景前景与调色后绘制，完整显示地点和按键；名称不能被门槛裁切。每个入口截接近、门槛、室内返回三种状态，长名称与两种电脑视口都检查。
- 台阶/桥面可用表面高度表现，但单层mask+y排序不能证明桥上桥下同时通行。需要并行通行时先做surfaceId/layer、逐层导航、显式楼梯连接、阴影、点击逆投影、NPC/队友和存档支持；未实现不得按多层玩法生图承诺。参考高差设计（来源：`xiangyang-elevation-design.md`），其中具体高度是方案值。

## 7. 验收、失效与完成状态

- 自动检测只证明数据约束；另对图检查碰撞是不是正确、墙有没有缺口、家具是否符合用途。反例至少覆盖删墙、缩房、错门、漏碰撞、遮挡裁断、拼接重复。
- 从合法起点以真实输入走到目标；瞬移站位图可用于局部量尺，不能计作路线通过。按门口正反/斜向、墙角、树根/树冠、桌椅四侧、桥岸和每条接缝逐项取证。
- 每张图记录区域/对象ID、版本、源与画板SHA256、截图SHA256、评审者、实际观察、结论及问题坐标。截图捕获≠已查看；独立复核应由不同评审者执行。没有独立复核只能报告自检。
- 图像/位置/占地变化：本区、相邻重叠区、接缝和跨区路线重验；道路/墙/桥变化还做全图连通回归；交互变更重验任务和存档。源哈希变更不得继承旧通过结论。
- `productionReady=true`需要设计、素材、结构、全部分区/接缝、运行和独立复查全部通过。当前functional-v2仍false：局部11图自检及已测进屋流程通过，其他接缝、树冠可读性和旧石材残留未完成全图验收。
- `map_preflight.py`/`map_review.py`现有工具面向objects/worldSize画板；当前预览采用scenes/sourceSize/polygons结构，不能不经适配直接当全图检查已完成。`verify_functional_preview_v2.cjs`仅覆盖其声明的局部，未实现的自动门宽/纹理识别等写人工门槛，不能冒称工具已有能力。

## 8. 开工和交付时的文档检查

在项目根运行 `python3 tools_scene/check_map_documentation.py`。它检查现行入口、旧页跳转/归档、相关链接、标准参数与当前代码/画板的有限一致性。检查通过只表示文档入口及已检查参数一致，不能作为地图美术或玩法验收。旧脚本重建会覆盖哪些文件必须先核对；不可用旧构建器重建新版画板，再拿旧报告放行。
