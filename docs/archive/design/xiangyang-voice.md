# 襄阳角色语音

状态：历史　最后核对：2026-10-19（2026-10-19 归档，只供追溯）

范围：当前 `#xiangyang` 体验章节。萧白保留文字；其他剧情人物固定音色；配音规模按[普通 NPC 单句方案](../../design/voice-npc.md)执行：叶蘅、苏芷多句，其余每人一句。正式生成清单见 [voice_lines.json](../../../tools_audio/voice_lines.json)，音色确认与补全流程见[语音管理](../../design/voice-management.md)。清单中的对白与游戏原文一致；情绪短句为新增演出内容，尚未接入游戏。候选试听默认用 MiniMax 准备，主要角色多句、普通 NPC 单句；正式全角色语音在确认音色后生成。

## 哪些台词配音

主要角色完整配救治、对质、醒来、医案引荐与分支决定。下表保留完整演出设计，其中普通 NPC 的全句配音已停用，改为一句识别语音，其余通过字幕承载信息。线索只要承载证据、人物判断或下一步行动就配完整句。可重复交谈首次播全句，之后保留完整文字并使用短句或静音。旁白、主角选项、任务提示、商品数量与价格、纯动作描述不配人物语音。

| 节拍 | 配音内容 | 演出要求 |
| --- | --- | --- |
| 老周倒地 | 叶蘅判断症状；苏芷指导按住上臂 | 急切但清楚，体现各自判断 |
| 合力救治 CG | 两人对脉象、指尖、呼吸的三句交流 | 全屏 CG 加字幕，无立绘；换句停上一句，最后一个画面节拍结束才退出 |
| 救治选项反馈 | 护场、拿水、追问三个分支及毒名、半日限期 | 全句；选择项本身不配 |
| 查访街市 | 包打听说明例钱纠纷；三娘说明茶碗；老伯确认左袖；叶蘅区分动机与证据 | 全句，避免把线索播成系统公告 |
| 茶棚对质 | 催钱、交钱或证据分支、三娘作证、两位女主护人、败后承认经手 | 全句；不同处置分支均录，不仅录最佳路线 |
| 失利返回 | 叶蘅让萧白喘匀气、准备好再去 | 柔和，避免失败嘲讽 |
| 解药 CG | 苏芷核药与施针；叶蘅观察吞咽；苏芷要求等待 | 全屏 CG；咳嗽用短句音效，勿由旁白报出动作 |
| 老周醒来 | 老周惦记货担；叶蘅劝休息、药费处理两分支 | 气息由弱到稳，避免立即中气十足 |
| 医案引荐 | 苏芷愿递医案；叶蘅保留决定权 | 完整配音，叶蘅郑重而非默认同意入谷 |
| 同行／留城 | 去渡口、先安顿病人、留城一日、叶蘅请教针法 | 全句；结案报告保留文字 |
| 深追渡口 | 船夫的货路、叶蘅的货签与箱痕、浪里鳅三种解法、寨主对质、最后证据边界 | 全句选配，保留所有关键分支 |
| 当前支线 | 风箱箭镞、校场、说书匣、竹片、盐船与井边居民的关键句 | 第二批；动态工钱与答题数量使用文字，勿每次生成一个数字版本 |

旧 `#street` 主角身世、默庵庙线及尚未接入的三年培养不进入本批。街上无名群演默认文字与环境音，免得移动过程中持续有人抢话。盐商、歪帽泼皮、汲水妇人与城防营教头虽无独立立绘，也分别建立角色 ID，角色 ID 和配音句分别管理；可以复用音色，但不能混用人物台词。

## 情绪短句

清单中的 `type/kind=emotion` 是可复用短句，独立于剧情全文。不要随机附到每句对白前。每次交互最多一条；同一句至少 20 秒冷却，同角色不同招呼也至少 8 秒冷却；进入剧情对白或 CG 时取消排队的招呼。

| 角色 | 短句 | 触发方向 |
| --- | --- | --- |

| 苏芷 | 别急。／嗯。／按住。／能救。 | 治疗、认可、救治动作、局势转折 |
| 老周 | 多谢……多谢两位姑娘。 | 唯一启用句，救治后虚弱致谢；求水、咳嗽及货担对白保留文字 |
| 包打听 | 嘘——／来得巧。 | 再次打听 |
| 柳三娘 | 哎哟！／我作证。／坐会儿？ | 惊讶、重复证言、茶棚招呼 |
| 说书老伯 | 慢慢说。／没看错。 | 询问、重复确认 |
| 疤脸刘 | 让开！／饶命！ | 蛮横、战败 |
| 巡街军士 | 站住！／说吧。 | 盘查、交谈 |

| 浪里鳅 | 喝！／找死！ | 酒局、开战 |

## 清单与新增规则

每句已补齐 `emotion`（中文演出情绪）、`emotion_api`（实际传给 MiniMax）、`delivery_notes`（试听验收要求）。新增台词同步填写三项，不允许只记标签而不发送情绪。候选试听同样逐句记录情绪，详见[台词情绪](../../design/voice-emotion.md)。

- `characters` 是角色表；`lines` 是后台角色台词列表的唯一内容源。`id` 为稳定身份，`character_id` 不随显示名变化，`source` 标注脚本、事件与原文。`priority=core` 是第一批，`support` 是深追、支线与复用短句。
- `type` 与 `kind` 当前保持相同值以兼容工具；`por` 与 `portrait` 同样兼容。`status=active` 表示计划启用，不代表已生成、已试听或游戏已接入；音频生成状态由后台另存。
- 已存在语句调整文字或情绪时保持 ID，并递增 `revision`。新增语句增加全新 ID，不按脚本行号重新编号。删除台词改为 `status=retired`，不得把旧 ID 分给另一句。
- 后续剧情每次改稿同步清单：新句、改句、退役句都显示差异。语音后台按文本、版本、情绪和绑定配置的指纹检查有效文件；“补全新增语音”生成缺失及已过期语句，跳过有效文件。
- 音色只在点击确认绑定后锁定并排队生成；试听候选不占用、不生成全角色。补全前显示新增／过期／失败数量，任务可查看进度并重试失败句。未绑定角色先显示“确认音色后可补全”。
- 修改一个角色的音色会让该角色旧音频过期；旧文件保留到新批完成与试听通过，禁止混用两种音色。NPC 可以绑定已有角色使用的基础 `voice_id`，界面列出全部使用者；主要角色之间仍保持音色区分。

## 播放验收

音乐与环境音在说话时降低，结束后平滑恢复。玩家可随时推进，上一句立即停止；没有音频时直接正常显示文字。配音句关闭打字提示音。语音音量与开关独立设置。游戏中只有当前台词可以说话，商铺短句、战斗喊声与 CG 对白不重叠。语音结束不自动跳过选择或退出 CG。

`voice_enabled=false` 仅停用配音，剧情原文与游戏交互保留。新增剧情不自动为单句 NPC 增配；39 条原情绪短句设计按角色范围筛选，不意味着全部仍启用。
