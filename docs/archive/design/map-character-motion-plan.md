## 当前问题的证据

| 项目 | 当前实现 | 影响 |
|---|---|---|
| 水平移速 | 步行75、跑步127.5世界单位／秒；之前通用步行270 | 为迁就小步幅而大幅减速，穿过1152世界单位的视口约15.36／9.04秒 |
| 纵向移速 | 在当前已投影地图坐标中再次使用0.5系数 | 上下只有37.5／63.75；该系数来自旧骨架投影，尚未与当前生成地图量测校准 |
| 动作周期 | 走路约438ms、跑步约352ms，各8帧 | 一周期是左右两步，约4.57／5.68步每秒；形成腿快、位移短的碎步感 |
| 一周期位移 | 水平走32.86、跑44.88，分别只有身高92的0.357／0.488倍 | 原稿步幅很小，仅提速度会继续提高换帧频率；只放慢播放又会滑行 |
| 制作方式 | 每批独立生成核心姿态，再按白模采样与验收 | 结构门只能筛选单帧，不能保证相邻帧的体积、衣褶、手臂和重心自然连续 |
| 验收缺口 | 重复播放了同一个数组、核对了选帧与单帧轮廓 | 只能证明程序循环，不能证明7→0姿态自然；之前对动作体验的通过结论过强 |

GIF 前四张为当前原地四向动作，人物放大2倍便于观察，每张完整循环一次后重复；播放周期从当前速度与stride推导，GIF时长按10ms量化。第五张执行真实移动控制器，在现地图的已检查直线空地展示走→跑→停。第六张比较当前、只提移速、只限制播放周期：后两者是诊断参数，不是采用方案。

## 正式制作路线：程序白模 → 角色参考生图 → 组表与实移动验收

2026-10-04 用户纠正后，以[动画管线 §0.1](../../anim-pipeline.md#01-开篇整改重新执行原型优先2026-10-04)为当前执行规则。

保留 grid94 的头身、衣装、光向和像素外观。先由程序生成完整连续的 2D 白模及关节数据，固定相机、比例、地面与动作相位；在当前地图和目标移速下自行检查。现有 Q 骨架可继续使用，但短步幅及不自然曲线需要在白模阶段改好。

白模通过后，以“同方向角色定妆图＋对应白模帧”为实际图片输入，生成角色动画帧。生成后逐帧叠合、连播、对齐、采样、组表，再进行游戏渲染与实机检查。程序负责动作约束，生图负责角色外观；参考生图失败时保留失败记录并修复对应帧。

2D 程序白模是可用的主流程；需要空间关系时可采用现有 3D 骨架或 Blender。此前推荐的完整 3D 角色预渲染属于备选，不替换用户明确的白模参考生图流程。OC.8–OC.10 的分层身体拼装仅作诊断，不能以其动作可控为由免去参考生图与外观验收。

## 与当前地图生成方式如何配合

1. **共用一份场景比例合同。** 人物可见身高92、脚底碰撞宽28继续作为建筑、道路、门洞的量尺。源图坐标乘`worldScale`一次变成地图世界坐标，不能让人物或移速再随地图原图分辨率缩放。外景1.8、室内0.72是各自图像转换，不是人物速度倍率。
2. **相机先在实际地图校准。** 选栖河村主路、门前、室内三块参考，放同一个站姿和地面校准框，记录近正交相机、深度投影、光向和成人尺度。地图规范当前没有已量测的固定俯角；不能直接宣布旧骨架的0.5或某个角度就是现地图的正确参数。新增地图复用该参考包。
3. **移动与动画统一计量。** 当前导航坐标已经是地图投影坐标。先按屏幕操作感定义移动档位，再由相机投影和动画真实根位移导出各方向的周期距离。记录`cycleTravelProjected`、`durationMs`、支撑／腾空区间与固定脚点。运行按实际位移推进相位，地图横纵尺度与动作投影只换算一次。
4. **先定穿越时间，再制作步幅。** 候选目标：一个1152世界单位宽的视口，步行约6–8秒、跑步约3.6–4.8秒。对应约144–192／240–320世界单位每秒；180／300作为首轮手感对照值，不直接视为定稿。新动作必须在目标速度下同时做到可读换脚、自然重心和可接受接地；如果达不到，重做动作或共同调整目标，不能再次单方面把移动降到75来换取数字通过。
5. **衔接与跟队。** 走／跑采用共同的左右脚周期标记，切换时保持当前支撑侧；起步、刹停和转向单独检查。跟随者可用小范围播放速率变化追上，超过范围换动作档位，不能无限加快腿频。纵向、斜向和过门必须纳入手感样片。

## 制作顺序与验收

先只做萧白便衣样板：同地图站姿→侧向连续走跑→正背面→四向起停与转向。先采用动作，再扩展叶蘅和其他可加入角色；现代装仍只需固定演出素材。

- 样板先用12帧走路、12帧跑步导出，时间从连续动画采样；12是样板采样选择，不能靠重复帧凑数，也不是画质保证。最终若8帧已经足够自然，可以保留8帧。
- grid94及整数3倍导出保留；身体比例、脚点和衣装由一套模型固定。新动作单元宽度按摆臂、衣摆和道具最大轮廓决定。
- 同时提交正常速度与半速检查、四向独立循环、首尾接缝、走→跑→停、90度转向、斜向、过门、跟队、同地图实移动。半速仅用于找错误，正常速度决定采用。
- 支撑脚应检查实际鞋底与地面运动，不能用“某个关节点位于剪影内”代替接地；原轮廓、透明、身份和导出门继续保留。
- 新增时间连续性检查：同方向头／胸／腰的宽度变化、衣色闪动、相邻帧手脚跳变、步行承重与跑步腾空顺序；异常帧必须在连续画面中回看。当前单帧QA不能自行放行整套动作。
- 技术通过、动作目视采用、实际浏览器操作分别记录。当前OC.4走跑状态为“技术可用、动作体验退回整改”，不能继续标为美术体验通过。

本轮导出是本地生产函数渲染，不是实机录屏。GIF有调色板和10ms时间量化，不用它代替原始RGBA或高频性能验收；浏览器访问策略限制仍单独记录。
