## 旧原型如何迁移（待实际逐ID审核）

| 当前内容 | 设计处理 |
| --- | --- |
| `fist`、`liuye`等基础招式 | 拳脚可核对对应粗浅拳脚；柳叶剑等已有独立技法先保留，不直接改名成归云传承 |
| `jinzhen`、`huichun` | 新目录保留同名语义，运行ID仍为null；开发时核对消耗、效果、图标，避免重复注册同名两条 |
| `baicao`、`dingshen` | 现有百草露、定神继续作为迁移前技能；不直接覆盖为百草回生／和脉同息，高阶另授 |
| `tuna` | 可作为调息入门的兼容来源；旧存档已学状态保留，名称与规则变更须正式迁移方案 |
| `yq_*、gb_*、lm_*、th_*、yy_*` | 玉泉寺、丐帮等旧原型归属不在当前主要门派目录；保留旧数据，不自动迁成照川、合川或归云绝学 |
| `bx_xin、bx_du` | 白鹇相关旧心法也须逐项核对；不因名字相近而让旧“中毒收益”自动转成新医疗特性 |
| 既有65格图集 | 本批123是设计量，不能简单声称新增123格；复用、重做、保留、退役逐项核实后才能得最终生产量 |
| 木剑、铁剑、针囊等已有物件 | 同类不等同同一件。本批命名先作候选；进入开发前去重并保留旧存档映射 |

## 首批开发范围建议（等待评审）

先验证萧白剑拳基础、苏芷急救、陆衡援护和符合时间的叶蘅照护；保留襄阳现有测试范围。只选本轮候选中实际取得条件成立的内容做原型，不在襄阳解锁年二针攻或后期绝技。

之后验证两条叶蘅路线和乙级循环，再做一组甲绝演出样例。完整20章内容不因目录写完立即铺开。旧原型章节号与新故事章号要建立显式映射，不能用`chapter>=2`同时替代心法开放、月份和角色路线。

## 技术与视觉验收分开

文档交付检查：ID唯一、图标ID唯一、阶段有效、引用可达、每项有作用／取得／视觉／完整提示词、无条目标记已生成。检查结果见[校验记录](../../../design/martial-review/validation.json)。

后续原型测试需验证：

- 群攻、多段、BP不会突破削盾预算；反击不循环，援护不重复转伤。
- 四档BP逐项对照；加段技不同时复制整招伤害，绝技满BP不重复乘普通倍率。
- 改序只移动未执行行动、不凭空双动；敌方延后遵守抗性和连续回合限制。
- 转赠BP的个人和回合上限有效，溢出提示正确；不能互相转赠制造无限资源。
- 绝技调息不能靠受控跳过消除；濒危保护不能由多名施者反复刷新。
- 人物专长不因传功复制，辅修高层二选一与现有基础收益分别结算。
- 增益到期、冷却、濒危保护与施者倒地时机正确；首领抗性显示与实算一致。
- 不同主辅组合合法且改修不丢学习进度；旧存档正确迁移。
- 年一叶蘅无专精、第13月按分支授业；缺课可补，关键主线不要求唯一绝学。
- 图标在实际尺寸与深浅背景审查；装备形制适合人物动作；状态提示不阻塞移动。

本轮没有改动运行JS、战斗、存档、商店或发布配置，因而未把现有游戏测试当成新机制已通过的证据。
