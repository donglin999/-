# 02 入口、启动、渲染状态机、操作流程

源：`js/qihe-cultivation-bridge.js`（`enter` `migrate` `openMartial` `openJianghu` 以及对 `mnEnsure` `derived` 的包裹），`js/qh-mode-cultivation.js`（`start` `render` `perform` `persist` `quarantine` `renderBroken` `onClick` `begin` `tick` `finishResult` `closeView`，keydown 监听）。

## 2.1 进入培养

1. 栖河第一章结束：`qiheTrialStart` 被包裹，原逻辑跑完后若 `S.qiheChapter.stage==='cultivation'` → `QiheCultivationBridge.enter()`。
2. bridge 启动时（仅栖河入口 `isQiheEntry()`）：`CultivationStory.enabled=true`、`CultivationRigTrial.enabled=true`；`progressNames.qh_staff='护路棍法熟练'`；push 动作 QH01（见 11 节）；再调一次 `CultivationDialogue.activities(CultivationData)`。
3. `enter()`：try `migrate()`（失败 toast `旧版培养进度导入失败：{msg}。原记录保留未动。` 5000ms，不阻断）；`S.qiheChapter.stage='cultivation'`；`S.chapter=max(2,S.chapter||1)`；`S.sect='guiyun'`；`QihePrologue.checkpoint()`；`Cultivation.start({inherit:true})`。
4. `migrate()`：若 `S.cultivation.qhImported` 已有则跳过。旧版 `S.qiheCultivation`（见 63 节）有 pending 则先 resolve/applyCultivationReward/closeResult。新建或沿用 `S.cultivation`，写 `qhImported=true`，`qhOrigin={rescue, chenCare, supplies:S.qiheChapter.*, coreOwner:'叶蘅'}`；有旧档时拷贝 `joined/progress/resources(合并)/learned/history`（history 每条加 `freePractice:true`，B01–B06/K01/K02 的 `nominalCost=5`，其余=原 cost）、`sequence=max(旧,history.length)`、`staffApplied`=QH01 history id 列表。最终强制 `joined=true, facts.joined=true`；`S.skills.qh_hulu_staff` 存在则 `learned.qh_hulu_staff={source:'陆衡·栖河第一章',period:-1}`。
5. 角色属性：bridge 包裹 `derived(u)`，对主角在基础值上叠加 `CultivationCore.growth(S.cultivation).bonuses`（mhp/mmp/atk/spd/crit/dodge）；`mnEnsure` 补 `S.zy`/`S.ji` 后调用 `reconcileWorld(S)`。

## 2.2 `Cultivation.start(options)`

- `ensureRoot()`：创建 `<section id="cultivation" hidden aria-label="归云谷养成">` 挂到 `#game`；委托 click 到 `onClick`；`Mail.bind(root)`；捕获 IMG error → 隐藏该图并给父元素加 `cu-art-missing`。
- 读档：非 inherit 时从 `sessionStorage[slot]` 读整份 S（slot=`xjh.qihe.cultivation.save.v1`），否则沿用当前 S；都没有则 `newState()`，`name='萧白'`，`origin='prologue'`，清空 skills/bag/weapon/armor/party/pet/pets。
- 停止 `Presentation.stop()` 与 `CultivationMotion.stop()`。
- 存档恢复：`S.cultivation` 不存在→`initial()`；否则 `CultivationCore.recover()`（见 14 节）。无法恢复：设 `broken={error}`，隐藏 `#panel #hud #prompt #mapui #tpad #dlg`，显示故障面板 `renderBroken`。修复成功且有修复项：`quarantine()` 把原数据另存到 `S.cultivationQuarantine`（最多 3 份，`{at:ISO时间,error,repairs,original}`），提示 `培养存档有失效内容，已修复：…。原数据已另存。`
- 旧剧情 pending 迁移：`Story.enabled` 且 pending 非 story 但动作有 once → `story=true`，`storyStep`= 动画未完 0 否则 1，删 animation，未结算则 `stage='choice'`。
- 非剧情未结算且无 animation → `beginAnimation`；未完成动画 `presented=false`（重新从画面出现时计时）。
- `syncNotices` → `reconcileWorld` → hp/mp 夹到 `derived()` 的 mhp/mmp（新开局满血满蓝）。
- 隐藏世界 UI，`mode='cultivation'`，`root.hidden=false`，`body.classList.add('cultivation-view')`，`view=null`，persist，render。旧档 `screen==='world'` 改回 `hub`。

## 2.3 存盘 `persist()`

`S.currentMode = screen==='world'?'scene':'cultivation'`；`persistState(S)`（全局主存档）；再写 `sessionStorage[slot]=JSON.stringify(S)`（失败只提示 `本地已保存；会话缓存暂不可用。`）。

`perform(fn,focus)`：先快照 `JSON.stringify(S)`，执行 fn → `reconcileWorld(S)` → persist；任何异常则整份回滚并提示 `操作未保存，已还原：{msg}`；最后 `render(focus)`。所有改状态的按钮都走 perform（Godot 侧需同样的事务式回滚）。

## 2.4 渲染优先级 `render()`

先画常驻层（背景、日期、体力、心情头像、设置钮、底栏，见 03 节）。`mandatory = pending||summary||mode!=='home'||!joined`；`locked = mandatory||view`。
- 若无 pending、无 view、无未读通知信，调用 `CultivationCore.dueStory(s)`；有到期剧情就 `start(s,id,{story:true})` 并 persist（自动开场）。
- 然后按顺序取第一个成立的分支渲染：

| 条件 | 函数 | 画面 |
|---|---|---|
| pending | `renderPending` | 修习演出/剧情对白/邮件演出 |
| summary | `renderSummary` | 面板「第N月 · 月底小结」：完成X次活动 + 成果记录 + 「继续」 |
| mode story | `renderDelivery` | 三月中旬同行送药对白，两选 `协同行路`/`请陆衡指导` |
| journey_ready | `renderDeparture` | 「整月历练」+「出发」 |
| journey | `renderTravel` | 「本月行程」：准备返程→确认返程；汉皋南门特例「这一程，到这里。未完待续。」+「查看行记」「返回标题 · 已保存」 |
| complete | `renderCompletion` | 「三年修习收束」+ 查看修习成果 |
| !joined | `renderArrival` | 「归云谷 · 正式入门」，台词“既入了门，就安心留下。\n明早来练场，我教你站桩和调息。”，继续→`join` |
| 有未读 notice 信 | `renderNotices` | 面板「谷中消息」，逐段正文，「知道了 · 继续培养」→全部标已读 |
| `offerAvailable()` | `renderOffer` | 「周砚传艺」：先台词，下一步出可学招式列表 + 「改日受教」 |
| view picker/gift-npc/letter-npc/mail-inbox | `renderPicker` | 底栏换成子菜单；mail 走 Mail 模块 |
| view walk-review | `renderWalkReview` | 溪畔本期观察回看（免费） |
| view rest | `renderRest` | 「结束本期」：下一阶段日期 + 「继续安排」「确认休息」 |
| view settings | `renderSettings` | 声音开关、武学与装备、调试日程开关、修习成果、小游戏 |
| view games | `renderGames` | 小游戏候选试玩 |
| view training-record | 面板「修习成果」 |

`offerAvailable`：home、已拜师、已学 stance、存在可学（availability 为空）且未学的 skill 动作（排除 QH01），且 `facts.weapon_offer_period!==本期`。

## 2.5 修习动作流程（普通课）

1. 底栏点栏目（或数字键 1–7）→ `view='picker'`，`selection={category, action:首项}`（skill 为 null）。
2. 子菜单点卡片 `practice` → availability 不通过则状态栏提示原因；通过则 `begin(id)`。
3. `begin`：QH01 直接 start+resolve（无演出）；未学的 skill 且非传艺 → `请先完成师父的传艺，再来练习。`；闲逛地点走 `stroll`（无剧情时留在子菜单并显示 idle 文本）；once 动作 `start(...,{story:true})`；其余 `start(...,{animate:true, directResult: RigTrial.enabled})`，并设 `pending.guidance = 首次学习 || (once 且授课人为周砚/叶蘅)`，`animation.presented=false`。
4. `tick(now)`（Presentation 每帧调用）：画框内 `[data-art="action"]` 画布首次绘制完成后才把 `animation.startedAt=now`、`presented=true` 并存盘；满 2000ms 后 `finishAnimation`→`resolve(directResult)`→`reconcileWorld`。
5. 结果：若无 courseBeat/lesson/trainingChanged 且非邮件，`resolvedAt` 后 **1000ms** 自动 `finishResult`；否则显示结果条「继续培养」。
6. `finishResult`：`closeResult`；若是首次学会且仍有可传艺 → `view=null`（回到传艺对白）；否则 `view='picker'`（留在同一子菜单）。

## 2.6 江湖页/武学跳转

`openJianghu(tab='party')`/`openMartial()`：隐藏 `#cultivation`，`mode='scene'`，`QiheJianghuUI.open(tab|'skill','hero')`；包裹 `panelClose`，关闭后 `mode='cultivation'`，`Cultivation.start({inherit:true})`。点击心情头像（`data-cu="jianghu"`，无 pending/view 时）触发。

## 2.7 切磋/考校

- `runFight`：剧情动作 `fight` 且 `visitor.phase==='choice'`；隐藏培养界面，`battle(Household.fightOptions(d))`，附 `guiyunHero:true`、`heroPor:'gy_hero_long'`；`gy_bamboo_wolves` 加 `temporaryDou:true`；结束恢复武器，`visitorChoose(win?0:1)`。
- `runTraining`：仅 `gy_zhou_test`；`GuiyunCombat.trainingOptions(route)`；剑路需装备 kind 为“剑”的武器，否则 `剑路考校请先装备已领取或已有的剑`；战后按 `opt.training.result`（默认 `hasty`）匹配 choices 的 key。

## 2.8 故障出口

`renderBroken`：面板「培养存档无法读取」，按钮「以新的培养进度继续」（quarantine 后删 S.cultivation，重跑 migrate+start）与「返回首页」（`location.href=location.pathname`）。
