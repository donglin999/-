# 01 总览：培养模式（归云谷养成）移植规格书

源：`xiaojianghu-legacy-prologue/index.html` 第 445–450 行（CSS）、第 470–471 行（同步 `<script>` 串）。本规格书忽略所有 review 脚本，例如 `qihe-cultivation-scene-review.js`、`qh-story-motion-review.js`，以及 URL 里的 review 开关。

## 1. 模块地图与加载顺序（index.html，同步脚本，按出现顺序执行）

后加载的模块会覆盖或扩展先加载的。顺序如下：

1. `js/shared-insight-pool.js`，全局对象 `SharedInsightPool`，跨模式共享的历练/悟性池（见 62）。
2. `js/pets.js`，宠物数据与逻辑（见 62）。
3. `js/qihe-guiyun-household-art.js`，全局对象 `window.GuiyunHero`，谷内主角绘制辅助（见 63）。
4. `js/qihe-cultivation-data.js` → `js/qihe-cultivation-core.js`：**旧版**养成核心，会被后面的 `qh-mode-cultivation-*` 覆盖，只为兼容保留（见 62）。
5. `js/qh-pre-hangao-data.js` → `js/qh-pre-hangao.js`，全局对象 `PreHangaoData`、`PreHangao`，出发前（前寒皋）剧本（见 60）。
6. `js/pei-companion.js`，全局对象 `PeiCompanion`，裴知古同行（见 61）。
7. 数据与剧本层，`window.Cultivation*` 子对象依次为：
   - `-scripts`：`CultivationScripts`
   - `-scenes`：`CultivationScenes`
   - `-side`：`CultivationSide`
   - `-neighbors`：`CultivationNeighbors`
   - `-mentors`：`CultivationMentors`
   - `-household`：`CultivationHousehold`
   - `-dialogue`：`CultivationDialogue`
   - `-visitors`：`CultivationVisitors`
   - `-library`：`CultivationLibrary`
   - `-balance`：`CultivationBalance`
   - `-data`：`CultivationData`
   - `-martial`：`CultivationMartial`
8. `js/pre-hangao-art.js`，前寒皋美术。
9. 战斗与武器衔接：`guiyun-battle-finish.js`、`guiyun-combat-runtime.js`、`hero-multiweapon-art-data.js`、`hero-multiweapon.js`。这些不在本次范围，只作为依赖列出。
10. `js/pei-companion-runtime.js`，裴知古运行时（见 61）。
11. 规则层：
    - `-relations`：`CultivationRelations`
    - `-growth`：`CultivationGrowth`
    - `-core`：`CultivationCore`，状态机与结算

    - `-motion-data`：`CultivationMotionData`

14. `js/qihe-cultivation-bridge.js`，全局对象 `QiheCultivationBridge`，入口函数 `qiheTrialStart`，负责与栖河主线对接（见 02）。

CSS 加载顺序（越后优先级越高）：`qh-mode-cultivation.css` → `qh-mode-cultivation-story.css` → `qh-mode-cultivation-actors.css` → `qh-mode-cultivation-mail.css`。其中 actors.css 会覆盖 story.css 里的立绘站位数值，所以以 52/53 为准。全局 zoom 规则中 `#cultivation` 被排除，培养界面自己处理缩放（见 03）。

## 2. Godot 分层建议

- **数据层**：把上面所有 `*-data`、`-scripts`、`-household`、`-dialogue` 等纯数据模块用 Node `require` 导出成 JSON，放在 `res://data/cultivation/*.json`，不要手抄。
- **规则层（Autoload `CultivationCore`）**：纯 GDScript，不依赖节点。负责：
  - 状态：存档结构见 14
  - 时间推进：见 10
  - 活动结算：见 11、13
  - 关系：见 33
  - 武学：见 40
  - 剧情触发判定：见 20
- **剧情引擎**：按队列消费 household、quiet、auto、main 四类事件（见 20–23、46、47），并输出对白指令。
- **呈现层**：主界面场景（见 03、04）、对白界面（见 48）、立绘站位（见 52/53）、动作演出 Tween（见 50）、小游戏子场景（见 24）、书信（见 32）。
- 规则层只发信号，呈现层负责播放。毫秒时序一律换算成秒，使用 `create_tween()` 或 `Timer`。

## 3. 术语表

- **月 / 时段（phase）**：共 36 个月，每月 5 个时段，合计 180 个时段。
- **slot / now**：全局时段序号，`now = (month-1)*5 + phase`。剧情的 window 起点和终点都用这个单位。
- **体力**：每个时段 12 点；活动扣除体力；用尽或玩家选择后进入下一时段（见 10）。
- **mode**：`home`（谷内）、`story`（剧情播放中）、`journey_ready`（准备出发）、`journey`（出发前剧本或同行）、`complete`（结束）。
- **once / `_seen`**：只触发一次的事件，触发后写入 `_seen` 标记并存档。
- **相遇计数**：`mentor_met`（师父）、`visit_met`（来客）、`stroll_met`（闲逛）三类，用作剧情条件。
- **事件类别**：
  - household：谷内日常剧情
  - quiet：无对白的静默事件
  - auto：自动触发
  - main：主线
- **重 / 层**：外功的进度称“重”，内功称“层”（见 40）。
- **cqw**：立绘舞台宽度的相对单位，站位与尺寸都按舞台宽度的百分比计算（见 48、52）。
- **mood**：立绘表情档，对白行中的情绪字段会映射到立绘差分（见 48）。
- **heroForm**：主角体型阶段 `short` / `mid` / `long`，随年月切换 Q 版立绘（见 50、63）。
