# 52 行记数据源（QiheJournal）

源文件：`js/qihe-journal.js`，导出 `window.QiheJournal={version:1,tasks,people,phase,knowledge,recordEncounter}`。除 `recordEncounter` 外都是纯函数，只读存档，界面每次重算。剧情文案是数据，移植时按原文搬进 Godot 数据表（建议放在 `res://data/journal_cast.tres` 或 json）。下面只写结构和推导规则。

## 1. 素材路径
- `portrait(k) = PRODUCTION_ASSET_PATHS[k] || 'assets/production/portraits/'+k+'.webp'`，用于整幅立绘，此时 `full:true`。
- `avatar(k) = 'assets/production/icons-and-props/'+k+'.webp'`，用于小头像，此时 `full` 为假，界面按 pixel 显示。
- 叶蘅：`assets/ui/jianghu-v4/portraits/ye-menu-v2.png`（full）。

## 2. CAST（人物底表，顺序即图鉴顺序）
字段 `{name,faction,role,art?,full?,bio?}`：
- 整幅立绘：xulingyi 徐令仪（正道盟 / 正道盟文议执事，p_qh_xulingyi_story）、censhuang 岑霜（归烬堂 / 对外交涉者）、shenyanhui 沈雁回（巡江司委办）、ye 叶蘅（栖河村）、song 宋先生（行路人，p_qh_song_story）。
- 小头像 `a_opening_*`：chen 陈伯、aunt 周婶、zhouyan 周砚、luheng 陆衡、apothecary 药商、bailiff 差役、steward 管事、retainer 护院、wukui 乌魁、procurement 采办使、procurement_aide 采办随从、chengduo 程铎。
- 没有图（界面显示 badge4）：merchant 店家、elder 村口老人、bandit 帮众。
- `nameId`：由 name 反查 id，用于对白说话人匹配。
- `questDef`：letter（一封未落款的拜帖，owner xulingyi，reward 6）、account（旧罐与玉匣，censhuang，8）、ledger（药单上的两道数，shenyanhui，6）。每项含 `{title,owner,reward,origin,summary,target,place,first}`。

## 3. phase(s) → {chapter,date}
`chapter = QiheMilestones.latest(s)||'江湖行卷'`。没有 qiheChapter 时 date 为「初到栖河」；stage 为 mountain/ended/cultivation 时为「山居」；refuge 时为「邻村接应」；escape/fire 时为「离村途中」；其余按 halfDay 取：`{0:'第一日',2:'第一日傍晚',4:'第二日傍晚',5:'第三日',6:'第三日傍晚'}`，都不匹配时为「村中行程」。显示在行记页 pagebar 右侧。

## 4. knowledge(s)：判定是否相识（met）与身份是否已知（identity）
- 来源：`S.qiheCodex.people`（recordEncounter 写入）、`prologue.arrival.greeted[name]`，以及多项剧情标记。例如 arrival 完成、relicSeen 或已有 c → ye；`c.stage≠opening` → apothecary、luheng；`events['fire-start']` → wukui、retainer、procurement_aide；`events['road-intro']` → bandit；委托任务出现过 → 其 owner。
- `identity`：除 xulingyi、censhuang、shenyanhui 外默认已知。这三人需满足以下任一条件：record 中已标 identity、已问过 `{id}-dispute`、对应任务出现过、或已开过会面（xu / three）。身份未知时，图鉴显示 role「栖河相识的来客」、faction「身份未记」、bio「在栖河相识的来客，目前已记下姓名。」
- `later(c)`：stage ∈ {fire,escape,refuge,mountain,ended,cultivation}；`departed(c)`：stage 不在 opening/days 中。

## 5. tasks(s,{mainLine}) → 任务行
没有 `s.prologue` 时返回 `[]`。mainLine 会去掉 `· J …` 后缀。每行通过 `add(r)` 补齐兼容字段 `t=title, d=origin, done=status==='done', group=kind||'支线', giver=CAST[owner].name`。
行结构：`{id, title, kind, status:'active'|'done', owner?, origin, objective, where, people:[id], action:{type:'resume'|'continue'|'npc'|'evidence', id?, label}|null, progress:[{title,detail,done}], paper?:{id,title,fields:[[label,value]],note,body}, reward?, chapterNpc?, chapterActivity?}`。
生成顺序：
1. 江湖经历：`QiheMilestones.list(s)` 中每项生成 `{id:'ev:'+i, kind:'江湖经历', status:'done'}`。
2. `main:prologue`「眼下」（仅在 `!(p.rested||c)` 时）：action 为 `{type:'resume',label:'继续游玩'}`。
3. `main:qihe`「眼下」（有 c 且未结束时）：progress 按会面、撤离、对证逐步追加，最后一步是「当前行程」（done=false）。`ms=QiheChapter.mainStep(c)` 存在时 objective 为「{title}：到{where}找{who}。」，action 为 `{type:'npc',id:ms.npc,label:'去找'+who}`；否则 action 为 `{type:'continue',label:'继续主线'}`。
4. 帮工（帮周婶三件事：还碗、取布、送药）。
5. 三个委托 `out:{letter|account|ledger}`：kind 为「支线 · {owner名}」。阶段 accepted 表示前往 target；ledger 在 checked 时前往 bailiff；其他情况回 owner 处。action 为 `{type:'npc',id:target,label:'标记地点'}`。已离村或已过时限且未完成的委托不列出。paper 的 fields 和 note 随阶段变化。
6. `window.QiheJournalExtras` 中各回调 `fn(add,step)`，例如蔺管事线；出错只打 warn。
7. 村中活动 `activity:{clinic|transport|practice|market}`：只列已完成的（`choices[id]`，practice 也认 `c.granted`），kind 为「村中活动」。
8. `main:evidence`（refuge 及之后）：kind 为「主线 · 对证」，未对证时 action 为 `{type:'evidence'}`。

## 6. people(s) → 图鉴人物
对 CAST 中 met 为真的人生成 `{...base, id, role, faction, bio, identity, first: record.firstPlace||'栖河（旧档未记录地点）', firstPhase, events:[{phase,text}], relations:[[otherId,label]]（只保留对方也已相识的）, tasks:[关联任务 id], affection?, portraitActor?}`。
- events 第一条固定为 `{phase: firstPhase||'栖河相识', text: identity ? '已记下{name}的身份与往来。' : '与这位来客相识。'}`，之后按剧情标记追加。
- 有 `s.cultivation` 时追加山居人物 `mountainPeople`，以 `portraitActor` 区分：zhou、shimu、yin、zhong、fang、dou、man、pei。art 取 `CultivationHousehold.portraits[actor]`。经历按 `cultivation.history` 生成，phase 为「第{floor(period/60)+1}年{floor(period/5)%12+1}月」，最多保留 10 条。每人 `affection = CultivationRelations.inspect(...)` 加最近 3 条往来记录。

## 7. recordEncounter(who,text)（唯一写入点）
包装 `say(who,text)` 与 `choose(who)`：在原函数之后调用。说话人名取 `who.split(' · ')[0]`，经 nameId 映射。首次遇见时写入 `S.qiheCodex={version:1,people:{[id]:{firstScene,firstPlace:SC[scene].name||'栖河',firstPhase:phase(S).date,identity}}}`。对白文本命中以下正则时把 identity 设为 true：xulingyi `/文议|正道盟|核办/`，censhuang `/归烬堂|交涉/`，shenyanhui `/委办|程巡检|跑商路/`。这里不主动存盘，随后续存档一起保存。

## 8. 与通知的关系
`QiheJournalNotices`（55 号文件）用 `people()` 与 `tasks()` 生成事实快照，用于检测“新相识”和“故事更新”。
