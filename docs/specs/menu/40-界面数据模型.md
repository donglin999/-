# 40 界面数据模型（QiheUIModel 只读部分）

源文件：`js/qihe-ui-model.js`，导出 `window.QiheUIModel`（version:1）。原则：**界面只读快照，所有写操作都走 `command()`**。预览时绝不修改 S，每次都在 `normalize(S)` 的深拷贝上计算。Godot 建议做成一个 autoload 单例 `UIModel`：读接口返回 Dictionary，写接口统一用 `command(dict)`。
加载时执行 `MN_SECT.guiyun='归云谷'`。

## 1. 工具与常量
- `copy(x)=JSON 深拷贝`；`human(id)= id==='hero' || (PARTY_DEF[id] && !PET_DEF[id])`。
- `names={weapon:'兵器',armor:'护具',acc:'佩饰'}`；`keys=['str','con','agi','wil','wis']`。
- `rec(s,id)`：hero 返回 s 本身，其余返回 `s.mates[id]`；`eq(s,id)`：hero 返回 s（装备字段直接在 S 上：`S.weapon/armor/acc`），其余返回 `rec.equip`。

## 2. normalize(source) → 规范化拷贝
1. 缺省补齐：`party=[] mates={} bag={} skills={fist:1} pts=0`。
2. `all = unique(['hero', ...旧 qiheRoster.members, ...party])`；若有 `qiheChapter` 且 stage≠'opening'，补入 `'ye'`。
3. `s.qiheRoster={version:1, members:all, availability:{...旧}, revision:旧||0, commands:旧||[]}`。
4. 宠物迁移：无旧 roster 且 party 含 dog 时设 `s.pet='dog'`。若 `PET_DEF[s.pet]` 存在，把 `s.mates[pet]` 迁到 `s.pets[pet]={st,lvSeen,hp,mp,equip:{acc}}`。补发成长 `points=(prior.pts||0)+(s.lv-lvSeen)*3`，按 `PET_DEF.growth` 循环逐点加；有升级时 hp/mp 置 null（视为满）；最后删除 `mates[pet]`。
5. `party` 只保留：human、非 hero、availability 为 present（缺省 'present'）的成员，去重后取前 3 个。第一章非 opening 阶段且无旧 roster 时，人数不足 3 则补 ye。
6. stage 为 'cultivation' 时：`chapter=max(2,chapter)`，`sect||='guiyun'`。
7. 对每名 human 成员：新同伴按 `PARTY_DEF` 初始化 `{st, pts:0, lv: ye 为 3，其余为 initialLevel||1, exp:0, lvSeen:1, equip 三格 null, skills:{各技:1}, hp:null, mp:null, mpBonus:0}`；补齐 `st 默认各 3`、`skills/prof/pts`。
   - `zy` 补为 `MN_ZY` 各键取 `MN_ZY0[origin]`（hero 用 s.origin），`ji={yi:0,du:0,shi:0,...MN_JI0[origin]}`。
   - `xinfa={main:null,subs:[],known:[],lv:{},prog:{},unstable:0}`。chapter≥2、角色不是 noXf、且（非 hero 或 hero 已学 `cultivation.learned.breathing`）时，自动习得 `tuna`（suzhi 另加 `bx_xin`），main 缺省为 tuna（suzhi 为 bx_xin）。
8. 调 `CultivationCore.reconcileWorld(s)`、`SharedInsightPool.sync(s)`；`virtue||={ren:(moral||10)-10,yi:0,xin:0,yong:0}`。

## 3. 在场判定
`availability(s,id)=qiheRoster.availability[id]||'present'`；`available = human && members.includes(id) && availability==='present'`。

## 4. calc(s,id) 派生属性
`b` = 三件装备 `mnFx(k)` 求和；`st[k]=r.st[k]+b[k]`；lv 取 hero 的 `s.lv` 或 `r.lv`。
```
mhp  = 60 + con*14 + lv*12 + b.mhp
mmp  = 30 + wil*7 + wis*2 + lv*5 + r.mpBonus + b.mmp
atk  = 8 + str*3 + lv*2 + b.atk + (hero ? s.atkBonus : 0)
def  = con + wil*2 + b.def
spd  = agi + b.spd
crit = 5 + wis*2 + b.crit
dodge= round(agi*1.5) + b.dodge
block= min(30, con + b.block)
move = 2 + floor(agi/5)
```
之后对 `MN_DK` 中每个键，若心法有 add 或 pct：`d=round((d+add)*(1+pct))`。hero 有 cultivation 时再加 `CultivationCore.growth().bonuses`。最后若存在 `CharacterCondition.apply(d,r)` 则应用。

`innerEffects`：chapter<2 或 noXf 时为空。对 main 与 subs 中每门心法：n=层数；若为主修且 `unstable>0`，倍率 m=.5，否则为 1；`per.add/per.pct` 各乘 `n*m`；`heal+=per.heal*n*m`；仅主修对 `f.e` 中每个元素累加 `eb[e]+=MN_XF_EB*n*m`；不处于不稳状态时，n≥3 加 `t3.add`，n≥5 加 `t5.add`。

`health(s,id)`：hp/mp 为 null 时视为满，否则夹在 [0, 上限]。

## 5. actor(s,id) 人物视图（各页共用）
字段：`id,name`（hero 为 s.name）、`role`（hero 为 '异乡来客'）、`portrait`、`active`（hero 恒为真，或在 party 中）、`available`、`availability`、`locked`（hero 为真，`lockReason:'主角承担当前剧情视点'`）、`stats`、`derived`、`hp`、`mp`、`level`、`exp`、`expMax=level*100`、`points`、`equipment{weapon,armor,acc}`、`skills`（skillView 列表，排除 fist）、`basicAttack`、`inner`、`zy`、`ji`、`virtue`、`conditions`、`relationship`、`training`。
- `basicAttack={id:'fist', name: 武器名||PARTY_DEF.atkName||'拳脚', kind: 武器 kind||atkType||'拳', description:'基本攻击，不消耗内力；BP每级增加一次攻击。'}`。
- `inner={...xinfa, capacity: max(hero 学过 xf_guanlan ? 1 : 0, [13,25,39] 中 ≤lv 的个数), open: chapter>=2}`。
- `ji.shi += Σ(5+2*(重数-1))`，对所有已学技能（不含 fist）求和。
- `virtue.yi += 2*(人数-1) + floor(Σaff/3)`。
- portrait：hero 长发时为 `assets/p_gy_hero_long.webp`，否则按 borrowed 取 `p_opening_hero_village`/`p_opening_hero_modern`；其余角色为 `p_{PARTY_DEF.por[0]||id}`。若 `PRODUCTION_ASSET_PATHS` 中有对应条目，优先使用。
