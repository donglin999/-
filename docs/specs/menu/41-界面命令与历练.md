# 41 界面命令 command() 与共享历练池

源文件：`js/qihe-ui-model.js` 中的 `command`、`poolOptions`、`poolApply`、`poolTrainingCost`、`skillWhy`，以及对 `mkHero/mkAlly/doSkill` 的包装。

## 1. 调用约定
`QiheUIModel.command({type, actorId?, itemId?, commandId?, expectedRevision?, ...})`
- 成功返回 `{ok:true, revision}`；重复 commandId 返回 `{ok:true, duplicate:true, revision}`。
- 失败返回 `{ok:false, reason, revision}`。reason 是直接显示给玩家的中文。
- 处理顺序：
  1. `writing` 为真时返回「正在保存，请稍候」（防止重入）。
  2. S 为空时返回「人物尚未初始化」；`c.cancel` 为真时返回「已取消」。
  3. **setMute / setTheme 最先处理，不受剧情限制，也不增加 revision**：
     - setMute：需要 `window.__audio`（否则「声音尚未就绪」）；`v = c.value==null ? !muted : !!c.value`；写入 `localStorage['xjh.mute']='1'|'0'`，再调 `__audio.setMute(v)`。
     - setTheme：需要 `BUI`（否则「界面主题尚未就绪」）；`v = c.value || (theme==='ink' ? 'scroll' : 'ink')`，只接受 ink/scroll，其他值返回「未知主题」；写入 `localStorage['bui.theme']`，再调 `BUI.setTheme`。异常时返回「设置保存失败：{msg}」。
  4. `mode==='battle'`、`busy` 且 mode 不在 menu/panel 中、或 `dlgBusy` 时，返回「当前剧情或战斗进行中」。
  5. `s=normalize(S)`。commandId 已在 `q.commands` 中时按重复处理。`expectedRevision` 与当前不符时返回「状态已变化，请重新确认」。
  6. 需要角色的命令（equip/unequip/useItem/learnFromItem/allocateStats/setMainInner/setSubInner/spendInsight）在角色不在场时返回「角色不在场或尚未结伴」。
  7. 执行 switch。成功后 `q.revision++`；commandId 推入列表，只保留最近 32 条；调 `persistState(s)` 后 `S=s`（**先存盘再替换内存**）。applyFormation 额外调 `resetFollowers()`，失败只打日志。
  8. 异常 message 作为 reason 返回；`finally` 中 writing=false。

## 2. 各命令
| type | 参数 | 规则与报错 |
|---|---|---|
| save / migrate | — | 只做 normalize 后存盘 |
| applyFormation | active[] | 长度 1–4 且无重复，否则「出战需为1至4名不同角色」；`active[0]` 不是 hero 时「萧白须留在首位承担当前剧情视点」；成员不在场时「角色不在场或尚未结伴：{id}」；最后 `party = active` 去掉 hero |
| equip | actorId,itemId | 先 `inspect`，非 equip 或不允许时用其 reason（缺省「不可装备」）；旧装备退回 bag，新装备 `bag[k]--`，然后 clampHealth |
| unequip | slot | slot 非法时「未知装备位」；槽位为空时「此位置为空」；装备退回 bag |
| useItem | itemId,quantity? | quantity 不为 1 时「当前每次使用一份」；gall 类物品 `mpBonus+=30`，其他按 inspect 结果加 hp/mp；`bag--` |
| learnFromItem | itemId,skillId/innerId | 目标 reason 非空则报错；未选目标时「请选择参悟对象」；hero 的修习武学调 `CultivationBalance.grantLevel` 与 `reconcileWorld`；book 使技能重数 +1；xfbook 使心法层数 +1 并把 prog 清零；`bag--` |
| allocateStats | stats{k:n} | 总数为 0 或超过 pts 时「可分配点数不足」；k 非法、非整数、负数或 `st+v>8+lv` 时「加点超出上限」 |
| setMainInner / setSubInner | innerId, confirmCost? | sub 已在列表中时直接卸下；否则取 innerWhy 的 reason。主修更换且旧主修存在时：未带 confirmCost 报「改修需确认内力清空和气脉不稳」；确认后 `mp=0`、`unstable=MN_XF_SWAP` |
| spendInsight | target,amount,expectedCost? | 调 poolApply；实际 cost 与 expectedCost 不符时「实际消耗已变化，请重新预览」 |
| feedPet | itemId 缺省 bun | 没有宠物时「尚未结伴宠物」；非 bun 或数量为 0 时「需要馒头」；满血时「宠物气血已满」；否则 hp+40（不超上限），bun-1 |
| equipPet | itemId 为 collar 或 null | 其他物品时「宠物仅可装备项圈」；数量为 0 时「数量不足」；与 acc 槽互换 |
| 其他 | | 「暂未支持此操作」 |

`innerWhy(s,id,k,slot)` 依次判断：chapter<2 →「暂未开放」；noXf →「此角色不修心法」；未知 →「尚未习得」；slot 不符 →「心法类型不符」；主修门派不符（hero 比 s.sect，其他比 mnDef.sect）→「门派不符」；辅修已满（容量：lv≥39 为 3、≥25 为 2、≥13 为 1，hero 修 xf_guanlan 为 1）→「辅修位置尚未开放或已满」；req 不满足 →「根基不足」；与其他非「中」性心法阴阳相反 →「阴阳相冲」。

## 3. 共享历练池（spendInsight / insight / insightQuote）
- `insight()` 返回 `{...SharedInsightPool.state(s)（含 balance）, actors:[在场成员 {id,name,options}]}`。
- `poolOptions(s,id)`：
  - pei、peizhigu 或 `growthMode==='witness'` 之外的角色有 `{key:'level',label:'人物等级'}`。
  - 已学技能（不含 fist）：hero 修习中且 `artForSkill` 有对应时，key 为 `art:{id}`，否则为 `skill:{k}`；label 取 artName||name。
  - 已知心法：`art:{id}` 或 `inner:{k}`。按 key 去重。
- `poolTrainingCost(need,request,balance)`：`total=ceil(need*5-1e-8)`，`budget=min(request,balance)`；`budget>=total` 时返回 total，否则返回 `floor(budget/5)*5`。即 **5 点历练换 1 点熟练**，只有结清尾数时才允许不是 5 的倍数。
- `poolApply`：request 必须是 1–1000000 的整数，否则「请输入1至1000000的整数历练」；选项不存在时「尚未习得，或此人物不使用该成长方式」。
  - level：调 `SharedInsightPool.levelQuote(lv,exp,balance,request)`，得到 cost/after/exp/points；`pts+=points`；满 100 级时 `xpFraction=0`；gain=cost（**1 点 = 1 修为**）。
  - art：`need = thresholds(a)[before] - martialXp[a.id]`；调 `addXp(c,id,cost/5)`。
  - skill：reason 取 upgradeWhy；`need = 6*n² - prof`；need 为 0 时「熟练已足，请按原突破条件完成进阶」；`prof += min(need,cost/5)`，达到 6n² 时重数 +1，prof 扣掉 6n²。
  - inner：chapter<2 或 noXf 时「尚未开放心法修习」；层数上限 5，满时「心法已练满」；`need=(.8*lv - prog)*100`；`prog += gain/100`，达到 .8*lv 时层数 +1、prog 清零。
  - cost<1 时「至少需要5点历练，或结清最后不足1点的熟练」。
  - 扣款 `SharedInsightPool.debit(s,cost,{actor,target,name})`；hp/mp 保持原值，但不超过新上限。
  - 返回 `{allowed,actor,name,target,label,kind,cost,balanceAfter,before,after,gain,experienceAfter,beforeStats,afterStats}`。`insightQuote` 在拷贝上执行，出错返回 `{allowed:false,reason}`。

## 4. 战斗接口包装
- `mkHero()`：skills 改为 `S.skills` 中全部已学技能（不含 fist）；`mkAlly(id)` 同理取 `S.mates[id].skills`。没有“装配格”限制。
- `skillCost(u,k)`：有 `u.mw` 时为 `max(0, sk.mp + mnHuo.mp + mastery.mp)`，否则为 `sk.mp`。
- `skillWhy(u,k)` 依次判断：未学 →「尚未习得」；武器类型不符 →「需装备X」；属性不足 →「需{STATN} v」；内力不足；最后取 `CultivationBalance.battleWhy`。
- `doSkill` 包装：我方单位 `skillWhy` 非空时直接 return，不出招。
