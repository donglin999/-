# 10 物品与装备数据结构

源文件：`js/core.js`（`ITEMS`、`STATN`、`SKILLS` 基础表）、`js/menu.js` 第 18–60 行（品质、栏位、扩充物品、物品工具函数）、`js/ui.js`（`ICO` 单字图标）。

## 1. 物品表 `ITEMS`（core.js 第 162 行 + menu.js 扩充）

字典：键为物品 id（字符串），值为物品对象。字段含义：

| 字段 | 类型 | 含义 |
|---|---|---|
| `name` | string | 显示名 |
| `desc` | string | 说明文案 |
| `price` | int | 买价（文）；缺省表示不可买卖 |
| `q` | int 0–4 | 品质索引，对应 `MN_Q`；缺省按 0（丁级） |
| `weapon` | `{kind, atk, crit?}` | 兵器；`kind` 为兵刃类别（剑/刀/棍/暗器/医具…），`atk` 攻击加值，`crit` 暴击加值（百分点） |
| `armor` | int | 护具；数值即防御加值（判定用 `typeof armor==='number'`） |
| `acc` | 1 | 佩饰标记 |
| `fx` | `{属性键: 值}` | 词条加成，键可为五维（str/con/agi/wil/wis）或派生值（atk/def/mhp/mmp/crit/dodge/spd/block） |
| `req` | `{五维键: 最低值}` | 装备需求 |
| `heal` / `mp` | int | 使用回复气血 / 内力 |
| `book` | 1 | 武学残页 |
| `xfbook` | 1 | 心法书（见 12） |
| `gall` | 1 | 蟒蛇胆：永久内力上限 +30 |
| `insight` | 1 | 领悟类消耗品（见 12） |
| `key` | 1 | 要物（任务物品，不可卖） |
| `mat` | 1 | 材料 |

## 2. 品质 `MN_Q`

索引 → [名称, 颜色]：0 `丁级 #6f6250`；1 `丙级 #2f6b45`；2 `乙级 #2d5a86`；3 `甲级 #6b3d8a`；4 `绝级 #b3561e`。
`mnQ(k)`：`mnQOn()` 恒为 true，返回 `MN_Q[ITEMS[k].q||0]`；若关闭则返回 `['','#3b2c1b']`。
（栖河另有品级显示规则，见 42 号文件 `qihe-grades.js`。）

## 3. 栏位 `MN_SLOTS`

`[['weapon','兵器','刃'],['armor','护具','甲'],['acc','佩饰','佩']]`：[键, 名称, 空栏占位单字]。
主角装备存于 `S.weapon / S.armor / S.acc`；同伴存于 `S.mates[id].equip.{weapon,armor,acc}`。

## 4. 物品工具函数（menu.js）

- `mnSlot(k)`：有 `weapon`→`'weapon'`；有 `acc`→`'acc'`；`armor` 为数字→`'armor'`；否则 `null`。判定顺序即此顺序。
- `mnFx(k)`：复制 `fx`，再把 `weapon.atk` 加到 `atk`、`weapon.crit` 加到 `crit`、`armor` 加到 `def`，返回合并词条。
- `mnCat(k)`：兵器/护具/佩饰；否则 `key`→`要物`；`heal||mp`→`药食`；其余 `杂物`。
- `mnFxTxt(a,v)`：`"{MN_FXN[a]} {+/-}{v}{%}"`，`MN_PCT` 中的键（crit/dodge/block）带 `%`。例：`暴击 +3%`、`气血 +15`。
- 属性名 `MN_FXN`：block格挡 atk攻击 def防御 crit暴击 dodge闪避 mhp气血 mmp内力 spd身速 str臂力 con根骨 agi身法 wil定力 wis悟性。
- 对比键顺序 `MN_DK=['atk','def','mhp','mmp','crit','dodge','spd','block']`。
- `STATN`（core.js）：`{str:'臂力',con:'根骨',agi:'身法',wil:'定力',wis:'悟性'}`，五维顺序即此顺序。

## 6. 铁匠铺 `MN_SMITH`

`['club','wood','knife','needles','iron','cloth','mianjia','vest','charm','collar','jade']`。`shop` 被包一层：`n.id==='smith'` 时把 `MN_SMITH` 与原清单去重合并，按栏位 weapon0/armor1/acc2/其它3 排序。另有 MutationObserver 把商店行的分类小字改为 `mnCat` 结果（佩饰、材料、护具）。

## 7. 商店对比 `statRows(k)`（覆盖 ui.js）

返回行数组 `[名称, 新值文本, 差值|null, 右侧说明]`：
1. 可装备物：对 `mnCmp('hero',{eq:{[slot]:k}})` 中差值非 0 的每项输出 `[MN_FXN, 新值(+%), 差, "旧 → 新"]`；全为 0 时输出 `['属性','—',0,'与现有持平']`。
2. `['词条', 词条列表用全角空格连接, null, 品质名或'—']`。
3. `['部位', 栏位名, null, '现用 X' 或 '现为空']`。
4. 有需求或不可装时：`['需求', '臂力 5 …' 或 '—', null, 红色 #e07a5a 原因 或 '已达']`。
5. `heal`：`['气血','+N',null,'当前 hp/mhp']`；`mp` 同理为内力。
`equipItem(k)` = `mnEquip('hero',k)`（商店“当场佩上”）。
