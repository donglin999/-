# 11 成员规则、存档补齐与派生属性

源文件：`js/menu.js` 第 1–126 行（`MN_MEM`、`MN_PREF`、`mnCap`、`mnEnsure`、`mnSync`、`derived`、成员访问函数、`mnCan`/`mnEquip`/`mnUnequip`/`mnCmp`）、第 127–155 行（`mkHero`、`mkAlly`、`battle` 包装），`js/core.js`（`newState`、`settleCharacterLevels`）。

## 1. 存档字段（主角 = `S`，同伴 = `S.mates[id]`）

主角（core.js `newState`）：`name:'无名'`、`origin:'orphan'`、`lv:1`、`exp:0`、`pts:0`、`st:{str:3,con:3,agi:3,wil:3,wis:3}`、`moral:10`、`hp`、`mp`、`silver:0`、`atkBonus:0`、`mpBonus:0`、`weapon`、`armor`、`acc`（menu.js 补 `null`）、`bag:{物品id:数量}`、`skills:{武学id:重数}`、`load:[已装配武学]`、`skSeen:[]`、`party:[同伴id]`、`mates:{}`、`chapter`。
同伴记录（`mnEnsure` 惰性创建）：
```
{st:{...PARTY_DEF[k].st}, pts:0, lv: k==='ye'?3:(P.initialLevel||1), exp:0, lvSeen:1,
 equip:{weapon:null,armor:null,acc:null}, skills:{P.skills 各 1 重}, hp:null, mp:null, mpBonus:0}
```
`hp/mp === null` 表示满。另有 `prof/profNote`（熟练）、`xinfa`（心法）、`zy`（兵刃造诣）、`ji`（技艺）、`load/skSeen`、`conditions`。
- `mnEnsure()` 遍历 `S.party ∪ S.qiheRoster.members`，只为 `PARTY_DEF` 中存在的 id 建档；依次调用 `CharacterGrowth.ensure`、`mnDimEnsure`、`mnSync`、`mnXfEnsure`。
- 升级（core.js `settleCharacterLevels`）：`CHARACTER_LEVEL_CAP=100`；`while exp >= lv*100`：`exp-=lv*100; lv++; pts+=3; hp=mhp; mp=mmp`。满级 `exp=0`。

## 2. 成员规则 `MN_MEM` / `mnDef(w)`

| id | wk 可用兵刃 | slots | 其他 |
|---|---|---|---|
| `hero` | 不限 | weapon/armor/acc | role 主角 |
| `suzhi` | 暗器、剑、医具 | 三栏 | learn[暗器,掌,内,医,剑]、teachAff 3、role 游方医师、sect baixian、gives huichun(aff 5) |
| `dog` | `[]`（不可用） | 仅 acc | role 忠犬、noXf 1（不修心法） |
| 其他 | 不限 | 三栏 | learn []、role 同伴 |

一键加点循环偏好 `MN_PREF`：suzhi[wis,wil,con,wis,wil,agi]、dog[str,agi,con]、orphan[wil,wis,con]、beggar[agi,con,str]、shepherd[str,con,agi]。
单项五维上限 `mnCap(w)=8+等级`（主角用 `S.lv`，同伴用 `mates[w].lv||1`；装备加成不计）。

## 3. 成员访问
- `mnMembers()`：`['hero', ...S.party 中已建档者]`。
- `mnName(w)`：主角 `S.name`，同伴 `PARTY_DEF[w].name`。
- `mnPts/mnSt/mnSk/mnRec/mnEq`：分别取未分配点、五维、武学表、记录对象、装备对象（主角装备对象即 `S`）。
- `mnUnit(w, mod)`：组装派生所需单位 `{st, lv, conditions, weapon, armor, acc, mpBonus, atkBonus(仅主角), xw:w}`；`mod.st` 叠加五维草稿，`mod.eq` 覆盖装备——用于预览与对比，不改存档。
- `mnHP(w)`：返回 `{hp, mp, d}`；主角 `min(S.hp, d.mhp)`；同伴 `null` 视为满。

## 4. 派生属性 `derived(u)`（覆盖 core.js，主公式）

1. 装备加成 `b`：对 `u.weapon/armor/acc` 每件取 `mnFx`，逐键累加。
2. 有效五维 `s[k] = u.st[k] + b[k]`（STATN 五键）；`lv = u.lv||1`。
3. 公式：
```
mhp   = 60 + s.con*14 + lv*12 + b.mhp
mmp   = 30 + s.wil*7 + s.wis*2 + lv*5 + u.mpBonus + b.mmp
atk   = 8 + s.str*3 + lv*2 + b.atk + u.atkBonus
def   = s.con + s.wil*2 + b.def
spd   = s.agi + b.spd
crit  = 5 + s.wis*2 + b.crit          （百分比）
dodge = round(s.agi*1.5) + b.dodge    （百分比）
block = min(30, s.con + b.block)      （百分比）
move  = 2 + floor(s.agi/5)
```
返回值另带 `st`（含装备五维）、`fx`（=b）。
4. 心法：`X=mnXfSum(xw)`，若 `X.act` 非空，对 `MN_DK` 每键：`d[k]=round((d[k]+X.add[k])*(1+X.pct[k]))`；`d.xf=X`。
5. 若存在 `CharacterCondition`，最后 `CharacterCondition.apply(d,u)`（状态异常修正）。

## 5. 装备规则
- `mnCan(w,k)` 返回原因串（空串=可装），按顺序：非装备 → `不可装备`；栏位不在 slots → `{名}用不了{兵器/护具/佩饰}`；兵器类别不在 wk → `{名}不使{kind}`；`req` 任一项 `st[a] < v`（裸五维，不含装备）→ `需{STATN} {v}`。
- `mnEquip(w,k)`：可装且 `S.bag[k]>0`；原栏位物品退回背包 +1；栏位=k；`S.bag[k]--`；`mnClampHP(w)`（气血内力截到新上限）。返回 bool。
- `mnUnequip(w,slot)`：物品回包 +1，栏位置 null，截 HP。
- `mnCmp(w,mod)`：对 `MN_DK` 输出 `[键, 旧, 新, 新-旧]`。
- `mnWearer(k)`：当前穿戴物品 k 的成员列表。
栏 UI 新版会改走 `QiheUIModel` 命令（见 41），但校验文案与上面一致。

## 6. 战斗接入
- `mkHero()`：`statUnit` 基础上覆盖 mhp/mmp/atk/def/spd/crit/dodge/block 为 `derived()`；`hp=clamp(S.hp,1,mhp)`、`mp=clamp(S.mp,0,mmp)`；`atkType` = 兵器 kind（琴/箫/笛/音律→`音律`）否则 `拳`，`atkName` = 兵器名或 `拳脚`；`skills = S.load` 中已学的；`skLv=mnEffLv('hero')`；`xf=mnXfSum('hero')`。
- `mkAlly(key)`：无档时用 `PARTY_DEF` 原值满血；有档则同上，`hp` 为 null→满，否则 `clamp(m.hp,1,mhp)`；立绘 `por` 取 `P.por` 中第一个已加载 `IMG['p_'+p]`。
- `battle` 包装：结束后若有结果且非训练且未结算，按 0.5 倍结算熟练（败/逃）；升重时 600ms 后 `toast("「名」突破至第 N 重"，1800ms)`（多条用全角空格连接）。同伴写回：本场升级或败北（非 noLose）→ hp/mp 置 null；否则 `hp=max(1,u.hp, 败北?round(mhp*.3):0)`，满则 null。品德勇气：逃跑 `virtue.yong-1`，胜头目 `+2`。
