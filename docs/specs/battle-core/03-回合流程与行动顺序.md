# 03 战斗入口、回合流程与行动顺序

源：`js/battle.js` `battle()` `battleLoop()` `calcOrder()` `newJit()` `endCheck()` `tickBuffs()`；包裹见 `menu.js` `battle`/`layoutUnits`/`tickBuffs`、`pets.js` `battle`、`hero-multiweapon.js` `battle`、`guiyun-combat-runtime.js` `endCheck`/`tickBuffs`。

## 1. `battle(opt)` 全部选项
| 选项 | 类型 | 作用 |
|---|---|---|
| foes | 模板[] | 必填，敌人模板（02 §5） |
| bg | 字符串 | 背景键（bb_*/bg_*/m_*）；缺省 `'bg_'+S.scene`；由 bstage 映射到氛围图（11） |
| boss | bool | 头目站位；禁逃；胜利 `S.virtue.yong+=2` |
| noLose | bool | 失败不回满同伴/宠物（menu/pets 包裹里区分）；现行剧情战全为 noLose |
| noFlee | bool | 菜单不出“逃跑” |
| tutorial | bool | 不带同伴/宠物；禁逃；开场 3 句教学；经验 ×0.5 |
| solo | bool | 不带同伴/宠物 |
| intro | 字符串/函数/数组 | 开场旁白，逐条 `say('',l)`，函数则 await 调用 |
| heroArt / heroPor | 字符串 | 主角战斗动作表 / 立绘；指定后开战前校验素材，缺失抛错 `当前衣装战斗素材未就绪：<art>` / `当前衣装战斗立绘未就绪：<por>` |
| allyArts / allyPorts | {key:art} | 同伴换装 |
| temporaryDou | bool | 追加临时同伴卢小豆 |

| guiyunHero | bool | 强制使用归云主角多兵器动作 |

返回 `'win'|'lose'|'flee'`。

## 2. 开战流程（时序）
1. 记 `hpBefore/mpBefore/bagBefore`（异常回滚、training 恢复用）。
2. 预载：背景、氛围背景（`BSTAGE.assetFor`）、立绘（含表情差分 `EXPR`）、全部战斗动作表 `BART[k].file`。全部就绪后才揭幕。
3. `fade(cb)` 遮罩内：`mode='battle'`；隐藏 `prompt hud blog border bhud`、触控板 `tpad`；构造 allies/foes；`layoutUnits`；建 `B`；显示 `#bt`；`#bt-help` 文本 `↑↓ 选择 · Enter/Z 确定 · Esc/X 返回 · Q/E 或 ←→ 蓄势 · 可点按`；`VFX.reset()`；`newJit()`；`renderCards()`。
4. 音效 `whoosh`。
5. `opt.intro` 逐条。
6. `opt.tutorial` 时三句（say 说话人为空）：
   - `【教学】敌人脚下的格子是它的「弱点」，初时显示为「？」。用对应的兵刃或内劲击中弱点，便会削去一层护盾。`
   - `护盾削光即「破势」：敌人本回合与下回合无法行动，且受到双倍伤害。`
   - `每回合积攒一点「蓄势」（菱形）。出招前按 E / → 或点「＋」投入蓄势：普攻变为连击，武学威力大增。`
7. `battleLoop()`；异常：`BattleAuto.finish()`，回滚 S.hp/mp/bag，关菜单，淡出，toast `战斗发生错误，请重试`，再抛出。
8. 结算见 08。

menu.js 的 `layoutUnits` 包裹（开战时一次）：心法特性 `tr.startBp`（bp+n，上限 5）、`tr.startDing`（`buffs.ding=max(旧,n+1)`）、`tr.startReveal`（每个敌人随机揭示 n 个弱点）。

## 3. `battleLoop()` 每回合
```
loop:
  B.round++ ; B.done = new Set()
  对每个活着的我方: if round>1 且 !boosted: bp = min(5, bp+1) ; boosted=false
  对每个敌: if broken 且 round > brokenUntil: broken=false; shield=maxShield; 浮字「护盾恢复」#9fd4ee 18
  B.order = storyLesson.order() | training? [...allies,...foes] | calcOrder()
  order 中所有单位 prio=false        ← 防御的优先只作用一回合
  newJit()
  B.next  = 同上规则再算一次（用新抖动，作为“下回合”预告）
  每个活着的敌: planIntent(u)（storyLesson 可替换）
  renderCards(); wait 250ms
  for u in B.order:
     if u.hp<=0: done.add(u); continue
     r=endCheck(); if r: return r
     B.cur=u; PeiCompanion.actionStart(u)（若有）; renderCards()
     敌方:
        if broken||stun: 浮字 broken?'破势中'(#aaa):'眩晕'(#e0c0ff) 18；stun=false；wait 450
        else: storyLesson.beforeFoe? → foeAct(u) → storyLesson.afterFoe?
              头目追加：bossy && hp>0 && hp<mhp*0.5 && !broken && !endCheck()
                        → planIntent(u); wait 300; foeAct(u)        ← 半血后每回合两动
     我方:
        defend=false; delete buffs.qhGuard
        if stun: stun=false; 浮字「眩晕」#e0c0ff 20; wait 600
        else: r2 = pet? petTurn(u) : allyTurn(u); if r2==='flee' return 'flee'
     tickBuffs(u); done.add(u); B.cur=null; renderCards()
     r3=endCheck(); if r3 return r3; wait 160
  B.cur=null
```
注意：防御是在**下一次轮到自己时**才清除 `defend`，因此防御覆盖该单位行动后到下次行动前的所有敌方攻击。

## 4. 行动顺序 `calcOrder()`
```
newJit(): B.jit = Map(每个单位 → rnd(0,3))   // 连续均匀浮点 [0,3)
calcOrder(): aliveOf() 按 key 降序
  key(u) = (u.prio?100:0) + u.spd + B.jit.get(u)
```
- 本回合顺序用上一回合末（或开战时）生成的 jit；算完立刻 `newJit()`，用新 jit 算 `B.next`，下回合的 `B.order` 实际又会用这份 jit 重算（此时 prio 已清、死亡单位已排除），所以“下回合”预告基本准确，但防御的 prio 会让实际顺序提前。
- 排序在预告时含 prio：防御者在 `B.next` 中排最前。

## 5. `endCheck()`
敌方无存活 → `'win'`；我方无存活 → `'lose'`；否则 null。training 版本见 10。

## 6. `tickBuffs(u)`（每个单位行动后）
1. `buffs.ding` 自减，≤0 删除。
2. 中毒：`bleedN>0 && hp>0` → `d=max(1,round(mhp*0.06))`，`hp=max(0,hp-d)`，`bleedN--`，浮字 `毒 <d>` `#86d65e` 20。（直接扣血，不经 hurt，不触发受击）
3. menu.js 包裹追加（我方、活着、有心法特性 tr）：
   - `tr.mpRegen`：`n=max(1,round(mmp*mpRegen))`，回内，浮字 `内力+n` `#8cf` 18
   - `tr.lowRegen`：hp<30% 时 `heal(u,max(1,round(mhp*lowRegen)))`
   - `tr.allRegen`：全体活着且未满的我方各 `heal(max(1,round(mhp*allRegen)))`
4. guiyun 包裹：training 中主角行动后记录动作（10）。

## 7. 行动顺序条（顶部预告，绘制见 06）
- 左侧 `第N回`；当前回合 `B.order`：已行动/死亡变暗，当前者放大 +8 并金框；敌方破势显示“破”。
- 分隔竖线后 `下回合` + `B.next`（过滤死亡、过滤“下回合仍破势”的敌人：`broken && brokenUntil>=round+1`），整体 alpha 0.75。
