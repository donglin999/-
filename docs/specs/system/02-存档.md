# 02 存档：键名、格式、自动存档、手动存档命令

源文件：`js/core.js`（`isQiheEntry` `qiheJourneyId` `qiheJourneySaveKey` `saveKey` `persistState` `save` `loadSave` `showSaveWarning` `newState` `normalizeCharacterLevel`）、`js/qihe-saves.js`（`QiheSaves`）、`js/qihe-map-trial.js`（`checkpoint` `journal`）、`js/qihe-jianghu-ui.js`（`sysPage` `saveManager` `saveNameForm` `saveCommand`）、`js/main.js`（定时存档）、`js/scene.js`（`goScene`）。

## 1. 存储介质与键名

全部用浏览器 `localStorage`（字符串键 → JSON 字符串）。Godot 建议：`user://saves/` 下每键一个 `.json` 文件，文件名=键名；另设 `user://settings.cfg` 存设置键。

| 键 | 内容 |
|---|---|
| `xjh.qihe-prologue.v2` | “原有旅程”（无 journey 参数时的默认进度，旧版遗留） |
| `xjh.qihe-prologue.v2.run.<id>` | 一条“旅程”（自动进度）。`<id>` 匹配 `^[a-z0-9-]{8,64}$` |
| `xjh.qihe-prologue.v2.slot.<id>` | 手动存档（不可变检查点）。`<id>` 同上规则 |
| `xjh.qihe-prologue.latest.v1` | 值为最近一次成功写入的旅程键（字符串），供标题页排“继续进度” |
| `xjh.mute` | `'1'` 静音 / `'0'` 有声 |
| `bui.theme` | 战斗界面主题 `'ink'`（墨迹题签）/`'scroll'`（卷轴木牌） |

`<id>` 生成：`Date.now().toString(36) + '-' + Math.random().toString(36).slice(2,10)`（如 `mhh2k3p0-4fa9x1qz`），若该键已存在则重生成。旅程键用前缀 `xjh.qihe-prologue.v2.run.`，手动存档用 `xjh.qihe-prologue.v2.slot.`。

（评审入口另有 `*.review.*` 键，忽略。非栖河入口回落键 `xjh.save` 已不可达。）

### 当前旅程的确定（`saveKey()`）
正式入口下 `saveKey() = qiheJourneySaveKey(qiheJourneyId())`：URL 查询参数 `journey=<id>` 合法则用 `...v2.run.<id>`，否则用 `xjh.qihe-prologue.v2`。即“当前在玩哪条旅程”由启动参数决定，整个运行期不变。Godot：用一个全局 `current_journey_key`，在标题页选择后设定，切换旅程时重新进入游戏场景（原版通过整页跳转实现，见 03）。

## 2. 存档数据格式

值为整个全局状态对象 `S` 的 `JSON.stringify`。顶层由 `newState()` 起步：

```
name:'无名'→栖河开局改为'萧白', origin:'orphan', lv:1, exp:0, pts:0,
st:{str:3,con:3,agi:3,wil:3,wis:3}, moral:10, hp, mp, silver:0, atkBonus:0, mpBonus:0,
skills:{fist:1}, weapon:null, armor:null, bag:{bun:2}, party:[], pet:null, pets:{}, flags:{},
scene:'temple'→栖河改为'prologue_backhill', x, y, unlocked:{}
```

栖河版关键子对象：`prologue`（`version:2`，必需）、`qiheChapter`（含 `stage`）、`cultivation`、`mates`、`qiheSave`（元数据）等，各系统另册。**本册只依赖：** `prologue.version===2`、`scene`（必须是已注册场景 id）、`x`/`y`（像素坐标）、`qiheSave`。

`qiheSave` 元数据：
```
{ name?: string(1~24字),   // 手动命名；无则按规则显示
  createdAt?: ISO字符串,     // 仅手动存档创建时写
  savedAt: ISO字符串,        // 每次写入刷新
  archivedAt?: ISO字符串 }   // 存在即“在回收站”
```

**有效性判定**（`valid`/`read`）：`s.prologue.version===2 && SC[s.scene]` 存在。标题页额外要求 `!s.qiheSave.archivedAt`。

**读入归一化** `normalizeCharacterLevel`：等级上限 `CHARACTER_LEVEL_CAP=100`；若 `lv>100`，写 `levelCapMigration={previousLevel,previousExp,cap:100}`（仅首次），`lv=100`；`lv>=100` 时 `exp=0`。

## 3. 写档函数（core.js）

`persistState(s)`：
1. 若有 `SharedInsightPool`，先 `sync(s)` 得到“江湖历练”发放列表。
2. `normal = 正式入口 && 键==当前旅程键 && s.prologue.version===2`；normal 时 `s.qiheSave = {...s.qiheSave, savedAt: now ISO}`。
3. `localStorage.setItem(saveKey(), JSON.stringify(s))`（失败抛异常）。
4. 成功后 `showSaveWarning(null)` 撤下警示（见 06）。
5. 若有历练发放：`toast('江湖历练 +' + 总量 + ' · 可在队伍中分配', 2400)`。
6. normal 时再写 `xjh.qihe-prologue.latest.v1 = 键`（失败忽略）。

`save()`：`try persistState(S) catch → console.error + showSaveWarning(e)`——自动存档失败不弹窗，只挂常驻警示。

`loadSave()`：读当前键 → `JSON.parse` → `normalizeCharacterLevel`；任何异常返回 `null`。

## 4. 自动存档时机（全部调用 `save()`）

| 时机 | 位置 |
|---|---|
| **每 5000ms 定时**：`setInterval(()=>{ if(S && mode==='scene' && !busy) save() }, 5000)` | main.js 末行 |
| 切换场景：`goScene` 的黑场回调内，放好主角坐标后 `S.x=tx;S.y=ty;save()`（即黑场全黑期间） | scene.js `goScene` |
| 开局/读档进入后：`start()` 末尾 `checkpoint()` | qihe-map-trial.js |
| 剧情 `checkpoint`：`S.x=player.x;S.y=player.y;save();hud()`；ink 剧本外部函数 `checkpoint` 同 | qihe-map-trial.js、story-runtime.js |
| 剧情战斗结束恢复后 | qihe-chapter.js |
| 其余剧情节点、商店、宠物、偷取、宝物等系统内显式 `save()` | 各系统文件（各系统册列） |

条件：定时存档只在自由探索（`mode==='scene'` 且非 busy）时写；剧情和战斗中不写，避免存到中间态。

## 5. 手动存档命令（qihe-saves.js `QiheSaves.command(type,...args)`）

统一返回 `{ok:true, message, navigating?, key?}` 或 `{ok:false, reason:'操作未完成：'+原因}`；`QuotaExceededError` 原因文案为“本地存储空间不足，请释放空间后重试”，无消息时“浏览器无法保存，请重试”。失败绝不跳转。

前置检查 `writable()`（除 list 外都先调）：
- 当前键必须是旅程键且为正式入口，否则“评审入口不能修改正式存档，请从首页进入游戏”。
- `S` 有效，否则“当前进度尚未就绪”。
- `mode ∈ {scene, menu, panel}`；若 `busy` 且 mode 非 menu/panel，或 `dlgBusy` → “当前剧情或战斗进行中，请结束后再操作”。

| 命令 | 行为 | 成功文案 |
|---|---|---|
| `save` | 深拷贝 S → `persistState` → `S=拷贝` | 已保存当前进度 |
| `create(name)` | 名称 trim 后 1~24 字（否则“请输入1至24字的存档名称”）；深拷贝 S，`qiheSave={name,createdAt:now,savedAt:now}`，写入新 `slot` 键；当前旅程不变 | 新存档已保存，原进度保留 |
| `rename(key,name)` | 改 `qiheSave.name`；若是当前旅程同时更新 S | 存档已重命名 |
| `archive(key,restore)` | 当前旅程不可（“当前旅程不能移入回收站”）；写/删 `qiheSave.archivedAt` | 已移入回收站，可随时恢复 / 存档已恢复 |
| `load(key)` | 在回收站则拒绝（“请先在回收站恢复这份存档”）；是当前旅程则返回“正在游玩此旅程”；否则先 `save` 当前，再：若是手动存档，**复制为新旅程** `...v2.run.<新id>`，`qiheSave={name: 原名前19字+' · 续玩', savedAt:now}`；然后跳转进入目标旅程（03 §4） | 正在载入存档 |
| `home` | `save` 后跳回标题页（URL 无 `play=1`） | 进度已保存，返回首页 |

**存档列表 `list()`**：遍历所有有效旅程/手动键；读取失败的行标 `invalid`。排序：当前旅程第一 → `savedAt` 新到旧 → 键名字典序。显示名 `label`：`qiheSave.name` ‖ 原始键“原有旅程” ‖ 手动键“手动存档” ‖ `'旅程 '+id前8位`。

手动存档原件不可被游玩覆盖：载入手动存档总是另开一条旅程。

## 6. 存档界面入口（qihe-jianghu-ui.js，设置页 `sysPage`）

设置页“行路与声画”网格按钮：声音（已静音/已开启）、战斗界面、**快速保存**（命令 `save`，成功 notify“已保存当前进度”）、**存档管理**、**返回首页**（确认框“保存当前进度并返回首页？之后可选择继续进度。”）、操作说明。

存档管理（`saveManager`）：说明“手动存档保留当前节点，载入后另开旅程继续。存档保存在本机浏览器。”；工具条【存档】【回收站】【新建存档(主)】；每行：名称（当前行加 `<small>当前</small>`）、`QiheEntry.description(state)`（损坏行“记录损坏，原件已保留”）、“手动存档/自动进度 · 时间”（`toLocaleString('zh-CN',{hour12:false})`，无时间“旧存档，时间未记录”）；按钮：非当前【载入】（确认“保存当前进度并载入这份存档？手动存档原件会保留。”）、【重命名】、非当前【移入回收站】（确认“将这份存档移入回收站？可随时在回收站恢复。”）；回收站视图只有【恢复】。空列表：“暂无存档，可新建保存当前进度”/“回收站为空”。新建/重命名表单：输入框 maxlength 24，占位“例如：入谷前”。

行程面板（`journal`，J 键或 HUD“当前行程”）：`choose('行程', 文本, ['继续游玩','保存进度','从头重新开始'])`；选“保存进度”→`checkpoint()` + `toast('进度已保存',1200)`；选“从头重新开始”再确认 `['保留进度','重新开始']`，选后者 `S=null; localStorage.removeItem(当前键); start(true)`（只清当前这条旅程）。
