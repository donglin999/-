# 16 规则：门派与声誉的结算逻辑

源文件：`js/qihe-jianghu-rep.js`（`QiheJianghu`）。数据表见 15，界面见 17。

## 5 存档 `S.jianghu`（`ensure()`）
```
{ver:2, fame:0,                                   // 全部 clamp 到 [-100,100] 并取整
 faction:{<fid>:{score:0, met:false, hostile:false, greetSeg:null, mendSeg:null}},
 bossHit:{'<fid>:<seg>': '<seg>'}, fameOnce:{'<type>:<npcId>': true},
 log:[{seg, kind:'faction'|'fame', id, delta, reason, npc}]}   // slice(-60)，只留最近 60 条
```
- 旧档迁移：`ver < 2` 且 fame 为空时，`fame = clamp(xia − e)`，然后写入 `ver = 2`。
- `seg() = S.segmentId || S.prologue.segment || S.scene || 'kaishi'`；`part() = S.prologue.part || S.part || 'kaishi'`。
- `clamp` 一律先 `Math.round`。`log` 中 delta 为 0 的不记。

## 6 核心函数（rep.js）
- `boundForFaction(id) = [max(lim[0], floor ?? −100), lim[1]]`，其中 `lim = PART_LIMITS[part].faction`。
- `applyFaction(id, delta, reason, npc)`：`score = clamp(score+delta, bound)`；`met = true`；`hostile = score ≤ −11`；按实际变化量写 log 并返回该变化量。
- `applyFame(delta, ...)`：按 `PART_LIMITS[part].fame` 夹住。
- `fold(npcId, delta)`：成员不存在、faction 为空、或 hidden 且未揭示时返回 0。`w = RANK_WEIGHT[rank] || 10`，`abs = |delta|/w`。正向且 abs < 1 时返回 0；否则 `n = sign × round(abs)`，负向算出 0 时取 −1。例：minor 被 −5 时得 −1；member 被 +15 时得 +2（round 1.5）。
- `implicate(npcId, delta, reason, once)`：主事 `boss = MEMBERS[npc].boss`；该字段 undefined 时取 `FACTIONS[faction].boss`，为空则不牵连。扣分落在**该成员自己的门派**上，log 里的 npc 记为主事。`once='segment'`：键为 `fid:seg`，同一段内只扣一次。
- `amountOf(spec, payload)`：数字直接用；`{from:k}` 取 `payload[k]`；`{by:k, map}` 取 `Number(map[String(payload[k])]) || 0`。**因此 bond 事件的牵连扣分**：reason 为 hostile_win 时 −3；steal_caught / steal_caught_kin / implicated 为 0；**其他 reason（gift、amends 等）查表得 undefined，结果为 0，不牵连**。`IMPLICATE_DEFAULT = −3` 虽然导出了，但原版没有用到（一比一移植时照此处理）。
- `stage(fid)` 返回 `{id, name, score, hostile, met}`（用 STAGES.find 取第一个 `score ≥ min` 的档）；`fameLevel()` 返回 `{id, name, score, abs}`。
- `on(type, fn)` / `emit(type, payload)`：简易事件总线。

## 7 事件结算 `settle(type, payload)` → EVENT_RULES（data）
| type | 规则（按顺序执行） |
|---|---|
| steal_caught | `fame`：`victimIsVillain` 为 true 时 −1，false 时 −2 |
| hostile_start | `faction`（成员门派）−5；`fame`：byPlayer 为 true 时 −3，否则 0 |
| hostile_win | `bond`：emit `bond_change {npcId, delta:−10, reason:'hostile_win'}`，由个人关系模块接收后再回到 bond 结算；`fame`：byPlayer 为 true 时 0，false 时 +1 |
| spar_first_win | `fame +1`，`once:'npc'`，键 `fameOnce['spar_first_win:'+npcId]` |
| bond {npcId, delta, reason} | `fold(delta)`；`implicate(IMPLICATE[reason])`，once segment |
| mend_paid {faction} | `factionSet` 设为 −10（delta = −10 − 当前分，仍受边界约束） |
| story {faction:{fid:n}, fame} | `factionMany` 逐个 applyFaction；`fame` 加 payload.fame |

payload 的人物键为 `npcId`（或 `id`）。没有对应规则时返回 `{ok:false, changed:0}`，否则返回 `{ok:true, changed, jianghu}`。模块加载时会注册 `on('steal_caught', p => settle('steal_caught', p))`。

`notify(fresh, before, fameBefore)`：把本次新增的 log 按势力合并（声誉合成一条 'fame'）；delta 为 0 的去掉。每行为 `{glyph:'名'或势力印字, name:'声誉'或势力名, delta, reason:REASON_TEXT, cross:'升至X'/'落入X'/'' , color:'#3a3a32'或势力色}`。有 `QiheJianghuSlips` 时调用 `.slips(rows)`（右上角纸签）；否则只把最后一行 toast 为 `"名 ±n · 原因"`，持续 2100ms。

## 8 对外查询（npc-core / 商店调用）
- `gate(npcId, act)` → `{ok, why}`，act ∈ trade/teach/spar/ask。不是成员时 ok。先查门派档：`GATE[档][act]` 有值就返回 `{ok:false, why}`。再查个人关系分（取 `S.bond[id] ?? S.qiheBond[id]`，可以是数字或带 `.score` 的对象）：≤ −50 为 `'bond_hostile'`，≤ −20 为 `'bond_hate'`。npc-core 会忽略以 `bond_` 开头的原因（见 06）。遇到 `faction_*` 时灰印，并播放 `npc_<id>_faction_no`。
- `priceMul(npcId)`：候选值为门派 GATE.priceMul、个人项（≤ −20 为 1.1，≥ 80 为 0.85，≥ 50 为 0.9）、FAME_GATE.priceMul，取其中有限数的 **最大值**；一个都没有时返回 null（调用方当 1 处理）。所以只要有一项涨价就是 1.1；全是折扣时取折扣最小的那项。
- `firstMeet(npcId) = clamp(GATE.firstMeet + FAME_GATE.firstMeet, −10, 10)`。
- FAME_GATE.e3 的 `flee` 只是数据标记，rep.js 里没有读取它的函数。
- 导出：`window.QiheJianghu = {settle, stage, fameLevel, gate, priceMul, firstMeet, on, emit, migrate, ensure}`。
