# 19 闲话与交情（同伴之间）

源文件：`js/qihe-banter.js`（`window.QiheBanter`，也支持 Node 的 `module.exports`）。**栖河试玩版没有接入任何显示入口**：闲话只会出现在汉皋城（hangao）和大地图自由模式（worldmap）里，这两处尚未制作，培养模式不用。本模块只提供规则和数据；唯一的运行时副作用是包装 `battle` 来记交情。Godot 移植时应把数据与接口做齐，界面留给后续场景接入。

## 1 常量
- `NAMES = {hero:'萧白', ye:'叶蘅', yinhongying:'殷红缨'}`：只收可入队人物。
- `REL = {ye:'ye', yinhongying:'yin'}`：萧白与此人的关系分读自 `world.cultivation.relations[REL[id]].score`，缺省为 0（`relation()`）。
- `STAGES = [{at:0,'生分'}, {at:6,'相熟'}, {at:18,'知己'}]`，阶段下标依次为 0/1/2。

## 2 交情（独立于萧白与各人的关系）
- 存档 `world.kinship['a|b'] = 场数`，键为两人 id 排序后用“|”连接（`pairKey`），例如 `'ye|yinhongying'`、`'hero|ye'`。world 即全局 `S`。
- `fought(world, opt, result)`：`world` 为空、`opt.solo`、`opt.tutorial`、`opt.storyLesson`、或 `result === 'flee'` 时返回 0；否则取 `world.party` 中在 NAMES 里的成员，两两各 +1（赢、输都算），返回记了几对。
- `kinship(world, a, b)` → `{battles, stage, name, next}`，next 为下一档所需场数，到顶时为 null。
- 接线：加载时如果 `window.battle` 是函数且没有 `__banter` 标记，就包一层 async：`r = await base(opt)`，然后 `fought(S, opt, r)`（出错时只 console.error），原样返回 r，并给包装函数打上 `__banter = true`。Godot 中等价做法是在战斗结束的信号里调用 `fought`，不改变战斗返回值。

## 4 接口
- `blocked(world, b, venue)`：返回空串表示可以出现，否则按以下顺序返回第一个原因：“地方不对”（venue 不在 venues 中）、“人不在”（非 hero 的一方不在 `world.party` 里）、“已出现过”（`banter.offered[id]` 已有值）、“交情未到”、“关系未到”（取 pair 中非 hero 的那一位）、“事情还没发生”、“萧白未满十八”。
- `due(world, venue)`：返回 list 中第一条不被挡住的，没有则为 null（此时不显示任何提示）。
- `offer(world, b)`：`world.banter ||= {offered:{}, seen:{}}`；第一次出现时记 `offered[id] = 已出现条数 + 1`，作为出现顺序。
- `finish(world, id)`：id 不存在时抛出“没有这条闲话。”；还没出现过时抛出“这条闲话还没出现过。”；否则记 `seen[id] = true`。
- `book(world)`：闲话册，按 offered 顺序列出 `{id, title, names:[中文名], read}`。
- `script(id)` → `{id, title, cast:pair, lines}`。
- `prompt(b)`：pair[0] 为 hero 时显示“<对方>有话跟你说”，否则显示“<A>和<B>在说话”（如“叶蘅和殷红缨在说话”）。
- 导出：`{list, NAMES, STAGES, fought, kinship, relation, blocked, due, offer, finish, book, script, prompt}`。
