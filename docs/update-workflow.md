# 每次更新的文档核对流程

状态：现行　最后核对：2026-10-19

## 更新前

核对工作区和运行 URL → 用户确认方案 → 负责该事实的设计页 → 当前实现 → 正式素材登记。当前栖河入口为 8792 的 #qihe-map / #prologue，中央四向地图为 m_qh_central。8137 的临时 4K 入口、兄弟工作区 opening-v4、封闭原版都不能作为本版本正式来源。

文档状态必须标明：目标设计、当前实现、待审候选或历史弃用。实际浏览器引用与文档冲突时先定位差异，不允许仅为了让检查通过而更新清单。

## 更新中

新设计先改负责它的设计页；代码、采用素材和当前实现记录随后同步。素材采用记录必须包含 ID、系统、正式路径、原件路径、参考图、实际尺寸、哈希、生成方式、验收结果与证据。来源、生成尺寸和线上状态不得凭提示词或计划填写。

正式清单与加载映射由整理工具生成；已有清单时默认禁止重新入库，只有确认设计和验收记录之后才使用 --adopt-reviewed。它表示本轮明确采用，不是免验收开关。

## 更新后

```bash
python3 tools_assets/check_production.py
```

检查正式资源存在性、哈希、解码、清单与 Markdown 登记、运行映射一致性，以及当前确认中央图。涉及地图须核对世界尺寸、碰撞、入口和前景；涉及人物须核对脚点、动作、尺寸与速度；涉及 UI 须核对物品/技能覆盖、悬停和操作。测试范围按本次风险选取，未经验证的项明确写待验。

构建脚本在清理 dist 前运行上述检查；失败会阻止构建。此检查不能自动判断所有美术和剧情质量，仍须人工核对负责文档。

## 每轮记录模板

保存为 docs/updates/YYYY-MM-DD-主题.md：

- 用户需求与已确认方案：
- 工作区、运行入口：
- 核对的设计页和正式素材条目：
- 实际修改与文档同步：
- 采用、替换、弃用及原因：
- 验证命令、结果、证据；未执行或失败项：
- 剩余事项：
- 本地完成 / Git 提交 / 线上发布：分别记录。
