# 文档书阁：查看与评审

状态：现行　最后核对：2026-10-19

统一入口：启动本地服务后访问 [文档书阁](http://127.0.0.1:8794/review/docs/)。

## 启动

在 `xiaojianghu` 项目目录执行：

```bash
python3 tools_docs/server.py
```

需要 Python 3.9 或更新版本，无须安装 Python 包或执行前端构建。浏览器使用的 Markdown 解析和清理库已随页面保存在 `review/docs/vendor/`，不依赖运行时 CDN。版本、来源、完整性摘要和许可随库保留。

端口被占用时可用 `python3 tools_docs/server.py --port 8795`，然后访问相应端口。终端关闭或服务退出后，再次运行即可恢复访问。不要用普通 `python -m http.server` 代替：评审保存需要此服务的接口。

## 收录范围与阅读

- 项目根目录的 Markdown，以及 `docs/`、`art_sources/`、`review/` 内全部非隐藏 Markdown；`docs/` 下 JSON、CSV 也纳入机器数据查阅。代码、密钥、生成任务日志和原始大图不作为文档收录。
- 首页默认进入 **游戏 Wiki**，查阅世界、人物、门派、章节、玩法、武学装备和地点设定；**开发文档**独立提供实现、数值标定、美术制作、地图生产、音频接入、测试交付、调研、机器数据与归档。
- 两个空间拥有独立首页、分类、统计、最近更新、收藏列表与待评审列表。顶部/侧栏可随时切换，人物图鉴也提供返回两个空间的入口。
- 原文保持原目录结构，不复制或改写设定。旧深链按文档实际所属空间打开，跨空间正文链接标注目标空间，仍共享同一篇文档的评审历史。
- 顶部搜索覆盖标题、正文与路径，多关键词以空格分隔，要求全部命中；默认只搜索当前空间；列表中可显式选择“全部空间”。列表可按评审状态、文件类型和更新时间筛选排序。
- 文档内的相对文档链接在书阁内打开，图片按原文所在目录解析；外部参考和演示网页另开页面。右侧提供文内目录与引用本篇的文档。
- 新增、移动或修改文件后点击“刷新目录”，也可刷新浏览器。文件更新时间来自本机文件系统，不代表设定确认时间。
- 收藏仅保存在当前浏览器。文档链接可以复制；“打印 / PDF”使用浏览器打印，隐藏导航和评审侧栏。

## 评审流程

1. 打开文档，选择“待评审”“需修改”或“已通过”，按需填写意见。
2. 点击“保存评审”后，结论、意见、时间与原文 SHA-256 版本一起保存。
3. 原文变化后，网站显示“原文已更新”，并放回待评审队列；旧意见保留历史版本标记。
4. 看完新版后再次提交评审。旧文档页面提交、多个页面同时覆盖评审都会被拒绝，并保留输入草稿；先刷新再提交。
5. “导出评审”下载全部结论、历史意见和当前原文版本，方便备份或交给 AI 整理修改清单。

**评审通过不等于设定已经用户确认，也不等于代码完成或测试通过。** 初次收录全部为待评审；不会根据正文里出现的“通过”自动批准。

未提交的意见草稿暂存在当前浏览器，已提交的记录保存在项目 `.doc-review/reviews.json`，每次保存保留上一版 `reviews.backup.json`。它们已加入 Git 忽略，不随源码提交。要换设备迁移评审，可以停服后把导出的 JSON 保存为新设备项目的 `.doc-review/reviews.json`，再启动服务；保留原有文件备份，且不要在服务运行时替换。

本版为单人本机评审工作台，只监听 `127.0.0.1`，链接不能直接从其他设备访问。把项目复制到其他设备后可在那里运行同一命令。多人登录、云端同步、原文网页编辑不在本版实现范围。

## 开发与维护

| 文件 | 用途 |
| --- | --- |
| [server.py](../tools_docs/server.py) | 标准库服务、实时索引、分类、评审保存与版本冲突校验 |
| [index.html](../review/docs/index.html) | 页面入口 |
| [app.js](../review/docs/app.js) | 全文搜索、渲染、跳转、收藏与评审交互 |
| [style.css](../review/docs/style.css) | 桌面、窄屏与打印样式 |
| [vendor 版本](../review/docs/vendor/versions.json) | 本地 Markdown 解析库和 HTML 清理库 |

评审接口 `GET /api/docs`、`GET /api/reviews`、`GET /api/export`、`POST /api/review`。写入要求同源 JSON 请求，同时验证原文版本和评审记录版本；临时文件和目标文件在同目录原子替换。Wiki 主要设定清单在 `tools_docs/wiki-sections.json` 中维护；门派介绍与人物正文按专用目录收录，但素材卡、衣装修正放入开发空间。新增其他文档默认进入开发空间，确认用于设定阅读后再加入清单；修改分类清单或分类规则后重启服务。分类规则在 `classification()` / `category()` 中维护，历史地图方案优先遵循现有 `map-document-status.json`；其他有混合状态的文档保持原文说明，不自动判定实装程度。

自动化检查：

```bash
python3 tests/document-library.test.py
node tests/document-library-browser.test.cjs
```

后者使用项目既有的 Playwright 运行环境，可以通过 `PLAYWRIGHT_PATH` 和 `CHROMIUM_PATH` 指定安装位置。测试启动独立端口，并使用临时目录保存评审，避免产生假的正式评审结论。
