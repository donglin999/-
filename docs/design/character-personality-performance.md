# 人设驱动的对白动作验收

状态：现行　最后核对：2026-10-19（原记：2026-10-05整改规范。适用于[当前可加入人类名册](companions.md)，每人6张完整状态；本页补充并修正[六张对白状态规范](companion-performance.md)中可能导致动作同质化的通用例子。[逐图动作设计与去留](../../art_sources/companion_personality_revision_20261005/action-design.json)是本轮执行依据。人数扩展时由图鉴当前`companion`名册决定检查范围，不固化为17人或102张。）

## 为什么不能再用一套情绪动作

旧生成器给全部角色套同一段担忧和惊讶身体描述，愤怒又沿用共同的设界手势。只换名字、道具和眉眼，最终仍像同一个人轮流穿不同衣服。旧的分辨率、alpha、预览切图通过记录不能证明这次的人物表现通过。

情绪是反应的起点。画身体前先确定**她在意什么、如何面对别人、此刻正在做什么**，再安排双手、肩身、头向、目光与重心。同为愤怒，可能是压住医案、收回图册、握紧绑带、合扇护人、停下修械；同为惊讶，可能是停笔复核、停下弹奏、松开工具、转身追问。推掌和手贴胸只是具体人物在具体语境下的一种选择。

不规定所有伤心都必须缩肩低头，所有惊讶都必须后仰贴胸，所有愤怒都必须推掌。冷静压住怒气、强撑悲伤、好奇追问同样可以成立；脸、身体、道具和台词须共同表达明确意图。对白图保持当前身份、画风和服装，不为了多动作换成战斗连招。

## 琵琶与所有随身道具的硬门槛

柳含烟六张均需说清并看清**谁承重、在哪接触、怎样固定**。本轮优先采用手持或抱持：一只手稳定琴颈或侧缘，另一只手或前臂承托琴身底部；手指、衣袖、琴身与琴颈的遮挡关系连续。如果一手离开，剩余手臂必须能实际承重，不能让琴身凭空贴着躯干悬浮。

本轮不复用无固定的背负琴造型。未来确需携琴时，须另设计琴袋／支架、完整肩带、可见连接点和受力方向，并作为新携行状态验收；不能补一句“背上琴”就当解决。琵琶的职业身份不意味着每个姿态都在弹琴，也不能在换图时无因出现或消失。

其他人物同样逐图检查：长棍／篙的两端、握点和倾斜方向；刀剑与腰带固定；图册／账夹的底部承托；工具与腰套连接；花扇与指节握持。头发、衣褶、轻纱不得代替绑带，手穿过物件、漂浮、断接或琴颈错位直接退回。

## 必须同时看单人与同情绪横排

1. **单人六图**：浅底和深底看全身，再以实际对白大小切换。检查与常态相比，手臂轮廓、头／肩身方向、重心至少两类有可读变化；每张脸与身体一致；服装、骨相、道具稳定。若差异主要来自表情，退回重画。
2. **同情绪跨人物**：至少将当前名册全员的愤怒、惊讶、担忧各做一张横向联系图，全身都可见。逐人读出其行动意图，再遮住人物名字比较手臂、肩线、躯干与道具受力；大多数人仍是推掌、手贴胸或同一双手收腰姿态时，不能以换道具算区分完成。开心与常态也建议横排抽查。
3. **记录结论**：每张保留当前原生图hash、本人逐图理由与实际证据；跨人物联系图记录涉及的全部状态ID及各自原生hash。重生成后旧证据不自动沿用。机器统计仅发现动作家族重复，图片本身仍由看图验收。

`semantic_family`记录实际动作家族，例如收图拒绝、压夹据理、收扇护人，不用“愤怒_角色名”制造虚假的102种动作。检查器允许少量自然共享：常态同一家族最多5人，其他同名状态最多3人；这不是人数内自动合格，最终还要通过横排看图。不能用改动作家族标签掩盖相同图片剪影。

## 新生成与旧图留用分别记录

本轮[开工前图像与调用提示词hash](../../art_sources/companion_personality_revision_20261005/baseline-native-sha256.json)固定开工时17人的102张旧图，逐图设计填写`retain`或`regenerate`及看图理由。之后新增人物没有旧图可留用，六张均须真实生成并复审。

- **重生成**：当前原生hash须区别旧图；当前`generation`须对应真实工具输出、输入路径与`actual_prompt_file`。实际调用必须含本人该情绪的新身体描述。合法改写或翻译允许人工逐项语义核对，须绑定调用文本hash和身体描述hash，不能只更新文档而沿用旧提示词生成。
- **留用**：图片及原调用提示词均维持原hash，单独进行本轮逐图复审。记录为什么这张旧图已经体现本人行动、情绪与道具承重；不可宣称它用本轮新提示词生成，也不可用一段“全都符合”的结论批量通过。
- **未完成**：新动作只写进文档、替换仍指向旧图、未看图、新原生未导出、跨人物联系图没复审均记录`pending`。旧六项质量门槛曾通过不能改成此次人设整改已通过。

当前manifest每张采用`personality_revision`记录修订ID、设计hash、决策、本轮结果、逐图理由、证据及被看图的原生hash。柳含烟额外有`prop_support_review`。跨人物记录用`personality_comparison_reviews`，与本轮三张联系图绑定。工具只核查这些声明与真实文件的对应关系，不自动判断人物是否好看。

## 检查命令

在项目根目录运行：

```bash
python3 tools_story/check_personality_states.py
python3 tools_story/check_personality_states.py --require-complete
python3 tools_story/check_dialogue_states.py --require-complete
```

第一条允许真实制作中的`pending`并输出差异；第二条要求当前名单每人六张的本轮复审、真实替换／留用来源与三组联系图全部完成；第三条继续检查原生、alpha、导出与既有结构门槛。报告为[本轮人设验收](../../art_sources/companion_personality_revision_20261005/personality-contract-check.json)。图像接受、用户定妆、预览和游戏台词绑定仍分别记录，不能互相替代。

需要程序合入设计hash时：`python3 tools_story/check_personality_states.py --print-design-digests`。合理改写的`prompt_alignment`取`method: manual_semantic_review`、`result: passed`、逐项解释、`prompt_sha256`和`body_sha256`，两项文本hash按实际UTF-8内容计算，不从文件名猜测。
