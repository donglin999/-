## 四个共用适配

| 适配 | 要解决的事 | 复用与新增范围 | 持久状态和不能混淆的结果 |
| --- | --- | --- | --- |
| A1 版本化故事事件与提交 | 同一事件可以从不同入口抵达，选择、任务奖励、关系、地图变化只提交一次，读档可续接。 | 复用 `qihe-chapter.js` 内部 `event()`、培养 `pending/result` 和 `persistState` 的模式，提取稳定事件 ID、条件读取、结果提交、奖励 ID 与迁移；对白播放器与培养数值仍用现有系统。 | 保存 `version/eventId/stage/choiceId/outcome/participants/claimedRewards`，不保存函数/DOM。阶段区分可重放演出与已提交结果；技术异常记 `aborted`，不得变成战败、死亡或背约。 |
| A2 任务同行与人物在场 | 借用向导、护送人、临时盟友与玩家现有编队可以共存，任务结束不会永久招募或吞掉原队友。 | 复用守路战自定义双方、小豆临时入场及名册 `availability`；增加任务队伍槽、实际参战名单、场景出席与返回位置。主角+三同伴的正常出战上限保持现行值；超额人物在场外承担任务或由玩家换位。 | `present`、`invited`、`remote`、`battleParticipants` 分开；大型棺/船/被护者作为任务实体，便携证物记录实际持有人与用途。结束、取消、失败、异常、重载都恢复原编成；不得把临时成员写进永久名册。 |
| A3 战斗目标与统一结果 | 支持击败指定人、守住若干回合、护住对象、试招后停手、破坏机关目标，真实战斗仍由现有战斗引擎结算。 | 从归云收招考校抽出目标检查钩子，复用 `battleLoop/endCheck` 与 `storyLesson`；在行动后/回合末按明示时点检查目标，提供任务指令或可攻击目标，不新增战棋移动。 | 返回 `win/lose/flee/stopped/aborted` 加 `objectiveResult`。`noLose`不是必胜。非全灭完成不能照搬“全部敌人的经验/掉落”；任务奖统一交 A1，普通掉落只按具体合同发放。 |

接口名与字段是建议合同，编码时结合现有全局脚本结构确定；不要求为一次剧情重写整个引擎。表中 `win/lose/flee/stopped` 是现有播放器返回值，持久化时按战斗目标负责合同映射成 `success/failure/withdrawn/aborted` 并保存 `reasonCode`；`stopped`由该场明示目标判定，不一律等于胜利。四个适配逐个接入并保留原有事件路径，不能全局覆盖 `endCheck` 后让旧收招考校、裴知古技能或旁观战失效。

### 共用结果与恢复规则

1. **成功**：先形成唯一结果，再在同一次保存中提交事实、奖励与下一入口。过场播放可重放，已交任务货、已加入的人和已领道具不会再次发放。
2. **失败或逃跑**：保留已经交付、救下、损坏或承诺过的事实，落在写明的补给/接应点；提供重试、换路线或接受有代价结果中的实际可行项。失败不自动清空整条地区链。
3. **暂停或取消**：未确认有代价的选择不扣物、不推进时间。行动开始后暂停保存最近检查点，继续从该点恢复；首版不承诺恢复到战斗中间某一帧或回合。
4. **战斗/脚本异常**：恢复任务开战前快照，保留异常前已提交事件，显示可重试状态，不写入人物战败。现有培养 `runFight` 把非胜结果映射败对白的实现不能直接复制到新章节。
5. **复看**：从行记进入时读取已提交的出席与选择，只播演出；不调战斗结算，不重新判路线，不重复改变关系。
6. **旧档**：当前汉皋南门完成档迁移为新内容入口，不重发出谷奖励；未知新版本/迁移失败保留原记录。新场景未登记前不能保存它的 ID。

### 玩法保留的首版形式

| 玩法 | 玩家确实要操作的部分 | 结果如何留下 |
| --- | --- | --- |
| 短追逐 | 在一张局部街巷/码头图走至目击点，调查两条路的线索，选拦截出口，处理阻挡或短战；走错后仍能去下一接触点。 | 先到/晚到、保护/丢失的具体物、是否动手和实际目击者；不凭按一次“追上去”自动算全胜。 |
| 潜入 | 调查守卫/通道，取得口令、钥匙或同伴帮助，走合法准备路线；未满足条件进入受限节点才触发发现/盘问/战斗。 | 取得证据、惊动谁、是否伤人、撤退入口；“潜入成功”不等于自动打开整片地区。 |
| 运棺/护送 | 起运清点，分段道路/渡船交接，检查绳索与落脚点，挡袭/守护/选择改道，送到指定收棺人。 | 棺及遗物完整度、护送参与者、承诺兑现、延误和被扣物；逝者不作为可控单位或战利品。 |
| 江上/海上交战 | 船上调查与准备，甲板固定回合战，可用 A3 守舵/断绳/护住登船点，胜后选靠岸与人员交接。 | 船能否行、谁被救、谁控制渡头、货/棺是否仍在；不把击败所有杂兵作为每场唯一目标。 |
| 独立比武 | 听清比法和后果，配装后真实单挑/目标考校，可认输、再练后重赛；首次完成与重赛分离。 | 名次/指点/彩头/人物认识各自记录；比武支线不能替玩家完成与其无关的主线查案。 |

### 首个可开发切片：P2-02正式入城/返谷 → P2-03《阿七来访》

首片分两阶段：先从当前8792汉皋南门完成档接通P2-02的最小必达城市事件与正式返谷，再在合法来访窗口进入P2-03。第一阶段负责验证新城市路由、真实步行与返谷保存；第二阶段负责验证人物伏笔、陪练与回到日常。两阶段连通后才是一段完整可交付的玩家路径。

**第一阶段 P2-02 最小城市链**：南门交接→城街亲见病人服用青蚨散后仍恶化→医馆与苏芷检查并对照现售药样→药铺/后仓实地调查及拦路小队战→回医馆交接救治、确认本批假药供货中断→南门确认返谷。只处理这一批药与眼前受害者，不在此完成整个叶家身世。旧汉皋/襄阳事件 ID 需通过主稿迁移表映射，不把旧原型完成旗标全部复制进正式档。

## 资源估算口径

地图按**可进入的独立空间**计数，室内、室外、楼层分开；同空间的夜色、管制、失火、任务道具为状态层，不默认为一张新整图。固定战斗背景、静态据点背景与 CG 另列。旧方案的 24 张图是旧范围估算，不是新故事的预算上限。

人物按**人物 ID × 出场阶段 × 实际职责**估算：仅固定对白的普通 NPC 不派全套大立绘；可招募者按 [角色类型与必需素材](../role-assets.md)补同伴阶段包；重要 NPC 只要参加切磋/临时援助/敌对战就有相应战斗包。冒名身份仍是同一个人，是否换装另列阶段，不重复造脸；已故人物以棺、遗物、回忆或画像表达，不能默认需要活人全套战斗资产。

“可复用”必须逐项核对正式素材清单、身份、衣装和当前动作映射；本表仅是故事反推需求，不把候选图和旧原型计作正式可用量。地图仍执行 [现行地图规范](../map-development-standard.md)，所有普攻/功法仍执行 [当前表现边界](../combat-presentation-boundary.md)。
