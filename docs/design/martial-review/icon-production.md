## 每件完整流程

1. 从清单锁定ID、品阶、用途、独有轮廓和色彩；不得为适配图片修改机制。
2. 以五档模板生成完整提示词，追加本件执行构图与参考角色；先保存到本批 `prompts.json`，生成后不回写历史提示词。
3. 使用内置 `image_gen`，一件一次调用，`transparent_background=true`；请求1024方图。实际输出大小另记，不能把请求值当实际值。未返回模型名时记录null，不宣称固定某型号。
4. 完成即复制原稿到项目 `art_sources/martial_icons_full_v1/`，使用 `icon_<id>-v1.png` 和单件JSON回执；默认生成目录原件保留。
5. `archive_martial_icon.py ID SOURCE` 测尺寸、RGBA、透明像素、alpha>16包围盒、安全边和SHA-256。不得覆盖不同图片；返修新建v2，并记录替代关系。
6. 人工查看主体、用途、同阶丰富度、轮廓差异、文字残片、裁切。网站提供按门派／种类／品阶筛选、大图和小图、深浅底／灰阶。程序统计通过不等于美术通过。
7. 有问题的原图留存并标记；语义错误用生图工具定向返修。安全边不足先记录为生产整理项，正式图集前按批准流程处理；不把网页CSS缩放冒充原图修复。
8. 新图状态是已生成待审；只有用户确认的样稿标已批准。独立的图标批准不会把特效描述或游戏机制也批准。
9. `build_martial_library.py` 汇总已有回执与批准样稿，未生成的明确显示待生成；支持中断后按缺失ID续作，不重复消费已完成结果。

## 特效联动

每个图标ID对应[一份特效分镜](../../archive/design/martial-review/vfx/README.md)，包括主形、起手、行程、命中、生效、收势、粒子速度张力、预算、声学类别和失败反馈。图标是静态意象，后续特效以程序粒子重构，不把本图直接旋转拉伸当演出。当前只准备描述，后续再生成／实现特效。
