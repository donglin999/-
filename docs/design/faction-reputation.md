## 0. 一页看完

1. **门派关系**：萧白和每个见过的势力各有一个值（−100～100，起点 0）。分档名和个人关系一样；**敌对线照大侠立志传：低于 −10 即仇视（敌对）**（第 2.1 节，拍板 1）。
2. **怎么变**：主要靠**牵连**——对一个门人的个人关系变化，按他在门派里的分量折进门派关系（主事 ÷5、门人 ÷10、喽啰 ÷20）；门人出事，**他的主事人另扣 3**；剧情选择和门派事务直接加减（第 2.3 节，拍板 2）。全部由数据表驱动，不写 if-else（第 8 节，拍板 22）。
3. **管什么**：门派档位管**普通门人**怎么待你；敌对后培养、游历里普通门人见面就打；**剧情人物只看个人关系**，门派档只影响初见；主线和固定剧情永远不受影响（第 2.4 节）。
4. **怎么修**：问候主事、给主事赔礼、做门派的事；敌对了**付银两请中人说和**，回到 −10、差额 × 10 两、最少 50 两；**官府不收钱说和**（第 2.6、2.7 节；第九轮第 3、4 项定）。汉皋固定中人**新写一人**，候选见第 2.9 节，待批准（第九轮第 2 项）。
5. **声誉一条正负轴**（拍板 3）：往正是侠名，往负是恶名，只记“被人看见、传得开”的事；**好事坏事一比一**（第八轮第 3 项，不做“坏事传千里”）；绝对值兼当“名气”。品德照大侠立志传的分工并存：声誉是江湖知道的你，品德是你实际做过的事（第 3 节，第八轮第 1 项定）。
6. **普通人结转**：个人关系跟着人走，门派关系全局保留（第 4 节，拍板 4）。
7. **开始部分很轻**：四个势力，门派关系 −10～+14（到不了敌对、到不了熟络），声誉 −29～+29（最多一档）（第 5 节，拍板 9）。
8. **「关系」页第三版**（第九轮第 5 项“可以”、第 6 项页签定名「关系」，声誉仍叫声誉）：照大侠立志传的“关系”页——左边按门类（门派／村镇／官府／其他）折叠的势力列表，每行“印＋名＋档（数）＋一笔关系线”，组内按关系高低排；右边选中势力的简介、眼下一档、门中人物卡；声誉只占顶上一行（第 9 节，第八轮）。
9. **村镇（城镇声望）**：照大侠立志传，村镇和门派是同一套关系、同一套档，只是列在“村镇”一组，管的是这地方的人怎么待你；声誉管的是江湖上怎么说你（第 2.8 节，细则待拍板：第九轮第 1 项用户答“要改”，改哪里待问清，本稿未动）。

### 1.1 《大侠立志传》

| 点 | 做法 |
| --- | --- |
| 门派与势力关系 | 门派、势力、**城镇**（凰木港、大梁城、楚襄城、霖安城、无名小村）都有关系值。关系 **> 80**：战斗中其门人会帮你；**< −10 即敌对，敌对后其门人见面就进入战斗**。门派声望有等级叫法（攻略里见到“崇拜”一档） |
| 个人如何牵动门派 | **门派权重**：改变某角色好感时，按他在门派中的权重改变门派关系——掌门、主要角色约 **5 点好感折 1 点**；门卫约 **15 折 1**；喽啰、杂兵 **50 折 1** 或完全不影响 |
| 打斗与击杀 | 触发战斗一般降 30 好感，再按权重降门派关系；击杀该门派一名角色一般降 **10** 门派关系 |
| 修复 | ① 门派关系在 **−10～40** 之间，每天**问候门主 +1**；② 未敌对时给门人送礼，按权重提升门派关系；③ **城镇、门派、人物的关系都可花铜钱到琳琅阁调解，但朝廷势力和西南、西域等偏远地区不能调解**；④ 礼节特性下与门卫对话按权重加关系 |
| 关系分档（第八轮补查） | 门派、阵营、城镇共用十档：仇恨 −100～−50、对立 −49～−20、冷淡 −19～−1、中立 0～5、友善 5～19、信赖 20～39、钦佩 40～59、敬重 60～79、敬仰 80～99、崇拜 100。人物关系另有十二档（死仇……生死） |
| 门派关系的用处 | 门派技艺请教要门派关系（如点穴，门派关系 30）；门派关系 100 解锁最后的门派任务；入门有品格门槛（儒圣馆：仁义礼智信、勇气都不低于 −10） |
| **名声**（第七轮第 5 项调研） | **单条、不分正邪、只升级**：0～10 级，累计经验 11550。来源主要是**剧情奖励与比武**（告示板、押镖也给）。作用：**加入部分门派、触发重要江湖事件的前置**；影响送礼效果；“礼节 100 彬彬有礼”特征在初见时按双方名声差加关系 |
| **品格六维**（第七轮第 5 项调研） | 仁德、义气、礼节、信用、智慧、勇气，各 −100～100，**记实际做过的事，没人看见也记**：偷拿红色物品被主人看见礼节 −10、没被看见也 −5；暗取、下毒、突袭成功仁德 −5；击杀中立 NPC 仁德 −10；任意 NPC 好感首次 ≥ 60 仁德 +3。用途：**队友品格倾向**（每名队友受其中两项影响，主角品格每变一次该队友好感 ±2）、入门门槛、到 ±100 激活特征——**“恶名赫赫”是仁德 −100 的特征**（作恶时低你 15 级的非首领角色逃离），不是名声 |
| 名声与品格的关系 | **两样并存、分工不同**：名声管“多出名”（门槛、事件、初见），品格管“是什么样的人”（队友好感、门槛、特征）。正邪的名头挂在品格上，名声本身不分正邪 |
| 个人关系是否保留 | 全游戏是同一个开放世界，人物关系挂在人身上，离开城镇不清零；门派、城镇关系同样全局保留（公开资料没写衰减，属推断） |

### 1.2 《大侠立志传》的“关系”页（第八轮调研：城镇和门派的声望页面）

用户第八轮：「你看下大侠立志传的这部分是怎么设计的（城镇和门派的声望页面，你去模仿吧）」。下面是看公开视频截图和攻略后整理的结构（截图只下载到本机临时目录自己看，**没有放进项目或渲染图**）。

| 部件 | 大侠立志传的做法 |
| --- | --- |
| 入口 | 人物菜单顶部一排页签：角色、物品、武学、武道、能力、**关系**、记事。城镇和门派**不分两页**，都在“关系”一个页签里 |
| 名声 | 不在关系页，挂在地图 HUD 左上（“名声（0 级）”，悬停出说明）。关系页只管各方关系 |
| 左栏：势力列表 | 一棵**可折叠的门类树**，四组：**门派、村镇、阵营、其他**（“＋”展开、“－”收起）。展开后每方一行：左边方形徽记（米白剪影图案）、名字、右边“档名（数值）”、下面一条关系条。**组内按关系从高到低排**；列表长了就上下滚动，没有分页、没有筛选 |

## 2. 门派关系

### 2.1 数值与分档（拍板 1：敌对线照大侠立志传）

| 档 | 门派关系 | 个人关系（赠礼稿，对照） |
| --- | --- | --- |
| 托付 | 60～100 | 80～100 |
| 信赖 | 35～59 | 50～79 |
| 熟络 | 15～34 | 20～49 |
| 初识 | 0～14（起点 0） | 0～19 |
| 冷淡 | −1～−5 | −1～−19 |
| 厌恶 | −6～−10 | −20～−49 |
| **仇视（敌对）** | **−11 及以下**（低于 −10，照大侠立志传） | −50 及以下 |

- 负向区间很窄：一次失手（−2）就进冷淡，三次进厌恶，再往下就敌对。门派记的是“这人对我们的人做过什么”，坏事传得快。
- 界面按档画（档比数值重要），不画成进度条（第 9 节）。
- 只列**见过的**势力：认识了该势力的任何一人才出现在页上。

### 2.3 怎么变（拍板 2：照稿）

**一、牵连（个人 → 门派）**：赠礼稿的个人关系每变一次（任何原因），都按分量折进门派关系：

> 门派变化 ＝ 个人变化 ÷ 分量，**每一笔单独四舍五入**；负向不足 1 记 −1，正向不足 1 不记。

- 偷护院失手：护院 −10 → 正道盟 −1；徐令仪牵连 −3 → 正道盟 −1；合计 **−2**（图 02）。
- 做完岑霜的解锁小事“旧货账”：岑霜 +8 → 归烬堂 +2。
- 赠礼送徐令仪喜欢的厚礼 +12 → 正道盟 +2；寻常礼 +2 → 0。

**二、牵连（门人 → 主事人）**：门人因**负向事件**（偷窃失手、敌对开战、敌对战被萧白打赢）掉个人关系时，他的主事人个人关系**另 −3**；同一势力每个主线段落最多一次。主事人自己是被下手的人时不再另扣；没有主事人的（差役、栖河村）不牵连。正向事件不牵连主事人。

**三、直接加减**（不经个人关系）：

| 事 | 门派关系 | 说明 |
| --- | --- | --- |
| 敌对开战（萧白挑起或对方见面动手） | −5 | 大侠立志传“触发战斗降 30”按本作尺度缩小；打赢后个人 −10 另按牵连折算 |
| 剧情选择 | 按剧本，一般 ±2～±10 | 只在 ink 写明的选择处；见第 6 节 |
| 问候主事 | +1 | 第 2.6 节 |
| 门派委托、门派任务 | +2～+10 | 培养以后 |
| 付银两请中人说和 | 直接回到 −10（厌恶底，清除敌对） | 第 2.7 节 |

- 势力之间**不互相牵连**；需要“此消彼长”时由剧情选择同时写两笔，玩家不用记势力敌友表。

- **初见好感**：第一次见到某势力的门人时，他的个人关系起点＝上表数值，加上声誉的初见加减（第 3.3 节），合计限在 −10～+10。之后各走各的。
- **个人和门派一起看**：先看个人关系。他和萧白已在**熟络以上**（私交），门派的冷淡、厌恶对他不生效；门派敌对时他不动手，但当着同门不交易，说一句（ink）。其余情况：价格取两者较差的一档；“不交易、不教、不切磋”任一方说不就不。
- **剧情人物**只看个人关系，门派档只决定他们的初见好感。
- **主线不受影响**（R-主线-01、R-剧情-07）：任何门派档都不挡主线对话、主线任务和固定剧情。
- 与 [人物与组织边界](system-completion-20261016/characters-factions.md) 一致：门派关系“只能帮助获得申请／复核机会，不覆盖前面的硬边界”。

### 2.5 敌对（仇视）

- **开始部分到不了**：门派关系最低停在 −10（厌恶底，第 5 节）。个人敌对仍按赠礼稿第 2.5 节。
- **培养、游历**：照大侠立志传，**该派的习武普通门人见面就打**。和个人敌对共用一套规则：每张图每个主线段落最多一次；打完他离开这张图到下一段落；真实战斗，借切磋战斗场，不受差距拒绝；输了醒在落脚处扣一成铜钱、不丢东西。
- **不动手的**：剧情人物、不习武的人（走开或喊人）、固定剧情或主线对话进行中、该派驻地里的主线场次、**归云谷（下限 −10，不会敌对）**。
- **敌对期间**：该派门人不交易、不教、不托事；驻地不让进（主线需要的场次除外）。

## 3. 声誉：一条正负轴（拍板 3）

### 3.1 定法

- 一个值 −100～100，起点 0。往正是侠名，往负是恶名；界面上是「关系」页顶上一行：一根七段的秤杆，标记往“侠”那头走是好名声，往“恶”那头走是坏名声（图 01 v3）。
- **只记“被人看见、传得开”的事**；没人知道的事记在品德里（第 3.4 节）。
- **好事坏事一比一**（第八轮第 3 项「不要」“坏事传千里”）：正向、负向来源都按原数记，不打折、不加倍。
- **绝对值兼当“名气”**：大侠立志传用名声做入门、事件门槛；本作需要“有点名堂”的门槛读声誉的绝对值（不论好坏），需要“名声好”的门槛读带符号的值。

### 3.4 与品德的关系（拍板 5 调研、第八轮第 1 项定：就这么分）

调研结论（第 1.1 节）：大侠立志传里**名声和品格并存**，名声只管“多出名”（不分正邪，只升不降，管入门、事件、初见），品格六维管“是什么样的人”（有正负，没人看见也记，管队友好感、门槛和极值特征），“恶名赫赫”挂在品格上。

本作方案（用户已定声誉一条，所以按本作的样子落地）：

| | 声誉（新） | 品德（现有 `S.moral` 总评、`S.virtue` 仁德／义气／信用／勇气） |
| --- | --- | --- |
| 记什么 | 江湖上**知道**的你：被看见、传得开的事 | 你**实际做过**的事，没人看见也记（大侠立志传：偷拿没被看见礼节也 −5） |
| 形式 | 一条正负轴（−100～100），绝对值兼当名气 | 照现有：总评 0～30＋四项 |
| 管什么 | 陌生人初见、商价、门槛、躲你、剧情回扣 | 同伴品格倾向（大侠立志传：品格每变一次，在意这项的队友好感 ±2）、旧剧情判定、属性页显示 |
| 能不能洗 | 能：做被人看见的好事，好事坏事一比一 | 只按剧情与行为变，不卖“品德书” |
| 同一件事 | 偷窃失手：品德 −2、声誉 −2；偷窃得手：只扣品德 | |

- 不做大侠立志传那样单独一条“名声”：用户已定一条，名气的用处由声誉绝对值兼任。
- 不合并两者：合并后“偷了没被发现”也会传遍江湖，不真实；现有品德已接进同伴与旧判定，动它风险大。
- 品德四项到极值的特征（类似“恶名赫赫”“人畜无害”）本稿不做，留作以后的提案。
- 界面叫法统一：`S.moral` 现在 `ui.js` 写“道德”、`menu.js` 写“侠义”，统一叫“品德”（第八轮第 1 项随分工一并定）。

## 8. 牵连与门派折算的代码架构（拍板 22：数据驱动，不用 if-else）

用户原话：「22，就这样（写好相关代码架构，不要用 ifelse 去完成」。

思路：**三张数据表＋一个结算函数**。人是谁的人、什么事动什么数、档位管什么，全写成表；结算函数只做“查表 → 展开 → 合并 → 夹限 → 落地 → 记日志 → 发提示”，自己不认识任何具体人物、门派或事件。加门派、加人物、加事件、改数值，都只加改数据行。

| --- | --- |

| `js/qihe-jianghu-rep.js` | 引擎：`settle()` 与 `OPS` 操作表、取值器、夹限、日志、提示；读档迁移 |
| `tests/jianghu-rep.test.cjs` | 表驱动测试：每条用例＝（事件、载荷、起始存档）→ 期望变化 |

### 8.3 结算函数（骨架）

```js
// 取值器：数字、字符串原样；{from} 取载荷字段；{by,map,else} 按载荷字段查表——用查表代替 if-else
const val = (spec, p) =>
  typeof spec !== 'object' ? spec
  : spec.from !== undefined ? p[spec.from]
  : (spec.map[String(p[spec.by])] ?? spec.else ?? 0);

// 操作表：每种操作把“变化”推进 out，不直接写存档
const OPS = {
  fold(ctx, r, p, out) {                                      // 牵连 个人 → 门派：查分量表
    const m = MEMBERS[p.npcId], d = val(r.amount, p);
    const fd = m && !m.hidden && m.faction ? fold(d, RANK_WEIGHT[m.rank]) : 0;
    fd && out.push({ kind:'faction', id:m.faction, delta:fd, reason:'fold', npc:p.npcId });
  },
  bond(ctx, r, p, out) {                                      // 引擎自己改个人关系（敌对战、牵连）：记一笔再折算
    const npc = p[r.who === 'victim' ? 'victimId' : 'npcId'], d = val(r.amount, p);
    out.push({ kind:'bond', id:npc, delta:d, reason:val(r.reason ?? 'event', p) });   // APPLY.bond 直接写赠礼稿存储，不再回调 settle
    OPS.fold(ctx, { amount:d }, { npcId:npc }, out);
  },
  implicate(ctx, r, p, out) {                                 // 门人 → 主事人；amount 为 0 时整条跳过
    const m = MEMBERS[p.npcId] || {}, boss = 'boss' in m ? m.boss : FACTIONS[m.faction]?.boss;
    const ok = val(r.amount, p) && boss && boss !== p.npcId && ctx.onceOk('boss:' + m.faction, r.once);
    ok && OPS.bond(ctx, { who:'npc', amount:val(r.amount, p), reason:'implicated' }, { npcId:boss }, out);
  },
  faction(ctx, r, p, out)     { const f = MEMBERS[p.npcId]?.faction; f && out.push({ kind:'faction', id:f, delta:val(r.amount, p) }); },
  factionSet(ctx, r, p, out)  { out.push({ kind:'faction', id:p.factionId, set:r.value }); },
  factionMany(ctx, r, p, out) { Object.entries(p[r.from] || {}).forEach(([id, d]) => out.push({ kind:'faction', id, delta:d })); },
  fame(ctx, r, p, out)        { const d = val(r.amount, p); d && ctx.onceOk('fame:' + p.npcId, r.once) && out.push({ kind:'fame', delta:d }); },
};

// 折算：四舍五入；负向不足 1 记 −1，正向不足 1 不记（用 Math.sign 和查表，不写分支）
const fold = (d, w) => Math.round(d / w) || ({ '-1':-1, '0':0, '1':0 })[Math.sign(d)];

function settle(type, payload) {
  const ctx = makeCtx(S.jianghu, curSegment(), curPart());   // onceOk：按段落记一次
  const out = [];
  (EVENT_RULES[type] || []).forEach(r => OPS[r.op](ctx, r, payload, out));
  const merged = mergeByTarget(out);                          // 同一目标多笔先合成一笔（提示“合并”态）
  const applied = merged.map(c => APPLY[c.kind](ctx, c));     // APPLY 也是表：bond 交赠礼稿存储，faction/fame 夹 PART_LIMITS 与 floor
  ctx.log(applied); ctx.toast(applied);                       // 跨档由 STAGES 前后对比得出，提示样式查 TOAST 表
  return applied;
}
```

- 声誉好事坏事一比一（第八轮第 3 项），`APPLY.fame` 只夹上下限，不打折。
- 村镇和门派同一套表：村镇只是 `FACTIONS` 里 `group:'town'` 的一行，`MEMBERS` 登记当地人；“当地被看见的事”由事件规则加一条 `{ op:'town', of:'here', amount }`（取当前所在村镇），不另写村镇代码。
- 规则表里没有的事件类型 `settle` 什么都不做并在开发模式打警告，测试用例覆盖每一条 `EVENT_RULES`。
- 偷窃、赠礼、切磋三稿只发个人关系变化和事件，不各自计算门派与声誉。
