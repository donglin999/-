## 1. 唯一数据来源与时间单位

- 通用时间/成本由[培养机制](cultivation.md)维护；日程合同由本文维护；事件排期数据在[事件目录](calendar/mountain-events.json)，禁止在章节文本和代码分别藏一份不同日期。
- 事件日期修改先改目录并运行检查，再同步[三年事件表](timeline.md)、人物篇和代码。旧文本不作为新日期权威。新增阵营必须增加对应目录/情景，不能继承山居通过结论。
- 三年36个月，每月五期：月初、上旬、中旬、下旬、月底。绝对slot从0到179：`slot=(绝对月份−1)×5+期序号`，期序号0到4。年/月只用于显示，跨年和分支不重置slot。
- 窗口两端均包含；duration表示连续占用几期，最晚开始为`窗口末−duration+1`。普通活动不推进日期；休息推进一期。整月历练占五期，不再领取同月据点体力。
- 短对话的顺序不是新的日历期；同一期内按行动先后结算。跨据点旅行不得伪装成谷中房间之间的移动，须有明确旅行预留。

## 2. 三层安排，避免逐篇随意填日期

| 层 | 负责内容 | 约束 |
| --- | --- | --- |
| 世界日历 | 季节、公共事件、整月地图、固定主线 | 先预留，全期独占不得与自由活动重复计算 |
| 人物日程 | 所在据点、求学、来访、同行、旅行、缺席 | 每情景每个人每期恰有一个基础所在地；缺席也显式登记 |
| 玩家行动 | 邀约、普通闲逛、通信、练习和选择 | 符合世界及人物条件后，检查本期体力和已有承诺 |

整期行程是独占预订，覆盖基础所在地，不能同时预订两个行程。普通行动在一期内顺序执行，不把两次同地行动误判为同时发生。主动写信只占写信人，不要求远方收件人与主角同地；来信通知不占正式人物行动。

当前目录的来访日期和基础人物位置是排期样例；13月汉皋行程已明确预订主角与叶蘅，其他整月地图仍仅预订主角，其他人物是否同行需具体编排。没有记录的数据不能由检查器推断为在场。

## 3. 事件合同

每个事件必须有稳定ID、标题、原始设计来源、制作状态、适用情景、事件类型、窗口、duration、cost、据点hub、参与人物、前置requires、是否必需required及互斥组group。缺项禁止入库。

| 类型 | 日期/成本语义 | 常见用途 |
| --- | --- | --- |
| block | 连续整期独占，cost=0；该期没有额外12点 | 整月地图、短篇主线、人物外出 |
| action | duration=1；消耗1～12点，可与其他行动顺序组合 | 人物4、近山／来客3、寄信1／送物2、练武5、学艺/生产3、打杂2 |
| plot | duration=1、cost=0；同一期条件满足后自动短对白，校验参与者在场，不独占整期 | 承诺、护送复盘、出行商议；仅对白里的回答由玩家选择 |
| notice | cost=0，不预订参与人物，不完成正式人物节点 | 来信、提醒、公开消息 |

正式事件另须设计这些字段并在接入阶段验证：

- `announcement`：何时通知、通知渠道、截止提醒；固定必需占期在发放本期体力前告知。
- `conditions`：事实、技能/关系、材料、权限、人物意愿；逐项给出来源和不满足时的替代办法。
- `effects`：一次性事实、成长、物资、关系、后续邀请；未结算不提前写入。
- `expiry`：错过、延期、通信承接、返程续接或替代节点；不得默认一律关闭整个人物线。
- `repeat/cooldown`：一次性ID或重复窗口；人物日常可重复，但阶段节点不可重复领收益。
- `priority`：明确邀请/必须节点/普通偶遇；强制剧情不能靠随机抽中。
- `migration`：版本变化如何处理进行中活动、旧事实和未完成邀请。

这些扩展字段目前未纳入离线求解器的数值状态演算，记录不齐或尚未验证时只能进入设计稿，不能作为正式游戏事件放行。

## 4. 前置、分支与互斥

- requires只引用存在的ID，依赖图必须无环。普通行动前置可在同一期先完成；block前置必须等整期完成后，后续最早进入下一期。
- 叶蘅第12月月底选择方向，第13月起改变日程。两路线13月都有明确汉皋行程：医路在苏芷接诊点开始临诊，针攻路参加师门历练；14月起分别常驻白鹇／归云。留谷与求学用两个情景排期，不能同一期同时出现在山居、汉皋与白鹇谷。
- 本轮只覆盖山居这两种情景；魔教/官府、不同同行组、特殊状态以后增加情景。出现会改变所在地或日历的分支必须有新情景，不用一份好感数值隐式替代。
- group表示本次不能同时完成的选择，不代表同一时间窗口有多个可选事件就冲突。替代解法应记录同一事件的不同结果，避免把三种解法当三次收费。
- 每个情景明确`goals`：必需事件与这些目标**联合求解**。可选事件单独可达，不表示全部可选同时可达；想验证一组人物线必须把它们一起加入goals。
- 事件抽取概率不得决定必需节点的可达性。明确赴约符合条件就直接进入，原作权重未经核实，不宣称复刻。

## 5. 冲突分类与处理

| 编号 | 冲突 | 应对 |
| --- | --- | --- |
| T01 | 同一人物/主角两个整期预订重叠 | 改窗口、换参与者、明确分支；不靠优先级静默删事件 |
| T02 | 活动只在历练占用期开放 | 延至返程、转地图节点或通信；窗口修订后重验 |
| T03 | 需要的人物不在同一据点 | 改为已知会面/来访/通信，旅行另计 |
| T04 | 前置未知、循环或晚于截止 | 修正事件链；不能只放宽最终事件门槛 |
| T05 | 单事件或目标组合超出本期体力 | 分散到多期、扩窗口；同一事件内战斗不重复收费 |
| T06 | 玩家目标包含互斥分支 | 明确哪些是替代路线，分别检查；不要求同时达成 |
| T07 | 技能/材料/关系门槛无法正常达到 | 计入成长和资源预算，提供合理由来或替代方案 |
| T08 | 提醒迟于最后可赴约时点 | 提前通知；考虑整月外出占用，不能只看剩余日期 |
| T09 | 改期后旧存档继续旧事件或重复结算 | 迁移进行中事务和邀请；检查事件版本与一次性结算ID |

T01～T06已有有限离线检查；T07～T09以及运行中的承诺冲突须在接入时补实现与专项测试，未验应阻止正式放行。检查失败不能自动挪日期并提交，应输出影响事件和候选修改供设计复核。

## 6. 成长与时间预算如何一起算

- 基准草案：180期−6次整月历练×5−9期短篇＝141自由期，最多1692点据点体力。新增整月外出减5期；若吸收旧主线，应以占用并集计数，不扣两遍。
- 闲逛次数不能只看总点数：每期12点、正式人物活动4点，体力最多容纳三次，实际受一次性事实与日期窗口约束。141期按30%～40%社交投入约可支付126～169次4点活动；这是测试画像，不是硬性要求玩家必须采用的比例。
- 必须先为核心人物线确定目标组，累计闲逛次数与练习/通信/生产成本；大量可选内容可以超过单轮预算，但任何必达组合都须有可行路径。
- 技能门槛按真实成长曲线反推练习次数；不得把此前“每次+3”的计算示例写成已实现成长值。当前课程增量、教学资格和地图收益分别读取实际数据。
- 2026-10-16用户确认单关系轴：按[关系细则](romance-rules.md)检查0—100四阶段、19/49/79瓶颈上限及托付80；结缘另查成年、正式资格与本人篇/心意。取消旧情意25/45/60阶段与人数加价。日常及剧情收益由关系负责页维护；时间系统只检查真实可用机会，不另建数值。
- 成长与资源审核需保存初始状态、每步条件/投入/收益、截止前最终状态。离线排期通过只证明可以安排这些行动，不能证明练习后能力够高、物品充足或随机选中。

## 7. 提醒与运行事务

1. 开始一期：先应用人物日程和固定占期，再显示可用活动与邀请。
2. 玩家准备赴约：核对资格、地点、余力、当前活动锁和截止；显示费用及重要后果。
3. 确认后：生成唯一事务ID，锁定事件和结果种子，扣一次成本，保存开始slot与版本。
4. 事件内部对话/战斗都在这次费用内；不自动完成别的邀约。
5. 完成后：以事务ID幂等结算，保存事实、收益和后续机会。刷新/恢复继续同一事件，不重新抽取、不重复奖励。
6. 休息推进：处理到期邀请和可延后节点，下一期再按日程发放体力。同一期缺体力不自动判永久过期；玩家仍可查看并决定推进。
7. 修改日程：进行中事件保留版本快照；未开始邀请按迁移规则调整并通知，旧事实保留。不能读档后默认重放全部主线。

此为接入合同；现有培养已具备部分活动事务行为，尚未接入本目录的统一排期，不能称新增日程系统已在游戏里生效。

## 8. 新增内容的工作流

1. 写事件卡：用途、参与者、必需/可选、结果、前置、窗口和成本。决定新剧情是否占整期，不以对白长度临时收费。
2. 录入目录，新增/修订人物在场区间和分支情景；确定目标组以及过期处理。
3. 运行检查，比较修改前后可达性、141期预算变化、旧目标是否失效。已确定日期不能为了新内容擅自改期。
4. 排期通过后验成长、资源、提醒与随机规则；扩写剧本，再接入运行代码。
5. 实机走指定路线并覆盖刷新、断点恢复、过期、出游返程与不同人物方向；保存当前目录哈希和证据。
6. 全部关卡通过才正式接受。仅静态通过、搜索超限或未知条件均不得标成“没有冲突”。
