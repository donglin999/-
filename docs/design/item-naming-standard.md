# 物品与装备命名规范

状态：现行　最后核对：2026-10-19

版本：2026-10-06.2。适用正式包裹物品、装备、养成资源和后续物品提案。名称清单见 [item-names.json](item-names.json)；实际定义在 `js/core.js`、`js/menu.js`、`js/story.js`、`js/quests.js`、`js/xiangyang-chapter.js`，养成资源在 `js/cultivation-data.js`。

## 参考与设计取舍

参考[《侠客风云传》武器资料](https://www.gamersky.com/handbook/201507/628651.shtml)中从材质、形制到含光、承影等名器的命名，及[《逸剑风云决》图鉴](https://yijianwiki.cn/index.php/图鉴)中器形、意象、工艺和药食用途的结合。下列方法是本作的设计归纳，不是对参考游戏全部命名规则的断言。借鉴命名结构，不整套照搬名器目录。

1. 基础物品先让人看懂：材质／工艺＋器形，如桃纹木剑、熟革软甲、素铜针囊。不用名字暗示不存在的稀有材质或神奇属性。
2. 重要装备可以意象＋器形，真正的名器可用短名；典故、赠与者及独有称号必须有剧情依据。已有提案的「照晚」「归山」「守诺旧氅」符合此方向，仍保留提案状态。
3. 药食、资源保持用途清楚：金疮药、羊肉笼饼、随行干粮。没有配方或造型证据，不能凭名字改成丹药、灵草或秘药。
4. 证物用来源／辨识线索＋物件：岘山书匣、浪纹密札、三痕竹片。来源、持有人和用途写在介绍中；证物没有品阶、品质色或高级品质特效。
5. 雅致来自具体意象和节制，不要求每件都用生僻字、四字成语或玄幻词。名字不能代替物件介绍。

## 硬性约束

- 一般显示名 2～6 个汉字；特殊图卷允许正文名＋卷次，正文尽量不超过 8 字。名称不含数量、数值、品质标签或营销前缀；数量和品阶由界面独立显示。
- 同一命名空间不允许重名；名称随 ID 维护。改名不改 ID、存档键、图集键、效果、价格、获得条件和实际品阶。
- `world:cloth` 是素布短衣，`resource:cloth` 是素织布料，两个命名空间分别核对，不能因为同名 ID 合并。
- 悬停介绍、商店、奖励、选项条件和相关对白同步检查。旧显示名仅作为兼容查找和历史对照，不再作为新开发依据。
- 名字与已有图标、材质、器形核对后才能通过。改名不自动批准新素材；沿用美术手册，文字与品质框仍由 UI 绘制。
- 新增物品先填：稳定 ID、类别、作用、来源、材质、形制、名称理由、实际品阶／无品阶，再补图标提示词和验收记录。只有提案时不得标记已接入。

## 金色及以上：必须有含义（硬性门槛）

适用甲（金）、绝（红）及以后新增的更高品阶，覆盖装备、药食、材料、秘籍和工具。按实际品阶判定，不按图标本身有没有金属金色判定；剧情证物继续无品阶。

每件必须填写 `naming`：

| 字段 | 要求 |
| --- | --- |
| `meaning` | 解释核心字词和整名含义，不能只写「霸气」「珍贵」「象征力量」 |
| `basis` | 指向取得任务、人物篇、工艺、产地、配方或已定器物特点；未实现的来源注明提案状态 |
| `design_anchor` | 说明名字如何与器形、工艺、用途或人物经历相对应，至少有一个具体锚点 |
| `lore_text` | 面向玩家的简短释义，正式接入后在悬停介绍或物品详情显示，不只留在内部表格 |
| `status` | 区分设计提案、剧情已核和正式已接入，不能把补写释义视为剧情已完成 |

- 不得先拼一个玄幻名字，再编设定凑解释。沿已有设计提取含义；依据不足就修改名字或补齐设计后再评审。
- 含义不能暗示未实现的功能，例如「留烬」不自动赋予火伤，「归途」不代表传送，「归息」不代表复活。
- 不要求每件都引用历史典故；原创人物经历、实际工艺和用途同样可构成含义。引用典故必须核查来源，不能杜撰出处。
- 缺失上述字段或含义与素材、剧情冲突，生成和接入验收均不通过。规则适用于后续所有高阶物品，当前装备目录只是第一批落实对象。

## 验收流程

1. 实际加载游戏，逐个比较 ITEMS 的 ID 和名称与当前清单，核对 30 件完整覆盖及养成 5 类资源。
2. 与改名前快照比较除名称和介绍外的全部字段，确认装备条件、攻击防御、恢复、价格和剧情标记无变化。
3. 扫描正式脚本中旧全称，确认商店、奖励、对话选项及条件没有新旧名称混用。
4. 打开包裹，检查普通和长名称、悬停介绍、品质预览和无品阶证物。记录测试页面与截图，只有真实浏览器结果才可写通过。
