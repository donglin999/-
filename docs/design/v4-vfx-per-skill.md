# 逐招专属特效规范 v1

状态：现行　最后核对：2026-10-19（原记：**执行中，2026-10-08**。）

用户原话：“逐个评审一下，我看到很多特效要么没选中单位，要么特效很垃圾，我需要你每个功法都专门去设计，而不是直接去进行复用，只是说可以复用的情况下可以复用而已。”

本页取代[组件库模板](../archive/design/v4-vfx-kit.md)作为招式特效的主方案。组件库模板已于 2026-10-19 归档，不再作为兜底（用户确认）：没有专属特效的招式，按[技能特效生成流程](skill-vfx-pipeline.md)做（R-特效-01、R-特效-02）。组件库的中性素材仍可按下文第 2 条只作辅助层。

## 1. 原则

1. **每一招都专门设计。** 先从该招的分镜（`skill-text-v4.json` 的 `vfx_v4` 四拍）里提炼出它**独有的视觉母题**：

   | 招式 | 独有母题 |
   | --- | --- |
   | 叠岚掌 | 两层掌劲叠压，加上山岚 |
   | 照川落日 | 落日余晖压在江面上 |
   | 回春散 | 药粉化雾 |

   再写清楚它和同门其他招式在画面上的区别。同门同路线的招式，主体形态不能只是换颜色、换大小。
2. **只有意象确实一致时才复用素材。** 例如同一把刀的刀光、通用的命中尘土、霜花碎屑。每次复用都要在设计表里写明理由。组件库的中性素材只能用于辅助层（尘土、通用光屑、地面涟漪），不能充当一招的主体。
3. **必须打中正确的单位：**
   - 敌方招：对 `fx.targets()` 的每个目标命中。
   - 我方招：落在 `fx.allies()` 的每个同伴身上。
   - 自身招：落在施法者身上（`fx.A.hand` 与 `fx.A.foot` 附近）。
   - 群体招：每个目标都要有完整的命中，不能只打中间。
   - 起手必须在施法者身上看得见。
4. **按战斗尺度设计**（评审结论，见 §4）：
   - 战斗角色在画面里很小。运行时以“舞台尺度 × k”绘制，k 约 0.75。按舞台尺度设计时，角色约 125 特效像素高。
   - **命中特效要盖过目标躯干并超出轮廓**：主命中至少约 1 个角色高，丁级可以略小。
   - **出手主体**（剑气、掌劲、音波等）宽度至少约 0.6 个角色高。
   - **伤害数字不能是画面上最显眼的东西。** 如果只看得到数字，就是不合格。
5. **品阶档位**沿用 F1–F5（[伤害数字规范](damage-numbers.md) §6），BP 只在本档内加强。

   | 品阶 | 档位 | 时长 | 要点 |
   | --- | --- | --- | --- |
   | 丁 | F1 | 0.5–0.8s | 一个清楚的主形 |
   | 丙 | F2 | 0.8–1.1s | 主形加一个辅助层 |
   | 乙 | F3 | 1.0–1.4s | 主形、辅助层，加轻度压暗 |
   | 甲 | F4 | 1.4–2.0s | 两段式；压暗、暗角、推镜 |

   绝级为 F5，已全部专属。
6. **颜色**：
   - 有属性的招式用属性主色（[伤害数字规范](damage-numbers.md) §1）。
   - 无属性的用兵器本色：剑冷银、刀钢灰带寒光、拳掌米白气浪、长兵木色与尘、暗器银亮、音律月白。
   - 医疗用翠绿或温白。
   - 援护、守势用钢青或月白。

## 2. 每招的交付物

| 步骤 | 产出 |
| --- | --- |
| 设计表 | 在本门设计文档（`docs/design/vfx/<门派>.md`）里，每招一节：独有母题、与同门的区别、四拍分镜（起手、出手、命中、收势，写明时间点）、主色、复用了哪些素材及理由、作用目标 |
| 概念帧 | 丁、丙级 1 帧；乙、甲级 2 帧。写进 `art_sources/fx_<门派>/spec.json` 的 `concepts`，用 `python3 tools_fx/fx_pipeline.py concepts <门派>` 生成，自查不合格就重画 |
| 单体素材 | 每招 2–5 个（复用的不算），写进 spec 的 `elements`（含运行时宽度 `width`）。生成用 `fx_pipeline.py elements <门派>`，整理用 `fx_pipeline.py build <门派>`，输出到 `assets/fx/<门派>_v1/` |
| 编排 | 写在 `js/fx/fx-<门派>.js`，用 `WuxiaFX.define(id, {...})` 注册，工具函数取 `WuxiaFX.lib`；写法参照 `js/wuxia-fx.js` 里第一批和第二批的专属编排。必须带 `grade name dur budget ramp lead hitAt`，我方招加 `side:'ally'`，群体招加 `group:true` |
| 评审 | 两层：评审页单招逐帧对照概念帧；实战截图（§3）三个时刻都合格，才算完成 |

## 3. 实战评审方法

1. 打开 `index.html?runtimePrototype=1#street`。用 `tabs_create` 新开**自己的**标签页，并 `tabs_select` 切到前台（后台标签页的计时器会被节流，截图时刻不准）。
2. 在控制台开战，用 `doSkill` 施放。
3. 按 `WuxiaBattle.t` 截取三个时刻：起手（命中前 40%）、命中（hitAt + 90ms）、收势。
4. 合格标准：三个时刻都看得出这一招，命中落在正确的单位上，并且画面主体不是伤害数字。

## 4. 实战评审结论（2026-10-08）

逐招截图见下表（113 条：81 招加 32 门内功主动）。总体情况：
- **组件库模板**：几乎都只剩伤害数字和受击闪白，主体太小、形态雷同，全部判为不合格，逐招重做。
- **专属编排**：
  - 合格：一剑澄江、松涛合阵、万籁归松（光柱落在每名同伴身上）。
  - 太小：崩石短打、金针刺穴、一息相续。
- **引擎**：按角色等比缩到 0.5 时，所有特效都偏小。已改为下限 0.75（`js/wuxia-battle.js`），相对角色放大约 1.5 倍。
- **防御强化招**（回岚步、松间错步、敛云守锋、逆流截江）不能直接施放，要在选“防御”时触发，需要单独做“防御时”的特效接入。
- **评审时没放出来的招**（重数开启条件），以及个别招的问题，见逐招表。
