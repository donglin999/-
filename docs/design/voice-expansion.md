## 页面流程

普通 NPC 和主要角色选音页均增加“按描述扩充音色”按钮。选定角色后打开对话框，输入 2–500 字描述，选择数量（1–6 个，默认 3 个）与生成方式，点击“生成候选和试听”。快捷描述提供凶狠、阴险、清亮少女、温柔亲切方向。取消不会提交任务。

提交成功后关闭对话框，页面显示扩充进度，新候选置于列表前面；自动取消“只看收藏”，避免新增项隐藏。生成过程可继续浏览，完成后试听。确认音色仍需原有确认对话框，新增候选不会更改已确认绑定。错误在对话框或任务进度中显示，保留描述以便调整。重试同一提交保持 request_id，不重复创建候选或调用接口。

## 两种生成方式

| 方式 | 描述如何使用 | 声音来源 |
| --- | --- | --- |
| 系统音色调校（默认） | 根据关键词选择基础声音并调整情绪、音高、语速和声音效果 | 系统音色的调校版本 |
| AI 设计新音色 | 完整描述发送到 MiniMax Voice Design，追加普通话及角色信息 | 返回独立自定义 voice_id |

系统调校支持凶狠、阴险、温柔、年轻、年长、低沉、清亮、快慢等方向，可组合。它是关键词规则，不是通用语言理解；未知方向会提示补充关键词。重复相同描述会优先避开已有相同声音参数，后续提供调校差异；不保证每次获得不同的基础音色。所有候选卡显示描述、来源和调校信息，不能把参数变体标成全新基础声音。

AI 设计需要使用普通按量计费 API 密钥，并满足账户权限与余额条件；Token Plan 及其积分暂不覆盖音色设计。设计返回的预览不作为最终角色素材，另调用 `speech-2.8-hd` 制作与角色清单一致的带情绪试听。设计阶段不自动重试：网络超时可能已经创建远端音色，须先查账户记录。失败不会自动换账户或偷偷切换生成方式。

单句 NPC 每候选只生成自己的识别句，可使用候选情绪覆盖。主要角色每候选沿用原有多句试听，并保持每条台词自身的情绪，避免把所有对白固定成同一种情绪。确认单句候选后优先复用刚才试听的音频。

## 数据与接口

`POST /api/candidates/expand`：

```json
{"character_id":"liu","prompt":"凶狠阴险，低沉慢语","count":3,"mode":"tune","request_id":"客户端生成的唯一请求 ID"}
```

返回 202 和 `{job}`，只表示排队成功。通过 `/api/jobs/<id>` 或 `/api/state` 查看完成状态。一次同角色扩充任务在执行时，新的扩充返回 409；其他角色任务可排队。系统调校试听共享原有串行请求队列和限流处理。

任务 `type=expansion`，记录描述、方式、数量、request_id、candidate_slugs、phase、进度与错误。`phase=design` 表示设计基础声音，`phase=auditions` 表示制作试听。候选持久化至 `.voice_state/state.json` 的 `user_candidates[character_id]`，启动时合并至原有候选列表。不要通过另一个 VoiceStore 实例修改运行中的状态。

失败的试听可在候选卡重试，保持同一基础声音；重启将中断任务标成 interrupted，已完成候选和音频保留，未完成试听由原有补全机制继续。若设计过程已获得部分声音后失败，保留这些声音供制作试听，不重设计已有声音。自定义音色的远端有效期依账户和 MiniMax 规则处理；本地记录不代表远端永久有效。

## Skill

本机已安装 `$game-voice-casting`，位置为 `~/.codex/skills/game-voice-casting`。它包含操作规范与 `scripts/expand_voice.py`，可通过同一后台 API 提交、等待或只读预览请求。网页运行时使用后台逻辑，不依赖 Codex 会话或临时启动一个 agent。

### 2026-10-05：订阅额度与自定义音色失败

本次陆衡一次设计6个候选，保存了1个独立音色后任务返回2061。依据[MiniMax官方错误表](https://github.com/MiniMax-AI/cli/blob/main/ERRORS.md)，该错误指当前Token Plan不支持请求的模型或能力，不能解释为剩余额度耗尽。随后戚铮、柳含烟的系统调校各9段真实试听成功，普通系统音色合成仍可用。

继续为陆衡已保存的音色制作试听时，接口明确返回1008，`status_msg=insufficient balance`；3句未生成，保留已有音色，不重新设计。后台实际使用Token Plan订阅密钥。用户的订阅额度和赠送积分截图不能直接证明此次自定义音色调用的计费条件；[官方服务说明](https://platform.minimax.io/protocol/paid-agreement)区分订阅密钥与普通按量API密钥，实际支持范围以接口和账户控制台为准。

页面与后台现保留错误码及脱敏接口说明，2061显示套餐范围限制，1008显示此次API调用的余额问题。已创建而缺少试听的候选有“补齐试听”入口；设计失败时可点“继续用系统音色调校”，打开默认调校表单，由用户提交。不会自动换账户或把系统调校伪装成新音色。后端38项回归通过，覆盖错误原因显示、密钥隐藏及部分设计失败后的原音色试听恢复。

## 老者描述识别修复

2026-09-30：吴长老的描述“多来几个老头声音，这些都太青年了”曾被错误识别成年轻方向，任务虽然完成，候选方向不符合要求。现补充老头、老爷爷、老伯、大爷、爷爷、老汉、老翁、老年、年迈等称呼，并排除“太青年了”“不要年轻”等否定或抱怨短语。明确要求老年男性时只从诙谐老者与慈祥老者基础声音中扩充，允许同基础声音调校差异；不再以降低青年声的音高代替老者声音。两页增加“年迈老者”快捷描述。新增回归测试覆盖用户原句。
