# 角色语音管理：确认音色与增量补全

状态：现行　最后核对：2026-10-19

本页定义制作后台的交互。台词与情绪短句见[襄阳语音](../archive/design/xiangyang-voice.md)，运行方式和 API 见[语音后台](voice-backend.md)。管理后台在本机运行，Cloudflare 上的游戏网页不承担生成任务。

## 固定生成接口

角色音色试听、正式对白、情绪短句和后续增量补全统一调用 **MiniMax**，当前模型为 `speech-2.8-hd`，每句显式发送清单中的 `emotion_api` 到 `voice_setting.emotion`，接口为 `POST https://api.minimaxi.com/v1/t2a_v2`。沿用本机已有的 MiniMax 凭据，不切换到其他语音服务。模拟模式仅用于开发测试，必须显式启用并标明。

## 从试听到确认

1. 后台默认自动补齐所有角色候选音色的试听样本，不要求逐个点击制作或确认。主要角色每个候选至少三句，普通 NPC 每个候选仅一句；仅复用参数和情绪一致的新版本样本；无显式情绪的旧试听重新生成。萧白不进入本轮配音名单。
2. 选择角色，直接点击候选的连播按钮听几句；也能单独重听某一句。准备中的候选显示进度，失败候选可直接重试。浏览器首次播放仍需要点按按钮。试听或选择候选不占用音色，不生成全角色正式台词。旧试听页保存在浏览器里的“定稿”也必须重新确认。
3. 点击确认，界面再次列出角色、音色与需要生成的语句数。确认后后台保存绑定；主要角色排队补全，单句 NPC 优先直接采用已有样音，否则只补这一句。
4. 候选显示全部使用者。普通 NPC 可选已使用音色，包括主要角色的音色；主要角色之间不可共用同一基础音色。后台按角色配音模式验证，两个 NPC 同时选择同一音色均可成功。

使用者按原始 `voice_id` 汇总，修改音高、语速或候选名称仍然列为同一音色。NPC 复用不释放原角色的绑定。更换已确认音色也需要确认；新绑定保存成功后，当前角色从旧音色的使用者列表移除，其他使用者保留；当前角色旧音频会被标为需要更新。

## 角色全部语句

角色页把完整对白与情绪短句分开标注，显示语句正文、中文情绪、实际 API 情绪、演出说明、来源和生成状态；可筛选待生成、已完成、需更新与失败的语句。已生成的正式语音可逐句试听。情绪短句的触发设计与游戏接入状态必须明确，不能把未接入短句当作已经可玩。

状态由后台根据语句和文件判断，不能由浏览器自行勾选“已生成”。测试生成物必须标为模拟，不计入正式完成数。

## 一键补全与任务反馈

确认音色后自动补全；后续剧情增加或改写台词时，打开角色页点击“补全新增／修改语音”。后台重新读取语句清单，只处理缺失或失效内容，保留未变化的语音。

有效语音对应稳定语句 ID、正文、情绪、已确认音色及合成参数。正文、情绪参数、演出说明或音色变化时旧文件不再算有效；增量判断不依赖文件名是否存在。删除或停用的语句不加入新任务。

任务反馈包括排队、生成中、完成、部分失败及逐句错误。重复点击不能为同一角色重复提交相同任务。失败后重试只补缺失内容；已成功语句保留。刷新页面仍能看见任务和绑定状态。

没有确认音色时补全按钮不可用。真实合成依赖本机服务与服务端凭据；浏览器不持有 API 密钥。模拟模式用于测试流程，不作为正式配音。

## 游戏播放方向

配音接入游戏后，有配音的台词关闭打字提示音，语音播放时降低背景音乐和环境音。推进台词停止上一句，不等待语音结束；字幕始终完整保留。情绪短句设冷却，不随每次靠近或行走反复播放。救治 CG 保持无立绘覆盖，语音与当前 CG 台词对应。

本轮交付制作清单和管理后台；实际角色音色由试听确认，正式音频在确认后的后台任务中生成。游戏播放接入状态以[音频文档](../archive/audio.md)为准。

## 情绪制作

每句必须记录情绪并实际传给 MiniMax，字段、映射和试听验收见[台词情绪](voice-emotion.md)。试听页显示真实情绪枚举，连续播放每句各自的情绪。每句修改情绪后保留音色绑定并增量生成；当前通过修改清单后补全完成，逐句情绪编辑与多版本对比界面尚未实现。
