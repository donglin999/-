# 宠物系统设计规范

状态：现行　最后核对：2026-10-19（原记：**设计方案，2026-09-30**。用户要求完善宠物系统的开发依据；本篇规定后续实现，不表示功能已上线。已运行的行为、数值和缺口见[现行实现](../archive/pets.md)，交付证据见[验收清单](pets-acceptance.md)。本篇是宠物玩法的维护入口；[队伍与宠物](party-pets.md)只负责队伍关系，不能另写一套宠物规则。）

## 1. 体验目标与范围

大黄应像会观察、会等待、愿意跟人的犬类伙伴。玩家走动时可靠跟随，停留时会在附近嗅闻或休息，危险时主动回应。动作和选择有可见原因；不能只用“正在嗅闻”等文字代替实际表现。

- 桌面优先：1280×720、1920×1080；鼠标悬停读详情、点击操作，键盘可聚焦和召回。
- 宠物独立于人类队伍，不占人类编队位置、不接受人类武学和兵器，不进入人类逐回合指令流程。
- 首期仅完善大黄；其他物种须登记活动方式、能走的地形、技能、食物和素材，不能直接换皮复用犬类全部行为。
- 普通战败不造成永久死亡；未收养宠物也能完成所有主线。宠物线索只能提供额外反馈、提示或替代路径。
- 探索自主活动先于新增复杂养成。首期不加入繁殖、捕捉概率、饥饿倒计时、稀有度抽取和挂机产出。

## 2. 功能状态与交付顺序

| 阶段 | 内容 | 完成条件 |
| --- | --- | --- |
| 现行 | 收养、队尾跟随、自动战斗、自动属性成长、喂馒头恢复、项圈 | 仅描述代码基线；不等同于下列目标通过验收 |
| A 探索活动 | 安全跟随、停留嗅闻/坐卧、召回、场景抑制、独立寻路 | 窄门、草地、跨图、对话和存读档验收通过 |
| B 战斗整理 | 紧急治疗优先、护主代价、原因反馈、休养不出战 | 按决策表复现边界；不因宠物决策卡住战斗 |
| C 培养与界面 | 信任、训练倾向、休养、宠物图像面板、食物比较 | 每个操作明确前后变化，旧档无损迁移 |
| D 内容扩展 | 水钵、熟人、嗅迹线索、新增物种 | 先登记场景互动和资产，再制作；不影响无宠物路线 |

阶段 A 可复用现有 walk/run/idle 制作原型，但缺少嗅闻、坐下、趴卧素材时不能宣称这些动作已完成。每阶段更新现行实现文档和证据路径。

## 3. 探索自主行为

### 3.1 状态与优先级

从高到低依次为：场景脚本接管 → 模式暂停 → 召回/安全归队 → 跟随 → 环境互动 → 闲逛 → 原地待机。使用明确状态机，随机只决定符合条件的闲动作，不决定是否穿墙或是否听召回。

| 状态 | 进入条件 | 可见表现 | 退出条件 |
| --- | --- | --- | --- |
| 跟随 follow | 主人移动、刚进入场景、活动被取消 | 沿可走路线到队尾锚点；远时跑、近时减速 | 主人停稳且宠物到位后进入待机 |
| 待机 idle | 主人停止 ≥1.5 秒，宠物已到安全位置 | 站立、耳动、摇尾，偶尔看主人 | 可活动则选择动作；主人移动立即归队 |
| 闲逛 wander | 待机累计 3–6 秒；宽阔安全地面；未召回 | 在附近走一小段，1–3 秒后嗅闻或站立 | 移动、召回、模式切换或空间不足 |
| 嗅闻 sniff_ground | 有可走落点或登记过的嗅迹点 | 降低头部、鼻端贴近地面，停留 1–3 秒 | 动作结束回待机；可被召回打断 |
| 坐下 sit | 主人停留 ≥8 秒、无临近危险 | 臀部落地、前足支撑、看人或耳动 | 主人移动先起身再跟随；不能滑坐 |
| 趴卧 lie | 停留 ≥20 秒；安全且安静；未受脚本控制 | 前足伸出、胸腹贴地、轻微呼吸 | 起身动作后跟随；召回最迟 0.6 秒开始响应 |
| 环境互动 interact | 有可用宠物兴趣点，路径及站位合法 | 喝水、嗅迹或对熟人摇尾 | 完成一次、条件失效或召回；优先归队 |
| 归队 return | 召回、主人离开、超出活动半径 | 中止闲动作，走/跑回队尾锚点 | 到位并满足跟随间距 |
| 脚本 script | 剧情显式接管 | 船上伏低、警觉江面等专用演出 | 脚本释放，不生成第二只跟随犬 |

普通对话、菜单、战斗和转场暂停探索自主计时。镜头仍展示场景时可保留原地呼吸，不随机走进对话人物之间；回来后重新待机，不补执行暂停期间累计的动作。

### 3.2 活动空间与寻路

参数为**首轮调试起点**，集中在宠物配置，不散落到场景脚本；依据实机效果调节后记录变更。

| 参数 | 起点 | 用途 |
| --- | --- | --- |
| 跟随间距 | 沿用队列 52 世界像素 | 大黄始终在所有人类同伴之后 |
| 普通活动半径 | 以队尾锚点为中心 80 世界像素 | 控制附近活动；不以队伍长度误判跑远 |
| 强制归队半径 | 距队尾锚点 120 世界像素 | 超出即回，禁止继续抽闲动作 |
| 闲动作冷却 | 6–12 秒 | 避免频繁摇摆和动作切换 |
| 兴趣点查询间隔 | ≥0.5 秒 | 不逐帧扫描全图或重复寻路 |
| 卡住判定 | 目标有效而 1.5 秒内位移 <4 像素 | 重算一次；失败则放弃活动并沿安全路线归队 |

- 队尾锚点来自主角真实足迹；有多人同行时不把“大黄距主角远”当作离队。
- 自主活动必须使用场景可走网格与逐步碰撞检查。不能沿用跟随的直线插值去走随机落点，也不能因为体型小而穿过栅栏、墙或树干。
- 草地、低草、苔藓、落叶和零散碎石可通行，坡壁、建筑、实心障碍才阻挡；兴趣点不能另造空气墙。
- 落点需与当前位置连通，留出身体宽度，避开出口触发区、剧情人物站位和队伍通路。窄桥、单人门洞、台阶入口取消闲逛，仅跟随。
- 优先保持在镜头可见区域；不能为找水钵跨图、触发出口或追到屏幕外。
- 正常移动靠走/跑归队。现行超过 400 像素瞬移属于补救逻辑；目标版仅在转场黑屏或不可见处允许安全重置，必须记录恢复原因，不能在镜头内闪现。
- 重算仍失败时，停止移动并等待安全恢复；不借关闭碰撞脱困。地图没有可站位置应报错并中止宠物生成。

### 3.3 玩家控制与活动反馈

队伍页提供“跟随活动”“紧随”“在此等候”三种模式，当前模式用图标和文字显示。

- 跟随活动：默认，停下后可在附近活动。
- 紧随：只沿队尾跟随和原地待机，适合窄路或玩家不想它闲逛时。
- 在此等候：仅本场景的安全站位生效；主人跨图或进入战斗时结束等候并交给场景/战斗规则，不留下丢失的宠物。
- “召回”是即时探索指令；在设置中提供可改键位，绑定前检查现有按键冲突。点击宠物的轻量交互入口同样可召回，不抢 E 键最近剧情目标。
- 环境动作不弹模态框、不锁主角移动、不把每次嗅闻都写入任务提示。靠动作、少量轻声和必要图标反馈；召回只需耳动/转头与归队。
- 主人刚离开时结束闲逛；卧姿允许短起身过程，归队不得因播完长动画而拖延。模式切换立即使旧目标失效。

## 4. 场景与兴趣点合同

只有登记过的兴趣点会触发功能互动，普通草簇仅支持随机嗅闻。不能从画面颜色推断“这里有水”“这里藏了物品”。

建议字段：`id、kind、scene、anchor、approach、show、enabled、cooldown、animation、onceFlag、effect`。`anchor` 是视觉目标，`approach` 是可站互动位置；两者分离，水钵实体不可站。单位在适配层统一，不能混用格坐标和世界像素。事件回调需验证当前场景、宠物身份及条件，已触发的一次性效果通过存档旗标防重。

| 兴趣点 | 前置条件 | 表现与结果 | 限制 |
| --- | --- | --- | --- |
| 公井水钵 | 收养大黄、钵中有水、站位可达 | 靠近低头饮水，街坊台词可响应 | 首期纯表现，不无限回复战斗资源 |
| 熟悉街坊 | 角色仍在场、人物允许互动 | 朝对方摇尾或短暂坐下 | 不挡主角交互，不生成完整人类对话 |
| 案件嗅迹 | 有任务前置且目标未完成 | 嗅闻、朝明确方向警觉，展示线索提示 | 不自动完成案件、不读取未开放地图；有非宠物替代线索 |
| 渡船 | 场景接管、已有犬类剧情 NPC | 伏低或紧张耳尾 | 停止跟随实例，不在船边自由走动 |
| 黑风寨 | 敌意状态未解除 | 紧随、短暂警觉 | 不自动开战、不跑向敌人；肃清后才恢复普通活动 |

进入地图时先判断剧情是否接管，再生成宠物；收养时移除原地点的犬类 NPC，任何时刻画面只能有一个大黄。兴趣点失效、中途离场、任务完成后取消当前目标，不能继续执行旧回调。

## 5. 战斗决策

目标使用有序规则，不随机掷技能。以下为**目标优先级**；现行代码护主先于治疗，需在阶段 B 修正，不能把此表当已上线行为。

| 顺序 | 条件 | 行动 | 无法执行时 |
| --- | --- | --- | --- |
| 0 | 不出战/休养、教学或主角单挑 | 不生成战斗单位 | 不暗中加技能或伤害 |
| 1 | 自身倒下或无合法行动 | 沿用战斗状态规则 | 不弹玩家操作面板，不挂起回合 |
| 2 | 主角存活且气血 ≤30%，治疗资源足够 | 舔舐主角 | 继续评估护主 |
| 3 | 主角气血 ≤50%，可护主，自身气血 >25% | 护主，消耗 6 内力 | 无资源、已有效护主或自身危险时继续评估 |
| 4 | 自身气血 ≤25% | 防御 | 不为护主反复自杀；本阶段不新增自疗技能 |
| 5 | 敌人存在未知弱点、可嗅探 | 嗅探 | 同条件按目标规则选择，不能读取隐藏弱点类型作弊 |
| 6 | 有存活敌人 | 普通撕咬 | 没有敌人结束回合 |

目标选择先按可合法攻击，再按气血比例低、已可利用的破势状态，最后用稳定单位顺序打破平局。技能实际消耗、疗效、揭示数量以共享技能表为准；不能在宠物模块复制另一份技能数值。舔舐仅治疗活着的主角，复活和治疗其他同伴须新增技能及独立规则后开放。

护主承担主角直接伤害的 50%，向下取整，只在敌方行动期间生效；不转移毒等持续伤害、不产生递归转移。持续至下一回合的具体失效时点以统一战斗回合语义明确测试。宠物倒下立即失效，负血量被夹到零；主角承担剩余伤害。战斗界面显示“护主：主角气血偏低”“舔舐：主角危急”等短原因，详细说明悬停可读。

训练倾向仅调整非紧急决策：护主型在正常血量下更偏防护，追击型偏攻击，好奇型偏嗅探。紧急治疗、自身保命和技能合法性始终优先；首期使用平衡型，三种倾向的数值须平衡验收后再开放。

## 6. 成长、照顾与关系

### 6.1 成长与装备

保留现行跟随主角等级自动成长；大黄每级 3 点按力量、身法、体魄依次投入。前期不再叠加独立宠物等级与可刷战斗经验。成长来源和下一次变化在详情可查，不让玩家误以为宠物需要分配人类属性点。

仅开放一个佩饰槽（项圈/铃牌等），装备必须标记宠物适用；显示真实装备图标与前后数值。人类剑、甲、秘籍拒绝装配，原因清楚；卸下返还背包一次。新佩饰先写用途、数值来源及资产登记，再生成图。

### 6.2 照顾

- 喂食显示食物图标、背包数量、恢复量及可用条件；点击立即执行，不用占满屏幕的纯文字选择。
- 满气血时普通恢复食物不可消耗；用于关系的零食单独分类和每日上限，避免消耗同一馒头却产生不同隐藏效果。
- 休养由玩家切换：探索仍可同行并减少活跃动作，战斗不参战；安全休息后恢复并显示结果。不在挂机时间内扣血、扣信任或永久逃跑。
- 战斗后气血/内力按合法结算保存；失败按统一战败恢复规则，异常中断不写入临时残血。
- 未来三年培养中，长期照顾由一次活动或事件结算处理。不得未经验证直接将探索秒数换算成月度衰减。

### 6.3 信任与训练（阶段 C）

建议信任 0–100，展示“熟悉、信赖、亲近”三个阶段及当前进度；收养初始 20，40/70 为后两阶段起点。该数值为设计起点，未实装。正常照顾、剧情互动和训练提升；不重复刷同一个动作。缺席、切图、离线不降信任。信任影响回应动作和可训练倾向，不影响是否服从基础召回。

训练通过明确的活动卡学习“紧随”“等待”“嗅迹”等能力：说明耗时、消耗、前置与结果；基础跟随、召回不要求先训练。三年培养时间系统未落地前不让训练按钮假扣月份；原型训练事件需显式标注即时，不混入长期日程。

关系事件必须有地点、前置、一次性标记和无宠物替代路线。未加入、休养或剧情接管时禁止触发错误事件。

## 7. 桌面宠物面板

在队伍页设独立宠物区域，可进入完整详情；视觉沿用[江湖行卷](presentation.md)。不把所有内容挤成一张文字卡。

| 区域 | 必须直接展示 | 交互 |
| --- | --- | --- |
| 主展示 | 大黄清晰的完整犬类图像、名字、同行/休养、当前活动图标 | 切换探索模式；召回入口 |
| 状态 | 气血、内力、等级来源；信任阶段（实现后） | 悬停显示数值、来源和恢复方式 |
| 佩饰 | 实际项圈图标、空槽形态 | 悬停比较，点击装备/卸下 |
| 技能 | 撕咬、嗅探、舔舐、护主各自图标，未学技能锁定 | 详情显示效果、消耗、触发条件与决策顺序 |
| 照顾 | 可用食物图标格、数量角标、休养按钮 | 禁用态说明满血/不足/当前模式限制 |
| 训练 | 已解锁能力图标、当前倾向 | 未实现模块不显示可点的虚假按钮 |

技能使用具体形象区分：牙齿/爪痕、鼻端气味、舔舐与水滴、犬护在人前的轮廓；不能四个技能复用同一爪印加文字。说明层不遮目标、不出视口，键盘焦点可读。召回不操作战斗模式，休养变更仅在下一场战斗生效，战斗中按钮禁用并说明。

## 8. 素材与生成规范

先登记行为、使用尺寸、参考形象、动作与脚底基线，再制作；生成结果只能算候选，经过组表、实机检查后才进入 assets。继承既有大黄黄棕毛、深色耳、卷尾、体型与俯视投影，不另画一种犬。

| 资产 | 内容 | 验收重点 |
| --- | --- | --- |
| 探索基础 | 四方向 walk/run/idle，复用现有条带 | 运动步幅随距离推进，爪底不漂；不能放大重采样后换画风 |
| 探索新增 | 嗅闻、坐下/起身、趴卧/起身、饮水；警觉优先复用耳尾变化 | 姿态变化靠骨骼，身体大小不跳；饮水鼻端朝钵口，起身接行走 |
| 战斗 | 撕咬、嗅探、舔舐、护主、受击、倒下 | 护主和治疗能辨别，不把探索坐卧直接当倒地 |
| 面板 | 清晰犬类完整图像、佩饰、技能、活动模式图标 | 在实际 48–72px 图标尺寸下仍可辨；不用放大模糊小精灵代替展示图 |
| 音效 | 轻嗅、爪步、喝水、召回回应、警觉短吠 | 闲动作低频，不连续吠叫；环境/动作音量和静音设置一致 |

探索管线基线见[动画管线 §6.7](../anim-pipeline.md)；战斗见[精灵规范](../battle-sprite-spec.md)。坐卧维持同一地面接触点，镜像允许范围按形象对称性登记；铃牌等不对称装饰不能直接镜像。夜景沿用场景光色，不单独给犬画强白光。

每条新增动作记录 `petId/action/direction/source/frames/duration/anchor/scale/palette/review`。原始图、处理图和运行图分开；评审至少包含四方向接触线、与主角同深度比例图、昼夜实机图、完整一次动作录像。参考图和构想图不能当实机验收证据。

## 9. 数据、模块和存档

建议继续以 `S.pet` 表示当前同行宠物，`S.pets[id]` 存持久培养数据，保持旧档兼容。只保存属性、资源、佩饰、信任、倾向、同行/休养和一次性事件记录；探索模式“等候”不跨图持久化。

瞬时状态单独保存在运行对象：当前状态、计时、目标兴趣点、路径、归队锚点、上次寻路和恢复原因。存读档后重新生成安全队尾位置，不保存过期路径、DOM、Promise、战斗单位引用或函数。

- `js/pets.js`：物种登记、成长、战斗策略、状态迁移；新增探索控制器不得在此自行渲染第二个犬。
- `js/scene.js`：提供坐标、碰撞、寻路、队尾锚点及唯一绘制实例；人类仍按原队列跟随。
- 场景脚本：只登记兴趣点/接管要求和事件条件，不复制 AI 循环。
- 菜单：读取统一模型，操作通过校验入口；不靠修改 DOM 当作存档更新。
- 技能/物品表：技能数值、宠物适用和资源效果的唯一来源。

迁移按版本执行且幂等：先迁出 `S.party` 中旧 dog，再转入 `S.pets`，保留伤势和佩饰，删除旧 `S.mates.dog` 前确认转换成功；缺字段填默认、不重置已有培养。未知 petId 保留记录但不生成运行单位，提示资料暂不可用；未知物品不静默删除，隔离等待兼容处理。

运行循环使用主循环 dt，不新增长驻 setInterval。切图/读档/战斗开始解除旧目标和回调；退出战斗重建探索对象。宠物未加入时不扫描兴趣点；对象存在但休养时不生成战斗单位。所有耗物/奖励操作先校验再提交一次，不能由每帧状态反复发放。

### 9.1 新增字段建议与兼容入口

以下是阶段 C 的字段草案，接入前确定迁移版本并补测试。保留既有字段名，避免迁移时把旧装备和伤势覆盖掉。

```js
// 持久数据示例；字段数值为设计起点，不是当前存档格式的声明。
S.pets.dog = {
  st: {str: 4, con: 5, agi: 7, wil: 3, wis: 2},
  lvSeen: 1, hp: null, mp: null, equip: {acc: null},
  trust: 20, tendency: 'balanced', duty: 'active',
  followMode: 'free', learned: ['follow', 'recall'],
  events: {}, careLedger: {}
};
// 瞬时对象示例；绝不序列化进存档。
// {state, stateTime, targetId, path, anchor, lastQueryAt, recoveryReason}
```

`hp/mp=null` 沿用现行满资源语义。`duty` 使用 active/resting；持久 `followMode` 只保存 free/close，wait 属于瞬时场景模式。信任与能力不能仅因字段新增就跳过收养条件。`careLedger` 的日期来源须接游戏时间系统，不用电脑日期或离线时长计算关系奖励；阶段 C 实现前不进行每日衰减或奖励重置。

统一操作入口建议为召回、设置模式、设置休养、照顾、佩饰更换、场景接管/释放；每个入口返回成功状态和可显示的失败原因。供界面读取的模型给出当前状态、合法操作、真实数值、技能触发说明，不让菜单复制战斗判断。

## 10. 扩展流程与禁止走偏的情况

新增物种必须补一张登记表：身份与收养剧情、移动地形、体型/接触点、行为状态、食物/佩饰、战斗技能与原因、成长来源、旧档兼容、资产清单、无宠物解法、验收用例。缺少任一关键项先完善登记，不直接批量生图。

开发顺序：规则与场景用途 → 状态/数据契约 → 最小可运行行为 → 动作参考与生成 → 本机实机验收 → 更新现行文档 → 发布。新内容不能把以下情况当作完成：随机偏移模拟闲逛、仅文字写“喝水”、到处瞬移防卡、从地面颜色推断互动、训练系统只有按钮、从图片猜碰撞、宠物偷读剧情隐藏状态或每次刷新重复奖励。

完整验收入口：[宠物系统验收清单](pets-acceptance.md)。新增规则须同步增加与其风险对应的用例，不把“页面无报错”当作行为与画风通过。
