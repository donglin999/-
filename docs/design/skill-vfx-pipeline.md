# 技能特效生成流程（概念图 → 素材 → 编排）

> 2026-10-14当前规则：[功法在原位简短施放，由目标处特效命中](combat-presentation-boundary.md)。参考场景中的角色不冲向敌人完成技能接触；群攻、多段结算按招式合同。用户本轮要求不自行生成特效，此轮只补描述与修正现有播放。

状态：现行　最后核对：2026-10-19（原记：**用户确认的标准流程**（2026-10-07）。以后新做或重做技能特效，默认按本页执行。归云谷剑法五档是第一套按此流程完成的样例，见[剑法特效 · 东方剑侠方向](sword-vfx-xianxia.md)。本页只讲"怎么做"，各招具体做成什么样写在各自的设计文档里。）

## 为什么是这个流程

前三轮剑法特效的教训：

| 轮次 | 做法 | 用户结论 |
| --- | --- | --- |
| 第一轮 | 程序逐点画，题材沿用参考视频（法阵、陨星、裂隙、光柱） | 偏西方魔幻 |
| 第二轮 | 程序烘焙素材（月牙、云、飞剑、远山）再组合，预算提高 9–28 倍 | 还是不够精细 |
| 第三轮 | **先生图定概念图 → 按概念图拆出单体素材 → 程序编排运动** | 认可 |

结论：精细度来自素材本身，靠程序画形状或堆粒子都补不上；程序擅长的是运动、节奏和镜头。所以由生图负责"长什么样"，由程序负责"怎么动"，两者分开。

| 步 | 做什么 | 产出 | 工具 | 用户确认 |

## 1. 定范围与关键帧

- **依据**：[招式合同](martial-review/move-contracts.md)、[特效分镜](../archive/design/martial-review/vfx/README.md)、`catalog.json` 的 `visual` 字段。从中取机制、段数、命中时点和"图形身份"。特效不得改动任何战斗数据。
- **关键帧数量按品阶递增**：

| 品阶 | 关键帧 | 说明 |
| --- | --- | --- |
| 丁 | 1 | 命中 |
| 丙 | 1 | 第二击 |
| 乙 | 1 | 贯穿或主命中 |
| 甲 | 2 | 蓄势、主命中 |
| 绝 | 3–4 | 起势、转场、主爆发、收势 |

- **品阶递进规则**沿用[剑法特效第 4 节](sword-vfx-xianxia.md)：每升一档都要多一层能说清楚的设计；压暗、暗角、推镜只给甲、绝；换景只给绝。
- **题材**：东方仙侠／武侠意象（剑气、剑痕、飞剑、祥云、水墨山水、天光、竹叶等），按门派与用途配色。禁止西方魔法阵、符文圆环、五芒星、闪电、陨石、空间裂隙、无设定依据的龙、宗教符号、文字与界面元素。

## 2. 合成参考场景

把评审页的战斗场景（街景、施法者、目标）按游戏实际站位合成一张 1536×1024 的图，作为所有概念图的生成输入。这样概念图的构图、人物位置和像素比例都和游戏一致，后面换算素材尺寸也有统一基准：1536 宽对应游戏 640 特效像素，约 2.4 倍。

实现：`tools_fx/gen_sword_vfx_concepts.py` 的 `build_reference()`。最近邻放大，不改人物。

## 3. 生成概念图

- **工具**（2026-10-17 起）：用生图源登记表的当前源，现为 302.AI（`python3 tools_common/imggen.py --prompt-file … --out … --ref <参考图>`），见[出图约定](../art-pipeline.md)“生图源登记与切换”。以下 codex 的用法只在切回 codex 源时适用：会话里有 codex MCP 时直接调用；没有时用 `codex exec`，配置与项目 `.mcp.json` 一致：`--enable image_generation -c model="gpt-5.6-sol"`，加 `--sandbox workspace-write -C <输出目录> -i <参考图>`。
- **提示词首行**必须是 `Model: gpt-image-2.5（使用 gpt-image-2.5 生图模型）`。内置工具由服务端选模型，回执里只记"提示词要求 gpt-image-2.5"，不写成已确认。
- **提示词结构**：通用风格段 + 本帧描述。
  - 通用风格段要写明四件事：
    1. 在参考图上叠加特效，人物与场景保持不变；
    2. 高精细 16-bit 像素画（硬边、有限调色板、深色描边、多阶明暗、有序抖动、局部发光、大量细碎光点）；
    3. 东方剑侠题材；
    4. 禁止项。
  - 本帧描述写：招式名、品阶、此刻画面里的主形、颜色、环境响应、舞台明暗，以及与上一档拉开差距的设计层。
- **调用规则**：每帧一次调用、一次生图。要求 Codex 不改写提示词，生成后复制为 `<id>.png`。并发不超过 3。
- **记录**：提示词全文写入 `prompts.json`；每张写一份回执 `<id>.json`（提示词、尺寸、SHA-256、耗时、工具说明），Codex 输出保存为 `<id>.codex.log`。
- **评审页**：按招分组展示，附完整提示词，可放大，例如 `review/sword-vfx-concepts-v1/`。
- **用户确认**：概念图定稿前不进入下一步。不合格的帧用 `--only <id>` 单张重生，旧图先移走，不覆盖已确认的原图。

## 4. 拆单体素材

概念图每次是整张重绘，人物和背景会细微漂移，不能与参考图做差抠出特效层。正确做法：以对应概念图为参考，**每个特效元素单独生成一张**。

- **元素清单**：逐张拆解概念图，列出可复用的主形。类别包括：剑气、命中光爆、祥云、光束、天光、飞剑、涟漪、尘烟、气环、远山、特殊大招主体、收势形态。同一元素可在多招、多档复用；右翼这类镜像件只生成一侧。
- **背景二选一**：

| 背景 | 适用 | 运行时 |
| --- | --- | --- |
| 纯黑 `#000000` 平涂 | 纯发光元素：剑气、光爆、天光、光束、涟漪、气环、爆发 | 亮度转透明度后加色叠加 |
| 真透明 PNG | 有暗部或实体的元素：墨云、白云、飞剑、远山、锋面、尘烟、折翼 | 普通混合 |

- **提示词**：通用段 + 背景要求 + 元素描述。
  - 通用段要求：画风与参考图对应部分一致、只画这一个元素、居中留白不裁切、不要人物场景文字。
  - 元素描述写清形状、配色层次、朝向。**朝向必须写明**，例如"弧面朝左"、"剑尖朝左"，运行时据此旋转。
- **调用**：附图要写明"只作画风与内容参考，不要在它上面修改"。回执多记录背景类型与参考概念图。
- **自查**：逐张看透明是否真实（`mode=RGBA` 且有 0 值）、朝向是否与描述一致、有没有夹带文字或场景。

实现：`tools_fx/gen_sword_vfx_elements.py`，原图在 `art_sources/sword_vfx_elements_v1/`。

## 5. 整理成运行时素材

`tools_fx/build_sword_vfx_assets.py` 对每个元素依次做下面几件事。原图不改动，可随时重跑。

1. **裁边**：黑底元素按亮度大于 14 裁边，透明底元素按 alpha 大于 10 裁边。
2. **缩放**：按目标宽度缩到 640×360 特效像素空间，用 LANCZOS。目标宽度按该元素在概念图里的占比确定（概念图像素 ÷ 2.4），写在脚本的 `WIDTH` 表里。
3. **压色**：中位切分，压到 96 色，不加抖动。
4. **透明度处理**：
   - 黑底元素：alpha 取最亮通道，颜色反预乘，近黑像素全透明。**这一步不能省**，否则加色画到透明图层上会合成出黑块。
   - 透明底元素：alpha 量化为 5 阶，保持像素硬边。
5. **导出**：无损 webp 到 `assets/fx/<套>/`；`manifest.json` 记录尺寸、混合方式和来源 SHA-256；`contact.png` 是 2 倍预览总览，用来一眼检查全部素材。

## 6. 程序编排

**分工**：素材负责主形，程序负责运动、节奏、点缀和镜头。不要用程序重新画素材已有的形状。

运行时接口在 `js/wuxia-fx.js`：

| 接口 | 用途 |
| --- | --- |
| `WuxiaFX.load(base)` | 读取 `manifest.json` 并加载全部素材，战斗前调用一次 |
| `fx.img(layer,id,x,y,{a,add,rot,sx,sy,ax,ay,clip})` | 画一张素材：锚点按素材内比例，可旋转、缩放、翻转（负缩放），`clip=[u0,u1]` 做横向显隐（光束伸出、飞剑凝成） |
| `fx.pop(id,x,y,{life,delay,sc,a,vx,vy,spin,...})` | 短时素材实例，缩放与透明度随寿命插值，用于光爆、天光、涟漪、尘烟、碎云 |
| `fly(...)` | 素材沿路径飞行并带残影（素材朝左为前进方向，旋转 = 切线角 − π） |
| `blast(...)` | 命中组合：素材光爆 + 程序剑痕、碎光、碎片、星芒 + 白闪 + 数字 |
| `fx.spawn` / `shed` / `converge` / `motes` | 程序粒子：沿途碎光、旋聚、环境光尘 |
| `fx.tint` / `vig` / `zoom` / `shake` / `flash` / `hit` | 压暗、暗角、推镜、震屏、闪光、白／黑剪影 |

编排规则：

- **分层**：`back` 层在人物后面（远山、合围墨云、气环、涟漪、尘烟），`front` 层在人物前面（剑气、飞剑、光爆、压迫型云团）。
- **节奏**：起手缓、主行程前段缓收、末段骤然提速（`accel`），命中定形快，收势带阻尼。命中时点以分镜为准，并写进 `fx.once`；接入战斗后改为由真实结算驱动。
- **朝向**：元素提示词里写了朝向，编排时按朝向换算旋转；朝向不对就用翻转或固定偏角修正，不重新生成。
- **预算**：粒子数按[剑法特效第 4 节](sword-vfx-xianxia.md)的档位预算执行；素材实例和运行时光带不计入粒子预算。

## 7. 对照评审

- **评审页**每招下方附该招的概念图，点击跳到对应时刻（`SkillReview.seek(id, ms)`），并排对照构图、主形、颜色和层次。
- **截图检查**：逐个关键帧截图，与概念图比较。容易出的问题：黑块、朝向错、素材太小或太大、遮住人物、远山位置不对、白闪盖住细节。
- **性能**：用每帧模拟加绘制的耗时（平均、p95、最大）和粒子累计／峰值作为记录。素材首帧加载另计；低端设备测试单独做。
- **用户确认**后才能接入战斗。

## 8. 写文档

每套特效在自己的设计文档里写清以下内容：
- 范围；
- 概念图清单与确认状态；
- 素材清单（元素、来源概念图、用途）；
- 逐招时间轴；
- 预算与实测数据；
- 已知差异与未完成项。

参考写法：[剑法特效](sword-vfx-xianxia.md)第 0 节、第 0.1 节。

## 扩展到新招式

目前三个脚本的帧表和元素表是为归云谷剑法写的。做新一套时：

1. 复制三个脚本，改为新套名，更新 `FRAMES`、`ELEMENTS`、`WIDTH` 表。风格段里的题材描述按门派调整，例如拳掌换成气劲、掌印，医术换成药叶、回流。
2. 先复用已有素材，例如命中光爆、尘烟、涟漪、祥云；只为新主形生成新元素。
3. 在 `js/wuxia-fx.js` 注册新技能并编排；评审页按 `set` 筛选展示。

若做的套数多了，再把三个脚本合并为按配置驱动的通用脚本。

## 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| `codex exec` 报 "No prompt provided via stdin" | `-i` 会把后面所有参数都当成图片。提示词改从标准输入传：参数末尾写 `-`，内容走 stdin |
| 发光素材在画面上是黑色方块 | 黑底素材没有把亮度转成透明度。重跑整理脚本，确认黑底分支生效 |
| 透明底素材出现棋盘格 | 生图画出了假透明。单张重生，提示词强调"真正的 alpha 透明，不要画棋盘格" |
| 素材飞行方向反了 | 生成时朝向与预期不同。编排时用旋转偏角或翻转修正，并在元素表里注明实际朝向 |
| 概念图人物有变化 | 正常现象，游戏用的是原人物精灵，概念图只用来定特效。不要拿概念图里的人物当素材 |
| 生图很慢 | 单张通常 1–2 分钟，偶尔 10 分钟以上；放到后台批量跑，脚本会跳过已完成的项，可以中断后续跑 |

## 当前边界

- **不是逐帧动画**：素材是静帧，动作靠程序变换实现。剑气飞行形变、锋面压落挤压这类需要逐帧形变的地方，下一步可以补逐帧序列，用 Aseprite（或其 MCP）做调色板锁定、洋葱皮对帧和图集导出。
- **只是预览**：已完成的特效还在评审页，未接入战斗，也没有音效与低端设备测试。
