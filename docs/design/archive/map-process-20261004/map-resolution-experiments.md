# 大地图清晰度实验与分块开发门槛

2026-10-03。本轮只验证栖河村北半图，不替换可玩背景。实验页面：`http://127.0.0.1:8774/review/chapter1-preview-v3/quality-comparison.html`。

## 实际结果

| 方式 | 实际参数 | 结论 |
| --- | --- | --- |
| 当前整图 | 1536×1024，室外worldScale=2 | 场景放大后原生密度不足，小房间使用独立图片、较小缩放，清晰度较好 |
| 直接要求4K | 请求3840×2560，PNG实际1536×1024 | 没有拿到原生4K；颜色更亮、局部更锐，但不能据此称4K素材 |
| 整图加坐标提示裁切生成 | 返回1536×1024 | 模型重构构图，范围不准确，拒收 |
| 精确裁片参考分块 | 两块832×555参考，分别生成1536×1024；重叠128原图像素 | 局部瓦片、工具和叶片更清楚，单位场景宽度采样约1.85倍；轮廓与色彩仍漂移 |
| 硬切拼接 | 原图x768处切换两块 | 晒药架、墙体和树冠断层，拒收 |
| 重叠渐变拼接 | 原图x704–832融合 | 架子、墙和树冠双影，拒收 |

拼接输出3072×1110是合成画布尺寸，两块素材的真实密度约1.85倍。合成阶段再放大不增加生成细节。当前工具未提供显式输出尺寸参数，本轮只能提示要求4K并读取实际PNG头确认，不能推断所有生成渠道都不支持4K。

## 本轮复现

1. 以 `village-preview-chen-clear-v4.png` 为几何与风格母图。
2. `tools_scene/prepare_quality_tile_references.cjs` 用Canvas精确裁出左(0,0,832,555)、右(704,0,832,555)，不对裁片做锐化或伪增细。
3. 内置imagegen分别重绘；右块额外参考左块风格。实际提示词保存为 `art_sources/chapter1_preview_v3/quality-experiments/prompt-tile-*-exact.md`。早先整图请求、坐标裁切尝试的完整提示词未恢复，只记录请求意图与实际结果，不伪造精确复现文本。
4. 对比页使用相同原图坐标、相同显示尺寸，可显示旧碰撞轮廓；用 `tools_scene/capture_quality_comparison.cjs` 保存17张比较截图。
5. 各张截图实际打开；同目录 `visual-review.json` 保存判定与图像哈希。素材尺寸、哈希与参考参数见 `art_sources/chapter1_preview_v3/quality-experiments/manifest.json`。

## 下一轮采用的分区约束

不能把生成范围简单按固定方格切开。先标出完整建筑、墙段、桥和大树的所属区域；跨区的物件由一个区域完整提供，另一块不得重复生成。尽量在空地、道路或低对比地面上拼接。

- 画板先标固定世界坐标、成人高度92、相机与色彩参考、每区域的生成密度。每块图记录sourceBounds和实际PNG尺寸。
- 共用边缘须从同一已确认图层复用，禁止两边分别重画后用透明渐变掩盖偏移。不能稳定锁边的生成结果，先拆成独立建筑与地面图层，再组合。
- 建筑根部、墙端、门洞和道路宽度都属于几何约束；局部更精美但移动门口或改变屋身宽度仍拒收。
- 每块完成后先以实际游戏镜头审查；随后在跨区路径与每条拼接线截图，检查双影、颜色断层、缩放与遮挡。新轮廓须重新生成占位和前景，不能直接沿用母图碰撞。
- 验收同时保存失败图和原因。至少通过局部近景、跨区行走、接缝近景和全图整体四项，才能替换可玩地图。

本轮确认了分块可以提高局部细节，但没有完成无缝高清大地图。当前游戏仍使用已修订陈家入口和碰撞的1536×1024背景。
