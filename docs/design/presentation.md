## 桌面界面：江湖行卷

目标分辨率为 1280×720 和 1920×1080；按固定桌面界面构图，不为了手机缩窄而牺牲信息密度。江湖行卷是可直接操作的 RPG 角色界面：**角色、装备、物品和武学本身可见，文字服务于识别与说明**。沿用宣纸、淡墨、朱印、深墨和少量赭金的风格；墨色承担层级，纹饰只用于边框和标题，不覆盖内容。参考成熟单机 RPG 的布局密度和逐格操作方式，不复制其具体图形、角色或排版。

| 区域 | 宽度与功能 | 不得退回的表现 |
| --- | --- | --- |
| 顶栏 | 常驻系统页签、当前角色、银两和关闭入口；页签含角色、行囊、装备、武学、队伍、任务、设置 | 当前页有清晰高亮，不能只有文字和细线区分；武学与心法同在“武学”页内 |
| 角色列 | 可切换的主角与队友头像、血/内力与身份；犬类使用物种相称的剪影 | 重要角色可快速找到；空队位不抢已入队者的注意力 |
| 主展示 | 主角及重要同伴至少半身立绘，统一头顶和腰线基准；立绘与装备槽、属性或修炼主题组成一个稳定画面 | 不把大面积纸张留白当成主内容；不能让站立小精灵替代主要立绘 |
| 内容区 | 装备按身体位置直陈、行囊是可扫描的图标格、武学按已学招式与心法分组陈列，任务有阶段和地点 | 不靠下拉选择或纯文字表格才能知道拥有何物；空格和锁定格仍有明确形态 |
| 说明层 | 鼠标悬停或聚焦即显示名称、类别、效果、条件、获取线索；点击执行装备、使用、修习等动作 | 说明不遮住被指向的格子，不溢出视口；无鼠标悬停时仍能通过键盘焦点读取 |

行囊、装备与武学共用 **48–72 像素的图像识别尺度**，具体栅格可按页变化，但同类格子、品质框、数量角标、锁定与已装配状态保持一致。武学页的招式和心法可用同页分区或子标签，切换时保留当前成员；已学、装配、主修、辅修与门槛不满足均可在格子上直接识别。技能详情说明作用对象、内力、熟练、下一重和限制；物品说明材质、用途、词条及装备比较。所有文字标注与图标含义一致。

制作顺序是：先出 1280×720 的每页线框，再以现有角色立绘和真实图标合成预览；复核信息层级、留白和悬停，再制作缺少的精细素材并接入运行页。预览图需由实际素材或清楚标记的占位组成，不把生成的整张 UI 图当成可交互实现。每页至少留一张全屏和一个悬停状态；角色、行囊、装备、武学及队伍页另留角色切换状态的实际游戏截图。

## 对话与人物视觉等级

左右与多人排布统一执行[对话立绘站位](dialogue-staging.md)：主角左、主要对话对象右；第三人中位，四人以上使用头像列与中位发言人。换话轮不将全部角色轮流塞到右侧。

对话正文在 1280×720 的最终显示尺寸不小于 18 CSS 像素，选项不小于 17 CSS 像素，行距至少 1.5；优先采用与宣纸水墨相容且笔画清楚的宋体/明朝体，不能为追求“古风”使用难读的书法字作正文。文字区从立绘之外的可读边界起排，正文、说话人和选项使用同一左边界；不要让字幕相对对话框主体无故偏左。对话不抢占可互动目标的整个画面。

同等级立绘使用固定的头顶、眼线和腰线范围；脸部大小与角色设定相符，不因原图透明留白不同而跳变。主角、可加入同伴和明确分类的重要 NPC 按各自必需包制作；普通任务与服务人物使用场景精灵或小头像，不因有名字、配音或参与重大事件就升成完整人物包。所有立绘在深墨和浅纸背景分别检查白边与透明晕圈。对话与战斗中人物等级的视觉差异应和叙事地位一致。

## 视觉层级

据点界面承担体力养成的常驻画面：当前据点、身份、季节、年月、当前时段、剩余体力 0—10、心情、活动成本、人物来访与邀约期限应在一屏读懂。菜单按[培养方案](cultivation.md)区分基本功、招式、生产、学艺、打杂、通信和闲逛；人物长谈通过闲逛进入。[路线框架](cultivation-routes.md)支持各线不同据点、人物和活动解锁，当前只细化周砚山居的画面与内容，归烬堂和巡江司的专属素材尚不制作。

具体区域尺寸、主画面与展开页线框、锁定提示、结果卡及输入规则集中在[培养界面设计](../archive/design/cultivation-interface.md)；课程、操作与首季样例从[体验方案](cultivation-design.md)进入。本页维护共用美术与表现要求，线框不代表正式素材已完成。

[大地图自由历练](world-map-journeys.md)每次占完整一月。出发前显示历练月份、下月月初的返程日期与目的据点、同行人和当前邀约变化；进入后改为地点探索与任务界面，显示可达区域、当前任务及已确定的行程时间，不显示一套可继续分配的据点体力。普通地图查看与局部走动不受现实倒计时催促。返程时用简短结算说明日期、据点、武学与物资、关系和未完成事项的变化，再开启新月体力培养。若未来有正式分叉，明确展示新的身份、据点、可用活动与旧事项后果，不改写开篇去向。短篇指定路线的外出仍显示其单独占用的时段。此节为界面目标，尚未实现。

| 对象 | 必需阶段 | 一致性要求 |
| --- | --- | --- |
| 萧白 | 现代装、入世便衣、山居练功／出游装 | 同一成年脸和发长；学剑后才持剑 |
| 叶蘅 | 村中医者、白鹇谷医师、山居同行 | 同一成年脸、体型、发色；两线以服装、医具与动作区分 |
| 苏芷 | 游方医者、后续白鹇谷关联状态 | 与叶蘅在颜色、发型、针囊轮廓上可辨 |
| 大黄 | 跟随、进攻、护主、受伤 | 一只宠物的连续外观，不把宠物当人类队员换装 |
| 场景 | 村址、山居四季、汉皋城街、谷中医舍 | 时间与季节能从光、植被和人流看出，不仅靠界面文字 |

立绘状态由角色、路线、季节事件和伤病决定。先确定角色阶段与事件需要，再制作或调整图。旧襄阳演示的素材可作复用候选，但“苍龙身世”图像与古代少年萧白设定不能直接作为新主线的权威外观。

对话、交互、任务和队伍菜单都应清楚显示“可做什么、会消耗什么、行动后发生什么”。任务接受或完成提示不能阻断移动；当前 `toast()` 已改为立即返回，后续仍须回归验收（原襄阳片段测试已随演示撤除）。
