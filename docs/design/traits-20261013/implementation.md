# 开发接入合同与验收清单

状态：现行　最后核对：2026-10-19

V2获取门槛已替换V1单事件授予：catalog.acquisition和routes.json是当前权威；旧种子事件只写路线进度，不能直接授予正向永久特性。

本轮是设计交付。当前character-growth-state.js的四项定义保持不动；未把catalog直接载入index.html。

## 唯一数据与实例

- catalog.json定义稳定ID、owners、category、polarity、grade、effects、trigger、duration、stacking、migration及integration。所有比率存0—1，概率加值单位probability_delta，面板固定量带hp/mp/item等单位。
- 实例建议：`{id,stage,acquiredAt:{clock,value},source:{eventId,transactionId,choice},expiresAt:null,counters:{},read:false}`；历史独立保存移除原因。人物主键与战斗/场景演员映射分开：hero/hero_short/hero_mid/hero_long同一角色，yin→殷红缨，不因立绘换装重新发特性。
- 人物是否已认识、剧情演员是否可见、正式加入、当前在队、当前可培养是五种事实。NPC初始特性可在认识后图鉴展示，不能因此建立可控队友。未接入的裴/沈/Cen武器合同不得标已生效。
- 旧`conditions`迁移同ID，不同时执行旧CharacterCondition.mul与新effect；旧minor_wound实例保留现有效果，不能因本包没设计其新获取事件而删掉。

## 触发与事务

原事件完整播放→原选择effects→计算此次事件原奖励（使用获得前特性快照）→授予/替换特性→一次原子保存→提交成功后通知。事件中断/刷新不得提前授予。`eventId + actorId + traitId + branchVersion`作为一次性键；同一事务重播不再次发奖励或加次数。

临危不乱在V2不再由救援发放：救援与抵达安全处只完成路线起点，必须完成后续独立护送、交接与复查，在新收官事件里授予。旧救援后获得提示也撤下。

培养以`facts[event+'_seen']`、`facts[event+'_choice']`及原p.id/period核对；仅有seen不能补互斥分支。首次出场“固有特性”由角色初始化授予；代码现有成长加成只映射展示，不再执行第二份effect。原事务窗口/费用不改；新增closing对白不占第二次4点活动。

## 时钟与结束

时钟必须有类型：permanent/story/rest/cultivation_slot/battle_end/owner_action。暂态按实际获得时钟记录，读档只计算当前时间，不用Date.now向前消耗游戏时间。换地图/开菜单/切人物不消耗期限。场数只数正常有效完成的战斗；纯预览、3v3旁观、回放和异常退出不消费准备状态。限时加成若同时有下一场/期末两个边界，以先到者清除。

“休整充足”新增最多2期时间上限属于下一版设计，现行仅一场。兼容旧状态没有获得时间时不猜剩余，按旧一场规则消退，并在下一次新获得时补全时钟。长期旧伤不可由通用clear('rest')删除，痊愈须人物事件记录。

## 结算接点

| 通道 | 接点 | 必须约束 |
|---|---|---|
| 经验 | CharacterGrowth.awardBattle | 已有主角120%，不重复叠乘；落后同伴规则继续 |
| 自然培养 | CultivationBalance.preview/核心resolve | 基础gain与martial xp分字段；不加成共享池购买 |
| 剧情历练 | SharedInsightPool的source奖励快照 | 旧receipt不可动态重算；本次授予不加成本次奖励 |
| 用药 | QiheUIModel.useItem及战斗物品入口 | 同一治疗函数、真实使用者、缺血封顶 |
| 商店 | quote与equipmentWrite采购入口 | 仅合格药食/材料，买卖防套利，原子扣款 |
| 防御/受击 | doDefend/真实hurt结算 | 首次token在有效伤害时消费，多段只有首个有效段 |
| 技能消耗 | UI skillCost与实际扣内力 | 退款/折扣只在真实效果后；零消耗不变负数 |
| 异常概率 | 既有状态施加计算 | 基础效果存在、按百分点相加、抗性和上限最后算 |
| 物品产出 | P02完成事务 | 计数保存、取消不计、额外来源分别展示 |

所有“生效”状态至少有一个实际消费者和相应显示，不允许只加菜单标签。效果作用受武器/阶段/场景条件限制时，UI必须显示当前不生效原因。

## 旧档策略

固有项从角色身份补标签，不补历史收益。永久特性只用确证的完整路线收官回填；单个旧事件只能补阶段，原奖励不重算；仅知seen而缺choice的鹅步不补任一分支，保留待回忆核对标记，不要求玩家重玩主线。临时状态不根据几年前的seen重新挂；受伤历史若后续痊愈事实存在优先清除。当前没有治疗事实的殷不因高好感清伤。

## 上线分批

A：统一标签UI、已有领悟/旧伤/疲惫/休整显示、实例迁移和过期。B：路线阶段记录、实质验证和收官授予；开始部分不直接送永久特性。C：防御token、武器条件项、Pei看破、三领队专长。每批必须实际结算验证；本包仅设计及预览，不提前把所有integration状态改成adopted。

## 必测场景

- 同一事件提交两次、在最后一句前刷新、保存失败：没有提前授予/双发。
- 救援两分支；方迟切磋输赢；对账两分支：对应约定同待遇。
- 鹅步circle/face_it互斥、旧档缺choice不猜；包扎ask_wound也有实际演练后才给。
- 殷夜归挂伤、谈往事不减伤、喝酒只殷本人、普通休息不治旧伤、痊愈不补满血。
- 方迟负伤→康复见证→除夕复查；没看可选康复也可在足够时间后检查，不能永远卡伤。
- 一次支持返1内力、无BP实际转交不返、未命中不消耗减伤、连续三击只第一击消费。
- 经验100→120不是144；共享池投入100还是100；旧receipt在新特性出现后不增加。
- 对非在场/未招募对象不可用药远程共享天赋；从别人面板切换不将旧状态写到新人物。
- 1440/1280及390视口、键盘/触屏、焦点、文本对比、长名称、无状态和已消退历史。

审计只跑静态来源与预览交互时，不写成以上完整运行测试全部通过。


## V2路线事务

保存`traitRoutes[routeId]={stages:{stageId:{evidenceIds,completedAt}},choice:null,closure:null,reward:null}`。现有剧情/练习事务只写可证明的阶段证据；同一证据不能被算作多次实操。检查所有阶段、资格、演员在场、收官选择和奖励未领后，原子写closure与唯一reward。stage计数满足也不得跳过最终验证。

两种收官选择同路线互斥，以routeId锁唯一奖励；不沿用早期goose_choice作为授予选择。旧V1测试记录单独保留为legacy_review，不自动视作路线通过；正常游戏尚未发过V1候选，不需要回收真实战力。

新收官通常是4点体力的一次普通活动，占一期内一个活动位置；不能把已有每一步重新收一遍费用。依赖新护送、调查、伤情复查的任务必须先排期，缺演员时预约，不用隐藏等待或随机触发卡死。

验收新增：仅完成种子事件必定不授予；完成全部阶段但未收官仍不授予；两次同一练习证据不计两次；收官保存失败不发奖；二选一不能重播拿另一项；补做与原窗口采用同难度条件；关键任务允许非战斗解法；失败重试只补失败部分。

照护收官按routes.final_event.cast_variants选择一个实际满足在场条件的演员版本；两套对白不能混播。谷内叶蘅和城内苏芷均需真实会面/交接，不因同一成长路线把缺席者硬搬进场。
