# 特征与状态 UI 设计

状态：现行　最后核对：2026-10-19

目标：沿当前江湖页的浅纸色、墨绿与朱砂做统一“特征与状态”区域，吸收用户截图的信息密度与标签交互，不照搬黑色底板。预览为独立设计页，不替换当前正常游戏。

## 桌面布局

- ≥1200px：左侧168px人物目录；中部约300px立绘、姓名/等级/关键面板；右侧剩余宽度为标签及详情。主角名字用萧白，NPC标签不默认可入队。
- 标签区域标题“特征与状态”，旁边显示当前生效数量。筛选：全部、固有、经历、增益、伤病、利弊并存；已消退只在历史筛选，不占当前标签。
- 标签为小图标+2—6字名称；一行3—4枚，自然换行。字体14—16px，行高1.4，点击区域至少40px高。品阶用细色边/小字表达；正负性用图标和文字共同表达，不只依赖红绿色。
- 获得后不自动挤走当前选中项；名称超长省略但aria-label完整。原本没有的特性不显示成“未解锁灰格”，避免泄露角色剧情。
- 详情默认显示已选择项，桌面悬停/聚焦可临时看提示，点击固定；不让大浮框遮挡人物姓名或当前标签。依次显示：名称/类别/品阶、生效标记、具体效果、来源、时效、解除/互斥说明。

## 移动和键盘

- <760px：人物切换为横向按钮，立绘缩为头像式概览；标签2列，详情在下方独立块，无悬停依赖。不能让固定页脚盖住最后一项。
- Tab可遍历角色、筛选、标签；Enter/Space选中；焦点框清晰。标签使用button与aria-pressed，筛选使用aria-pressed；详情区aria-live=polite，切换不夺焦点。
- 图标沿既有线性图标语法：书页=领悟/记录、药叶=医疗、盾=防守、足迹=步法、钱袋=采买、酒杯=混合、绷带=伤病。预览图标用本地内联SVG/符号，不生成人物图片或新图集；正式落地再与现有图标注册核对。

## 标签状态与信息

永久：“永久 · 来自师母的账本”；按场：“剩余1场”；按期：“本期结束消退”；剧情伤病：“长期 · 需专门治疗”。休息清除与回合倒计时分开，不把“长期”写成“永久不可治”。未在当前条件下作用时显示“条件未满足”，仍保留标签并说明为什么。

详情里的数值写“暴击率+3个百分点”“购买药食便宜3%”，不写“战力提升”“察言+1”等难以核验的虚值。面板中的绿色小箭头只表示当前变化，不将原始属性改写。旧伤可展开基础值→实际值，治疗后保持当前血蓝。

## 通知与历史

沿已认可的小尺寸浅黄色渐变轻提示，约2.4秒；默认“记下了：问清再练”，副文“人物 → 特征与状态”。一次事务多项变动合成一条“特性有了变化（2项）”，点击定位列表；不让角色在对白里朗读获得+5%。标签有小圆点未读标记，打开后清除；不会因为重复打开触发获得动画。

被覆盖时提示“伤势缓解：负伤待养 → 伤口渐合”，旧阶段进历史。移除负面状态不能误报“获得痊愈加成”。正式面板只展示已生效数据；开发预览顶部固定“设计稿，未接入正式数值”，不得混作游戏完成截图。

## 预览操作

示例角色：萧白、叶蘅、殷红缨、徐令仪、岑霜、沈雁回；不使用固定数量文案，读取catalog.traits.length。可查看所有20项设计索引（含方迟/裴知古），不为缺少已登记立绘的角色伪造新头像。可切换伤势阶段、互斥步法与生效条件；只是内存演示，不访问localStorage或游戏状态。


## V2：稀缺路线奖励的展示

人物页默认只展示所选结业示例实际获得的结果，不能把全部后天候选铺成已拥有的标签。萧白第一年末默认是固有“历练领悟”＋修行路线择一；未完成路线时只有固有能力，临时休整单独显示。

详情必须写完整路线名、最早阶段和“收官后授予”；触发页列各阶段的实际要求、新旧事件状态、补做路径和收官对白。普通支线完成只在经历/行记记录进度，不弹“获得特性”、不显示半个特性加成。开发索引仍可看全20项，但明确是候选，不伪装成玩家当前拥有。

既有鹅步小事件的选择改为初试记录；预览里的步法二选一表示复杂路线收官选择。修行路线同理。只有收官才能显示获得通知，次数型实操不把重复刷同一期变成捷径。
