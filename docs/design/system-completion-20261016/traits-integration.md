## 2. 七条路线逐条施工合同

每行必须形成“来源→独立实践→问题处理→验证→收官”完整链。下列是接入检查重点，不代替原路线的确切事件ID、演员、费用和窗口。

| routeId | 本次应补的数据/事务 | 失败与替代路径 | 授予边界 |
|---|---|---|---|
| `route_escort` | `crisis/plan/road/independent/aftermath`逐阶段证据；新增护送记录人员、物资、路况判断与实际交接 | 没有早期原记录用等价复盘；绕行、求援、组织通过均可，不强制陆衡入队 | 第二年起合法预约，`tr_escort_closure`成功才授予`steady_in_crisis`；单场战胜不算人货交齐 |
| `route_evidence` | 两份获准查阅原件、至少两处独立来源、矛盾处理和更正留底；同一传闻转述不可算第二源 | 不会核验可请教；错判后补证更正；导师缺席排合法预约，不偷取叶蘅遗物 | 第二年合法入城行程起，`tr_evidence_closure`；不能把传闻或已看过对白当已证实 |

| `route_accounts` | 学习/核账/实际采购/处理短缺/退还余款或补齐交接，按原`learn/check/purchase/shortfall/return` | 原路线允许协商补齐和补凭据；本次建议采购任务提供定额预支并要求退余款，额度须进入任务经济账，不要求刷钱；重试保留正确账目 | `tr_accounts_closure`才给`careful_accounts`，真实花费由采购事务负责，收官不再扣已支付费用 |

| `route_care` | 认药/观察/学习/独立照护/至少隔1游戏期随访按阶段记录；同一病例重复用药不算不同验证 | 本次建议监督任务提供可登记的基础工具/药材，数量待经济账核定；医者缺席用已定义cast_variants的真实合法版本 | `tr_care_closure`给`bandage_practice`；谷内叶蘅/城内苏芷版本不可混播或搬来缺席者 |

除修行附着复盘外，现有收官定义为4点体力普通活动；它属于**培养时钟中的活动成本**。若路线实际到游历/城镇阶段完成，不得把培养4点体力机械扣到城市角色：需在该收官的合法排期版本里标明城市剧情时间点、资源成本和推进方式，引用[时间规则](../event-scheduling-system.md)。当前只标`needs_schedule_variant`，不能让城市收官代码凭空推进一期。这是接入前的阶段差异，不私自改原JSON全部费用。

### 证据实例与一事一次

建议保存：

```text
traitRoutes[routeId] = {
  version, ownerId,
  stages: {stageId: {evidenceIds, completedAt, sourceRevision}},
  choice: null | choiceId,
  closure: null | {eventId, transactionId, completedAt},
  reward: null | {traitId, transactionId, catalogueRevision}
}
```

`evidence`独立记录`id、actorId、eventOrActionId、attemptId、clock、place、outcome、sourceIds、payloadHash`。练习实例用原活动事务ID，不用“第几次打开页面”；故事阶段证据用完整完成事实，不只`seen`。两条路线能引用同一真实经历，但每路线不能把同一证据伪装成多次独立实践。核验记录保留来源组ID，独立证言按来源组去重。

授予条件为：该角色身份允许→阶段最早窗口满足→每个必需阶段成立→演员及事件合法→新收官选择明确→互斥组未结业→奖励尚未领。全部成立才能写`closure/reward`；在最后一句之前刷新、提交保存失败、回放、取消都不授予。

事务顺序沿[既有接入合同](../traits-20261013/implementation.md)：结算时先用获得前特征快照算原事件奖励，再赋予新特征，一次保存后提示。含对白或战斗的收官同时服从[长事件事务](world-events-save.md#2-一次行动的完整过程)：开始前校验并持久化一次成本与`costReceipt`，进入`executing`，最终才写奖励。首次开始写入失败不扣费；已开始而收官写入失败保留同一`executing/costReceipt`，不再次扣费、不提前授予，恢复原游标重试结算。只有父事件因技术原因整体放弃时，才恢复父事件开始前快照并一次撤销该成本；内部战斗重试不能再退父成本。已完成收官不可借回滚重选另一奖励。

`routeId+ownerId`锁结业唯一性，`eventId+ownerId+traitId+branchVersion`锁同一提交；重复通知不能再次增加数值。路线二选一不是可随属性重配洗掉的成长点，保持原已选经历，若以后允许改修须独立剧情和决定。

## 3. 伤病与暂态时钟

| 类别 | 接点 | 自动到期与恢复 | 不允许的替代 |
|---|---|---|---|
| 殷旧伤 | 已确认来源与治疗任务阶段 | 同ID三阶段替换；最终只接受负责页的痊愈事件事实，保留康复历史 | 休息、升级、通用净化、好感、普通药与重配都不治旧伤 |
| 方迟伤病 | 完整`gy_brother_hurt`→康复见证→合格复查 | 负伤/复养按目录；受伤期间陪练入口说明原因与补约；可选康复缺失时按既有补检查路径 | 降本人等级、自动招募、为避免卡关偷偷清伤 |
| 疲惫 | 真正守夜分支等已设计事件提交后 | 完整休息事务成功才解除，与休整充足互斥 | 看过负伤剧情但没守夜者不挂；菜单开关、现实过夜不恢复 |
| 休整充足 | 新版本真实休息按目录快照 | 已有实例沿旧一场；下一版“再推进2期或下一场”须补时钟后采用 | 旧档无获得时点不猜已过期，也不补发过去无数次休息收益 |
| 微醺 | 原剧情仅殷实际喝酒 | 下一有效战斗结束或下一期，先到者；通道尚缺时整体保持未采用 | 给主角/小豆同挂、只加暴击却漏负收益、从旧seen永久补挂 |
| 轻伤 | 当前旧定义/实例 | 沿`cleanse=treatment`；新发生事件另按已审来源配置 | 正常失败自动随机加伤、删掉旧实例或等同剧情旧伤 |

时钟必须显式为`permanent/story/rest/cultivation_slot/battle_end/owner_action`，不以`Date.now()`推进。城市只取剧情时间点，不换算成现实天数或养成月份。下一场状态是否在逃跑时消费的建议见[失败恢复](build-recovery-accessibility.md#2-b08每种战斗必须配置退出合同)；正式接入前须在唯一战斗结果适配层定一种规则，不能在`battle.js`和特征模块各扣一次。训练、旁观、回放、异常不消费；主线重试恢复战前状态，而不是额外复制同名BUFF。

状态派生不得改原始`st`；负面同字段取最强、正面同字段取最强后相乘；原状态与新特征同ID只执行一次。提升上限不补当前HP/MP，降低仅钳制一次。使用原始未修正基础面板，不把已经乘过旧伤的57攻击再乘0.4。

## 5. 实施批次、迁移与验收

1. **已有事实的显示与迁移。** 统一actorId映射，正常标签/历史说明，读取已有状态；未知ID原样保留不生效。先不接新奖励。校验菜单、战斗与状态计算同值。
2. **阶段记录。** 现有完成事件只回填可证明阶段；缺choice保留待核，不猜鹅步、守夜、治疗。新阶段保存证据及实际成本。不开收官奖励。
3. **收官事务。** 逐路线验演员/资源/排期/替代后开放，原子发一次。优先一条已可达修行路线作为正式试点，不能直接宣布七条全完。
4. **新增效果。** 各consumer完整实现、边界测试通过才将该条`integration`改成采用；微醺等阻断项保留关闭。旧同ID消费模块停用，避免双算。
5. **完整旅程核验。** 正常档从起点走到收官，核对缺钱、低练度、缺席、失败补做和读档；只读预览不计这一阶段证据。
