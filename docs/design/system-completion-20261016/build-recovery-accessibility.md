## 1. A01：四类投入分开，不把草稿取消当退款

| 对象 | 现状 | 建议默认 | 必须保留的事实 |
|---|---|---|---|
| 未提交加点 | 当前菜单草稿可重置 | 继续免费取消，无事务、无退款 | 原已提交点数与属性不动 |
| 已分配升级属性点 | 当前只保存合并`st/pts`，没有完整来源账 | 安全休整点战外免费重分**有证据的升级点**；费用与地点仍待采用 | 人物等级、经验、出生五维、培养成果、剧情加值不退 |
| 已投入江湖历练 | 等级/已学功法消费已接入；详细显示账截断保留最近100条 | 已完成消费不退款、不转人、不转技能；保留装配自由，防止反复重置复制等级收益 | source一次性领取、spent及余额守恒、授业资格、已完成升级 |
| 自然练习、功法重数、永久根基 | 真实学习与培养成果 | 保留；换武器/换运转功法不抹掉，也不折银两或历练 | 原教学、重数、练习记录、永久成长以及路线收官选择 |

免费属性重配是本轮推荐方案，原因是属性选择不应永久阻断转流派；它不产生钱或新的成长。可低成本收费的替代需与经济负责页联合核验，当前不擅自写一个价钱。**本轮未选择“退款已投入历练”**：现行账本不足以逆推全部历史消费，且返还经验会涉及升级点、已满足的门槛和已完成剧情。若以后允许，须单独决定可逆范围与历史来源迁移，不能用当前等级反算退款。

换装和换已学主动招式沿原有战外规则；主辅内功切换及其恢复代价沿[武学规则](../martial-review/rules.md)，该页的“休整后免费切换”仍是方案，不在这里假称8792已取消旧不稳定期。

### 来源账与旧档

新增建议字段：`growthAllocation={version, baseline:{st,sourceRevision,evidenceIds}, allocated:{str,con,agi,wil,wis}, unspent, mutations:{transactionId:receipt}, migrationStatus}`。`baseline`只包含已证明的不可重配原始五维；装备、内功百分比、伤病不写入其中。永久培养若由独立字段派生，不再次叠进baseline。

新增正式加点时记来源与各属性投入；`unspent+sum(allocated)`应等于可重配点总数，每次迁移与提交都核验。证据必须持久保存，不借只留最近100条的历练显示账恢复永久加点账。

旧档没有完整来源时：保持现有战力；将迁移时的合并`st`冻结为旧基线，仅对迁移后能追踪的升级点开放重配，界面明确“此旅程早期投入未记录，保留原属性”。不能根据`3×(等级−1)`从五维硬扣，因为人物固定入队、旧共享等级迁移、脚本奖励与历史调试都可能不同。以后能提供确定旧版本基线的迁移器再拓宽范围，每种版本单独审计。

### 转流派操作合同

入口为人物属性→调整已分配点，角色必须正式加入、当前在场并可培养，不能在战斗、对白、旅行事务或其他未提交编成中操作。知古可否拥有可重配升级点依其见闻成长负责页，不把普通战斗经验自动接给她；宠物不进入此入口。

先显示可重配总量和不可动基线，再给属性草稿、新武器与技能有效性预览。原加点上限`8+本人等级`仍约束**本次增加分配**；历史越界的冻结基线保持但不能继续增加，不能静默削减旧战力。装备属性不参与这个限额。

确认页并列：人物、前后五维、前后派生值、当前HP/MP变化、失效装备/技能与原因、尚未分配点、消耗（推荐0）。导致武器不满足门槛时先把该项标为待卸下，确认时一次完成卸装入包；背包/装备唯一性校验失败则整个操作不发生。已学技能留在已学列表，但不可用项不被自动施放。

`quote`只读；`commit(actorId,baseRevision,allocation,transactionId)`重新核对角色可用性、余额、上限和物品归属，在副本上算结果，保存成功后替换内存并通知。同一事务再提交返回原收据，异版本草稿要求重新预览。取消、刷新、保存失败都不扣费、不归还第二遍点。

重配沿现有状态变更的血蓝原则：`afterHP=min(beforeHP,newMaxHP)`，MP同理；提高上限不自动补满，降低后重新升高也不返还被截断部分。不能通过重配绕过疗伤、恢复或获得无代价治疗。[可复算例](build-recovery-accessibility-calculations.json)覆盖守恒与降低上限再恢复。

## 2. B08：每种战斗必须配置退出合同

当前[battle.js](../../../../xiaojianghu-legacy-prologue/js/battle.js)仍保留无`noLose`时“回旧庙/扣半银两”的通用分支；`training`回滚主角血蓝与背包；异常清理恢复战前相关状态。调用方逐场覆盖，不等于全类型已有统一恢复。**以下表是拟替代旧兜底的目标设计**。

| 类型 | 成功与普通失败 | 资源与恢复建议 | 退出位置、后续与逃跑 |
|---|---|---|---|
| 教学/教习叫停 | 按训练目标记录稳/急/未演示；失败能复盘 | 参与者战前HP/MP、物品数量恢复；不发可刷经验钱；一次性教学事实独立 | 回教习前安全站位；可重试或结束，未教授动作不能硬锁 |
| 合意切磋 | 胜负各自对白，不等于永久敌对 | 采用训练回滚；首次完成奖励单独receipt，不因重试重复发 | 同一约定地点；开战前提供取消，战中投降作为切磋结果 |
| 擂台/比试 | 依赛制晋级/败退；不能赢后又被旧分支写败 | 不扣背包银两比例；报名费只在报名事务扣一次；官方包扎是否回满由该赛事明示，不隐含赠药 | 退到赛场休息点；再次报名/败者后续由赛事合同决定，首奖不重发 |
| 普通野战 | 清敌成功；全队倒地失败 | 拟不扣钱、不丢证物；失败保留已用消耗品，队伍恢复到可操作最低线`max(当前HP,ceil(0.3×最大HP))`，MP保留；此30%沿旧`noLose`起点作建议，非已确认全局值 | 最近已登记安全点；逃跑回接触前安全点并启用原明雷保护，不立即重锁同群 |
| 主线挑战 | 失败不销毁完成主线的资格；由已配置替代结果继续或重试 | 重试从本次战前快照恢复HP/MP/物品，不保留本次奖励/熟练；“接受失败分支”按具体事件资源账执行，先预览 | 回挑战前选择节点；玩家可调整合法配置；不得刷首次奖励或用失败补满原本已损的HP |
| 护送/救援 | 战斗赢不代表交接完成；目标损失按开战公开标准判定 | 可重试型回战前快照；继续失败线保留实际消耗，任务物件转为作者定义的损失/追回状态，不任意删除主线要物 | 指定接应点或安全路线；任务若只可一次，须有可完成主线的替代，不能临场宣布永久锁死 |
| 旁观/回放/评审 | 仅演示 | 不写正式成长、物品、准备状态场次、胜负计数 | 回原入口，不能复用正常结算 |
| 技术异常 | `aborted`，不是故事失败 | 恢复战前事务快照，零奖励零惩罚；已成功保存的胜利收据不可重复执行 | 保持可重试界面/安全原点；写档失败保留原档与错误说明 |

“最低可操作HP”“报名后包扎”“接受护送失败支线”尚未批准。可先按表审计当前每场调用，未选择具体恢复策略的生产战斗不得落回旧庙默认分支。

### 结算、状态时钟与物品守恒

一次战斗运行生成唯一`encounterRunId`，开战快照包含参战者而不只主角的血蓝/状态，背包与装备归属、银两、BP初始规则、位置、任务阶段和存档版本。首次奖励receipt持久化；快照不是可见存档列表中另一个免费复制旅程。

若战斗属于一个已经开始的培养/任务事件，记录`parentActionTransactionId`；战前快照位于父事件已提交一次体力或报名费之后。按[长事件事务](world-events-save.md#2-一次行动的完整过程)，父事件开始写入失败才是尚未扣费；开始成功后最终结算失败保留同一`executing/costReceipt`供恢复。战斗普通重试或技术异常只恢复本次战前快照，不另退父事件体力/报名费；父事件整体因技术原因放弃时才一次恢复父事件开始前快照、撤销父成本并关闭子战斗。子层不得再追加退款。已结算成功的父/子回执禁止回滚重领；场景加载失败只重载表现。

结束分两步：先生成`BattleOutcome`（见[growth-combat](growth-combat.md#5-b07战斗题型目标优先级与信息)），再由`recoveryPolicyId`和任务合同合成同一待保存事务；成功后才跳场景。成功收据已存在则展示原结果，不重发经验/钱。不能先扣半钱、再由剧情补回造成异常窗口。

- 正常胜/败/逃跑是否消耗“下一场”状态必须明示；本方案建议正常完成的胜败消耗，主动逃跑也消耗已进入战斗的准备状态，防止不断试开局保留BUFF。训练、回放、异常与重试回滚不消耗。该建议需与[特征接入](traits-integration.md)统一采用，不能两套时钟分别扣。
- 战斗中受控跳过行动、绝技调息、护卫到期继续按各状态负责页；“退出战斗”不等于治疗持久伤病。
- 普通失败不挂未经设计的永久伤病、不丢主线证物、不撤正式同伴资格。特殊剧情后果只写明示事件事实，不能藏在随机战败回调里。
- 重试回滚的是本次战前记录；不能恢复到理想满血、重掷任务固定掉落、退还开战前已花的钱。选择失败分支后旧战斗receipt终结，重新开始应走新任务尝试ID，首胜/首做仍由源事件去重。
- 逃跑成功不等于清场，不触发首胜奖励；逃跑失败沿本场行动消耗。明雷保护和刷新沿[野外](../wilderness-encounters.md)，不在这里新增秒数或刷新频率。

## 3. A02：难度与可访问性分开保存

建议三档，**尚未确定倍率和采用状态**。先确定行为差异，等B05阶段测试后才选定数值，不提前把“剧情0.7/挑战1.3”写入运行。

| 档位建议 | 改变内容 | 必须一致 |
|---|---|---|
| 剧情体验 | 新机制解释更细；主线失败可获明确准备建议；敌方伤害/续航减压若采用须经同套题型验证 | 故事结果、角色身份、已得奖励；关键解法仍由玩家选择 |
| 标准 | 以轻度、均衡可达档作为主线校准基线 | 不要求刷怪或绝学全收集 |
| 挑战 | 优先更成熟的合法意图组合、资源决策；数值增加需保持预告和反制窗口 | 不新增隐藏先手或临时免疫，不因难度锁普通剧情 |

切换只在战外可操作状态，下一次新战斗生效。重试页可先退出战斗后切换，显示采用档位；不在已开始战斗中改血量。任务领取与首奖不随切换重置；建议三档经济奖励相同，避免降难刷资源再升难领奖，独立挑战称号若未来采用须明确它记录整场哪档。当前不新增称号或成就。

`journey.combatSettings={version,difficultyId,changedAtEvent}`随旅程保存；`device.accessibility`为本浏览器默认，载入其他旅程不强行恢复旧字号/音量。首次加载缺字段沿现有默认，设置变更原子保存；不可写本地存储时当前会话仍可读到失败提示，不宣称“已永久保存”。

### 第一批可访问性规格建议

| 项目 | 行为与验收 |
|---|---|
| 文字与字幕 | 正常/大/特大三档按界面布局测试；文本容器换行、允许滚动，不裁掉角色名、数值或选项；同语音字幕可手动推进，周砚未配音仍完整可读 |
| 颜色信息 | 弱点同时有兵器/属性文字与图形；红绿状态同时显示正负、图标和数值；未知弱点用“未识破”，不能只靠色块 |
| 减少动态 | 可关闭震屏、全屏闪白、浮动镜头与高频粒子；保留攻击目标、命中时点、伤害/盾变化和状态结果。原位功法规则不变 |
| 音频辅助 | 战斗意图、关键剧情提示和交互反馈有视觉对应；音乐、效果、语音分开调整，静音能通过全部必达环节 |
| 键盘与触控 | 所有可点击目标可聚焦，焦点可见；返回/确认/切角色/调BP有明确映射；触屏不依赖悬停，长按不作为唯一详情入口 |
| 键位重绑 | 冲突时提示替换/取消，保留可恢复默认入口；确认与返回不能同时绑定同键，输入文字时不触发战斗指令；存储版本未知先保留原设置 |
| 演出速度 | 加速只改变等待，不跳过结算或把多段合并扣盾；暂停和逐条查看日志保留结果；减少动态与自动战斗互相独立 |
| 必达小游戏 | 失败可重试；若采用跳过，以等价“完成基础要求”的明示结果继续，不默认顶级成绩或稀有奖；不隐藏关键线索/授业事实 |

不把可访问性选项记为“作弊”，不降奖励，不因玩家字号大/关震屏改变故事。手柄支持需要单独决定设备范围与焦点模型，本轮不宣称已支持。数值档位、字号缩放比例、小游戏哪些可跳仍需实测/产品采用，但行为边界已在本页明确。

## 4. 验收矩阵与交付状态

| ID | 正向场景 | 边界/失败场景 | 通过标准 |
|---|---|---|---|
| A01 | 剑转拳重新分配后换装，技能栏显示实际失效项 | 旧档无来源、重放事务、存储满、角色离场、上限降低再升高 | 点数守恒、历史收益不回滚、不凭空治疗、一次保存；旧档解释清楚 |
| B08 | 上表每类至少一个真实出口；同伴也能回到可操作状态 | 同归、逃跑、末击异常、收据已存后刷新、背包消耗、主线物件；父事件预付后子战斗重试/父事件整体回滚 | 不落旧庙兜底、不重复奖励、不把技术错误罚成剧情失败；子重试不退父费，父整体回滚最多一次退款 |
| A02 | 同档键鼠/触屏/大字号/减动态完成必达战与教学 | 切档领奖、读档设置、无声、灰度、重绑冲突、自动战斗 | 结果一致、信息完整、关键内容可达；手柄未测不写通过 |

本轮仅做文档与算例检查。仍需用户采用的产品决定：属性重配是否采用免费方案；普通野战失败恢复线与擂台包扎规则；三档难度是否实施及其系数；小游戏基础跳过范围。既有确认规则的冲突已经单独纠正，不将这些推荐冒充确认。
