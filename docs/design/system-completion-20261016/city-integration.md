第一批接入必须提交一张映射表：`prototypeId → formalItemId/serviceId/sceneId/npcId/questId`。逐项写 `reuse / replace / unavailable`，未映射绝不回退到生成假物品。人物身份与位置以 `story-atlas.json`、负责人物页及事件排期为准；原型的“全部已认识”不能带入。

## 2. 可玩片段分段合同 C01

以下是**建议的实施拆分和验收范围**；完整M01—M08剧本仍为原负责页的设计稿，不在这里替作者新定事件结果。

| 阶段 | 进入与触发 | 成本、玩家选择与结果 | 失败、重复与保存 |
| --- | --- | --- | --- |
| P0 南门交接 | 读取当前正式南门交接事实，冻结当前装备、同行者、背包快照 | 不发原型220U、不默认持剑；现有同行者按归属与安排到场 | 中断后回同一交接点；已经完成的入城前事件不重发；只有迁移到可玩城市版本才提供下一步 |
| P1 M01入城与住处 | 正式地点/人物到位，依逐场稿盘查与住店教学 | 走普通对话与固定核验；保留叶家药箱归属；师父预付范围明示 | 分支仅写已发生事实；主线不要求窃取、鉴定等级或支付未知门槛 |
| P2 T1公开自由服务 | 首批建议开迎客店、告示墙、铁铺、药铺／杂货、人物普通对话 | 从真实铜钱买实际可装备物；接一个无战斗跑腿、一个已有条件的可选战斗任务；取消交易无成本 | 所有任务用真实地图位置与交付；空钱包仍有公开办事路径；战败保留恢复和继续方式 |
| P3 时间推进与证据核验 | 根据主线负责稿逐个接T2至F；剧本、场景或语音未完成节点不写成已经接入 | 推进前显示截止事项；支线可跳过；主线有普通查证与专业人物协助 | 不用原型“一句文字完成主线”冒充完整旅程；缺失必达内容时明确停在最后完成节点 |
| P4 F自由期与M08返谷 | 所有必达核验完成；玩家主动到南门选择回谷 | 汇总实际净现金、物件、关系、未完事；确认进入年一六月月初 | 取消留在F；确认后一次结算；不再领五月五期体力；历史城市存档按自身阶段继续，不能强制退回南门 |
| P5 后续服务扩展 | P0—P4端到端通过后，逐项接鉴定、典当、两条制作链等 | 只开已完成数据合同的服务；赌坊、通用耐久和完整锻造为候选后续 | 独立服务原型测试不替代正式背包、任务与保存验证 |

**第一段能够提审的最小闭合循环**：南门真实存档→M01→一个公开任务→购买与装上→可选真实战斗或无战斗完成→返回同一城内落点→保存重载。它验证接入能力，不能标成“五月城市篇完整”。完整旅程必须继续通过P3和P4，不借调试按钮跳过主线再声称正常返谷完成。

## 3. 状态归属与提交约定

### 3.1 单一事实源

| 事实 | 唯一持有方 | 城市模块可保存 | 禁止重复持有 |
| --- | --- | --- | --- |
| 铜钱、背包数量 | 现行 `S.silver`、`S.bag` | 交易回执 `txId`、引用的ID与数量 | 原型 `S.inv` 或第二钱包 |
| 主角／同伴装备与成长 | 现行角色、队伍、装备、成长模块 | 服务导致的变更请求与结果回执 | 因进城统一等级、统一换剑或抹同伴独立等级 |
| 主线／任务事实 | 正式剧情系统（汉皋域可用 `S.hg`） | 服务完成的事实ID引用 | 同时在城镇布尔表维护第二个“主线已完成” |
| 城镇节点、报价次数、店铺状态 | `S.town.hangao`设计域 | `schemaVersion, visitId, beatId, counters, stockTaken, receipts` | 现实日历自动刷新状态 |
| 关系、结缘、已认识人物 | 正式人物关系模块 | 服务对象ID、事件ID | 把原型PEOPLE.known全部复制为true |
| 空间与日程 | 场景／事件排期模块 | 最近安全返回点、有效任务导航 | 同一个具名NPC同时在店铺、义诊棚和队伍实体重复出现 |
| 有状态物件 | 待适配的托管/唯一物件服务 | 当票、鉴定结果、物主、来源的引用 | 同一件在背包和当铺同时可操作 |

**有状态物件先解决再启用**：可堆叠普通物维持数量模型。对于未辨旧剑、人物私物、当物，本轮推荐先用明确的唯一任务ID／专用物品ID和托管表承接，不给全游戏装备强加实例字段。唯一ID被典当时正式背包扣一件、托管表记一件；赎回反向转移。若同一物品ID可同时存在不同鉴定／强化状态，就必须先完成独立实例方案与旧档迁移，不能靠数组下标或最新修改时间区分。在此之前该服务保持不可用。

### 3.2 交易与保存

即时买卖与不含演出的领奖使用同一结构：校验前置→给玩家预览→提交时重新校验→在一份变更里扣钱/扣材/移动物品/写事实/发奖→保存→反馈。任一步失败，提交前状态不变；UI成功提示必须在提交成功之后。包含对话/战斗的长事件，开始扣费与最终结算分两次持久化，遵守[世界事件事务](world-events-save.md#2-一次行动的完整过程)：已开始后的收官写入失败保留原costReceipt，不再次扣费、不提前发奖励。

建议回执包含 `txId, kind, sourceInstanceId, beforeRevision, afterRevision, deltas, result`。重载时发现相同 `txId` 只显示结果，不重复执行。不能只给铜钱加防重标记却遗漏关系、道具、熟练和声望。

评审与正式使用明确的入口模式；评审中“重开”“改铜钱”“直达F”“全人物认识”不得写正式存档。导入旧城市原型sessionStorage不是正式迁移路径。正式存档升级按版本填缺字段、保留未知物品ID，不删旧人物剧情；迁移前保留一份本地可回退快照，不在载入时再次结算历史奖励。

### 3.3 失败与恢复

- 钱不够、库存不足、任务已结算、物件被装备、地点不可达：显示具体原因，不提交部分变更。
- 地图加载失败：提交前失败保留原节点和费用；提交后失败保留新逻辑节点、已付费回执及安全返回信息，画面使用安全占位并重试目标场景，不回退时间、不重复收车费。
- 战斗败北或中止：沿统一战斗合同恢复到任务配置落点；一次性消耗、重试成本和教学资源恢复须预先说明，城镇不另写全体一律掉钱规则。
- 离城结算失败：未提交则仍在F；已提交则恢复六月据点及同一回执，不能同时留一份城内可领与一份返谷可领奖励。
- 错过可选支线：标注可后补、当次结束或人物另有安排，不自动算成犯罪或战斗失败；主线必要核验仍有路径。

## 4. 局部违法与追责 A04

**现行边界**：[生活技能](../life-skills.md)记录的暂停决定不因本页恢复。保留的生活技能设计仅允许配置的非主线持物，成功品德−2／关系−1，失败品德−3／关系−2且该NPC警觉，10文赔礼恢复对应手段；许青空囊是合意训练，无真实物品与品德处罚。本合同不扩大至任意人物、店铺全库存或全城追捕。

新增的是让作者配置的剧情冲突可追溯的**局部事件数据候选**：

```text
incident = {
  id, sourceEventId, townId, targetNpcId,
  actionKind, consent, itemRef, outcome,
  witnesses: [npcId], knownBy: [{npcId, reasonEventId}],
  consequences: [{ownerSystem, targetId, deltaOrRestriction, onceKey}],
  repair: {type, cost, requiredEvidence, releases: [restrictionId]},
  protectedRoutes: [mainQuestServiceId], status, resolvedBy
}
```

`knownBy`只能由当场目击、明确传话、报案或玩家公开承认的事件增加；同队人物也不是自动全知。城市声望、势力声望、单一关系值（阶段瓶颈和经历另记）分别由后果配置写入，不能对所有组织统一扣分。所谓“修复关系”只解除该事件指定的限制，既有损失、已得物与一次性成果不会清空。

| 情形 | 触发、成本与后果 | 重复／失败／补救 | 主线与存档要求 |
| --- | --- | --- | --- |
| 合意训练 | 目标明确同意、空囊练习；沿生活技能规则 | 只计有效训练，不产真实物、无违法标记 | 不能因叫作“偷取练习”污染城市声望 |
| 已配置普通偷取 | 只有开放此技能版本且对象有显式持物时可用；先展示风险 | 一件物成功取得一次；失败按原规则警觉，10文赔礼只恢复该NPC对应手段；已取库存不刷新 | 固定主线对话、合法交易与必要核验保留；没有目击的人不因此改对白 |
| 剧情揭穿／斗殴 | 只由逐场稿的既定选择触发，不能以“威慑按钮”替代整场剧情 | 战斗、赔付、组织后果由该场明确；不能照搬窃取10文赔礼洗掉所有事件 | 固定证据与必要服务提供代理人物或事后核验；恢复方式在结果反馈给出 |
| 归还物件／赔偿 | 核对事件、物主与原件；显示金额和解除范围 | 原件已消费则不能假归还；可有等值赔偿，但额度由作者配置；第二次点不扣钱不加关系 | `resolvedBy`与物件移动一起提交；关系不因反复道歉无限增加 |
| 主线证物／叶家遗物 | 始终不入偷取、典当、制作或随机赃物池 | 通过原剧情的允许、借用、展示或交付处理 | 不以犯罪处罚永久吞掉；物主与使用同意沿人物负责文档 |

**首批具体候选**：只接现有剧情中明确发生的局部冲突回执与服务反馈；通用窃取入口继续服从原暂停状态。是否恢复生活技能是另一个产品决定，不通过此合同偷偷启用。城市声望本身的0—100与20/40/60门槛仍属城市旧方案，不把它升级为通用善恶／法律值。

需要写出的一条局部后果至少包括：谁看见、谁被告知、损失谁的信任、拒绝哪项非必要服务、怎样解除、解除后仍保留什么记忆、谁继续提供必达核验。没有这七项的事件不能写“全城敌对”占位。

## 5. 接入验收场景

| 编号 | 场景 | 完成标准 |
| --- | --- | --- |
| CI-01 | 正式南门存档，零钱／有钱、无剑／钢剑各一份 | 入城保留实际装备与资源，没有原型220钱或自动剑；旧已完成事实不重演领奖 |
| CI-02 | 谷中→城门→公开任务→购买并装备→战斗→返城→保存重载 | 同一物件、铜钱和任务事实始终一致；战斗呈现用实际装备，非原型临时数据 |
| CI-03 | 不学生活技能、不赌博、不做工、不做可选战斗 | 主线核验可完成；有必要服务与合理补救，不强制走违法或刷钱路线 |
| CI-04 | 正常逐点与T5跳T9两条路线 | 时间合同分别生效；截止预览准确，跳过节点不送奖励 |
| CI-05 | F选择回谷、取消、再确认、结算中断后重载 | 只一次进入六月，保留购得物与关系，五月不再发五期体力 |
| CI-06 | 开两个评审标签、重开城市原型、改测试铜钱 | 正式存档前后字节或规范化状态不变；正式入口无测试按钮 |
| CI-07 | 旧存档在南门、城市中段、六月据点各一份 | 按版本迁移不倒退进度；未知ID保留；无重复关系或奖励 |
| CI-08 | 只有甲目击的失败偷取事件 | 只甲及被明确告知的人反应；赔礼仅解除对应限制，主线服务始终可用 |
| CI-09 | 事件甲已赔礼，再触发独立事件乙 | 甲修复不能清掉乙；重复赔礼不重复扣款、不刷关系；已取物不重生 |
| CI-10 | 打造/鉴定/典当服务无正式物件映射 | 显示不可用及原因，不生成替代假物；普通买卖与任务继续可用 |
| CI-11 | 叶蘅义诊／客店安排与主线集合 | 同一节点同一人物实体只有一处；转场后恢复她的安排，不能因玩家买卖自动绑为随从 |
| CI-12 | 全部服务的取消、双击、保存中断 | 每次事务只完成一次，钱物事实无半提交；可恢复并有准确反馈 |

通过要求是正常入口端到端证据、资源前后账和迁移测试同时具备。文档审查、原型界面测试和函数测试各自记录，不互相冒充。本文完成的是可评审设计与验收合同，尚未执行上述游戏场景。

## 6. 待决定的具体选项与影响

1. **首次城市接入服务范围**：建议先公开任务、买卖、住宿和主线，后接状态复杂的典当／鉴定；代价是首版服务较少，收益是能先检验完整旅程。若一次全开，必须先完成物件身份和所有失败回退。
2. **城市货币显示**：已由2026-10-16用户确认统一为“文”、保留数额，不再是待决项。
3. **生活技能恢复**：建议本次不恢复通用窃取，仅实现作者配置冲突的局部后果；若用户决定恢复，须重审师承、对象范围与风险反馈，再复用这里的数据结构。
4. **有状态物件范围**：建议首批只支持专用唯一物件和托管映射；全量装备实例需要独立迁移与UI设计，不与城市普通买卖捆绑上线。

这些选择不影响本次已确认时间旧文修正；本轮没有为候选新增“用户已确认”规则，也没有改人物登记或关闭／开放任何实际服务。
