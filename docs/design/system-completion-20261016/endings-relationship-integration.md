### 2.3 失败类型与优先级

1. **普通不足**：未成年、关系未到、课程未完、日程冲突，展示已知缺项和下一可做项，不记录永久失败。
2. **原窗口错过**：记录原事件/具体期数/未完成原因，关闭原入口，开放已设计的补救线；角色记得这次缺席，不回放成“当年一起经历过”。新补救不能额外要求恋爱、全收集或某个未采用技能。
3. **本人选择保持友情**：仅关闭主动恋爱提示，正式资格和个人事业继续；想改变时需本人对话，不能菜单改数值。未回应心意为暂缓，不等于拒绝或永久断线。
4. **具体严重背约**：按负责人篇列举的伤害、欺骗或对立决定判断；先给争议和恢复办法。永久结果只允许该事件已明确提示并经采用的分支。单次战败、材料不足、错过一次提醒、技术异常都不能套用永久结果。
5. **同时触发**：客观在场/安全和年龄先于关系；明确未了责任先于招募；已取得正式资格优先于旧版“未看人物篇”检查；个人意愿优先于泛用分数。故事强制离队不清空恋爱，是否继续关系须另有本人事件。

补救奖励以新事件ID去重。原事件发过的物品不再补发；原事件未发的奖励也不默认全补，人物页必须声明是同一权利的补领还是不同补路报酬。纪念物归赠与后接收者，角色任务文书和公用物归原所有者；回忆重播无收益。

### 2.4 单关系轴已确认（2026-10-16）

用户本轮明确选择“沿用单关系轴与阶段瓶颈”。现行设计统一为个人关系0—100：初识0—19、熟络20—49、信赖50—79、托付80—100；各人瓶颈开放对应上限，突破不凭空加值。旧独立情意轴与70+3、上限85的多人门槛取消，不再保留为并行可选实现。

首次结缘检查正式资格、托付关系≥80、双方成年、个人篇及规定感情事件、明确本人心意与真实会面条件；已有结缘人数不参与门槛。男性/师长同样能到托付，但不因此获得恋爱入口。第一年所有关系增长仍只代表友情与信任。

吃醋和修复作用同一关系值，具体扣分、返还与频率仍是[待审方案](../romance-jealousy-review.md)。已通过瓶颈事实、个人篇、正式资格和已结缘身份不会因短期降值被删除；新的亲密节点可依当前数值和明确未解决的争议暂停。修复不要求重新招募/表白，不重复发纪念物。原本没有通过的瓶颈仍不能靠返分突破。

旧档不把信任/关系/情意三个旧字段相加，也不把旧关系抄一份当爱情。以现行关系与有可靠来源的事件为准；未知旧字段保留来源备查，已有结缘资格保留。具体迁移是后续接入测试事项，本轮仅统一设计口径。

## 3. 事件与存档接入

建议在现有事实之上增加带版本的关系进度投影，不与`qiheRoutes`或`relations`复制出多个权威值。存档保存：已发生事实、错过事实、补救进度、个人篇完成、本人恋爱意向、结缘结果、一次奖励和未完成约定；界面阶段由这些记录和关系值计算。

读取旧档时：已有正式同伴维持正式；已有结缘保留；旧PG知古节点只作为实际经历，不倒推出她直到游历才入队；没有亲历的旧章节不转成见闻。映射不明的字段原样保留并记来源，不直接解释成爱情或组织权限。

进入最终不可逆节点前，按玩家**已知**事项列：能继续处理的个人篇、已错过且有补路的事情、已完成待回应的心意、现有职业约定、未收回借物。提示不泄露未知人物和结局，也不要求把列表清空才能继续。确认推进时保存不可逆点快照，继续沿正常存档恢复规则，不写只有回到远古存档才能补救的隐藏门槛。

## 4. 结局是成果组合，不是总好感打分（B14）

### 4.1 不锁定新主线的输入模型

采用`endingRulesVersion + storyPlanId`；每个存档只使用自己已采用的故事计划，不把旧“共济盟约候选”和新三方战争候选同时判定。负责终局篇决定具体值域，本页提供兼容字段和判定顺序。

| 结果轴 | 最小输入事实 | 允许的结果表达 | 禁止的推断 |
|---|---|---|---|
| 追责 | 已核证据、证人实际抵达/明确替代、受理结果、交易或妥协的本人决定 | 责任已明确并获处理／部分责任成立／有条件止损／尚未处理，逐责任对象说明 | 一本日记等于所有人定罪；高声望自动补证；某人被击败等于责任已公开 |
| 救援 | 各受助群体实际脱险、后续安置和可持续供给的完成事实 | 已救且安置稳定／已救但后续仍有限／救出部分／本存档未完成对应行动 | 胜利画面等于所有人全救；拥有医者就自动建立全地区医疗网 |
| 遗产 | 叶蘅本人选择、知情范围、保管者、授予/分享的实际事件 | 有限传承／逐步分享／共同保管等采用稿允许的选择；保留未公开的合理结果 | 萧白代替她处分家传；未公开全部等于坏结局；玉匣缺失等于无法调查 |
| 地区/组织 | 已采用路线的行动、有效身份、具体权限、驻地或服务结果 | 谁负责哪些地方、仍需履行哪些约定；仅用采用稿定义的变化 | 旧提案突然升级成全武林/整个朝廷服从；私人交情自动变成任命 |
| 个人事业 | 角色自己的职业选择、交接、完成/仍在继续的目标 | 各人有独立去处与持续事业；未完成只如实说明当前阶段 | 没入队就没有生活；结缘后所有人放弃职业住进同一屋 |
| 私人关系 | 正式资格、当前在场、友情/结缘、已解决或未解决的具体分歧 | 逐人友情/亲密/通信/暂别段落及已有共同约定 | 以最后结缘者覆盖其他人；关系分代替主线事实；一句异议自动叛变 |

### 4.2 判断顺序、互斥和默认结果

1. 校验计划版本、关键人物/物件的唯一状态、事件因果。出现不能解释的冲突时停止结局确认，返回可恢复存档与诊断；不能用“取最后一条文本”静默藏错。
2. 读取主线已实际完成的结果，不依赖可选同伴齐全或全部支线完成。未取得的可选证据仍是未取得，不补“真相大白”。
3. 分别判追责、救援、遗产和地区结果；不存在统一的隐藏完美分。某次妥协可能及时救人但追责受限，两条结果并列说明代价。
4. 逐角色先算本人事业/所在地点/已承诺职责，再算与主角的关系表现；不在现场用有通信根据的来信或回访约定，不复制一个身体到两地。
5. 最后合成共享收束场面；参与者取当时确能会合者。没有支撑的“天下太平”“全部留谷”“所有人和解”不得作为默认句。

| 可能冲突 | 优先判断与处理 |
|---|---|
| 同一人既在异地履职又在庆功同场 | 在场/日程是硬条件；改为来信或不同时间的回访，不撤销事业 |
| 同一遗物同时已转交和仍在队伍 | 以唯一实例的已提交归属流水核对；无合法再次交接则阻止生成 |
| “已经正式加入”又显示“未完成招募” | 既得资格保留；旧稿节点变回访/个人成长，不重招募 |
| 救出全部与某群体仍被扣押同时出现 | 按群体ID逐项验实际救援结果；总称由集合求出，不能手填“全部” |
| 已结缘但有尚未解决的分歧 | 两条事实并存：保留关系，描述待谈事项；没有明确事件不擅自分手或虚构和好 |
| 计划内结果是“暂别”，文案写“永远同行” | 采用已有共同约定的期限；不能用抒情句推翻真实去向 |
| 三方候选之一胜出但其他候选也有旧标记 | 按已采用计划和互斥事件版本校验；不让旧审稿事实变成当前存档真实历史 |
| 少做一位人物支线 | 只缺该人物对应回响；主线已完成的成果保持，不降成全局失败 |

### 4.4 终局保存与物品

结局先生成只读预览快照`endingSnapshotId`，包含采用版本、输入事件ID和每段文本的来源，不在播放时再扣物或发资源。确认完成后一次写入通关事实与明确的结局奖励键；回放不重新发放、再改人物去向或补见闻。中断播放可按同一快照续看；读取旧档重新游玩形成新的真实结果，不改旧快照的历史。

剧情保管的物件只有实际交接才改变归属；多人结缘纪念物各有独立首次领取键。尚未归还的借装在最终离队/归任前明确处理，角色自己的书、兵器、文书不被误收进公共仓库。通关继承另有负责方案，本页不自动让关系、金钱或装备进入新周目。
