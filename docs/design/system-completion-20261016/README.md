- 城市活动逐项规定剧情节点、刷新、当票、住宿、重复收益和保存；给出可复算采购与套利案例。

## 一致性检查与限制

技能检查基线写在仓库外`/tmp/xjh-consistency-system-completion-20261016-before/`，需处理0、提示221；提示主要是历史章节编号、旧美术年龄与旧名称的否定引用。程序只覆盖已登记的年龄、门派和少量规则，不能据此认为26个系统问题自动解决。

人工核对另外发现图谱未纳入殷红缨、知古旧加入阶段，关系与情意两套资格，以及货币显示单位冲突；三项已由用户确认并同步，具体取舍与范围见[已确认口径](decisions-needed.md)。没有把未确认的新规则写进consistency-rules.json。

合同检查工具`tools_docs/check_system_completion.py`验证26项覆盖、局部链接及14个正反例，包括活动不推进剧情时间、保存失败不扣款、重复事务不重复收益、人物不同时在远方与队内、传闻不能无证据升级为已核验。它是设计模型检查，不是游戏战斗或全剧情测试。

最终检查、逐项修正、保留提示和实际未实现项见[一致性复核记录](../../archive/design/system-completion-20261016/consistency-review.md)。

## 实施顺序

先采用规则与版本口径 → 城市时间与资源表 → 一组世界后果/失败处理 → 阶段成长和敌人验证 → 人物传承与联合日程 → 一个从谷中出发、城市行动、返谷保存的可玩片段。全名册人物篇、后期结局和新周目按该片段验证结果逐步扩展。
