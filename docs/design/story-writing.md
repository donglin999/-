# 剧情文案规范

状态：现行　最后核对：2026-10-20（原记：**2026-10-16 建立**。这是写剧情台词的唯一入口规范：新写、改写、审读剧情（包括用 codex 起草的稿子）都按这一页来。配套的 skill 是项目根目录 `.claude/skills/story-writing`，自动检查脚本是 `tools_docs/story_lint.py`。）

本页收拢了散在各处、已经确认过的写作规则，并补上之前缺的部分。原规则的出处都列在条目后面；与负责文档冲突时，以负责文档为准，并回来改这一页。标“待定”的是还没拍板的，先按括号里的暂行做法写。

## 一、逻辑先于指标（最重要）

设计文档里有很多约束：关系要涨、某个功课要教、要区分亲见和听说、不能承诺一定办成、要写交接……这些是**写作时要满足的条件，不是台词的内容**。一场戏先得是一件说得通的事，约束是在这件事里自然地被满足，而不是让人物把约束念出来。

### 1. 动笔前先写“戏眼”三行

每场戏写台词之前，先写下这三行（写在剧本旁的注释或设计稿里，不进游戏）：

1. **谁想要什么**：这场戏里至少一个人有一个具体的、当下的想法。
2. **什么挡着他**：一件小事、一个误会、一种顾虑、一个不情愿的人。
3. **散场时什么变了**：一个人的看法、两人的关系、手里多了一样东西、知道了一件事。

三行写不出来，说明这场戏只是为了凑某个指标，不要写——换一件真正会发生的事，或者把这个指标并到别的戏里。

### 2. 每一句都要有来由

- **人为什么在这儿**：说话的人此刻出现在这个地点，有生活上的理由（住这儿、路过、来找人、被叫来）。按日程，不在谷里的人不能出场。
- **为什么说这句**：每句话要么回应上一句，要么推动这场戏往“散场时什么变了”走。删掉以后这场戏照样成立的句子，删掉。
- **人只知道他该知道的**：人物的知识边界以 `cast.md`“人物写作边界”、`story-atlas.json` 和各人物卡为准。萧白不知道叶家真相；周砚知道一部分、不知全案；新认识的人不会叫出对方的小名。
- **前后不能打架**：上一场说了要做的事，这一场要么做了、要么交代为什么没做；时间、地点、谁受了伤、谁出了门，和日程表一致。
- **选项都得是这个人会做的事**：两个选项都要说得通，结果顺着选择来；不设“明显的正确答案”去骗关系值。

### 3. 指标怎么放进戏里

| 约束（设计里写的） | 不要这样写 | 应该这样写 |
| --- | --- | --- |
| 关系要往前走 | 加一个选项让人说“谢谢你，我很高兴” | 两人一起解决一件小麻烦，最后一句里多了点随意或玩笑 |
| 某门功课要教到 | 师父背诵要点 | 弟子做错了一个具体的动作，师父指出来，弟子再做一次 |
| 亲见和听说要分开 | “亲见、听说，各记一栏。” | 人物自然地问一句“你亲眼看见的，还是听人说的？” |
| 不承诺一定办成 | “不写成到了就一定能办成。” | “去了也未必问得到。问不到，就再写信。” |
| 交接要清楚 | 两个人对着一页纸讨论交接格式 | 托别人带的东西出了岔子，才知道该写清楚；或者干脆不写这个点 |
| 某个设定要露出来 | 人物主动解释设定 | 让设定变成人物要面对的一件事，玩家自己看出来 |

### 4. 现有稿子里的反例

这些是之前用 codex 生成、目前还在游戏里的台词，问题都是把设计约束念了出来。以后遇到同类写法要改：

- `gy_l02`《多出来的半天》：萧白和陆衡整场在讨论改日期、标改过的行、交接后要再对一次——没有人想要什么，也没有人被什么挡住，只是把“交接要写清”拆成了对话。
- `gy_y03`《清单上也写自己的名字》：叶蘅说“想看看外头的大夫遇上难症，怎样找人商量。忙不过来时，又怎样请人接手。”这是设计稿里叶蘅的学习目标原文换了个说法，不像一个十八岁的姑娘会说的话。
- `X-01-A-01`：萧白说“能参加什么，按我真的学过的来。”这是“不把没学的算成会的”这条规则，被直接放进了主角嘴里。

自动检查的 `RULE_ECHO` 一项会挑出这类句子（同一场里扎堆出现就升为“需处理”），但最终要靠人读。

## 二、能做出来的演出（避免动画动作）

当前的技术做不了剧情里的人物动画：角色在对白里只有**静态的 Q 版立绘和表情**，场景只有**背景图**，过场只有**字幕卡**，战斗另有一套。写剧情时：

- **不写需要动起来才看得懂的情节**：翻墙、追逐、扑倒、拥抱、搀扶着走、挥剑过招、策马离去……都做不出来。
- **改用这些办法**：
  1. **对白交代**：动作发生在对白之外，人物用一句话说出结果。“……你怎么从墙上下来的？”比画出翻墙更省也更有趣。
  2. **静态表情**：人物的反应用表情立绘表现（惊讶、尴尬、生气、睡着）。缺哪个表情就按需生成，同屏人物的大小和水平线要统一（站位由 `xiaojianghu-legacy-prologue/tools_scene/qihe/build_actor_layout.py` 生成）。
  3. **字幕卡切时间**：“一个时辰后”“当晚”“第二天”，把动作跳过去，直接接结果。
  4. **结果画面**：确实需要一个画面才讲得清的，用一张静态 CG 或换一张背景，按 `story-presentation.md` 第 5 节的 CG 投放规则。
  5. **真打**：需要打的，走真实战斗（`fight`），不在对白里写招式来回。
  6. **立绘动感**（2026-10-20 起）：被撞开、吓一跳、上前一步、被拖走、侧边登场这类“一下子”的反应，可以在台词上写 `motion`，让整张立绘短促地动一下。它只加强反应，不能用来演连续动作；动作表和写法见 [`dialogue-staging.md`](dialogue-staging.md)「立绘动感」。
- **心里话**用全角括号（）写在萧白的台词里，可以写他看到了什么，但不要变成旁白式的动作描写。
- 普通 NPC 的限制见 `story-presentation.md` 第 1 节；多人站位见 `dialogue-staging.md`。

## 三、格式

- **不用旁白**（2026-10-08 用户：去掉旁白，提高沉浸感）。所有叙述都换成人物台词、萧白的心里话或字幕卡。
- **字幕卡**：只写时间或“时间 · 地点”，如“第二个月”“夜 · 溪东”“四月底 · 出发前”。不写剧情说明。
- **心里话**：萧白独白用全角括号，如“（三十五……三十六……）”。
- **每句长度**：一个气泡一般不超过 40 字，最多 64 字；超过就拆成两句，或删掉解释性的半句。
- **选项**：萧白要说的话用引号写原话（“你做得对。”），要做的事用动作写（卷起裤腿下水去捞）；一般不超过 16 字。选项不暗示哪个加关系。
- **表情**：只在情绪转折处点明，不一句一换；强烈情绪（惊讶、生气、大笑等）两句后自动回到这场的基调（2026-10-11 用户）。剧本里用 `mood`（说话人）和 `moods`（其他人）标注。
- **不说“第几章”**：只说开始、培养、游历、终局四部分（2026-10-10 用户）。
- 文档库剧本的编号、方括号写法见 `story-scripts.md`“读稿约定”。

## 四、语言与口吻

- **时代感**：南宋背景，给现代玩家读。用浅近的白话，带一点古风用词，不堆文言，不写半文半白的长句。
- **不用的词**：游戏数值和系统用语（关系值、好感、收益、体力、熟练度、解锁、结算、任务……）任何人都不说；现代网络用语、热梗、外文缩写不用。自动检查的 `MECHANIC`、`MODERN` 两项会挑出来。
- **萧白的现代人身份**：表现为思考习惯和不适应（看不惯竖排字、横着写、想到一个现代的比方），不用热梗，不把编程词汇当武学答案（`cast.md`）。心里话可以比说出口的话更现代一点。（待定：心里话能现代到什么程度。暂行：可以有现代人的想法和比喻，不出现现代专有名词和网络用语。）
- **称谓**（待定：完整称谓表。暂行如下）：
  - 萧白称周砚“师父”，江采薇“师母”，殷红缨“小师叔”，钟拙“二师叔”，方迟“大师兄”，卢小豆“小豆”或“小师兄”，叶蘅“叶蘅”，裴知古“知古”（熟了以后）、初识叫“裴姑娘”。

- **每个人的说话方式**：可入队人物和各门派人物以 `story-atlas.json` 的 `voice` 字段为准（含示例句）；归云谷一家见下表。写之前先读一遍，写完对照着念一遍。

## 五、内容边界

- **年龄**：萧白第一年 17 岁，第二年正月初一满 18。满 18 之前不写暧昧、不出现结缘；所有可结缘角色都已成年（2026-10-09 用户）。
- **暧昧要克制**：靠称呼变化、停顿、玩笑里的认真、照顾人的小动作来表现，不写露骨内容（`romance-rules.md` 第二节第 6 条）。
- **关系变化要有原因**：一起经历了什么才变，不能只靠数值跳（同上）。
- **人物不脸谱化**：门派人物和反派的写作边界见 `story-atlas.json` 各条备注（如“不画成慈悲圣贤再突然下流”“冲突是固执，不是私德败坏”）。女性同伴的人物要素见 `companion-women.md`“写作规格”。

## 六、用 codex 起草时

codex 生成的稿子容易为了满足条件而生硬套用，所以：

1. 给它的材料要包含：本页、相关人物的 `voice` 和人物卡、这场戏前后的剧情、这场戏的“戏眼”三行。**不要把设计约束清单直接交给它让它“都体现出来”**——只告诉它这场戏要发生什么事，约束由你在审读时核对。
2. 明确告诉它：不要旁白，不要动作描写，不要把规则写进台词，每句不超过 40 字。
3. 它交回来的稿子**不能直接入库**：先跑自动检查，再按第七节逐条审读；逻辑审读最好另开一个没看过设计文档的审读者（子代理）来读，只给它剧本和前后剧情，问它哪里看不懂、哪里不像真人说的话。
4. 它不能自己新编设定（新人物、新门派、新身世）。需要新设定的，先回到设计文档里定下来。
5. **用 MiniMax 起草（2026-10-16 起的做法）**：剧情由人设计，先写简报 JSON（每场的时间地点、在场人物、前后场、戏眼三行、每段要点和选项文字，样例见 `docs/design/scripts/briefs/pre-xiangyang-mainline-brief.json`），再运行 `python3 tools_story/minimax_draft.py <简报> --out <草稿目录>` 让 MiniMax 只把要点写成台词。它常见的毛病：漏写互斥的变体段、写括号动作、人称写错、每句都标表情、心里话冒出现代名词——人工改定后，用 `python3 tools_story/apply_story_drafts.py <简报> <草稿目录>` 写回剧本（只换台词、场景说明和选项文字，段落、条件、效果不动）。

## 七、写完的检查

### 自动检查

在 `xiaojianghu` 目录运行：

```bash
python3 tools_docs/story_lint.py --out <临时目录>
```

读 `<临时目录>/report.md`。会检查：旁白、“第几章”、占位符、游戏数值用语、现代用语、设计约束式的句子、第一年的暧昧词、需要动画的动作描写、过长的句子、一句一换的表情、重复句。只查某几场时加 `--scene 剧情id ...`。“需处理”要改掉；“提示”逐条看上下文再定。

### 人工审读清单

台词手法参考：[《侠客风云传》台词手法调研与本作用法](xkfy-dialogue-study.md)（好笑要有人物逻辑、难受时克制、用萧白心里话立别人、登场要有画面）。

每场戏都过一遍：

1. 戏眼三行写得出来吗？散场时真的有东西变了吗？
2. 每个人为什么此刻在这里？日程上他在不在？
3. 每一句删掉以后，这场戏还成立吗？成立就删。
4. 有没有人说了他不该知道的事？
5. 有没有哪句是在念设计约束，而不是人在说话？
6. 两个选项都像萧白会做的事吗？结果顺着选择走吗？
7. 有没有要靠动画才能看懂的情节？
8. 每个人的口吻对得上 `voice` 吗？换个名字还认得出是谁在说话吗？
9. 第一年里有没有暧昧？关系变化有没有原因？
10. 表情是不是只在转折处换？缺的表情记下来去生成。
11. **认人与知情**：头一回见面的人，是否先问清对方是谁、或由在场的人引见？谁认识谁、谁此刻知道什么，按戏眼卡核对（2026-10-20 用户指出）。
12. **信息来源**：“全谷都知道了”“听说……”这类话，信息是谁传的、怎么传的，戏里交代了吗？
13. **打趣要有来有回**：玩笑、挖苦之后，被打趣的人有没有接话，打趣的人有没有再软一句？一句话收住会显得刻薄。
14. **往事要有铺垫**：人物提起设定里的过往（如师母走镖），这一场或前文有没有引子？突然抛出就删或补引子。
15. **主角对女主主动举动的反应**：女主做了有分量的事（主动回信追问、替人着想），萧白有没有一句心里话或回应？
16. **来信不记流水账**：每封来信至少承担一项：埋伏笔、揭示一件事、让写信人更立体。三项都不沾就重写或删。
17. **不为接梗硬塞台词**：为了抢镜头、凑笑点而加的规矩或俏皮话，删掉这场还成立就删。

### 可选剧情与回扣

涉及可选剧情（闲逛、串门、邀约、来客），或者回扣了它们的场次，按[可选剧情、回扣与分支规范](optional-story-dependencies.md)：新可选剧情登记进回扣登记表；在 `xiaojianghu-legacy-prologue` 跑 `node tools_scene/qihe/check_story_hooks.cjs`，错误为 0；用 `tools_scene/qihe/dump_route.cjs` 导出“只看固定”“全看”“部分看”三条路线做冷读。（R-剧情-07）

### 设定一致性

涉及人物年龄、门派、造型、时间的，再用 `consistency-check` skill 跑一遍。

## 八、待你拍板的

1. 萧白心里话的现代感上限（暂行：可以有现代人的想法和比喻，不出现现代专有名词和网络用语）。
2. 完整称谓表，尤其是游历部分各门派人物之间、对萧白的称呼。
3. 每句长度上限（暂行：一般 40 字，最多 64 字）。
4. 现有剧情里自动检查挑出的问题要不要统一返工，尤其是第一节第 4 条列的那批 codex 稿。
