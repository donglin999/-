# 对话立绘站位与多人演出

状态：现行　最后核对：2026-10-20（原记：OC-2026-10-04.4，2026-10-04用户纠正后采用。共同字体、框和人物等级见[画面规范](presentation.md)；[剧情表现](story-presentation.md)负责选择对白、静态动作与CG。）

## 人数与站位

| 参与人物 | 固定安排 |
|---|---|
| 主角独白 | 主角左位，禁止默认放右 |
| 一般NPC与主角 | 主角左侧立绘，普通NPC只用正文旁小像，不因此新增大立绘 |
| 两位有立绘人物 | 主角／视角人物左位，主要对话对象右位；双方同时在场，换说话人只换高亮与表情 |
| 三位有立绘人物 | 左、右主位保持，第三人中位；中位人物不得遮正文和名字牌 |
| 四位及以上 | 最多三幅大立绘；左、右主位固定，其他参与者在上方头像列。头像列中的人物发言时进入中位，上一位退回头像列；主位不随话轮跳边 |
| 无主角的剧情 | 脚本明确指定左／右主位，未指定按出场顺序分配；不能全堆到右侧 |
| 旁白／全屏CG | 旁白隐藏人物层但保留本段分配；CG中抑制全部大立绘与头像列，结束恢复原位 |

人物左右由会话角色分配，不由当前说话人或反派／同伴类型临时决定。主角换衣仍占原位，人物表情沿用同裁框；不能通过翻转角色修站位，持物左右和服装须保持一致。

## 人物朝向（2026-10-20 用户）

用户 2026-10-20：“后面你还要注意是否人与人是面对的问题啊，像现在就是直接背向的（除非剧情需要）”。

- 对话的人要面对面：左位的人脸朝右或正面，右位的人脸朝左或正面；中位不限。萧白默认左位，所以站在右边和他说话的人必须有**朝左或正面**的立绘。
- **不靠镜像翻转解决**：翻转会把右衽变成左衽，发饰、伤痕、持物也会左右互换，同一个人换句就“换了一边”。上面“人数与站位”已规定不能翻转修站位。
- 剧情需要背对（转身走开、赌气不看人）的台词写 `facingAway:true` 豁免。
- 每张立绘的朝向登记在 `xiaojianghu-legacy-prologue/docs/assets/cultivation-actor-facing.json`（R 朝右、L 朝左、F 近正面），新立绘入库时同时登记；`node tools_scene/qihe/check_facing.cjs [--list]` 用真实站位逐句检查，背对或未登记都会报出来。
- 生图时按要站的位置写朝向：要站右位的人物出朝左（或正面）的版本；双人图里对着萧白说话的人也要朝向萧白那一侧。
- **朝左版的接法**（2026-10-21 用户：“直接采用接入”）：朝右的人每个表情档重画一张朝左版，文件名在原档后加 `_left`（如 `zhou_smile_left.png`，夸张底图为 `zhou_left.png`），不覆盖原图。人物登记进 `js/qh-mode-cultivation-story.js` 的 `LEFT_READY` 后，多人镜头站最右位时运行时自动换用朝左版，并带 `data-facing="left"`。目前有：裴知古、裴述、周砚、殷红缨、莫松年、孟知微、照川来客；“躲在父亲身后”双人图直接换成朝左版。
- **朝左版的大小**：朝左版取景可能和原档不同（殷红缨几档原图是全身远景，朝左版是半身），不靠肉眼对齐，由 `build_actor_layout.py` 逐张量脸、单独生成 `[data-facing="left"]` 站位，舞台上脸高、脸线和其他人一致；自动量错的写进脚本 `LEFT_FACES` 人工给锚点。出图时一张一个请求、并发发出，不按批次串行。

## 构图与可读性

- 双人各占左右约28%，三人各约29%；人物层在正文框后，底部身体可被框自然遮挡，脸部不能被框遮住。正常立绘统一约72%画面高度，不使用叶蘅专用的负底边偏移。
- 发言者保持完整明度；其他人物用亮度轻度压暗，保持原有不透明度，避免背景透过身体；不能完全黑成剪影。以名字牌和表情同时标识发言人，不依赖颜色独自传意。
- 正文框跨底部，文字与选择共用起始线；正文≥18px、选项≥17px、行距≥1.5。多人层不能挤成窄文本栏。
- 头像列复用对应阶段头像或现有立绘裁脸，不把整幅全身立绘缩成难辨的小人。头像列是当前对话参与者的显示，不做可点击切人控件；普通围观者不会因存在于地图上自动加入立绘阵容。
- 脚本使用`DialogueStage.begin({id,cast:[{who,sp,slot}]})`／`end(token)`声明完整参与者。未迁入脚本仍由真实发言者自动补充，普通NPC保持小像。会话结束或切场景清理；不将上一段无关人物带入下一段。

主角独白、双人往返、三人接话、四人及以上换中位、普通NPC小像、主角换衣、表情差分、CG全部抑制／恢复和会话清理均需检查。1280×720、1920×1080保存全画面；立绘不得越界、遮脸、遮选项。代码夹具只能证明分配与状态；实际构图仍需目视核对。

## 立绘动感（2026-10-20 用户采用）

用户 2026-10-20 看过试验动画后采用：“这个动感实验可以的”。起因是“挨打的时候立绘会很快地平移一下有一种逃跑的感觉更加生动”。

**是什么**：整张立绘的短促平移、倾斜和缩放，在说出这句台词时播一次。它不是肢体动画，不加帧、不出新图；人物的情绪仍靠表情立绘表达，动感只负责“这一下发生了”。

**培养 Q 版剧场的站位**：同样按上面“人数与站位”的表，萧白默认左位。`js/qh-mode-cultivation-story.js` 的 `composition` 不管 `cast` 怎么排都先把萧白放到最左；确需萧白站右的剧情在定义里写 `heroSide:'right'`。（2026-10-20 之前 Q 版剧场直接按 `cast` 顺序摆人，萧白常被排到右边，属于没按本页执行。）

**双人 Q 版同框**（一张图里画着两个人，如扶梯子、躲在父亲身后）有两种用法，在台词上写：

- 只写 `duo`：整句只显示这张图，适合**萧白本人就在图里**的镜头（扶梯子）。这是全身远景，人物比单人半身小，相当于镜头拉远。
- 再写 `duoCast:["peishu","pei"]`（图里是谁）：这张图只占一个站位，其余在场的人照常站，萧白仍在左位和他们说话（躲在父亲身后）。双人图按图里主位人物的脸对齐，和单人立绘**脸一样大、脸线一样高**；对齐锚点在 `build_actor_layout.py` 的 `DUO_FACES` 人工登记，重跑脚本生成。

萧白在场、又不在双人图里时，必须用第二种，不能让双人图把萧白挤出画面。

### 动作表

方向以“背向对手”为外：左位的人往左是外，右位的人往右是外。

| 写法 | 名称 | 表现 | 适合的台词 |
|---|---|---|---|
| `knock` | 挨打后撤 | 向外弹开、微倾，再回原位（0.6 秒） | 被打、被撞、被一句话噎住 |
| `flee` | 吓得逃开 | 先往里缩一下，再快速向外横移，停在外侧 | 吓跑、躲开；之后此人通常离场 |
| `startle` | 吓一跳 | 原地小跳、压扁回弹（0.4 秒） | 被吓到、意外发现 |
| `step` | 上前一步 | 向对方靠近一小步，停在那里 | 逼问、凑近、主动搭话 |
| `drag` | 被拖走 | 斜向往外下方拖出画面并淡出 | 被人拉走、拽走；此人随即离场 |
| `shake` | 发抖 | 小幅左右抖动（0.4 秒） | 害怕、冷、气得发抖 |
| `slump` | 泄气 | 微微下沉、压低，停在那里 | 挨训、认错、失望 |
| `nod` | 点头 | 轻轻一沉一回 | 应承、托付 |
| `enter` | 侧边登场 | 从外侧滑入 | 此人在本场第一次出现的那句 |

### 写法

在台词对象上写 `motion`（剧情源 `xiaojianghu/docs/design/scripts/chapter-two-dialogue.json`，编译到运行文件）：

- `"motion":"startle"`：作用于本句说话人；
- `"motion":{"who":"pei","move":"slump"}`：作用于指定人物（必须在本句的大立绘里）；
- `"motion":{"who":"duo","move":"startle"}`：作用于本句的双人 Q 版图。双人图没有左右之分，只用 `startle`、`shake`、`nod`。

### 用法规则

1. 一句最多一个动作；动作要和这句台词的意思对得上，删掉动作这句也成立，才说明它只是加强，不是靠它讲事。
2. 一场一般 2～5 处，放在笑点、转折、登场和离场上；同一个动作一场不连续用两次。
3. `flee`、`drag` 播完人物停在画外，下一句的 `cast` 里不应再有此人；`step`、`slump` 停在终点，换句后自动复位。
4. 不能用来演需要连续动作才看得懂的情节（翻墙、追逐、过招），这些仍按[剧情文案规范](story-writing.md)第二节处理。
5. 有 Q 版大立绘的人都可以用，它不算[剧情表现](story-presentation.md)第 1 节所说的专属动作演出；只有正文小像的普通 NPC 没有大立绘，不用。

### 运行与验收

- 动作样式在 `js/qh-mode-cultivation-story.css`，只用 CSS 的 `translate`、`rotate`、`scale` 单项属性，与站位用的 `transform` 叠加，不改站位。
- 选项画面沿用上一句时不重放；同一句重绘不重放；系统开了“减少动态效果”时不播。
- 验收在本机 `?uiReview=1&cultivationScene=<剧情id>` 逐句看：动作方向对、播完回到站位（停在终点的除外）、脸不被对白框挡、没有闪动。手动试动作用 `&storyMotion=1` 打开右下角面板（只在本机评审入口，不进发布包）。

## 完整对白状态节拍（2026-10-04）

可加入人类使用[六个完整状态](companion-performance.md)，节拍记录`character / stage / dialogue_state / intent`。每张同时改变表情、手势、肩身与重心，不组合独立动作和表情。不随机轮播；情绪或意图转折时切换整图，同情绪连续数句沿用。换说话人时只高亮，除非听者有真实反应。

身体语言不匹配情绪的整图不能显示为该状态；缺图默认常态并记录缺口，不能称为完成。新版资源生成、预览显示与实际剧情映射分别验收，站位左右不会因为切状态而改变。
