## 原因与内容核对

8792当前入口原先无标题选择，直接读取`xjh.qihe-prologue.v2`。已有存档记录`arrival.stage=done`后，程序按进度进入村落，序章后山演出不会重播。序章并未被删除。

当前运行入口包括序章P-01～P-05、风起栖河段村中生活至山居第一夜、培养部分入谷培养及赴汉皋前事件（本页核对时城名为襄阳，2026-10-13 起入城前改为汉皋，襄阳城已撤除）。培养部分采用的培养快照包含乡邻来信、旧友回信、陆衡来访、护送及入城邀请/出发安排（时段2～19）；早期“只有首期文字菜单”的记录不代表现行快照。完整三年、后续出师与所有分支质量不因本次入口核对而视为全面验收。本次只修启动与存档选择。

## 当前启动规则

- 首页、`#qihe-map`与`#prologue`显示当前游戏启动页，主按钮「从序章开始」，从后山初遇自动播放，不恢复现代办公室/苏醒段。
- 有合法存档时显示「继续进度」，并注明序章、风起栖河段或培养部分及所在场景；最近新旅程与原有存档不相同时，也保留「继续原有进度」。
- 「从序章开始」创建独立旅程存档，完整继续到后续章节，不覆盖、不删除现有进度。旧存档`xjh.qihe-prologue.v2`原样保留；独立旅程使用`xjh.qihe-prologue.v2.run.<id>`，最近旅程指针只记录有效已写入存档。
- 显式选择开始/继续后使用`play=1`进入；刷新继续当前旅程与当前未完成片段，不被启动页打断。回普通入口可再次选择旅程。
- 专项UI、战斗、支线和开始部分演出评审入口沿用原有独立存档，不显示普通启动页，也不进入最近游玩记录。
- 损坏或无法读取的旧存档不自动覆盖；启动页提示后仍可创建独立新旅程。
- 新旅程第一次画面就是后山，不先闪出村落。后山底图在正常载入阶段预载；固定人物脚点移到对白框上方的画面安全区，避免只露出头部。固定开场隐藏探索HUD与操作提示，对白推进仍可用。
- 写档与读档容错（2026-10-16，审查 P0 技术修复，不改数值）：
  - 游玩中的写档（自动存档、容器领取、资源采集、装备买换、培养操作）统一走`saveKey()`与`persistState`，不另写固定键。自动存档写失败时显示常驻提示「进度未能保存」，下次写成功后自动撤下。
  - 培养存档先迁移后校验：读入时接受`economyVersion`不大于当前版本的旧档（进行中活动的版本同样处理），迁移后再严格校验；比程序新的存档仍拒读。
  - 培养读档校验失败时不抛错卡死：原数据隔离到存档字段`cultivationQuarantine`（只追加，保留最近 3 份）；能修复的先修复——失效的动作选择重置为默认、失效关系人物条目丢弃、历练里失效地点去掉、进行中活动指向已删动作时只清除该活动（是否退回体力待用户确认，目前不退）。修不了时显示说明，并给「以新的培养进度继续」（原数据先隔离）与「返回首页」两个出口。
  - 主线事件断点续接出错时不再静默无限重放：捕获错误、写控制台日志、在画面上提示并记录连续失败次数（`qiheChapter.storyError`）；阶段值无法识别时回到合法阶段（未开始过的回`opening`，否则回`days`）。连续失败后是否允许跳过、跳过按什么结果继续，待用户确认，目前只提示。
- 探索设置可[管理存档及返回首页](expansion/ui-flow/settings.md)。返回首页保留当前旅程参数，去掉`play=1`，确保当前进度排在继续选择首位；手动节点载入时创建独立旅程，原节点不参与自动覆盖。回收站记录不在启动页展示。

## 验证要求

检查旧档不跳入村落、显式新旅程进入P-01-01、旧档字节未变、继续恢复原场景/章节、开场中刷新保留检查点、评审与游玩档隔离。浏览器核对实际初遇对白与现代短发人物；不把入口检查写成整章复测。
