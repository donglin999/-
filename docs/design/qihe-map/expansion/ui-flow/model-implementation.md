# 江湖 UI 数据层实现与调试

状态：现行　最后核对：2026-10-19

[开发目录](README.md) · [接口合同](contracts.md)

实现文件：`js/qihe-ui-model.js`，仅栖河入口启用。复用既有物品、功法、战斗公式；新界面不直接执行会提前扣除物品的旧菜单函数。

## 已接接口

- `snapshot / roster / active / view`：招募名册、四人出战、候补资料、属性和三装备位。
- `inventory / inspectItem`：共享行囊检索、分类、数量、作用对象、换装差值和不可用原因。
- `inspectSkill / skillEffects / skillWhy / skillCost`：已学招式、BP 效果、施展限制和火候折算后的实际内力消耗。
- `previewStats`：纯加点预览，输出 `allowed/reason/cap/spent/remaining/before/after/stats`，不改权威状态。
- `inspectInner`：主辅修适配、层数、改修代价、特性开放状态；未实现特性明确标记。
- `pet / settings`：独立宠物资料、声音和界面主题。
- `command`：接收命令及可选 `expectedRevision/commandId`，返回 `ok/reason/revision`。

## 原子操作

编成、装备、卸下、单次用药、残页指定参悟、加点、改主修、辅修、喂宠物和项圈都在克隆存档上校验与运算。存储成功后才替换 `S`；存储失败保留旧阵容、旧血蓝、物品数量和成长数据。保存失败可保留界面草稿重试。

名册保留所有已招募成员；`S.party` 兼容存储当前出战的最多三位同伴，主角固定首位，宠物不占人类名额。候补成长与装备仍保留。序章教学的叶蘅属于临时参战；风起栖河段正式结伴后才加入名册。五人及以上旧档保留所有成员，其余转候补。

## 武学完整接入范围

栖河入口已学主动招式不再受旧六格 `load` 限制；保留原存档字段用于兼容。普通攻击单独展示，不占招式列表。正式出战、玩家选招、自动战斗读取有效消耗和施展门槛；武学详情、战斗预估和伤害执行共用 `skillEffects` 的 BP 规则。既有火候、内息、心法层数按引擎实际公式展示。

无效施展在外层拒绝，避免内力不足或兵器不符时误记熟练。主修特性的派生加成包括三层、五层效果；未实现特性不伪称可用。

## 已执行验收

执行：`node tools_scene/qihe/verify_ui_model.cjs`。

27 项通过，覆盖：

- 只读预览不写状态；迁移幂等；未知物品保留。
- 候补换装与成长；四人上限、重复成员、主角锁、暂离限制。
- 换装物品守恒；取消、过期版本、重复提交；满血药物拒绝。
- 编成、装备、卸下、用药、加点、残页、主辅修、宠物喂食和项圈的模拟存储失败完整回滚。
- 加点预览与提交结果相等；高层心法派生与正式引擎相等。
- 高重数技能的 BP 详情与战斗预估相等；折扣后恰好足够的内力能正常施展。
- 宠物独立迁移和自动成长幂等；序章临时同伴与风起栖河段正式招募区分。
- 培养奖励接入正式熟练进度且重复恢复不重复入账。

这组测试是引擎及事务验收；真实浏览器中的布局、焦点、悬停、遮挡、分辨率和输入体验需另行截图验收。
