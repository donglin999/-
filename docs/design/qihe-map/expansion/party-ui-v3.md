## 2. 名册、出战、在场是三件事

- **已结伴名册**：保存已正式加入的人类；离开当前队列仍保留属性、装备、武学、关系和地点。不能仅凭`S.mates`残留记录认定已招募。
- **出战阵容**：名册中当前选中的最多四人，位置编号1–4；空位合法，不要求凑满。默认萧白出战，但不以“主角”身份永久锁定。
- **可用性**：同行候补、驻地待命、暂离、剧情强制同行分别记录。暂离角色可看档案，不能跨地图凭空上阵、用药、换装。
- **出战与地图跟随**：常规探索只生成出战同伴跟随者；候补在驻地或待命处。剧情NPC使用独立演出位置，避免同一人物同时作为NPC和跟随者显示。
- **当前序章**：首次狼战仍由剧情指定萧白与叶蘅；完成约定的正式结伴节点后才进入名册。教学固定阵容的锁只对该场战斗有效。
- **宠物**：独立名册与当前宠物卡；建议一个自动参战位；跟随永远位于人类最后。人类满四人时也不挤占宠物卡，预览应明确“人类2/4”，不能写含混的“队伍2/4”。

## 3. 队伍页布局与操作

**左区（约60%）**：上方固定显示四个人类出战位置，标姓名、气血、角色倾向；下方为可滚动候补名单，提供“可加入阵容 / 全部已结伴”筛选。驻地、暂离、剧情锁定的原因就地显示。候补人数不由四格限制。

**右区（约40%）**：显示当前选中人物的立绘、参战定位与条件，以及“查看属性”“武学”“编入出战”等操作；选中人物只是查看对象，**不会自动换人**。详细成长与大量物品分别进入武学、行囊页，不在本页挤入完整背包。

**底部**：固定显示“人类出战 2/4”与“应用编成”；宠物为独立小区域，标“自动参战”与当前倾向，无手动技能按钮。

操作闭环：

1. 选候补 → 点“加入阵容” → 选空位；四人已满时改为“替换队员”，必须点选被替换者。
2. 显示一次阵容差异（谁加入、谁退回候补、不可变更者及原因），点“应用编成”才保存；取消完整保留旧阵容。编辑草稿可暂时清空，但应用时必须至少有一名可用人类，否则提示“至少选择一名出战角色”并拒绝保存；开战入口也必须再次校验。
3. 人类换位可点箭头或拖放；键盘同样能完成。锁定位置不代表永久固定职业站位，战斗先后仍由战斗速度规则决定。
4. 换下不卸装备、不退款、不清武学，不回复气血/内力；再次上阵继承原状态。
5. 名册看板可以展示所有已结伴者。装备/用药对象只允许当前在场并可操作者；隐藏候补不会改变已选对象而误扣给其他人。
6. 离开有未应用阵容的页面时明确“应用 / 放弃 / 继续编辑”；不能切页就静默提交。尚无候补时显示空态，不能放一串疑似已招募的剧情NPC。

预览为整图明确标注“编成示例”“演示名单”的**评审样例**：萧白、叶蘅位于两个出战位，其余两位为空；候补以苏芷演示，右侧显示她的立绘与操作。**这不是开始部分当前存档，苏芷出现在候补中不代表开始部分已正式招募她。** 实现时只按真实招募数据生成名单，不能把预览演示名单写入开局存档。

## 4. 换人时机与剧情约束

| 状态 | 规则 |
| --- | --- |
| 安全探索、无对话、无事件结算 | 可在在场且可用的人类之间编队；不消耗开始部分半日 |
| 驻地待命者不在当前地点 | 按钮提示“返回驻地邀请”；菜单不提供远程传送加入 |
| 剧情对话、转场、结算、入战准备中 | 编队提交禁用，显示具体原因；读人物资料可保留 |
| 正式战斗已经开始 | 固定入场快照，不能中途从江湖页换人或刷新技能；战后再调整 |
| 必须某角色参与的剧情 | 提前标注所需成员；阵容不足/满员时在交互触发前让玩家调整，不静默踢人 |
| 序章等明确固定阵容战斗 | 显示“本场剧情阵容”，用临时战斗名单；不覆盖玩家常设名单，不发招募状态 |
| 主角剧情必需时 | 对萧白显示本段锁定及原因；其他阶段是否允许换下由同一可用性规则判断，不能写死永久锁 |

拟定优先级：明确的本场固定名单 → 当前剧情必需条件校验 → 玩家已应用的出战名单。任何正常战斗都不能因读取旧`S.party`而把第五个人加入。固定脚本也应遵守四名人类上限；群众协助做剧情/场外效果，不假扮第五名可控队员。

主角可换下属于新增能力：必须先改掉`mkHero()`固定注入、战斗结算和护主目标等依赖。当前章需要主角的剧情保持局部锁；不能只放开菜单按钮而让后台仍强加萧白。地图视点与战斗编队分开配置，当前剧情视点仍为萧白；以后可切探索领队时再配置对应角色素材与交互归属。

## 5. 数据接口提案与旧档迁移

建议新增版本化`S.formation`，包含`version`、`roster`、`active`和各角色的`availability`；`active`使用包含`hero`在内的统一角色ID，已应用阵容长度1–4；仅编辑草稿允许暂时为空。角色成长仍存原`S`/`S.mates`，不复制第二套属性。临时战斗名单是入战参数，不写进`roster`。

统一提供读接口`recruitedHumans()`、`activeHumans()`、`canDeploy(id,context)`与写接口`recruitHuman()`、`applyFormation()`；名字为提案。`S.party`过渡期只作由阵容导出的兼容视图，所有直接push/splice的剧情、菜单、跟随和入战入口必须一起迁移。单改战斗截取前三个同伴会把候补管理与存档留在错误状态。

迁移必须幂等、先校验再提交：

1. 对合法旧存档：先运行宠物迁移，将dog从人类队列移出；有效旧`S.party`按原顺序并入已结伴名册，萧白补入一次。**不扫描所有`S.mates`自动招募。**
2. 旧档无出战字段：默认萧白＋前三位当前可用同伴；多余同伴保留候补及所有成长和装备。现有有效阵容不重复重排。
3. 已有新阵容：去重复、人类名单剔除宠物、拒绝未招募/未知ID，人数超过4保留前4，剩余已招募者为候补；当前剧情强制条件冲突时提示调整并禁止开战，不静默丢弃玩家选择。
4. 已招募但暂离者留名册并禁用上阵；不能为填空把不可用角色拉回来。主角在可用时可作为非法空阵容的安全恢复对象；无可用角色则保留档案并阻止入战，提供返还安全节点，不伪造招募。
5. 未知ID原始数据保留在迁移诊断/备份中，不删除其装备记录；不把未知资产放进可战斗列表。损坏JSON的恢复入口应保留原始存档备份，不能静默覆盖成新游戏。
6. 应用阵容时再次校验：编辑过程中剧情改变可用性则拒绝过期提交；新数据整体保存一次。气血、背包、半日不随编队操作变化。
7. 老档叶蘅补入只能依据明确的正式结伴剧情标记；不能仅据曾参加狼战、出现跟随影像或有`S.mates.ye`来补。

## 6. 宠物需明确的实现边界

已实现：独立记录、项圈与喂食、队尾跟随、自主护主/治疗/侦察/攻击。本次建议：人类四位之外保留一个宠物位，且宠物参与战斗需要同样的在场检查。

主角不参战时，现有`petTurn()`会直接返回，必须修复后才能开放这种阵容。建议：大黄依然能自主攻击/侦察；护主仅对在场的萧白生效，技能说明写明目标，不自动改成保护任意队员。缺目标时继续评估其他行动，不能空过整回合。不要在预览上加入未实现的训练模式切换或指令按钮。

## 7. 实现后的验收用例

- 两人开局显示2/4，叶蘅仅在正式招募后可编辑；序章临时联手前后名册无变化。清空编辑草稿后不能应用，开战前也拒绝无人阵容；至少一名可用人类方可进入正常战斗。
- 已招募6人：四人出战、两人候补；替换取消不变，应用只交换一次；读档保持顺序与各自装备、武学、血蓝。
- 正常战斗、剧情战斗、素材预加载、头像栏、地图跟随读取同一有效阵容；从旧档恢复也无第五个人类。
- 四人＋宠物：四人可操控，宠物自动行动、末位跟随；宠物不出现在人类加点/换装目标中。
- 满员时选择新人要求明确替换；重复ID、未知ID、宠物混入、缺失/错误类型字段分别被校验，原始资产不丢失。
- 固定剧情必需角色不能换下，并说明原因；剧情结束解除本段锁；固定战斗结束恢复常设名单。
- 主角被允许换下的后期样例：战斗不自动补回主角，宠物仍能行动；菜单查看萧白不把他自动上阵。
- 战斗中、结算中和对话中不能提交换人；编辑期间角色暂离，旧草稿提交被拒绝。
- 候补受伤不会因换上/换下恢复；不在场人物不能远程接受共享行囊用药/装备。
- 键盘完成候补筛选、替换、取消、应用；候补列表长至30人时仍可滚动且四人出战区固定可见。
