# 独立行囊：大库存与操作对象

状态：现行　最后核对：2026-10-19

> 视觉布局以[V4](jianghu-ui-v4.md)为最新：取消常驻右侧详情，改为图标悬停与选中后操作条；本页库存、事务、候补可用性与验收规则继续适用。

2026-10-05 · **V3 评审方案，尚未接入游戏。** [返回](README.md) · 上轮系统审计（已删除）

本页替代 V2 将完整行囊挤在人物立绘右侧的方案。人物页保留三个装备槽及“更换”入口；完整库存进入独立行囊页。四人出战上限约束战斗编成，不约束已结识成员总数，也不限制共享行囊可服务的正式成员数。候补仅在场且可用时可换装、用药；驻地或暂离成员可查看，不能远程操作。选中某人不会自动让其上阵。

## 现状与本轮提案

| 内容 | 已实现 | V3 提案与接入要求 |
| --- | --- | --- |
| 存货 | `S.bag[itemId]` 保存共享数量；只显示正数量且存在于 `ITEMS` 的条目 | 保持共享存货，不创建个人背包，不设置虚构容量上限 |
| 列表 | 七分类，类型/品质排序，全量 DOM 网格，至少24个占位格 | 独立宽页，分类、搜索、筛选、稳定排序和按行虚拟滚动；少物品不铺几十空格 |
| 操作对象 | `mnWho`，`mnMembers()` 仅主角及 `S.party` | 接编成统一的“已加入成员”选择器，分出战/候补，操作前另检查在场可用状态；不得直接遍历所有 `S.mates` 当作已招募 |
| 换装 | `mnCan/mnCmp/mnEquip/mnUnequip` 校验、比较、旧装归包 | 点物品先选中，固定详情后明确点“装备给萧白”；候补需统一成员访问适配 |
| 药食/残页 | `mnUse`，单件恢复、选择武学/心法、取消不扣物 | 保留单件机制；连续恢复可做明确数量确认，不能对所有物品套批量“使用” |
| 材料 | 资源采集进入共享包；靠近对应 NPC 才可交付 | 归入材料类，显示用途和交付地点；不提供远程兑换 |
| 存档 | `save()` 写整份 `S`；采集/交付有先落盘再更新状态的提交逻辑 | 物品事务统一检查、持久化、成功反馈；存储失败不能报“已保存” |

本轮只设计页面与交互，不增加制作、分解、强化、快捷消耗栏、远程商店或出售玩法。战斗中的道具选择仍由战斗规则控制，候补不成为战斗道具目标。

## 页面布局

- 顶栏：江湖一级导航，“行囊”选中。人物页的“更换兵器”可带目标人与兵器筛选进入这里。
- 左栏约 14%：当前操作对象、气血/内力简况、出战/候补分组。分组独立滚动；空战位只出现在队伍编成页，不拿空头像挤占行囊。宠物另一个入口，仅呈现已支持的喂食、项圈操作。
- 中栏约 59%：分类及数量 → 搜索/筛选/排序 → 图标网格。1920宽目标8列×5个完整可见行，随有效宽度降为6列；每格有图标、名称、可用数量。字符不靠整页缩小适配。
- 右栏约 27%：固定物品详情。上部名称、描述、用途；装备显示当前与替换后的真实派生差值；下部选择目标/数量/操作按钮。长描述只在详情内滚动。
- 底栏：已筛出条目数、共享银钱、键位提示。显示“显示 40 项 / 共 126 项”一类浏览量，不写成“40/126 格容量”。126仅能来自真实过滤结果或明确标注的压力样例。

1280×720 至少保证6列、主要文字可读，左侧名单收为可展开对象选择器；详情仍保留。更窄视口将详情做覆盖抽屉，关闭返回原物品，不能压成四栏小字。

### 少量与大量库存

- 0件：说明“尚无此类物品”，显示清除筛选；不露出不可用的默认物品操作。
- 1—20项：从左上紧凑排列，留白用淡纸纹，不填满空格，也不缩放成超大图标。
- 数百项：一个共享列表，仅网格区域滚动，固定分类/搜索/详情；按可视行加前后各两行缓冲渲染。键盘离开可视行时先滚入再聚焦。
- 无强制分页；底部提供当前显示范围，滚动条可拖。切分类记住各分类滚动位置，输入新搜索回顶；换人只刷新可用条件与比较，不突然重排清单。
- 选中 itemId 跨排序保持；物品用尽后选邻项，若无项则清空详情。查找不到时保留搜索词并提供清除，不能误显示旧物品按钮。

## 分类、筛选与搜索

一级：**全部、装备、药食、秘籍、材料、要物、其他**。装备二级：全部/兵器/护具/佩饰；如呈现“宠物装备”，它只是同一装备集合的可选过滤视图，不新增主分类、不复制物品ID或数量。现有数据映射优先级：装备 → `key`要物 → `book/xfbook`秘籍 → `heal/mp`药食 → `mat`材料 → 其他；`gall`蟒蛇胆单独映射药食并注明永久提升。每个物品只有一个主分类。

`qh_dry_branch/qh_wild_herb/qh_river_reed` 目前未设置 `mat`，须由显式分类元数据归为材料。`qh_staff_notes` 是 `key`要物，名称有“笔记”也不能当作可消耗秘籍。用名称猜分类不可作为生产逻辑。

| 功能 | 规则 |
| --- | --- |
| 搜索 | 按中文名称、已存在描述匹配，空白规范化；不搜未获得物品，不假设拼音词库已实现 |
| 筛选 | 当前对象可装备/可使用、只看随身可用库存；不适用的筛选隐藏，切药食时不残留兵器条件 |
| 排序 | 默认分类→名称→ID稳定排序；可选名称、数量、装备属性；属性排序仅装备分类开放，并指明按哪项 |
| 品质 | 现有 `mnQOn()` 的 `S.chapter≥3` 门槛继续遵守；开始部分不显示彩色稀有度筛选或金紫品质边框 |
| 最近获得/未读红点 | 当前无完整获得时间/已读元数据，本轮不画可用按钮；未来需统一获得入口后再加 |
| 穿戴情况 | 详情列出所有正式成员中谁已装备；显示“包内可用 ×N”与“身上 ×M”两个量，不能把穿戴件当可消耗库存 |

默认清单只含包内正数量。可选“查看已穿戴”时，纯穿戴条目也可展示，但显示“在叶蘅身上·包内0”，按钮仅跳转该人装备详情；仅在该人在场可用时允许明确卸下，不直接从别人身上抢装备。宠物佩饰的穿戴数单独合计。

## 完整交互

### 换装

1. 选择已加入角色（可为候补）→选择装备→右栏显示“给叶蘅装备”、部位和限制；驻地或暂离对象只展示详情和当前状态，换装/用药按钮禁用并解释原因。
2. 合法时通过 `mnCmp(w,{eq:{slot:itemId}})` 计算真实差值；属性不满足时展示具体条件，并禁用确认。
3. 点击明确按钮后再检查成员仍有效且在场可用、数量仍足够、槽位可用；一次事务替换，旧装备回包，新装备数量减1，气血/内力正确截限。
4. 更新数量、穿戴标签、目标属性；选择对象不改变四人出战名单。不可偷偷把候补加入 `S.party` 来绕过旧函数限制。
5. 人物页跳入时，返回应回到原装备槽并保留人物。普通浏览换人不得自动装备。

### 药食与数量

- 默认使用1份；选择目标后显示当前值、实际恢复值与溢出，满值时禁用、不扣物品。
- 批量数量仅针对已确认可重复的恢复品；上限是库存与恢复需求的较小值。混合恢复品按“每次仍有任一收益”模拟逐件恢复，考虑医术增益和取整，不能简单用气血缺口除以标注值。
- 数量框整数校验，允许±1，不允许负数、NaN、超过库存；点确认后按钮暂禁用，避免双击重复扣除。
- 武学残页/心法残卷：先选目标再选有效招式/心法，显示门槛与提升，单件确认；关闭或取消不扣除。蟒蛇胆等永久提升物单件明确确认，不开放“一键全部吃”。
- 宠物仍走宠物专属规则，不能把人类药食列表的全部按钮复用给大黄；当前已支持的是羊肉馒头喂食和铜铃项圈。

### 材料、要物与任务

- 野草药不是成品药，不显示“服用”。材料右栏展示已有用途与 NPC 地点，任务要物展示携带说明。
- 行囊不会远程完成任务或兑换。走到 NPC 附近触发交付后，再刷新库存。任务需要数量如无统一数据，不能从描述捏造“已收集2/3”。
- 栖河枯枝兑换文案写“干粮”，底层奖励为 `bun`（物品主名仍羊肉馒头）；应统一阶段显示名适配，不能新建第二种同效果道具造成两套计数。
- 银钱底层都是 `S.silver`；2026-10-16用户确认全作统一显示“文”，正式界面与城市原型保留原数额，不做文两换算。旧“两”字样已作显示纠正，不构成资产变更。

## 数据合同与旧档边界

| 页面字段 | 当前权威来源/接口 | 待接入点 |
| --- | --- | --- |
| ID、名称、图标、描述 | `ITEMS`、`mnIco`/`MENU_ICONS` | 缺图保留文字与一致占位；不显示 undefined |
| 包内数量/金钱 | `S.bag`、`S.silver` | 只接受有限非负整数；未知ID保留存档但不生成可用按钮，不因目录缺失删除玩家物品 |
| 部位/属性/要求 | `mnSlot`、`mnFx`、`ITEMS.req`、`mnCan` | 复用计算，不在UI复制公式 |
| 当前装备 | 主角 `S.weapon/armor/acc`；伙伴 `S.mates[id].equip` | 候补依统一正式名单读取，不依靠战斗出战数组；写入前检查在场可用，驻地/暂离只读 |
| 当前/替换后派生 | `mnHP/mnD/mnCmp` | 选择人变化立即重算；无效目标回退主角并取消未提交动作 |
| 学习型物品 | `mnUse`、`mnUpWhy`、`mnXfOn`、`mnXfList` | 本轮武学机制评审若替换旧装配规则，校验与说明需整体对接新合同，不能保留失效门槛 |
| 资源用途/兑换 | `QiheResources.kinds/recipes/receiver/exchange` | 不复制兑换价格或取消距离、剧情阶段校验 |
| 宠物 | `S.pet/S.pets`、现有喂食/项圈处理器 | 独立目标类型，不混进人类武学、战斗候补列表 |
| 保存 | `saveKey()`、整份 `S` | 栖河使用 `xjh.qihe-prologue.v2`；读旧档补UI默认值，不能覆盖其他入口档 |

搜索、焦点、排序、滚动属于界面状态，初期可只保存在菜单会话，不添加装备实例ID或无限扩写存档。物品数量继续按 itemId 合并；现有同名装备没有独立词条实例，不假装可逐件收藏/锁定。

`save()` 目前吞掉持久化异常，换装/药品也并非原子持久化流程。后续实施需让物品事务报告成功/失败，借鉴 `QiheResources.commit` 的先持久化再提交模式；更新包、装备、恢复值必须作为整体，失败保持旧状态，并提示未扣除。不得将本设计写成这一问题已经修好。

## 验收计划（待实现后执行）

| 测试 | 通过条件 |
| --- | --- |
| 0、1、12、80、500个有效条目 | 0项有空态，小库存不铺空格，500项仅渲染可视行及缓冲，首次打开/筛选/滚动可操作；记录目标设备截图与耗时 |

| 出战/候补各一名切换 | 两人独立装备与气血，不改出战名单；在场候补可操作，驻地/暂离候补只能查看；确认前离场也须拒绝 |
| 装备1件、库存0但他人穿戴、装备不合格 | 正确转移一次；不偷卸他人装备；拒绝时无变化 |
| 连续点击、数量超限、满血、取消参悟 | 无重复扣除、无负数量；满血不消耗，取消不变 |
| 混合恢复/医术加成/永久提升 | 恢复预览与结果相同，批量无无效尾件，永久品不批量 |
| 要物、野草药、近远两处资源交付 | 无乱用药/远程兑换，剧情阶段限制继续有效 |
| 旧档加载、保存重载、存储失败 | 数量装备完整保留；失败可见且不会部分扣除；档位不串 |
| I/B/Esc、输入中文时热键、键盘滚动 | B统一入口后仅一监听；搜索输入不触发移动，Esc先详情后菜单，返回焦点正确 |
