# 台词情绪与语音合成

状态：现行　最后核对：2026-10-19

[返回目录](README.md) · [襄阳配音](../archive/design/xiangyang-voice.md) · [制作后台](voice-backend.md)

## 内容源

- [正式台词](../../tools_audio/voice_lines.json)：剧情对白、识别句与短句，每句记录正文、中文情绪、实际接口情绪、演出说明、版本和剧情来源。
- [候选试听](../../tools_audio/voice_auditions.json)：当前角色的试听稿（沿用旧试听并增加当前同伴及开篇人物），每句同样记录情绪；每个候选使用该角色相同台词与情绪，方便横向比较音色；普通 NPC 只启用 single_preview_index 指定的一句。
- 音色候选定义在 `gen_voice_pick.py`；旧脚本已停止直接生成。统一从 `voice_server.py` 发起 MiniMax 任务。

| 字段 | 用途 | 是否发送给 MiniMax |
| --- | --- | --- |
| `text` | 真实台词，保持游戏原文 | 是，作为 text |
| `emotion` | 策划中文情绪，例如急切克制、感激虚弱 | 否，供编辑与审核 |
| `emotion_api` | 模型支持的情绪枚举 | **是，作为 voice_setting.emotion** |
| `delivery_notes` | 气息、节奏、人物口吻等演出要求 | 否，当前接口没有通用演出提示词参数；供试听验收 |
| `revision` | 改稿版本 | 否，参与缓存指纹 |

演出说明不能拼进台词，否则会被朗读。不能把标记存在清单中就称为已经控制了语音；实际控制以发出的 API 参数为准。

## 当前模型与映射

固定 MiniMax `speech-2.8-hd`。本项目采用已核实的七种情绪：`happy/sad/angry/fearful/disgusted/surprised/calm`。API 官方说明默认自动判断情绪；本项目每句显式指定，避免重要剧情只依赖自动判断。当前模型不使用 `whisper`，也不使用模型适用范围有歧义的 `fluent`。[MiniMax 官方参数](https://platform.minimax.io/docs/api-reference/speech-t2a-http)

| 剧情方向 | emotion_api | 演出验收 |
| --- | --- | --- |
| 日常交谈、核对线索、医生救治指令 | calm | 自然、有停顿；急救清楚利落，冷静不等于平直播报 |
| 欢迎、认可、感谢、释然、嬉笑 | happy | 根据角色克制笑意，不把所有感谢演成欢呼 |
| 病中虚弱、初醒、旧伤、落败 | sad | 气短、句尾轻落；sad 不能保证虚弱音质，必须听验 |
| 威胁、挑衅、愤怒、不耐 | angry | 保留角色攻击性，避免过量喊叫 |
| 慌张、求饶、惊恐、紧张担忧 | fearful | 节奏和呼吸有波动，避免无关恐怖腔 |
| 突然发现、惊讶 | surprised | 重音体现变化，不持续大惊小怪 |
| 明确厌恶 | disgusted | 仅在具体剧情需要时使用；当前清单不强行添加 |

这是粗粒度情绪控制，并非自由表演指令。叶蘅急救用 calm 配“急而不乱”的验收说明；老周醒来用 sad 配气短说明。低声不是更换音色或强行切换模型。若试听仍然生硬，应逐句调整情绪、标点与停顿，不为获得情绪效果随意改变角色音色。

## 缓存与重生成

情绪参数、中文标签、演出说明、文本、版本、音色设置、模型、provider、合成实现版本均进入指纹。改动任一项会使对应片段过期。实现版本升级为 2；旧版未传 emotion 的试听不能冒充新版，即使文字和 voice_id 一样也须重做。

本次已重新生成 17 个启用角色、133 个候选、503 段带情绪试听，所有候选完整可用，当前缺失与失败均为 0。后续仅续补缺失或失败片段，已成功的新版本保留。音色仍需用户确认；试听生成不绑定角色，不触发整角色正式台词生成。

新增台词必须同步填写 `emotion/emotion_api/delivery_notes`；同一句改情绪保持 ID、递增 revision。正式台词改情绪后使用“补全新增／过期语音”，只更新变化语句。逐句编辑情绪、保存多个版本并选择采用的界面属于后续交互，当前不宣称已实现。

## 听感验收

同角色各句应听起来是同一个人。比较时固定 voice_id、模型、pitch、speed；仅情绪随句变化。生成音频会有细微差异，情绪改变可能影响音高与力度，不能保证波形或听感完全相同。先听全句连播，再听急救、感谢、慌张等重点句，检查吞字、重音、语气与角色年龄感。确认音色后正式台词同样传 emotion_api。

当前使用范围调整见[普通 NPC 单句方案](voice-npc.md)：原情绪档案保留，只有 voice_enabled=true 的台词参与制作。单句 NPC 不需要多个情绪试听片段，所选一句仍发送其实际情绪参数。

## 当前人物同步

2026-10-05的声线、108条状态示例和开篇关键对白见[同步说明](voice-current-cast.md)。单句NPC只要求指定句的情绪，主要角色试听覆盖至少两种API情绪。状态名描述细节，API仍是粗粒度参数：裴知古回神用calm、查实用happy、护证用angry，不把“入迷”伪装成模型支持的新枚举。
