## 3. 本作方案：墨线“方胜”令牌

- **形状**：三处统一用菱形（取“方胜”纹意象，与战斗现有菱形和墨迹语言一致）。母图是正方形透明图，界面把它旋转 45° 的方框裁成菱形；HUD 由现在的六边形改为大一号的菱形，菜单出战编成由圆形改为菱形。
- **图与框分离**：图只画人物本身（透明背景，不带框、不带底色、不带文字）；框、底色、状态全由代码画。这样敌我、阵营、状态、主题都只改框，不用重出图。
- **朝向**：我方站画面右侧面朝左，头像统一**三分之四侧面朝画面左**；敌方统一**朝画面右**。轮次条里朝向本身就是一层敌我提示。
- **构图**：头顶到胸口上缘的半身，眼线放在方图高度约 40% 处，脸宽约占方图 45%～55%。同一套图的眼线、脸宽对齐（与 R-画风-03 的“按眼睛到下巴统一大小”同一思路），批量后期时按测得的眼线与下巴位置统一缩放。
- 战斗轮次条的小档（24～32 像素）另出一张“紧头像”裁切版（只到领口），用于防止小尺寸里脸太小。是否需要单独一张，由首批对比决定（见第 8 节）。

- **出框（2026-10-20 评审修正）**：把方图整张塞进菱形会被四角削掉头顶（第二轮评审页实测萧白、叶蘅头发被菱形上角切掉）。改为：菱形只当底板与边框，人物下半身被菱形下沿裁掉，头部允许探出菱形上沿。界面裁切区 = 菱形下半 + 菱形上方 4%～96% 的竖带（CSS `clip-path:polygon(0 50%,4% 46%,4% -45%,96% -45%,96% 46%,100% 50%,50% 100%)`）；图用“头部居中裁切”档，按菱形边长的 124% 绘制、上移 18%。头部裁切的顶边在 4%～96% 范围内有内容时（如狼的毛铺满整框）不出框，整张收进菱形内，避免露出方形硬边。排版时每个令牌上方预留约 16% 边长的空间给探出的头。

### 3.1 图标演出：专门设计，不是立绘裁图（用户 2026-10-20 修正）

用户看首批后的原话：“要清晰的，但我的意思不是让你一比一复刻，是一样的人和一样的风格，但是要有 icon 的特殊设计，例如表情，或者例如半身等等，而不是直接截图”。

所以：画风取清晰的方向 A；人和画风与立绘一致，但每张图标重新设计**表情、姿态、手势、道具、角度**，像一张角色名片，一眼看出这个人是谁、是什么性格。要求：

- **表情有性格**：不用立绘那种中性正脸，按人物登记的性格给一个有辨识度的神情（见下表）。
- **构图重新做**：半身或胸像，头部比立绘裁切大，略带俯仰或侧转；允许一只手或标志道具进画面（针、木棍、刀鞘、绳索），道具可以斜穿画面，在菱形里形成对角线。
- **剪影先读**：缩到 30 像素时，靠发型轮廓、道具斜线、主色块就能分出谁是谁。
- **同一套规矩**：光从左上来，线色、淡彩饱和度与立绘一致；我方朝画面左，敌方朝画面右；仍是透明底、不带框。
- **不改设定**：服装、发型、配色不变，不加设定外的饰物或武器（萧白开篇无剑，只有木棍）。

## 4. 画风：两个方向

本作现有两套画风：对话立绘是白描淡彩高清半身（960×1280，`*_hd_20261017`）；地图是像素精灵（萧白蓝灰 C 包、NPC 像素统一表），战斗用 `b_*_hd_20261017` 精灵。按 R-画风-01，`scene-pixel-*`、90 格 Q 版扁平像素等测试批次一律不作参考。

| | 方向 A：白描淡彩头像（推荐） | 方向 B：像素头像 |
| --- | --- | --- |
| 画法 | 与对话立绘同一画风，线条比立绘略粗、衣褶简化、明暗对比加强，保证 24px 可辨 | 64×64 逻辑像素，约 20 色，1px 深褐描边 |
| 参考图 | 正式对话立绘（同一人同一张脸） | 正式对话立绘＋该角色正式战斗精灵 |
| 优点 | 与对话立绘一眼同一人；HUD、菜单旁边常同屏出现立绘，风格不打架；放大到 64px 以上细节好看 | 与地图精灵、用户参考图更接近；小尺寸边缘锐利 |
| 缺点 | 24px 以下细节会糊，需靠紧头像版与锐化 | 与对话立绘的脸不易对上；生图模型出的“像素”常无干净网格，要靠后期强行对齐 |
| 后期 | 去边、按眼线对齐缩放、下采样时轻锐化；不做透明度二值 | 按 R-画风-02 走 forge pixel 后期：`tools_assets/vendor/agent_sprite_forge/generate2dsprite/pixel_reduce.py` 网格检测与锁色、透明度二值、选择性 1px 描边、轻度提亮；检测不到干净网格的直接判不合格 |

2026-10-20 用户已选清晰的方向 A（见 3.1）；B 不再继续。原推荐理由：三处里两处（状态栏、菜单）都挨着立绘体系；战斗精灵本身已是高清版，像素脸在战斗里也不比淡彩更统一。B 作为对照一并试生成，由用户比较后定。

宠物与动物（大黄、灰狼）同样按所选方向画，不用 Q 版。

## 6. 生成与后期流程

1. 参考图：正式清单登记的对话立绘原件（同一人同一张脸），动物用正式战斗精灵首帧放大；不得取 `deprecated-tests.md` 里列的批次。
2. 生图：用登记表当前源（R-生图-01，现为 302ai-sunburst），统一入口 `xiaojianghu/tools_common/imggen.py`，`--size 1024x1024 --opaque-fix`；提示词首行 `Model: gpt-image-2.5（使用 gpt-image-2.5 生图模型）`（R-生图-02），带透明背景段落（R-生图-04）。当前源不可用时须先经用户同意再临时换源，并在批次 README 写明实际用的源。
3. 每人每方向出 2～3 张备选，评审页按实际尺寸摆放后由用户挑。
4. 后期：方向 A 去边→测眼线与下巴→统一缩放居中→导出 L/M/S；方向 B 另走 forge 像素后期（第 4 节）。
5. 用户确认后才进 `assets/production/` 并登记（R-素材-01）。

## 7. 接入计划（只是计划，本轮不改代码）

1. 新文件 `assets/production/icons/characters/ci_<角色>_<档>_<日期>.webp`，登记 `production-assets.json/.md/.js`，`check_production.py` 通过。
2. 新增一个小模块（暂名 `js/qihe-char-icons.js`）：`charIcon(id,{size,outfit})` 返回路径；萧白按 现代装 / 借衣 / 长发 返回不同图（取代 `qihe-hud.js`、`qihe-ui-model.js`、`qihe-jianghu-ui.js` 里各自写的三段判断）；找不到图时回退现有逻辑。
3. `js/qihe-hud.js`：`.qh-face` 改为菱形，`img` 改用 `charIcon('hero',{size:'L'})`，去掉 `height:180%` 的裁头写法。
4. `js/qihe-jianghu-ui.js` 的 `face()` 与 `js/menu.js` 的 `mnFace()`：优先用 `charIcon`，`.qj-mini` 改为菱形框。
5. `js/bui.js` 的 `buiDia()`：`U.face(u)` 前先查 `charIcon(u, 档)`；框色按第 5.2 节身份表；敌人图标按 `u.sp`/`u.art` 映射。保留自动裁头作回退。
6. 测试：现有战斗与菜单测试不变差（R-测试-01），8792 实机截图三处。
