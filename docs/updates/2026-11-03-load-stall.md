# 线上载入卡死整改（2026-11-03）

状态：本地完成，已发到测试预览地址 https://loadfix.luotuo-36x.pages.dev 验证；未提交，正式地址（main、qihe）未发布。

用户：“序章无法正常打开”“我现在这台电脑都打不开”（截图停在“载入画卷中”，进度条约七成）。

## 原因

- 开场要等 550 多张图、约 52MB 全部下完才放人进去，见 [2026-11-01-scene-audit.md](2026-11-01-scene-audit.md) 的“正式网址载入慢”。
- 这台电脑到 Cloudflare 的线路很慢：一张 0.6MB 的图要 3～10 秒。线路还不稳，有时整条连接一两分钟不回数据，收到响应头就停住。
- 这时任何一张图不回，`Promise.all` 就一直等，载入条永远停住。
- 修之前：线上无头测 3 次里 2 次卡死，测试地址（只改排队）5 次里 2 次卡死。关掉 HTTP/3 更差，4 次里 3 次卡死。

## 改动（`js/core.js`）

- **开场图排队**：最多 8 张同时下。单张 12 秒没下完就换参数重试，最多重试 2 次。
- **立绘不挡开场**：立绘（`p_*` 和表情，约 34MB）不再挡载入条，排进后台慢慢下，后台最多同时 3 张。
  - 对话框立绘本来就用 CSS 网址按需显示。
  - 开战前 `battle.js` 会补齐要用的立绘。
- **看门狗**：载入条 15 秒没动，或总共等了 25 秒，就先进标题，没下完的继续在后台下。全部下完后重新切一次图；开场必需图没下成的，再补下一次。
- **进场地图**：单次 45 秒没下完就放弃这次、换参数重试，原先没有超时。等进场地图时后台立绘和后台地图先暂停，把线路让给眼前要用的地图。

## 验证

- **本机模拟断流**：三成图片请求永远不回应，26 秒进到标题。点“从头开始”后序章开演，对话能往下翻，没有页面错误。
- **测试预览地址，真实线路**：
  - 载入连测 6 次全部进入，用时 10～21 秒。
  - 从标题点“从头开始”进序章连测 5 次全部开演，载入 9～23 秒。
  - 中间那一版没给进场地图让带宽，有 1 次卡在“载入地图中”，这一版已修好。
- **回归测试**：`verify_cg_direction`、`verify_chapter`、`verify_staging`、`verify_audio`、`verify_scene_reach`、`qihe-finale-browser` 通过。

## 留意

- 线路慢的根子没变：首次进入仍要 10～25 秒，后台立绘要几分钟才下完。下完之前，个别立绘或战斗图第一次出现会慢一点。
- 要根治，得换国内访问顺畅的托管（国内 CDN 或对象存储）。这件事要用户定。
- 序章配乐另由音乐会话出候选，评审台第三十八轮“序章配乐”，没接进游戏。
