# 2026-10-16 精灵与道具后期改用 agent-sprite-forge

## 需求

用户认为自写的精灵和道具后期脚本在重复造轮子，要求先比对开源技能 agent-sprite-forge 与现有流程，各做一个给他看。看完对比后确定：

1. 角色精灵整张采用 Codex 重画结果（用户原话：“现在的产图路径不支持我们只修轮廓”）。
2. 道具的选择性描边与提亮成为今后道具的统一风格。

## 对比（同一张 Codex 原图出发，均在临时目录完成）

| 对象 | 现有流程 | forge | 结论 |
| --- | --- | --- | --- |
| 岑霜行走精灵 `s_opening_censhuang`（原图 `character-pixel-fix-20261007/codex/out/opening_censhuang_c0_r3.png`） | `merge.py` 只替换轮廓问题带，脸和衣服内部沿用原表，面部仍糊 | 整张采用重画，五官与衣褶更清楚；锁原表调色板后 31 色、透明度两档、无杂点无青边、16 帧头脚行与原表一致 | forge 更好；不锁调色板会混入原表没有的橙红像素，必须锁 |
| 宋家竹篮 `r_qh_song_basket_v1`（原图 `qh-song-disguise-20261008/codex/out/props.png`） | 网格搜索缩到 18×16，游戏内大小糊成褐色圆点 | 像素后期，篮沿有深色描边、叶子可辨 | forge 更好；颜色比原稿偏橙（默认提亮） |

另外实测：forge 的 `pixel_reduce` 正确拒绝了 Codex 输出（“不是干净像素网格”，块内一致度 0.557），按已知放大倍数和相位强制缩回后结果正常；非整数放大倍数（10.5）的道具原图只能走像素后期。

## 改动

- 文档库 `docs/art-pipeline.md` 新增「精灵与道具后期（2026-10-16 用户确定）」。
- 新增 `tools_assets/vendor/agent_sprite_forge/`：forge 提交 `5324342`（2026-10-06，0.4）的 `generate2dsprite/scripts` 与 `video2dsprite/scripts` 原样副本，MIT 许可，见同目录 `VERSION.md`。未拷贝它的生图路由（配了 API 密钥时会优先走付费 API）。
- 新增 `tools_assets/sprite_finish.py`：Codex 原图（原生透明或纯色底）→ forge 抠图 → 按已知放大倍数与相位缩回、锁原表调色板 → 按原帧位置拼表 → 核对头顶行、脚底行、轮廓重合度、调色板、透明度、孤立杂点；输出精灵表、`report.json`、`contact.png`。
- 新增 `tools_assets/prop_finish.py`：原图（原生透明或纯色底）→ 按从左到右拆件 → forge 像素后期（默认选择性描边与提亮）→ 整数倍放大、可选固定画布；结果为空或高度不足直接报错。
- 两个脚本都只写入新目录，已存在则拒绝覆盖；不改正式素材、正式登记和运行时代码。

## 验证

| 检查 | 结果 |
| --- | --- |
| `sprite_finish.py` 处理岑霜 | status pass；与手工对比版逐像素一致（差异 0 像素）；16 帧头脚行均与原表一致，轮廓重合度 0.991～1.0 |
| `prop_finish.py` 原生透明输入（app-server 生成的青瓷酒坛，主体透明度原为 252～253） | 原生 16×20、16 色、透明度两档；描边与提亮正常 |
| `prop_finish.py` 纯色底输入（宋家四件） | 竹篮 18×16 明显改善；包袱 12×13 相当；账册 9×10 结构丢失，变差；绳子目标高 5 加描边时整件被清掉（脚本已报错），高 7 时断成两截并多出碎块 |
| 正式素材与运行时 | 未改动，未重跑 `check_production.py`（本次无正式素材变更） |

## 采用与限制

- 角色精灵：今后用 `sprite_finish.py`。
- 道具：原生约 12 像素以上用 `prop_finish.py`；10 像素及以下、细长物件效果不可靠，须逐件人工核对或加大原生尺寸，不得直接登记。
- 现有正式道具与角色没有重做；是否批量重做待用户决定。
- forge 的“单张原画→图生视频→整套动作”需要视频服务，本机没有，未使用。
