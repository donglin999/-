# 2026-11-05 · 开始部分与培养模式的 Esc 菜单统一

状态：现行　最后核对：2026-11-05

## 需求（用户原话）

“肯定还会有一个问题你没测出来，第一章和第二章的 esc 弹出来的菜单是不一样的，这肯定要统一啊”

（“第一章、第二章”即开始部分的探索地图和培养模式。）

## 原来什么样

| | 探索地图（开始部分） | 培养模式 |
| --- | --- | --- |
| 按 Esc | 江湖菜单的设置页：七个页签，设置页有声音、战斗界面、快速保存、存档管理、返回首页、操作说明 | 只关小窗；没开小窗时什么也不弹 |
| 右上角齿轮 | — | 另一个“养成设置”小面板：声音、武学与装备、调试日程、修习成果、小游戏试玩。没有存档管理，也没有返回首页 |

## 决定

只保留江湖菜单这一套。

- 培养模式里按 Esc：先逐层关小窗。什么都没开着、也没有对白时，打开江湖菜单的设置页，和探索地图时同一页。
- 右上角齿轮也打开这一页。“养成设置”小面板不再用。
- 培养模式专有的项放在设置页最后一行，只在培养模式时出现：
  - 修习成果；
  - 小游戏试玩；
  - 调试：谷中日程（只在调试版出现，导出的正式版没有）。
  - 点“修习成果”或“小游戏试玩”会关掉菜单，回到培养界面并打开对应页。
- “武学与装备”按钮的功能，菜单里本来就有对应页签，不再单列。
- 设置页副标题按所在模式显示：探索时是“栖河试玩 · 四向地图版”，培养时是“归云谷 · 培养”。操作说明里 Esc 一条改为“逐层返回 · 探索和培养时打开设置”。

改动在这几处：`cultivation.gd`（Esc 与齿轮、`open_jianghu`）、`menu/page_sys.gd`（培养专有的三项）、`menu/menu.gd`（`from_cultivation`）、`flow/flow.gd`（回标题时收起培养界面）。

## 顺带查出并修好的

1. **从培养模式的菜单里点“返回首页”“载入存档”时，培养界面会重新盖回标题页。** 原来的“江湖”按钮就有这个问题。
   - 现在菜单关掉后先等一帧，已经回标题就不再恢复培养界面；
   - `Flow.to_title` 也会收起培养界面。
   - 验证：临时去掉这两处防护，测试立刻报“没干净地回到标题”；还原后通过。
2. **培养模式里打开江湖菜单报“bool 构造不存在”，菜单数据整理被中断。** GDScript 的 `bool()` 收到空值、字符串、字典会报错，原版 JS 只看真假。
   - 全部 12 处可能收到这类值的 `bool()`，改用 JS 式真假判断（`npc/util.gd` 的 `t()`）；
   - 单元测试加了一条写法检查，以后再这样写会直接报出来。
3. **预防性改动：** 从培养模式打开菜单时，不再看地图和对白的“忙碌中”标记，因为这时地图没在运行。这一条是猜测有残留，没有实际复现，只当防护。

## 加进自测

- 旧存档回归：每份存档读进来后，在当时的模式里按一次 Esc，必须打开江湖菜单的设置页，关掉后回到原来的模式。
  - 培养模式正有对白、小窗时按设计不弹菜单，这种情况跳过不算错。
  - 进了培养模式的存档，再测一次“菜单里返回首页”能干净地回到标题。
- 截图对比：加两个用例，探索地图按 Esc（`esc-scene`）、培养模式按 Esc（`esc-cultivation`）。
- 单元测试：加 `bool()` 写法检查，共 14 个测试。
- 全套自测：13/13 通过。15 份存档在探索地图里按 Esc 都打开设置页；培养模式那一侧，有一份存档实测打开的是同一页，另外两份正有对白，跳过。

## 没做的

- 读一份培养模式的存档时，会先落在归云谷地图上，要找周砚或休息才回到培养界面。原版也是这样，没有改。
