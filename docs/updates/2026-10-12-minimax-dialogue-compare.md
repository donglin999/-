# MiniMax 同剧情对白对照

- 需求：用户要求调用 MiniMax 最好模型 API，重写同样几段剧情供对比。
- 负责文档：[候选试写与来源](../archive/design/cultivation-minimax-compare-20261012/README.md)；核对 `ai-onboarding.md`、人物/归云谷一家、第二章对白整改及实际逐句机器源。模型按官方当前公开 API 的旗舰 MiniMax-M3 选择，未使用旧 M2.5。
- 本地成果：正式 8792 的独立 review 页，四场 63 句，与当前稿并排及连贯阅读；API 原稿保留，Codex 点评独立列出。51 句改写、12 句未改。请求参数、实际型号、失败尝试和输出哈希均有记录；密钥不进入产物。
- 验证：机器源未改变，63 句 ID/顺序/字幕/演员检查通过；浏览器四场/阅读模式/步法条件/意见保存导出通过；936 项正式素材检查通过。对照截图和检查结果在正式工作区同名 review 批次。
- 限制：这是候选比较，不是四场已通过文学审稿；模型仍有生硬搭配，逐场标注。第二次流式返回没有用量，未估算账单。
- 未修改正式对白和存档，未生成配音，未 Git 提交、未推送、未线上发布。

## 第二轮：取消逐句限制

用户要求根据人设与剧情重新编排。改用无旧台词、无旧句 ID、无句数要求的创作梗概，四场最终分别调用 MiniMax-M3；路图段截断后由 M3 根据自己的新稿补全。原稿及第一轮保留，新增整场对照，可选左栏版本、剧情选择/步法状态、独立舞台说明显隐、单独意见保存导出。

实际产出 207 条对白/心声＋41 条独立舞台说明；模型创作内容原样展示。来源与结构核验通过，但文学/事实审查未通过：称谓错误、信件新线索、路况矛盾等在每场审核中列明。用户是在比对模型试稿，不能误称已采用或合格。

参数更正与失败尝试见负责文档；M3 的 reasoning_effort 参数不生效。最终三场使用推理模式，路图在推理稿基础上由直接模式补完。本地候选完成，未改变正式游戏或存档，未提交或发布。

## 第三轮：恢复原版篇幅

用户要求限制台词总量。本轮按原版五条可见路径设置85%—115%字数预算。MiniMax调用未稳定满足预算和语义要求，保留七次实际请求后，由Codex根据已有候选与剧情事实编辑压缩，明确标注作者分工。最终短稿并非API原文，不冒用模型署名。

抄图280字、问路303字、拜师面402字、初识心法326字、叶家来信186字，均通过预算；无独立动作段。现有对照页默认短稿，可选回看长稿，保留旧稿与旧意见。来源、API记录、编辑稿与长度报告在正式工作区short-rewrite；浏览器五路径、版本、意见、1440/390检查通过，素材936项通过。仅本地候选更新，正式剧情未变，未提交或发布。
