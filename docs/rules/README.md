# 规则管理

状态：现行　最后核对：2026-10-19（原记：现行　最后核对：2026-10-19）

## 为什么有这个目录

规则原来散在 CLAUDE.md、导入引导、美术管线、各设计页、记忆里，改了一处、别处还写着旧说法，AI 读到旧的就照旧做（例如生图源换成 302 后，两份文档仍写“默认走 codex”）。现在：

- **正文只写一处**：`rules.json` 是单一来源，`规则登记表.md` 由脚本生成，不手改。
- **其他文档只引用编号**，例如“生图源见 R-生图-01”。
- **改规则要用户批准**：新增、修改、废止条目后，用户确认，再运行 `python3 xiaojianghu/tools_docs/check_docs.py --approve-rules` 登记指纹；没登记，检查失败、发布构建停下。
- **旧说法会被抓出来**：每条规则可写 `stale`（已废止旧说法的正则），检查脚本在现行文档里找到就报错。

## 条目字段

| 字段 | 含义 |
|---|---|
| id | 编号，`R-领域-序号`，废止后不复用 |
| area | 领域（协作、生图、画风、地图、特效、剧情、系统、素材、发布、验证、文档） |
| rule | 规则正文 |
| scope | 适用范围 |
| source | 出处：日期、用户原话、详细说明所在文档 |
| status | 现行／废止；废止的写 `superseded_by` |
| supersedes | 取代了哪条旧规则 |
| stale | 旧说法正则，可省 |

## 检查脚本做什么

`xiaojianghu/tools_docs/check_docs.py`（发布构建 `scripts/build-pages.cjs` 第一步会跑）：

1. 规则指纹：rules.json 改了没批准 → 失败。
2. 过时说法：现行文档里出现 stale 正则 → 失败。docs/updates、archive、_attic、art_sources、review 是历史记录，不查；命中处前面有“不得、不能、废止、改为”等词或在引号里的，算在讲禁令，不算。
3. 死链：超出基线（`deadlinks-baseline.json`）的新死链 → 失败。基线是 2026-10-19 已有的 96 条，清理后用 `--rebase-links` 缩小。
4. 状态：现行文档页首没写“状态：现行／历史／草稿”的，只警告计数（第三步补状态后再改为失败）。
